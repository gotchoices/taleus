# Complete — tallysim experiment runner + CLI + first experiment

Final ticket of the tallysim **network-model tier** (`tallysim-model-generators` → `tallysim-oracle` →
**runner**). It turned the seeded generators + whole-graph oracle into an experiment harness and produced
the tier's first checked-in result. Downstream work (`tallysim-discovery`, `feat-tallysim-trading-model`)
builds on the sweep runner and the no-op "step the economy" seam delivered here.

## What shipped (unchanged from implement, plus the review edit below)

- **`src/scenario.ts`** — the plain, JSON-serialisable `ScenarioSpec` / `SweepSpec` model, the `AmountSpec`,
  and the `EconomyStep` seam with its shipped `noOpEconomyStep` default.
- **`src/runner.ts`** — `runSweep` (a streaming generator yielding one `RunRecord` per cell × seed; no
  buffering, no filesystem), `runSweepToArray`, three independent seed streams (network / workload / economy)
  each offset by the run seed, and the economy hook called once per run.
- **`src/metrics.ts`** — pure aggregation: `summarizePaymentMetrics` / `summarizeClearingMetrics` /
  `summarizeDistribution`. Degenerate inputs guarded (P over zero trials is 0, never NaN; zero-sample
  distribution reports `count: 0`).
- **`src/serialize-records.ts`** — pure JSON-lines + streaming CSV (`CsvAccumulator`) serialisers;
  non-finite → JSON `null` / empty CSV cell.
- **`src/cli/sweep.ts`** — the one Node-only file; reads a spec, streams JSON-lines, builds the CSV on the
  same pass. Kept off the neutral build and the `no-node-globals` guard; compiled by `tsconfig.cli.json`.
- **`experiments/route-existence/`** — four committed specs, `out/*.{jsonl,csv}`, the combined
  `route-existence.jsonl` (594 records), `regenerate.sh`, and a README. Reproduces byte-identically.
- Docs: `docs/design.md` §§ Metrics + Runner/experiments fully written (incl. the first finding); README,
  `docs/index.md`, and `AGENTS.md` updated to list tallysim's runner tier.

## Review findings

Read both implement commits (`55e3fab`, `b7da953`) with fresh eyes before the handoff summary; re-derived
the finding against the committed CSV data; scrutinised every new source and test file plus the docs it
touches. **Gates green throughout: build + lint + test pass, 163 tests (13 suites)** — up from 162 (one test
added below). The experiment reproduces **byte-identically** (ran `regenerate.sh`; working tree stayed clean
for `experiments/`). The `no-node-globals` guard scans the four new core files and passes; the CLI is
correctly excluded.

**Finding spot-checked against the data (correct).** Pulled `out/uniform-unlimited.csv` at `N=10000, D=6`:
`largestComponentFraction` climbs 0.03–0.06 (deg 1) → ~0.57 (1.5) → ~0.80 (2) → ~0.94 (3), and `pRouteExists`
crosses between degree 4 (~0.33) and 6 (~0.93). Both match the `degree^D ≈ N` claim and the percolation
threshold in `docs/design.md` § Runner / experiments → *First experiment*. The documented numbers are real,
not illustrative.

**Minor — fixed in this pass (1):**
- **A vary path reaching into a materialised network mutated shared state.** `cloneScenario` keeps a
  `materialized` `Network` by reference (deliberately — not deep-cloned), and `setByPath` would happily set
  a leaf under `network.materialized.*`, corrupting that shared object across every cell *and* the caller's
  base scenario. Only `network.params.*` happened to throw before (and cryptically — "no object at params",
  because a materialised source has no `params`). Added an explicit guard in `validateSweep`: for a
  materialised base network, every `vary` path must start with `workload.` — fail fast with a clear message
  otherwise. Added `runner.test.ts` coverage for the dangerous `network.materialized.entityCount` path
  (the pre-existing `network.params.meanDegree` rejection test still passes, same message substring).

**Tripwire — recorded, not ticketed (1):**
- **Network/workload stream independence is contingent on the spec, not enforced.** The runner derives the
  network stream from `network.seed + runSeed` and the workload stream from `workload.seed + runSeed`. These
  are independent *only when the spec gives them distinct base seeds*; if a spec sets
  `network.seed === workload.seed`, both `SeededRandom`s start from identical state and the draws correlate.
  Every checked-in spec uses distinct seeds (1000 / 2000), so it is fine now. Parked as a `NOTE` at the seed
  derivation site in `runner.ts` (next to where `ECONOMY_SEED_OFFSET` already separates the economy stream) —
  if that convention ever stops holding, offset the network seed the same way. *Not fixed now:* adding the
  offset would change every committed experiment byte for no present benefit.

**Checked and correct — no change:**
- **Resource cleanup** — `runToOutputs` closes the JSON-lines fd in a `finally`; CSV is written only after a
  clean stream. A mid-stream throw leaves a partial `.jsonl` on disk (acceptable for a dev CLI).
- **Type safety** — no `any` in the new code; `NetworkSource` / `AmountSpec` / `CapacityDistribution` are
  discriminated unions and `cloneCapacity` switches exhaustively.
- **Determinism** — byte-identical across two full `runSweep` runs and the full `regenerate.sh` rebuild.
- **Degenerate / error paths** — empty/isolated/single-entity networks, zero queries, zero-sample
  distributions, empty `seeds`, and vary-into-materialized all covered and correct.
- **max-flow opt-in** — only `payment` + `metrics:['max-flow']` samples it (`maxFlowSamples`, default 32);
  `pairs` is populated only for drawn pairs, so sampling never reads an undefined pair.
- **Decomposition / altitude** — pure metrics + serialisers cleanly separated from the Node CLI; small
  single-purpose functions; comments purposeful.

**Pre-existing `NOTE`s acknowledged (no action):** materialised-network-by-reference (`runner.ts`),

## Known gaps carried forward (from the implement handoff, still open — not defects)

- Runner metric cross-checks lean on pair-independent topologies (complete / isolated); a stronger check
  would pin a non-trivial materialised topology and assert the runner's aggregated metrics against an
  independent per-pair oracle computation over the *same* drawn pairs. Belongs to a future hardening ticket,
  not this review.
- The clearing workload + max-flow sampling are unit-tested but exercised by no checked-in *experiment*; a
  clearing-availability experiment is natural follow-on work (future ticket).
