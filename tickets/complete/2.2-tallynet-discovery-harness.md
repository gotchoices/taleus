----

The `tallynet/testing` harness: a `VirtualClock` (deterministic simulated time on a min-heap with a
microtask drain between fires), a `SeededRandom` (mulberry32, reproducible per seed), and an
`InMemoryNetwork` that wires one `DiscoveryNode` per graph node over the shared clock so a whole route
search runs in one process on compressed, deterministic time. Shipped behind the new `"./testing"`
subpath export (kept out of the main `src/index.ts` barrel by design). `randomGraph` and
`negateNumericTerms` round out the module.

This ticket was the **review** pass over that implementation (implement commit `d00718e`).

## Review findings

**Verdict: implementation is sound and high-quality. No correctness defects found.** The code is
well-decomposed, carries thorough class/module docs, obeys the platform-neutral rules (verified: the
`no-node-globals` allow-list is keyed on the exact path `clock.ts`, so `testing/clock.ts` is correctly
*not* allowlisted and genuinely uses no `setTimeout`/`Date.now`/`Math.random`), and builds + lints
clean.

### Checked, with disposition

- **Virtual clock correctness** — min-heap `(time asc, seq asc)` ordering, lazy-deletion of cleared
  timers, same-instant cascade handling in `advance`/`runUntilIdle`, and the microtask-drain
  termination argument all verified by reading. No out-of-order time advance is reachable: new timers
  are always scheduled at `virtualNow + max(0,ms) ≥` the firing timer's time. `pendingTimers` correctly
  reports 0 after a drained run (an empty `earliest()` implies an empty heap for a min-heap).
  **Found: nothing.**
- **Rejected / dropped / latent delivery paths** — traced through `send` → `Pending` → `harvest` →
  `pruneCandidates`. A no-neighbour `linkId` rejects and is pruned `failed` (the `Pending` constructor
  attaches a rejection handler, so no unhandled rejection); a `drop` arms no timer and is pruned at
  max-depth; `latencyMs` defers only the request leg. All verified sound. **Found: nothing wrong, but
  no test coverage** — see below.
- **Shared link id → back-link cycle prune** — confirmed: the back-link candidate's nonce
  (`makeNonce(session, linkId)`) equals the plan tail's, so `createContext`'s cycle check drops it.
  The shared-id design is correct, not a shortcut.
- **Determinism under concurrent originators** — session codes are drawn synchronously at the top of
  `UniOriginator.discover` (before any `await`), in call order; the participant draws no randomness
  (candidates sorted by nonce). Reproducibility holds for the default harness. Verified.
- **Test coverage (the one gap) — FIXED INLINE.** The harness's two headline link-condition knobs,
  `latencyMs` and `drop`, shipped with **zero** assertions (the handoff deferred "scenarios" to the
  sibling, but these are the harness's *own* primitives, testable in isolation). Added two focused
  tests to `network.test.ts`: *"defers a delivery by exactly its link latency"* (asserts one timer is
  armed at `+latencyMs` and the hop settles at exactly that instant) and *"a dropped link arms no
  timer and never delivers"* (asserts `pendingTimers === 0` and the delivery never settles). Suite now
  **185 tests / 15 suites, all green**; lint clean.
- **Docs** — read `packages/tallynet/docs/design.md` §Testing approach / §Simulation hooks. They
  describe the intended harness (virtual clock, seeded random, injectable latency/drop/sleeping nodes,
  seeded random graph with assertions, `tallynet/testing` subpath) and accurately match what shipped.
  The §Testing mention of wiring `updatePeer` is forward-looking (the commit phase is a later ticket);
  no update needed.

### Deferred by design (not defects, not re-filed)

- The deep stress scenarios — latency folding a late answer into a later round, `drop` pruned at
  max-depth within a real search, multi-path dedupe, and the **1,000-node seeded scale test** — belong
  to the sibling `tallynet-discovery` (ticket `2.3`, currently in `implement/`). The heap + drain are
  *built* for scale but remain *unproven at 1,000 nodes*; that assertion lands with 2.3.

### Observation routed to the sibling (no new ticket)

- `packages/tallynet/src/discovery/index.ts` re-exports `types`/`hooks`/`store`/`participant` but **not**
  `engine`/`originator`, so `DiscoveryNode`, `DiscoveryResult`, and `OriginatorOptions` are not reachable
  from the main `tallynet` package barrel. The harness is unaffected (it imports those modules directly),
  but a plain `tallynet` consumer cannot name `DiscoveryNode`. Those two files are owned by
  `2.3-tallynet-discovery`, which is still in `implement/` and will pass through review — the fix (add
  the two `export *` lines) belongs there, not here. Flagged so the 2.3 review catches it.

### Tripwires (all already recorded in-code by the implementer; listed here as the index)

- `DRAIN_QUIET = 16` is a margin'd guess for microtask-drain quiescence — noted at the constant in
  `clock.ts`; raise it (or switch to an explicit quiescence signal) if a deeper promise chain ever
  under-drains.
- Duplicate link ids across the graph: `linkLookup` keeps the last — `NOTE:` at the site in
  `network.ts`; only matters if parallel edges sharing one id are ever modelled.
- Term inversion defaults to identity; `negateNumericTerms` is opt-in via `invertTerms` — documented in
  the `network.ts` module doc and the `randomGraph` note.

No new tripwires added — the implementer's set is complete.

## Deviations from the ticket's API sketch (reviewed, all accepted)

All intentional and sound: `trace` is a single shared `TraceSink` (a sink is itself a function, so a
per-node factory is indistinguishable at runtime; every event carries `nodeId`); `hasher?` added to
config (the node requires one; one shared hasher so both link ends agree on nonces);
`InMemoryNetwork.deliver` exposed as the raw one-hop primitive; `VirtualClock.pendingTimers` getter for
leak assertions; `advance` given the same self-reschedule guard as `runUntilIdle`.
