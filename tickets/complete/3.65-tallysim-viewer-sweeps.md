The sweeps view is the fifth and last viewer rendering tier: a `Graph | Sweep` mode toggle on the shell, and
in Sweep mode a line chart of **one metric vs. one varied parameter, one line per series** (e.g. the chance a
payment routes rising with how densely the network is connected), loaded from a parameter-sweep file or an
embedded sample. The implementation (pure core `sweep-data.ts`, source loader `source.ts`, uPlot renderer
`chart.ts`, UI wiring `view.ts` + shell/styles) landed green but with **no browser render ever run** — the gate
was build + type-check, not a pixel seen. This review did the adversarial pass over that seam.

**Build, lint, and tests all green** after the review changes (`yarn build && yarn lint && yarn test` in
`packages/tallysim-viewer`): tsc clean, eslint clean, 94 jest tests pass (was 86; +8 new).

## Review findings

### Correctness — one important bug found and fixed inline

- **Chart stranded on the empty message once data arrives (`chart.ts`, `draw()`).** The headline flow was
  broken: click **Sweep** (no data yet → `draw()` → `showEmpty()`, which sets `plotHost.style.display = 'none'`)
  then **Load sample sweep** → `draw()` measured `plotHost` *before* restoring its display, read 0×0, and
  returned early as if the tab were hidden. The sample (and any file loaded while the empty message showed) never
  rendered — a dead-end only escapable by never entering the empty state first. Reachable on the very first
  manual checklist step, which is exactly why a build-only gate missed it.
  **Fix:** reordered `draw()` to resolve the empty-vs-plot display *first* — compute series, show the empty
  message and return if there are no points, else `showPlot()` to reveal `plotHost`, *then* measure and defer
  only on a genuinely hidden tab (an ancestor is `display:none`). Small, self-contained reorder within the one
  function, so fixed in this pass rather than spun out.
- **Side benefit — stale series colours after a cross-mode theme toggle.** The old measure-first/`destroyPlot`-last
  order meant `setPalette()` while the Sweep tab was hidden bailed before rebuilding, and the later show path only
  called `setSize()` (never a redraw), so the lines kept the *previous* theme's `seriesScale` until the next data
  change. The reorder moves `destroyPlot()` to the top of `draw()`, so a hidden-tab `setPalette()` now clears the
  plot and the show path rebuilds it with the current palette. Verified by tracing the shell's
  `applyTheme → sweepView.setPalette` and `applyMode('sweep') → relayout` paths.

### Test coverage — gap closed

- **`source.ts` had zero direct tests**, yet the design doc claimed it was "covered by `sweep-data`'s tests".
  Its `detectSweepFormat` sniffing logic (extension → `{`-lead → `generator` → comma fallback) is distinct
  branching that `sweep-data`'s tests never exercise. Added `src/sweeps/source.test.ts` (8 cases): extension
  precedence over text, each sniff branch and the comma fallback, sample round-trip + column classification,
  name-vs-sniff equivalence, malformed-JSONL throws, empty-file reads to an empty table. Updated `docs/design.md`
  (the module table and the Testing section) to state `source.ts` is now jest-covered rather than overstating it.

### DRY / efficiency

- **`alignSeries` was computed twice per draw** (`chart.ts` — once in `draw()`, once inside `options()`). Folded
  it to a single pass: `options()` now takes the already-aligned data. Minor, but it was redundant work on every
  redraw and the handoff flagged it.

### Checked and found clean (no action)

- **Pure core (`sweep-data.ts`)** — the non-finite→gap and distribution-`count:0`→gap guards, mean-per-cell,
  `alignSeries` null-gap behaviour, jsonl≡csv column/role agreement, and the RFC-4180 CSV reader are well
  covered by `sweep-data.test.ts` and read correctly. No changes.
- **`view.ts` picker wiring** — default selection seeding, the `dist:<family>` metric → sub-field reveal, the
  `gapWhenZeroColumn = ${family}.count` guard (dropped only when the sub-field *is* `count`), x-removed-from-series
  handling, and the parse-error-to-status path all trace correctly. Error policy (malformed line throws to the
  status line; empty file is not an error) matches the core and is now test-pinned via `source.ts`.
- **Shell mode toggle (`shell.ts`) + CSS (`styles.ts`)** — the per-mode panel/main show-hide, `relayout()` on
  Sweep-becomes-visible, and `applyTheme → setPalette` are consistent; the chart host flex layout and
  `--tsv-*`-driven legend/axis colours are present. (Canvas rendering itself remains a manual check — see below.)

### Tripwire (conditional — recorded, not a ticket)

- **x-axis picker lists every numeric column**, including all distribution sub-fields (~50 on a discovery sweep).
  This matches the spec ("x may be any numeric column") and is fine now; it only becomes work if the list ever
  reads as noise. Already parked as a `NOTE:` at `view.ts` `xOptions()`; restrict to params + scalar metrics, or
  group under an optgroup, only if that trips. No ticket filed.

### Still owed to a human / CI (not introduced here, not resolvable in-agent)

- **No real browser render was performed.** `chart.ts` + `view.ts` are browser-only; past the pure pipeline
  (does uPlot actually draw, does the legend relocate into its strip, does hidden→visible resize fit) the gate
  is the build + a manual `yarn dev` pass. The empty→data bug above is now fixed in code and reasoned through,
  but a human should still run the Sweep-mode checklist (load sample → two-line chart; switch metric to a
  distribution → sub-field appears, no spurious 0 at the count:0 cell; load the same sweep as `.jsonl` then
  `.csv` → identical lines; toggle series-by + light/dark → chart and legend redraw/re-theme; corrupt a JSONL
  line → parse-error in the panel status).
- **Bundle size >500 kB** (`vite build` single-chunk warning: sigma + graphology + uplot). Pre-existing across
  the viewer, not introduced by this tier; no code-splitting added. Left for a dedicated effort if it matters.
- **Live-run source tab remains unwired** — intended; the first mode switch ships `Graph | Sweep` only, and
  `3.66-tallysim-viewer-live-controls` is the follow-up. The shell seam comment still marks the mount point.
