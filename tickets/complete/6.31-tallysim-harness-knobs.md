## What shipped (Half A of the split from `tallysim-timeout-harness-metrics`)

Recovery of members an interior non-relayer cuts off from the commit push moved **into the protocol** (via the
landed prereq `tallynet-stalled-recovery`): `VirtualClock.runUntilIdle()` fires every live timer until the heap
empties, so the protocol's deadline one-shot and periodic recovery-loop ticks already run inside the single
drain. This ticket:

- **Removed the simulator's manual pull pass** (`recoverStrandedByPull` + its call site) from
  `consensus-harness.ts`. `runLiftForOutcome` reads the settlement off the originator straight after
  `runUntilIdle`, with no pull pass. `LiftResult.pullCalls` / `.recovered` are **intentionally** left in place
  hard-coded to `0` — the split boundary that keeps `consensus-metrics.ts` and `voter-harness.test.ts` green
  with no edit. Half B (`6.32-tallysim-timeout-harness-metrics`) removes the fields and re-homes the counters.
- **Added two per-experiment knobs.** `RunLiftOptions.ttlMs` → `buildLift`'s mint (lift deadline);
  `ConsensusConfig.recoveryGiveupMs` → `buildSimNetwork` (how long past the deadline a node's recovery loop
  polls before abandoning). Both surfaced on `ConsensusSpec` and threaded through `consensus-runner.ts`
  (spread-only-when-set). `SIM_RECOVERY_GIVEUP_MS` (60_000) stays the default.

Three new tests in `consensus-harness.test.ts` cover self-recovery and the two knobs.

## Review findings

**Verdict: ready for `complete`.** Core change is behaviour-preserving and the knobs thread correctly. Two
staleness defects this change introduced were fixed inline; no major tickets filed.

### Checked & confirmed (no change needed)

- **Core removal is behaviour-preserving.** After `runUntilIdle` the protocol recovery loop heals stranded
  members during the single drain, so reading `settled` with the manual pass gone is identical. Evidence: the
  **unedited** `voter-harness.test.ts` record-availability tests still pass (members 3,4 reach `commit` via the
  loop; `pullCalls`/`recovered` both `0`). Nothing else depended on the removed pass's clock side-effects.
- **`ttlMs` threading.** `buildLift` mints the transaction code with `generate(ttlMs)` (default `600_000`) while
  **reusing** the discovery session code, so the deadline anchors on the fresh transaction code and is
  discovery-independent — the exact-delta test (`700_000 − 100_000 = 600_000`) is a valid behavioural proof.
  All three threading sites use `!== undefined` guards (not truthy), so the no-knob path is byte-identical and a
  deliberate `0` would still thread (and correctly throw in `generate`, which rejects non-positive ttl).
- **`recoveryGiveupMs` threading.** `buildSimNetwork` → `consensus?.recoveryGiveupMs ?? SIM_RECOVERY_GIVEUP_MS`;
  `consensusConfigFromCompiled` sets it only when supplied; `cloneConsensus`'s `{ ...consensus }` deep-copies
  the scalar; `validateConsensusSweep` already permits `consensus.*` vary paths. Both knobs varyable, no change.
- **Split boundary intact.** `LiftResult.pullCalls`/`.recovered` hard-coded `0`; `consensus-metrics.ts` and its
  `pullMessagesPerLift` / `recoveredTotal` columns remain (vestigial but compiling/green). Owned by Half B
  (`6.32`) — not re-reported as a bug, per the implement handoff.
- **Lint + tests.** `yarn workspace tallysim build` (exit 0), `lint` (exit 0), `test` → **426 passed, 34
  suites**. Re-linted clean after the inline comment edit.

### Found & fixed inline (minor)

- **Stale design doc.** `packages/tallysim/docs/design.md` still described the now-removed simulator-driven pull
  as the live mechanism ("the simulator now drives a **pull pass**", "the **simulator itself** triggers the
  recovery pulls"). This ticket's removal (plus the landed prereq) made those statements false. Rewrote the two
  mechanism passages to describe the protocol recovery loop and that the simulator drives no pull; reframed the
  forward pointer from "self-timing-out" (landed in `tallynet-stalled-recovery`) to "self-re-routing" (still
  deferred to `tallynet-propagation-timeouts`). The metrics-column prose (`pullMessagesPerLift`,
  `recoveredTotal`) was left for Half B, which removes those fields.
- **Stale in-code comment.** `LiftResult.cooperatingMembers` JSDoc said "exactly as the pull pass excludes
  them" — a dangling reference to the removed function. Trimmed.

### Noted, deliberately not actioned (with reason)

- **Test duplication (nit, kept).** New test #1 ("stranded members self-heal…") is a near-verbatim duplicate of
  the existing `voter-harness.test.ts` "with contact points…" test (same `line(5)`, seed `7`, refuser `2`,
  options, and assertions). **Kept, not deleted:** it co-locates with and anchors the two genuinely-new knob
  tests in the same describe block, and documents the "no manual pull" transition at the `consensus-harness`
  level where the change lives. Low-harm redundancy; flagged here so a future consolidation knows it exists.
- **Runner-plumbing coverage (deferred to 6.35, not a new ticket).** The new tests drive `ttlMs`/
  `recoveryGiveupMs` through `buildSimNetwork`/`runLiftForOutcome` directly. The scenario→runner threading
  (`consensus-runner.ts`: `ttlMs`→`liftOptions`, `recoveryGiveupMs`→`config`) is correct by inspection (trivial
  spread-when-set) but has no end-to-end test. `6.35-tallysim-timeout-scenarios` (already in `implement/`)
  builds the explicit timeout experiments that exercise these knobs through the runner, so the coverage lands
  there by design.

### Tripwires

- **None new.** The pre-existing `NOTE` in `consensus-runner.ts` (rebuild-per-query pays keygen per query;
  cache identities if grids grow) is out of scope and untouched. The `O(members²)` clock-drain `NOTE` that lived
  inside `recoverStrandedByPull` was correctly removed along with the function.
