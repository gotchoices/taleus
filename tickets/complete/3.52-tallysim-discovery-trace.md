Shipped and reviewed. A versioned NDJSON **trace file format** for a discovery-simulation run (header + network snapshot + one line per protocol event, in time order), the streaming writer and lazy reader, and a Node CLI driver. See the implement commit `ticket(implement): tallysim-discovery-trace` for the full shape; the review additions are below.

## What shipped (unchanged from implement)

- **`sim/trace-format.ts`** — `TraceLine` union (`header` | `network` | `event`), `TRACE_FORMAT_VERSION = 1`, `buildTraceHeader`, `makeNetworkSnapshot`, `serializeTraceLine`, `parseTrace`. Version + shape checked on read with actionable errors.
- **`sim/trace-writer.ts`** — `makeTraceWriter(header, snapshot, out, options?)`: header + network up front, then one line per event as it arrives (never accumulates). `options.sessions` filters to selected session codes. Platform-neutral (`LineSink`, no `node:fs`).
- **`cli/trace.ts`** — Node driver; reads a `SimScenario` JSON, runs the workload, streams the trace to stdout or `--out <path>`. Two-pass (header needs session codes, minted inside `discover()`).
- **`model.ts`** — extracted `networkToSerialized` / `networkFromSerialized` (+ exported `SerializedNetwork` / `SerializedTally`); `serialize`/`deserialize` delegate. No behaviour change.
- **`scenario.ts`** — added `SimScenario`.
- **`docs/design.md`** — § *Trace & replay format* filled in.

## Review findings

Reviewed from the full implement diff first, then the handoff. Build, lint, and test all green: **227 tests, 19 suites, 0 failures** (implement left 216/18; +11 from the new CLI suite). No `.pre-existing-*` files written. Live CLI smoke test re-run against the built artifact (byte-identical across runs, line order `header, network, event…`, `--query` selection self-consistent).

**Fixed inline (minor):**

- **CLI had no automated test** (the implementer flagged this as the biggest hole and exported `parseArgs` + `recordTrace(scenario, args, versions, open)` with an injectable in-memory `open()` for exactly this). Added **`cli/trace.test.ts`** mirroring `sweep.test.ts`: `parseArgs` coverage (spec path, `--out`, `--seed`, repeated `--query`, and the error paths — missing spec, unknown flag, missing value, non-integer seed, negative/extra-positional); `recordTrace` over an in-memory sink (streams header+network+events and parses back self-consistently, every event joins to a header query); `--query` selection records only the chosen query; byte-identical across two runs; a sub-two-entity network yields a valid header+network file with no events.
- **Redundant network materialisation.** `drawQueries` re-ran `materializeNetwork(scenario.network, runSeed)` purely to read `entityCount`, while `recordTrace` had already materialised the same network one line earlier. Refactored `drawQueries` to take `(workload, entityCount)` and reuse the existing network — one materialisation per run instead of two (one-time cost, but free to remove).
- **Out-of-range `--query` silently produced an empty trace** (header with zero queries, zero events, no warning). Now fails fast before the sink is opened, with a clear message naming the valid range (`--query 5 is out of range (the scenario draws 3 queries, 0..2)`), consistent with the CLI's other fail-fast validations. Covered by a new test (rejects, writes no partial file).

**Checked and confirmed correct (no change):**

- **Two-pass determinism** — the load-bearing assumption is that pass 1 (no trace sink) mints the *same* session codes as pass 2 (with trace sink). Verified in source: the session code comes from the `InMemoryNetwork`'s shared seeded `random` (fixed `SESSION_CODE_SEED`), and the trace sink is pure observability — `safeTraceSink` is only *called* with built events, it never draws from `random` nor schedules timers. Both passes build a fresh network with the same seed and run identical queries, so codes and events match. Confirmed live: every event's `sessionCode` (from pass 2) is present in `header.queries[]` (from pass 1).
- **Docs accuracy** — `docs/design.md` names `late-answer-folded`, `query-sent`, and `settled` events; all three exist in tallynet's `TraceEvent` union (`packages/tallynet/src/trace.ts`). The § matches the shipped format (line kinds, ordering, versioning, streaming both ways, selected-query recording, byte-identical determinism, two-pass reason).
- **`model.ts` error-prefix change** (`deserialize:` → `networkFromSerialized:`) — confirmed no caller matches the old prefix; `model.test.ts` asserts only `/formatVersion/`.
- **Happy path / edge / error paths** — version mismatch, garbage version, non-header first line, empty input, missing network line, malformed JSON, trailing blank line, `Infinity ↔ null` round-trip, and a hand-built consensus (`settled`) event round-trip are all covered by `trace-format.test.ts`; streaming, byte-count, session filtering, and the real-harness path by `trace-writer.test.ts`.

**Major findings:** none — no new `fix/`, `plan/`, or `backlog/` tickets spawned.

**Tripwires (conditional — carried from implement, still parked in code, no ticket):**

- Network snapshot held in memory while serialising — `NOTE:` at `makeNetworkSnapshot` (`sim/trace-format.ts`). Only trips if entity counts ever dwarf event counts.
- `stats().bytes` counts the on-disk NDJSON size (each line + 1 newline). An in-memory accumulator that joins lines *without* newlines would see `bytes` overcount by `lines`. Documented in the `TraceWriterStats` doc comment; fine for the CLI (it appends `\n`).
- `utf8ByteLength` reimplements the UTF-8 code-unit scan rather than using `TextEncoder` (the neutral build compiles with `types: []`). Reviewed: correct for well-formed strings and lone surrogates; the only exercised path is ASCII JSON. No change.

No new tripwires added by the review.
