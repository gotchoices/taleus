## What shipped

The participant half of unidirectional (route) discovery in `tallynet`: the logic that runs at every
node a query passes through. A port of ChipNet's `unidirectional/participant.ts` with every
discovery defect from `docs/chipnet-review.md` fixed, split into a durable/in-flight state model so a
SQL-backed store can persist it. The originator side and end-to-end multi-hop wiring remain to the
`tallynet-discovery` engine ticket.

Surface (all re-exported `discovery/index.ts` → `src/index.ts`): `types.ts` (data model, generic over
`TTerms`/`TPayload`), `hooks.ts` (`DiscoveryHooks` + `defaultHooks`), `store.ts` (`StoredContext`,
`ParticipantStore`, `contextKey`, `MemoryParticipantStore`), `participant.ts` (`Participant`:
`enter`/`reenter`, budgeted fan-out, harvest/fold/prune, conclusion paths, `prependMatch`).

Validate: `yarn workspace tallynet build && yarn workspace tallynet test && yarn workspace tallynet lint`
(green: 12 suites, 148 tests).

## Review findings

**Scope reviewed:** the full implement diff (the four serialisability fixes in `participant.ts`),
every file under `discovery/`, both test files, `src/index.ts` re-exports, the supporting
`digest.ts`/`sequencing.ts` ports the code leans on, and `docs/design.md`. Build + test + lint run
green.

**Correctness — one minor defect found and fixed inline:**
- **Late-erroring sleeping candidate was spuriously retried and leaked an in-flight entry.** A
  candidate that slept past a round budget (kept for a later round) and then *errored* in the window
  between rounds was caught by the next round's opening `harvest` (added to `errored`), but
  `issueBatch` ran before the end-of-round prune and re-issued a fresh sub-query to it — one wasted
  `queryPeer` call, and the re-added `inFlight` entry was never cleaned once the candidate was pruned
  `failed` (a slow per-node map leak under repeated late failures). The late-*success* path was
  already handled correctly; only the error branch had the asymmetry. **Fix:** `issueBatch` now skips
  any candidate already in this cycle's `errored` set (participant.ts). Added a regression test
  (`a sleeping peer that errors between rounds is pruned (failed) without a spurious retry`) that
  asserts exactly one `queryPeer` call; confirmed it fails without the fix (two calls) and passes
  with it.

**Serialisability fixes (from the implement run) — verified legitimate, not cosmetic:** confirmed
`digest.ts assertEncodable` iterates `Object.keys` and throws on an `undefined`-*valued* key (not
just a top-level `undefined`), so the four conditional-omission sites in `participant.ts`
(`createContext`, `buildMatchPlans` self + peer, `foldPlans`, `makeResponse`) are required for any
context/plan/response to survive DAG-CBOR encoding in a SQL-backed store. All read sites use optional
access / `?? []`, so omitting the keys breaks no consumer.

**Correctness paths traced and found sound:** cycle removal (pruned at `enter`, never re-queried);
duplicate-visit rejection via the single `contextKey`; failed/no-reentrance/max-depth/expired/
timed-out prune reasons; late-answer folding (`candidate.depth < context.depth`); restart recovery
from durable `lastResponse`; idempotent re-fold (path-keyed dedupe, `prependMatch` doesn't touch the
path, so self is never double-prepended); timer cleanup via `budgetedStep`'s `finally` (matches the
leaked-timer assertion in `afterEach`); Pending rejections are always handled (constructor attaches a
reject handler), so no unhandled-rejection path.

- **`maxDepth` semantics — worked through, NOT a defect.** Each node checks its *local* round count
  (`context.depth >= query.maxDepth`), which at first glance ignores the node's path position. But
  the originator drives every wave; a node at hop *h* always has a lower local depth than the
  originator, so the originator's own `maxDepth` check (where local depth == global wave count) is
  always the binding constraint and halts the whole search at ~`maxDepth` hops. Intermediate nodes'
  checks are redundant but harmless — no over-search. No action.

**Tests:** the 25 participant + 10 store cases cover happy path, each ChipNet defect, validation
(no-link-id disclosure), budget/timers, late answer, restart, concurrency, and serialisability
(spy-store `canonicalEncode` on every save). One regression case added this pass (above). Example-
based, not property/fuzz — acceptable for v1.

**Conditional / forward notes (parked, not tickets):**
- `planKey` dedupes by path alone — already carries a `NOTE:` at the function for the day two plans
  share a path but differ in members/payload (fine for single-denomination v1).
- The `Session code mismatch` branch in `validateQueryState` is unreachable with `MemoryParticipantStore`
  (it keys by the reentrance's own session); tested via a stub store that returns a mismatched context.
  Kept as a defensive check against a non-trivial host store — earns its keep.
- `maxQueryAgeMs` declared but unenforced (reentrance age unbounded) — intentional per its doc comment;
  the engine ticket decides if it needs enforcing sooner.
- `random` (`RandomSource`) accepted but unused — the participant is deterministic (candidates sorted
  by nonce); held for the engine's tie-breaking.

**Gaps (floor, not ceiling) — out of scope here, belong to the engine ticket:**
- No multi-hop integration test (single node over stub `findAddress`/`queryPeer` only); real transport
  framing and the originator's budget accounting are unverified. ChipNet's 6-node happy path is the
  port target for `tallynet-discovery`.
- No property/fuzz testing of `prependMatch` member-upgrade merging or deep candidate graphs.
- The mixed `selfIsMatch` + remaining-candidates `enter` case (self plan returned *and* a reentrance
  offered) is handled by the code but not directly asserted.

**Docs:** `docs/design.md` § Discovery already describes the durable/in-flight split and the
per-round model; no update needed. The `undefined`-key encoding subtlety is an implementation detail,
correctly captured in code comments at each fix site.

No major findings → no new `fix/`/`plan/`/`backlog/` tickets filed. The sole defect was minor and
fixed in this pass.
