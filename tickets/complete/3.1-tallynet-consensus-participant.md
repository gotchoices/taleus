### Major — filed as a ticket

- **A forged commit vote can shadow a referee's genuine vote (liveness/outcome defect).** Commit-phase signatures are stored *unverified* while the promise phase is incomplete (the mechanism that makes honest out-of-order delivery work). But the "first signature per referee wins" rule runs before verification, so any forwarding node can inject a garbage `C`/`NC` bearing a referee's (public) address during the promise phase; it is stored unverified, and the referee's genuine vote then collides with it as `changed`/`equivocation` and is dropped. The fake never counts (never verifies), so no *false* commit is possible — but genuine votes get silenced, which can stall or wrongly void a lift a single malicious relay targets. Promises are unaffected (verified immediately on merge). Dormant today (module not yet wired to production; all tests single-node) but **definitely** triggers once multi-node propagation meets an adversarial/buggy peer — a latent defect, not a tripwire. Filed: `backlog/debt-tallynet-forged-commit-shadows-vote.md` (prereq `tallynet-consensus`; fix + multi-node regression tests belong with the 3.2 harness).

### Tripwires (already recorded in-code by the implementer; re-indexed here, no action)

- **Per-pass commit re-verification.** `countVerifiedCommits` re-verifies every retained commit on each `getRecordState` pass, in a loop; `canonicalPromiseSet` (`digest.ts`) re-maps/re-sorts per verify. Fine at lift scale; `NOTE:` comments at both sites say to cache per `(promise-set, signature)` if referee/promise sets ever grow large. Left as-is.
- **Propagation-timeout seam.** A stuck commit phase (tie, or referees yet to vote) stays `propagating` and does not settle in-band — v1 has no timer. `NOTE:` at `getRecordState`'s propagating branch marks the injection point for `feat-tallynet-propagation-timeouts`, keyed off `expiresAt(transactionCode)` (no new field). (Minor doc note: `design.md` says the timeout injects at `advanceState`'s branch; the actual seam `NOTE:` sits in `getRecordState`, which `advanceState` calls — same control point, not worth a change.)
- **`MemoryTrxStore` holds records by reference.** The participant guards this by pushing a distinct per-peer snapshot (`snapshotRecord`); the suppress/re-push test exercises it. A durable store must preserve the "distinct object per push" contract (documented in `store.ts`). (The snapshot is a fresh shallow copy with copied arrays, not an `Object.freeze` — the doc prose calls it "frozen," which is loose but harmless since the live record reassigns its signature arrays rather than mutating them in place.)

### Checked and acceptable (no action)

- **Merge order deviates from the ticket prose on purpose** (membership → role → have-one → verify → store, not verify-first). Consequence: a forged relabel arriving *after* a member's genuine signature reports as `equivocation`/`changed` rather than `forged`; the outcome (refuse second, keep first, log once) is identical. Rationale is in the `mergeSignature` doc comment. Acceptable. (The *before*-genuine adversarial variant is the separate major finding above.)
- **`settled` trace can be emitted more than once** across a throwing-release retry (the `isReleased` guard short-circuits the actual release, but the `settled` event precedes the release attempt and re-fires on retry). `release` itself is still exactly-once (gated on the store flag, set only after success). Harmless trace duplication; left as-is.
- **Release-once across re-delivery and restart** — guarded on the store flag, set only after `release` resolves; a throwing release leaves it unset and retries, never double-releasing. Tested (re-delivery, restart-after-release, restart-before-release, throw-once retry).
- **No infinite loop in `advanceState`** — each step signs exactly once and the `weHaveSigned`/`promisePhaseComplete` guards prevent re-requesting the same signature; a solo `[P,R]` node cascades promise → commit → release and stops.
- **Strict-majority-both-ways** arithmetic (`> R/2` each way, over distinct referees) is mutually exclusive; even split settles neither. Tested for R = 1, 2, 3.
- **Platform-neutrality** — `no-node-globals.test.ts` passes over the new source; time via injected `Clock`, no `Date.now`/timers/`Math.random`/`Buffer`/node imports.

### Gaps carried forward to 3.2 (not defects here)

- **Multi-node propagation is entirely untested** — every test is one node over hand-built records. Convergence across a real route (ring/star order, a commit racing promises between distinct nodes, push fan-out reaching quorum) is `implement/3.2-tallynet-consensus`. The out-of-order and push tests simulate *delivery order at one node*, not graph-wide convergence.
- **Referee reachability** — a referee-only member rides no link, so it is reachable only via a `physical` address or multi-hop relay; whether every nominated referee is reachable is a 3.2 propagation question. Not exercised here.
- **Concurrent `update` re-entrancy** — `update` mutates the stored record object with no locking; two inbound updates for the same transaction interleaving on one node is a 3.2 concern. Single-threaded test path does not hit it.
