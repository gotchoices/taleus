New unscoped Yarn-workspace package **`packages/tallysim-viewer`** — a static, server-less browser dev tool
to *view* a simulated tally network. This ticket delivered the scaffold + the platform-neutral, headlessly-
tested **core** (no rendering yet): trace indexing, the nonce de-anonymiser, the pure playback model, and the
sweep-output parser. See `docs/design.md` for the settled stack and the de-anonymiser insight.

The rendering tiers (graph view, replay controls, live in-browser runs, sweep charts) are the next tickets
and extend `docs/design.md` without re-litigating the stack.

## Review findings

Adversarial pass over the implement diff (`8fea795`) with fresh eyes, then the handoff. **No major findings —
no new tickets filed.** Minor findings fixed inline; two conditional concerns recorded as tripwires.

### Verified correct (checked hardest)

- **De-anonymiser (keystone) — correct.** Traced the full nonce round-trip end to end:
  - The sim harness builds links with `id = linkIdForTally(i) = "T"+i` (`tallysim/src/sim/harness.ts:100`)
    and constructs `InMemoryNetwork` **without** passing a `hasher`, so the trace's nonces use the default
    `nobleHasher` (`tallynet/src/testing/network.ts:217,419`). The viewer's `createDeanonymiser` recomputes
    `makeNonce(sessionCode, linkIdForTally(i))` — also defaulting to `nobleHasher`. **Hashers match**; this was
    the one way the decode could have silently produced wrong-but-plausible edges, and it is sound.
  - `linkIdForTally` is positional and injective, so **two tallies on the same node pair get distinct nonces —
    no aliasing.** Added a regression test pinning this (the handoff's top "probe hardest" item).
  - Session-salting, the `undefined` sentinel for an unknown nonce, and the non-contiguous-walk sentinel are
    all correct and tested.
- **Sentinel-vs-throw** choice (`nodePathOfPlanPath` returns `undefined`, not throw): acceptable. The contract
  is documented in the interface JSDoc; the graph ticket must honour it (not silently drop a route). Recorded
  as a contract note, not a defect.
- **Found-plan split confirmed intended.** A file trace cannot reconstruct a found route (`plan-found` is a
  bare marker; `plan-returned` carries one inbound nonce, no plan id/path), so `deriveActiveSet` surfaces found
  plans as markers + lit explored edges, and `nodePathOfPlanPath` is fed a `Plan.path` from the live-run
  `QueryOutcome` in a later ticket. This split is correct and documented in `docs/design.md`.
- **Active-set "accumulate, never un-light"**: correct replay semantics (the explored subgraph grows with
  time); max round/depth and last-event-kind-by-time are order-robust; `late-answer-folded` updates in place
  (tested: no duplicate, later round wins).
- **Sweep byte-identical (JSONL vs CSV) — verified against the real `tallysim` serialisers.** `params` is a
  flat `Record<string, number>` of already-dotted paths, so the viewer's one-level `flattenInto` is a
  pass-through that matches the CSV's direct `row.set(path, value)`; `metrics` is one-deep
  (`DistributionSummary`, `pruneReasons`) and the viewer's one-level flatten mirrors
  `serialize-records.ts`'s `flattenMetrics` exactly. Non-finite (`Infinity`→`null`/empty cell) reads as
  **absent**, never `0` — tested on both formats.
- **CSV reader**: RFC-4180 correct by inspection (quoted commas/newlines/`""`, CR/LF/CRLF, no spurious trailing
  record). The quoted-field test covers commas + escaped quotes.
- **Scaffold hygiene**: `dist/` is gitignored and not committed; `tsconfig`/`vite`/`jest` configs are sound;
  `main.ts` is a DOM-only shell importing nothing from `core/`. Doc edits to `AGENTS.md` + `docs/index.md` are
  accurate. `README.md`/`docs/design.md` reflect the built reality.

### Minor — fixed inline this pass

- **`trace-index.ts` interface JSDoc overstated ordering.** `eventsForSession`/`allEvents` were documented "in
  time order", but the index preserves **arrival** order (it never re-sorts; bounds are tracked by comparison).
  True for a well-formed trace, misleading for the live/concurrent builder. Tightened both JSDocs to "arrival
  order (= time order for a well-formed trace; not re-sorted)", matching the module header's own honest note.
- **Test coverage** for two handoff-flagged "probe hardest" paths was absent; added:
  - `deanonymise.test.ts`: parallel tallies on one node pair → distinct nonces, no aliasing.
  - `timeline.test.ts`: an empty / unresolved nonce lights the node but **no** edge (the originator's own first
    `query-received`).
  Viewer suite now **23 passed / 4 suites** (was 21).

### Tripwires recorded (index only — not tickets)

- `deanonymise.ts`, at the plan-walk site: `NOTE:` — a self-loop tally (`stock === foil === current`) walks
  back to the same node (repeated entry, not sentinel). Generators never emit self-loops; only a hand-built
  trace could. Decide route-vs-sentinel *if* self-loops ever become real. (Conditional → NOTE, per handoff.)
- Pre-existing NOTEs from implement, re-verified as appropriate and left in place: `deanonymise.ts` reverse map
  is O(tallies) per session (lazy + cached); `timeline.ts` `deriveActiveSet` recompute is O(events) per seek.
  Both only matter at scales the viewer is not built for yet.
