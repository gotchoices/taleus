## What shipped

The discovery-simulation **wiring** joining tallysim's two tiers — the all-seeing **oracle** (ground truth:
*does a route exist*) and the real decentralised route-discovery protocol (`tallynet`) — so an experiment
can measure whether the protocol finds the routes the oracle proves exist. It turns a tallysim `Network`
into a running `tallynet` discovery network on compressed, deterministic time, gives each node a local-only
capacity view equal to the oracle's directed-edge capacity, imposes network conditions, and runs one payment
query to completion.

- `sim/naming.ts` — the single node↔entity bijection + `linkIdForTally`.
- `sim/terms.ts` — `LiftTerms`, `invertLiftTerms`, `makeCapacityHooks()` (overrides only the two capacity checks).
- `sim/conditions.ts` — `compileConditions`: count-based seeded selection; precedence sleeping > late > drop > base latency; drawn from a dedicated seed stream so session codes stay stable.
- `sim/harness.ts` — `buildSimNetwork` + `runQuery` (discover-then-drain).
- `workload.ts` (new) — `materializeNetwork`/`drawAmount`/`drawPaymentPair` extracted from `runner.ts`; `runner.ts` rewired.
- `distributions.ts` — `uniformInt`/`lognormalSample` exported (additive).
- `index.ts` — exports `./workload.js` and `./sim/index.js`.
- `docs/design.md` — new `## Discovery simulation` section.

The discrete-event scheduler was **not** rebuilt — this consumes `tallynet/testing`'s `VirtualClock` +
`InMemoryNetwork`. Everything simulator-specific lives in `tallysim/src/sim/`.

## Review findings

**Scrutinised:** the full implement diff (`f6992e7..5b637b3`) read before the handoff summary; the
`found ⊆ oracle` correctness anchor against the real `tallynet` API; the `workload.ts` extraction; the
conditions compiler; source hygiene; docs; and the full build/lint/test suite.

**Correctness anchor — verified sound.** `found ⊆ oracle` rests on each node's forward link view equalling
the oracle's directed-edge capacity. Confirmed end to end: the harness builds each link from the *same*
`capacity.ts` helpers the oracle's graph view uses (`capStockToFoil`/`capFoilToStock`), and
`InMemoryNetwork` applies `invertLiftTerms` on the `node2 → node1` direction (verified in
`tallynet/src/testing/network.ts`), so a node `u`'s forward view of a link to `v` is exactly `cap(u→v)`.
`makeCapacityHooks` correctly re-checks `capFwd ≥ amount` in both `negotiateIntent` and `planSatisfies`, and
rejects the empty (self-match) path. tallynet API usage (`discover`, `DiscoveryHooks`, `UniQuery`, `Plan`)
matches the current signatures.

**`workload.ts` extraction — proved byte-identical, not just asserted.** The handoff flagged that the
committed experiment fixtures were not directly diffed. I regenerated all four `route-existence` sweep specs
(`uniform-{unlimited,realistic}`, `scalefree-{unlimited,realistic}`) from the built CLI and diffed both the
`.jsonl` and `.csv` outputs against the committed `out/` — **zero differences**. The extracted functions are
verbatim moves and draw order (`drawPaymentPair` then `drawAmount`) is preserved. Oracle-runner output is
confirmed unchanged.

**Conditions compiler — sound.** Determinism, count-based `round(fraction·pool)` selection, the partial
Fisher–Yates bounds (`nextInt(arr.length - i)` always ≥ 1 inside the loop), the drop-pool exclusion of
sleeping/late-incident links, the draw order, and the precedence ladder all check out and are covered by
`conditions.test.ts`.

**`from === to` — probed, benign.** Untested in the suite (the handoff only claimed "no throw"). Probed
empirically: it does not throw and returns self-loop plans (e.g. `1→0→1`). This does **not** violate
`found ⊆ oracle` — the oracle treats `from === to` as a *cycle* (`Oracle.selfPayment`, `oracle.ts:17`) and
also reports `exists=true`, so the two tiers agree. `drawPaymentPair` never produces `from === to`, so it is
not a real workload input. No change needed. The `found ⊆ oracle` test correctly `continue`s on
`from === to`, so it carries no false confidence.

**Build / lint / tests — all pass.** `yarn workspace tallysim build` + `lint` (exit 0) + `test`:
**199 tests, 16 suites, 0 failures.** No pre-existing failures surfaced (no `.pre-existing-*` files written).

### Major — routed to the downstream ticket (not a defect in this code)

- **Reach-budgeting warning was missing from the metrics ticket (`3.53-tallysim-discovery-metrics`).** The
  headline finding — the protocol's reach is ~half its `maxDepth` (`maxDepth ≥ 2(L − 1)` for an `L`-hop
  route) — is critical to how that ticket sets up its depth sweep, or its "found vs oracle" gap will read as
  a connectivity failure when it is really expected reentrance cadence. Added an edge-case bullet to
  `3.53`'s "Edge cases & interactions" pointing at `design.md` § "Rounds ↔ hops". No code defect here.

### Tripwire — conditional, documented, no ticket

- **Protocol reach ≈ half `maxDepth` (`2(L − 1)`).** Reproduces with default hooks, ample capacity and zero
  latency, so it is **intrinsic `tallynet` behaviour**, not something this wiring introduces. Whether it is
  a `tallynet` inefficiency worth optimising is a protocol-level question for `tallynet`'s own review, out
  of scope for this tallysim wiring — so no ticket is filed. Parked where a future reader meets it:
  `design.md` § "Rounds ↔ hops" (architectural, no single code site) and memory `tallynet-peer-match-depth`.
  The `found ⊆ oracle` guarantee holds regardless; the protocol simply undercounts oracle-reachable routes.

### Noted — acceptable as built, no action

- **Sleeping *target* does not block a route** (a neighbour peer-matches it from its own adjacency; only a
  sleeping non-target **relay** blocks). This is a correct model for route *discovery* — payee liveness is a
  commit-phase (consensus) concern, not a discovery one. Documented in `design.md`; the degradation-gap test
  pins seed 0 / `line(4)` and asserts the sleeping set is `{1}` so it fails loudly if selection drifts.
- **Late-node test numbers empirically tuned** (`lateLatencyMs: 3000`, `maxDepth: 8`). The test asserts only
  that a route is still found when a large latency exceeds a round budget; it does not characterise the
  TTL/latency ceiling. Acceptable — an existence assertion, not a boundary claim.
- **`SESSION_CODE_SEED = 1` fixed module constant.** Safe: outcomes depend only on nonces, never session-code
  *values*. Documented; flagged only in case a future multi-run harness wants it parameterised.
