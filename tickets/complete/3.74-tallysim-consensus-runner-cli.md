## What was built (implement summary, verified against the diff)

The **sequential consensus sweep runner** — the consensus counterpart to the discovery `sim-runner.ts` — plus
its serialiser and a Node CLI:

- **`sim/consensus-runner.ts`** — `runConsensusSweep(spec)` (async generator, one `ConsensusRunRecord` per
  `cell × seed`), `runConsensusSweepToArray`, and the `ConsensusRunRecord` type. Per run it clones the
  materialised network, draws the workload, and drives each query `buildSimNetwork → runQuery → runLiftForOutcome
  → analyzeLift`, then `summarizeConsensusMetrics`. Sequential-only (a committed lift mutates balances on the one
  kept network; order matters). Rebuilds the sim per query (link terms freeze at construction).
- **`serialize-consensus-records.ts`** — the consensus serialiser, reusing the generic machinery in
  `serialize-records.ts`; supplies only the consensus CSV column order.
- **`cli/consensus.ts`** — `parseArgs` / `runToOutputs` / `fileSinks` / `main`, modelled on `cli/simulate.ts`
  minus `--concurrent` and `--trace`. Flags: `<spec.json> [--jsonl <out>] [--csv <out>]`.
- **Wiring** — `src/index.ts`, `src/sim/index.ts`, `package.json` (`"consensus"` script).

## Review findings

**Checked:** implement diff read first with fresh eyes, then the handoff; the three load-bearing design
decisions (sequential-only, deliberate duplication, validation widening); source hygiene (file size, comment
clarity, function size/naming, DRY); type safety; resource cleanup; error handling; determinism; export wiring;
the duplicated plumbing diffed against `sim-runner.ts` for accidental divergence; docs re-read against the new
reality; test coverage (happy / edge / error / degenerate / determinism); and `lint` + `test` + `build` + an
end-to-end CLI run on a generated network. Correctness, efficiency, and resource-cleanup review surfaced nothing
actionable beyond what is recorded below — the runner composes already-reviewed prereq pieces (`runLiftForOutcome`,
`analyzeLift`, `summarizeConsensusMetrics`) and the duplicated plumbing matches `sim-runner.ts` with no
accidental divergence (only the two intentional consensus additions).

- **[minor — FIXED inline] Docs did not reflect the new runner / CLI / serialiser.** `docs/design.md` documented
  the consensus *harness* tier but not the new **consensus sweep runner**, its **CLI**, or the **serialiser** —
  the change landed with no doc update. Added a § *The sequential consensus sweep runner* subsection (pipeline,
  the sequential-only invariant, rebuild-per-query, the seed streams, the validation widening, and a pointer to
  the duplication tech-debt), extended § *Output serialisation and the CLI* to name `serialize-consensus-records.ts`
  and `cli/consensus.ts`, and added `consensus` to the CLI usage block. Verified against the shipped code.

- **[minor — FIXED inline] Load-bearing branches had no runner-level tests.** The discovery runner tests its
  degenerate (`entityCount < 2`) guard and all three `validateSimSweep` throw cases; the consensus runner tested
  neither, though design decision #3 (the **validation widening** to accept `conditions.*` / `consensus.*` vary
  paths on a materialised network) is exactly the behaviour the CSV x-axis depends on. Added five tests to
  `consensus-runner.test.ts` (4 → 9): the degenerate fully-zeroed record; empty-seeds and empty-values rejection;
  a structural vary path on a materialised network still rejected; and — the point of the widening — a
  `consensus.refuserFraction` vary path **allowed** and sweeping two cells. All pass.

- **[major — FILED as `backlog/debt-tallysim-sweep-clone-extraction`] ~90 lines of sweep plumbing duplicated.**
  `applyVary`, `cloneSimScenario`, `cloneConditions`, `cloneCapacity`, and the validation helper are copied from
  `sim-runner.ts` (private there) into `consensus-runner.ts`, several byte-identical. The implementer copied
  rather than extracted on purpose — extraction re-touches the pinned byte-identical discovery sweep, so it is
  its own change, not an inline review fix. The hazard (a future `SimScenario` field cloned in only one copy →
  silent per-cell data loss) is real, so it is tracked as a `debt-` ticket with the target shape and a
  byte-identical-discovery-sweep acceptance bar. Not fixed inline, by design.

- **[tripwire — parked, not a ticket] Rebuild-per-query keygen cost.** The runner rebuilds `buildSimNetwork`
  (re-deriving consensus identities) once per query, because an already-built `InMemoryNetwork` freezes link
  capacity. Fine for this tier's small grids; if a grid grows large, cache the identities/nodes across rebuilds.
  Already recorded as a `NOTE:` comment at the rebuild loop in `consensus-runner.ts` (`runConsensusQueries`).

- **[tripwire — parked, not a ticket] Resource-handle accumulation.** `makeSimResources` is built once per run
  and its handles accumulate `promiseCtxs` / `releaseSuccesses` across every query (the runner never reads them —
  it uses the port only for the stateless promise/commit gates). Bounded and tiny at this tier (queries ×
  route-length). It is conditional on far larger query counts than this tier runs, and shares a home with the
  keygen `NOTE:` at the same loop; left as knowledge, not queued work.

- **[verified, no action] Sequential-only invariant.** Confirmed `concurrent` is deliberately absent: a committed
  lift mutates `tally.balance` on the one kept network and the next query must see it, so the lift order is
  load-bearing. Documented at length in the module header and now in the design doc.

- **[verified, no action] Determinism & seed streams.** Confirmed the refuser set and resource port are built
  once per run (outside the per-query loop), refuser/identity seeds are offset by the run seed and independent of
  the discovery streams, and the determinism test replays byte-for-byte. The end-to-end CLI run reproduced the
  expected commit-rate response to `consensus.refuserFraction` (0 → `pCommitGivenFound` 1; 0.25 → voids with
  `voidReasons.refused-promise` > 0 and a lower rate).

- **[verified, no action] Nothing eaten / no janky parsing / cross-platform.** The runner/serialiser are
  platform-neutral pure/async code; only `cli/consensus.ts` touches Node (`node:fs`, guarded `main()`), excluded
  from the neutral build as its siblings are. The CLI's `finally` closes the jsonl fd on both success and throw.

**Empty categories:** No correctness defect, type-safety issue, resource leak, or swallowed exception was found —
the runner is thin composition over already-reviewed prereq modules, and the one genuine maintainability concern
(duplication) is filed rather than defect-fixed because it is a refactor over a pinned path.
