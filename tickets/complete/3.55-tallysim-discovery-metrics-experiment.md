## What landed

A new checked-in discovery experiment at `packages/tallysim/experiments/found-vs-oracle/`, the discovery-tier
counterpart to the oracle-tier `experiments/route-existence/`: committed `specs/*.json` (`SimSweepSpec`
files), a `regenerate.sh` that rebuilds tallysim and streams each spec through `node dist/cli/simulate.js`,
committed `out/*.{jsonl,csv}`, a combined self-describing `found-vs-oracle.jsonl` (42 records), and a
`README.md`. Plus a `### Found vs. oracle — the discovery experiment` write-up in `docs/design.md`
(§ Discovery simulation).

**No production source changed.** The engine (`sim/sim-runner.ts`, `sim/protocol-metrics.ts`), the CLI and the
serialisers are the two prereq tickets' work, consumed as-is. The cost-ceiling `NOTE:` at
`sim-runner.ts:184` predates this ticket (added by `tallynet-discovery`).

Three sweeps, all at one fixed topology (`scale-free`, `edgesPerNode = 3`, mean degree ≈ 6, **unlimited**
capacity, 50 queries, seeds `[1, 2]`) so each isolates one variable from capacity gating:

- **depth-sweep** — `D ∈ {2..6}` × `N ∈ {100, 1000}`: `pFoundGivenExists = 1` in every cell (no reach gap at
  matched depth); depth shows up as message cost.
- **sleeping-sweep** — `sleepingFraction ∈ {0..0.5}` at `D = 6`, `N = 100`: `pFoundGivenExists` falls ≈ 1 → 0.39.
- **latency-sweep** — `latency ∈ {0..200}` ms: time grows linearly, `pFoundGivenExists`/`roundsUsed` flat.

## Review findings

Adversarial pass over the implement diff (`dd5ca06`) read first, handoff second. The work is docs +
experiment artifacts only — low blast radius — so the review centred on **data integrity, reproducibility, and
whether every documented claim is backed by the committed numbers**.

**Checked and verified (clean):**

- **Reproducibility — byte-identical.** Copied `out/` + combined file aside, re-ran `regenerate.sh`, then
  `diff -rq` on `out/` and the combined file: identical, and `git status` on the experiment dir is clean after
  regenerating. The determinism claim holds.
- **Correctness guardrail.** All 42 committed records report `falseFoundCount === 0` (found ⊆ oracle) —
  `grep` tally confirmed `42 × :0`. The engine also asserts this guardrail in
  `sim/protocol-metrics.test.ts` and `sim/sim-runner.test.ts` on its own seeded runs.
- **Lint / build / test.** `yarn workspace tallysim lint` exit 0; `build` clean; `test` 273 pass / 23 suites.
- **Apples-to-apples depth comparison.** Confirmed at `sim-runner.ts:188` the oracle is probed at the
  protocol's *same* `query.depth`. Combined with the `tallynet-discovery-depth-reach` fix (reach = `maxDepth`,
  § "Rounds ↔ hops" at `design.md:491`), the matched-depth `pFoundGivenExists = 1` result is honest, not a
  cadence artifact. The implementer correctly declined the stale "budget maxDepth at 2×" framing — consistent
  with the recorded project fact (discovery reach = maxDepth = L).
- **Every quantitative doc claim traced to data.** Re-derived each number in the `design.md` write-up from the
  CSVs: depth `messages` (N=1000: ≈6.4 @ D=2 → ≈404 @ D=4); sleeping seed-averaged `pFoundGivenExists`
  (1.0/0.87/0.78/0.57/0.48/0.39); `nodesTouched` fall (≈22 → 5); `messages` rise-then-fall with sleeping;
  latency `timeToCompletionMs` (0/21/106/213/426, max = latency × 6). All match.
- **Cross-references.** "§ First experiment", "§ Rounds ↔ hops", and the `sim-runner.ts` `NOTE:` pointer all
  resolve to real, accurate targets.
- **Combined-file navigability.** The three sweeps carry disjoint `params` key sets (depth: `workload.depth` +
  `network.params.entityCount`; sleeping: `conditions.sleepingFraction`; latency: `conditions.latency.value`),
  20 + 12 + 10 = 42 records — a reader can partition cleanly, as the README claims.

**Found — no defects.** No correctness, hygiene, DRY, type-safety, or error-handling issues. `regenerate.sh`
is clean (`set -euo pipefail`, path-safe, fixed spec order for byte-stability). The `_note` spec field is
accepted by the runner (regeneration succeeded).

**Minor (fixed inline): none needed.** Nothing to correct — docs are accurate against the data.

**Major (new tickets): none filed.** The one real limitation is that **all three sweeps hold capacity
unlimited** — the finite-capacity found-vs-oracle divergence is never exercised. This is explicitly scoped out
by the ticket and documented in both the README gaps and the `design.md` write-up ("Realistic finite capacity …
is the natural next sweep"). It is future *enhancement* work, not a defect in what landed, so filing a ticket
now would be getting ahead; left as the documented next cut.

**Tripwires (conditional, not ticketed):**

- **Cost-ceiling** — route discovery is ~O(network) per query, so discovery grids must stay modest. Already
  parked as `NOTE:` at `sim-runner.ts:184`, echoed in `design.md` (§ Found vs. oracle, `>` note) and the
  experiment README (§ Keep the grid modest). Carried from the core ticket; verified still in place.
- **No smoke test pins the committed outputs.** Like the sibling `route-existence/`, nothing asserts the
  guardrail/determinism on *these* checked-in files (the engine-level guardrail is unit-tested on its own
  runs). Matches sibling precedent and documented in the README gaps. Only bites *if* these shell-regenerated
  experiments proliferate and a silent determinism/guardrail regression needs catching — at that point a single
  shared smoke test (run one spec, assert `falseFoundCount === 0` + byte-stability) is cheap. Recorded here;
  not ticketed.

**Observations (informative, no action):** depth-sweep rows for `N=100` at `D ∈ {4,5,6}` (and `N=1000` at
`D ∈ {5,6}`) are byte-identical — the small-world graph saturates, so deeper bounds add nothing. That is the
intended plateau demonstration, not redundancy to trim. Sleeping-sweep `timeToCompletionMs` is dominated by
budget-ceiling timeouts (searches waiting on relays that never wake); this does not affect `pFoundGivenExists`
(a sleeping relay is unreachable under any finite budget), so the "lost dark relays" attribution is sound.
