Final ticket of the `tallynet-consensus` chain (core → participant → **this**). The record model, signing,
store (core) and the per-node state machine (participant) were already built and unit-tested. This ticket did
the **wiring + end-to-end proof**: put the consensus engine on the public surface, extended the in-memory
network harness to push records between members, and proved atomic settlement across whole routes under
adversarial / failing peers.

## What shipped

- **Public per-node API** (`consensus/engine.ts`): `ConsensusNode` (mirrors discovery's `DiscoveryNode`), a
  thin wrapper over `TrxParticipant` — `start(record)` (originator seed), `update(record, from?)` (participant
  ingest), `outcome(transactionCode)` → `'commit' | 'void' | 'pending'`.
- **`TrxParticipant.outcome()`** (`participant.ts`): reuses the private classifier; its terminal states
  (`consensus`/`rejected`) are role-independent, so a relay or a polling simulator reads the same commit/void
  a member does.
- **Public barrel**: `consensus/index.ts` re-exports `engine.js`; `src/index.ts` exports the consensus surface.
- **Harness extension** (`testing/network.ts`): consensus nodes built only when `signerFor` + `verifier` are
  injected; a name↔member-key bijection (addresses by base64url ed25519 pubkey); a fire-and-forget `updatePeer`
  honouring `LinkCondition` (`drop`, `latencyMs`); `deliveryErrors`; a cooperative default resource;
  `consensusNode()`/`consensusStoreOf()`/`memberKey()` accessors; and `buildLift(spec)` resolving a route +
  `extraLinks` to real graph edges and filling each node's live `nonceToLinkId` map. Platform-neutral.
- **VirtualClock async-callback tracking** (`testing/clock.ts`, `clock.ts`): a `Clock.setTimer` callback may now
  return a promise; the virtual clock's drain never quiesces while a callback is in flight. This was the
  implementer's run-4 fix that converged the suite (13/17 had stalled at `pending` because the drain's
  16-quiet-hop heuristic gave up mid-`update`). Discovery callbacks return `void`, so discovery is unaffected.

### Tripwire parked (not a ticket)

- **`update` is not re-entrancy-safe per node.** It reads the stored record, merges, then saves across `await`
  points. Two deliveries of the *same* transaction arriving **concurrently** at one node (a host fanning in
  pushes without awaiting the first) can lose a first-sight record (two `getRecord`→undefined, two fresh
  objects, second `saveRecord` overwrites the first) or duplicate a signature. The in-memory harness serializes
  deliveries one callback at a time off the `VirtualClock`, so this never trips in-repo — it is conditional on a
  real host's concurrent delivery model (not built yet). Parked as a `NOTE:` at `ConsensusNode.update`
  (`consensus/engine.ts`): a real host must serialize `update()` per `transactionCode`.
- (Carried from implement, still valid) liveness edge at `participant.ts` `mergeSignature` (forged-commit-before-
  promise-phase stall, safety-preserving) and the clock drain heuristic vs. discovery's void chains at
  `testing/clock.ts` `DRAIN_QUIET` — both already `NOTE:`-tagged at their sites.

### Honest gap left open (not actionable now)

Fire-and-forget convergence is hand-traced + scenario-tested (linear/ring/diamond, dropped push, sleeping node,
referee sets), **not** proven or fuzzed over arbitrary topologies / delivery orderings. The monotonic-growth
argument for push termination holds on inspection, and the downstream tickets (`tallysim-consensus`) will drive
far larger random graphs through this harness, which is where that fuzzing naturally lands. No ticket filed — it
is the simulator's job, and the chain's next hop (`tallynet-bind-taleus-core`) does not depend on it.
