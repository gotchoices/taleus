# What landed

Second (final) ticket of the `tallysim-voter-model` split. Four voter-model dimensions were added to the
sequential consensus sweep runner and documented in the design doc:

1. **Loop-route (circular) payments** — `ConsensusSpec.routeShape: 'linear' | 'circular'` (default `'linear'`).
   A circular run draws one origin per query (`drawCircularOrigins`), mints a session code via a self-query,
   and lifts the shortest simple cycle built straight from the graph (`buildCircularOutcome`, pre-existing) —
   the clearing-discovery stand-in (real discovery is `feat-tallysim-clearing-discovery`).
2. **Nominated vouchers** — `voterNomination: 'self' | 'well-known'` + `wellKnownFraction`. Well-known is
   measured from graph degree, not a model flag.
3. **Padded-voter (stacked) rejection** — `stackedVoters: number`. Every node staples that many obscure
   referees onto every plan it folds into; the originator's counting scorer drops any stacked plan at
   discovery time (`-Infinity`) and counts it.
4. **Raised agreement threshold** — `consensusMethod?: ConsensusMethod` threaded onto `buildLift`.

New metrics: `planRefusalCount` + `planRefusalShare`, emitted as the last two CSV columns.

Build, `yarn test` (423 pass / 34 suites), and root `yarn lint` are all green.
