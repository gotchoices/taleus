**Second of three split discovery-metrics tickets.** Serialises the discovery sweep's `SimRunRecord`s and ships the Node `simulate` CLI that drives the sweep to files. Implemented in commit `d926e06`; reviewed and completed with no code changes required.

## What was built

- **Generic serialiser core** (`serialize-records.ts`): CSV/JSON machinery made generic over the metrics payload (`MetricsRecord<M>`, `metricsRecordToJsonLine`, `createSweepCsvAccumulator(metricColumns)`, …). Oracle `RunRecord`-typed functions kept as thin wrappers pinning `RunMetrics` + the oracle `METRIC_COLUMNS`, so oracle byte-output is unchanged.
- **Sim serialiser** (`serialize-sim-records.ts`, new): sim JSON-lines + CSV helpers, supplying only the sim CSV column order.
- **`cli/simulate.ts`** (new): reads a `SimSweepSpec`, iterates the async `runSimSweep` with `for await`, streams JSON-lines to stdout/`--jsonl`, builds CSV on the same pass (`--csv`), `--concurrent`, and `--trace`/`--query`/`--seed` dumps a replayable trace of the unvaried base scenario via `cli/trace.ts`'s `recordTrace`. Injectable in-memory sinks keep the run path filesystem-free for tests; `main`/`fileSinks` do the `node:fs` wiring. `"simulate"` script added to `package.json`.
- **`cli/trace.ts`** refactor: private `drawQueries` replaced by the shared `drawPaymentQueries(...)`; `packageVersions` exported for reuse.

## Review findings

Adversarial pass over commit `d926e06`: read the full diff before the handoff, traced the serialiser/CLI/trace interactions, scrutinised SPP/DRY/modularity, type safety, resource cleanup, error handling, byte-identity, and source hygiene. Ran `build` (clean), `lint` (clean), `test` (273 passed, 23 suites), and an **end-to-end smoke of the compiled CLI** (`--jsonl`/`--csv`/`--trace --query 0`) to exercise the real `node:fs` wiring the unit tests skip.

- **Correctness — none found.** The oracle refactor is byte-identical by construction: `METRIC_COLUMNS` content and `flattenMetrics` logic are textually unchanged, the oracle functions are pure wrappers, and the unchanged `serialize-records.test.ts` (which asserts CSV header order, distribution expansion, and non-finite cells) still passes. The `drawPaymentQueries` swap in `trace.ts` preserves draw order and seeding exactly (the only shape change — constructing an unused `SeededRandom` for the degenerate `entityCount < 2` case — has no side effect on any shared stream). `SIM_METRIC_COLUMNS` covers **every** field of `ProtocolRunMetrics` (15 scalar/distribution fields + all six `pruneReasons` keys in `zeroPruneReasons` order), so nothing is silently dropped by the `metricOrder.filter(...)` column gate. Confirmed in the smoke test: CSV header matched the canonical order exactly, the trace header carried the unvaried base scenario (entityCount 8, meanDegree 2), and `params` carried only the varied path.
- **Edge / error paths — adequate.** `parseArgs` rejects unknown flags, missing values, non-integer seeds, and negative query indices (all unit-tested). An out-of-range `--query` throws inside `recordTrace` and propagates cleanly (trace fd closed in a `finally`). Non-finite → JSON `null` / empty CSV cell is tested on the sim side. `--concurrent` and `--trace` cannot interact: `recordTrace` is always sequential and independent of the sweep's concurrency.
- **Resource cleanup — correct.** Both the jsonl fd (`fileSinks` `close` thunk, called in `main`'s `finally`) and the trace fd (`recordTrace`'s `finally`) are closed.
- **Source hygiene — good.** Files are small and well-decomposed (`simulate.ts` 219 lines across `parseArgs`/`runToOutputs`/`fileSinks`/`main`; `serialize-sim-records.ts` 77 lines). Conventions match the sibling `sweep.ts`/`trace.ts`. No stale references to the removed `drawQueries`; README and `design.md` updated to the new reality (oracle + sim serialisers, three CLIs, `--trace` semantics).
- **Test coverage — floor met, with two acknowledged gaps (not defects, see below).**
- **Major findings — none; no new tickets filed.**

### Acknowledged gaps (no action — consistent with package convention)

- **`main`/`fileSinks` (`node:fs` wiring) has no unit test**, matching `cli/sweep.ts`/`cli/trace.ts` whose `main` is likewise untested — the package deliberately keeps the filesystem out of tests via injectable sinks. Verified manually with the end-to-end smoke run above instead.
- **The `simulate.test.ts` spec is deliberately tiny** and does not exercise `conditions`, a `budget`, or a materialised-network base. Those flow through the scenario into `runSimSweep`, not through this ticket's new CLI/serialiser code, and are covered by the core/harness/`protocol-metrics` tests.

### Tripwire (unchanged, already recorded in code)

- `flattenMetrics` descends **exactly one level** (number, or an object of numbers). A future two-level-nested numeric metric would be silently dropped from the CSV. Parked as a `NOTE:` at the flatten site in `serialize-records.ts` — recurse (and widen the column-order lists) if that shape ever appears. No action now; every current metrics shape is flat or one-deep.

## Unverified claim (deferred, not agent-runnable)

- Full oracle data regeneration (`experiments/route-existence/regenerate.sh`, multi-spec, N up to 10 000) was **not** run — wall-clock exceeds the agent idle budget. The format-level byte-identity is covered by the unchanged serializer tests and the identical `METRIC_COLUMNS`/`flattenMetrics`; a human wanting full certainty can run that script and confirm `git diff` on `route-existence.jsonl` is empty.
