## Review findings

### Correctness — one major finding (routed to backlog)

- **`makeNomineesFor`'s `'self'` and `'well-known'` policies do not compose with how the harness folds a
  nomination into a voting member.** Confirmed from `tallynet` source, not speculative: a discovery `self`
  match is always `[P]`-only; `prependMatch` adds a nominee as a *separate* `[V]` member and never merges
  `types`. So `'self'` (a node nominating itself) appends a duplicate-key `[P]`+`[V]` member → rejected by
  the `NoDuplicateMembers` validation rule → the lift never forms; `'well-known'` nominating an on-path hub
  silently drops the vote (stays `[P]`). Both are sound only for OFF-path nominees, which is the only pattern
  `tallynet`'s own tests exercise. Dormant today (nothing wires `makeNomineesFor` until
  `tallysim-voter-harness-drive`), so it is a latent defect, not a reachable bug → filed
  `tickets/backlog/debt-voter-nomination-on-path-composition.md` and left a `NOTE:` at the function pointing
  there. The pure functions themselves are correct (they emit the `RefereeNomination` shape they claim); it
  is the *model* that is wrong, which is why this is a fresh ticket rather than an inline fix — the repair
  needs a `[P,V]` marking path designed together with the wiring ticket.

- **`voterAwarePenalty` scalar-packing checked and sound.** Verified the dominance claim
  (`voters ≫ obscure ≫ hops`): with `obscure ≤ voters` and `hops ≤ hopBound`, the two fractional terms sum to
  `< 1` so the integer `voters` strictly dominates, and one obscure step (`1/(voters+1)`) always exceeds the
  whole hop term, so obscure strictly dominates hops. The ranking is bound-independent, so `selectPlan`
  (hopBound = max hops of the set) and `voterAwareScorePlan` (hopBound = `query.maxDepth`) order any plan set
  identically, as the test asserts. No NaN/÷0 path (denominators ≥ 1; `Number(key)=NaN` → counted obscure).
  The score is always finite ≤ 0, so the originator's `rankPlans` never drops a voter-aware plan. Correct.

- **`refusesStackedVoterSet` / `obscureRefereeCount` / the `acceptsProposal` gate** verified against the real
  `ResourceContext` shape: `ctx.record.topology.members` is the `DependentMember[]` the gate reads, and a
  `false` return signs `NP` (voids), per `promiseDecision`. `isReferee` correctly excludes `[P,V]`. Correct.

- **`wellKnownEntities`** — `degreeSequence` is id-indexed and includes degree-0 isolates; `round` + lower-id
  tiebreak match the tests (incl. fraction 0/≥1 and empty network). Correct.
