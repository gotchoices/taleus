## What shipped

The tallysim-viewer replay tier animates a payment's **consensus (sign-and-settle) phase** on top of the
discovery spread, driven entirely by the v2 trace header's `lifts[]` entries (no inference). Promises light
each route hop, referee votes preview the outcome, and the route turns solid on commit or flashes crimson and
clears on void. Implemented across the pure core + overlay tiers (unit-tested) and the browser-only
transport/panel (build-gated, visually unverified — see findings).

Implementation detail lives in the implement commits (`git log --grep="ticket(implement): tallysim-viewer-consensus"`)
and in `docs/design.md` § *Consensus phase*; not restated here.

**Gates (re-run during review):** `yarn workspace tallysim-viewer test` → **117 passed / 11 suites**;
`eslint ./src` clean; `vite build` clean (the >500 kB chunk warning is pre-existing and unrelated to this
change). No pre-existing test failures surfaced.

## Review findings

Reviewed the full implement diff (`4042d32~1..a9a2de9`) with fresh eyes before reading the handoff, then
cross-checked the trace event shapes the reducer depends on against their definitions
(`tallynet/src/trace.ts`, `tallysim/src/sim/trace-format.ts`).

**Correctness — checked, sound.**
- `createLiftResolver` member→entity and edge→tally maps: index-alignment `route[i]↔route[i+1]` on
  `tallyPath[i]` is correct (`tallyPath.length === route.length − 1`, verified against `TraceLiftEntry`). The
  order-independent pair key is unambiguous for simple path/cycle lifts (a circular route's only repeated node
  is its origin, whose two incident pairs are distinct). One genuinely-conditional collapse case — see Tripwire.
- `deriveConsensus` reducer: event-field access (`record-pushed.to`, `promise-signed.signatureType`,
  `referee-vote.decision` `C`/`NC`, `settled.decision` `commit`/`void`) matches `tallynet/src/trace.ts`
  exactly. Commit solidifies the whole `tallyPath`; void releases only promised hops; stall leaves promised with
  no decision; backward-scrub recompute is identity; unresolved member keys are surfaced, never dropped. The
  discovery loop correctly guards consensus events out (`isConsensusEvent`) so a member key never reaches
  `entityId(...)`. A discovery-only/v1 trace binds no lift ⇒ no `consensus` key ⇒ discovery replay unchanged.
- **Event bucketing verified** (the one cross-cutting assumption): consensus events carry `sessionCode`
  (`TraceBase`), and the lift reuses its discovery session code, so `eventsForSession` returns both discovery
  and consensus events for the bound session. Playback time-stops include consensus event times, so the
  scrubber steps through settlement. Correct.
- `paint.ts` overlay composes over the spread, is suppressed in isolate mode, and keys released hops only inside
  the flash window (else falls back to resting) — matches the tests.
- `controls.ts` wiring: `liftIsolated` is reset on session- and colour-mode change and is part of the
  found-signature, so the panel repaints correctly. `currentIsolate` short-circuits colour-by-session first.

**Source hygiene — clean.** Small single-purpose functions, JSDoc concise and accurate, no dead code. New CSS
classes: `tsv-replay-note` is styled (`styles.ts`); `tsv-replay-lift` is an unstyled semantic hook on a
`tsv-replay-route` button (harmless, inherits base styling). The "outcome badge" is appended label text, not a
distinct styled element — a cosmetic naming nuance, not a defect.

**Docs — checked, accurate.** `docs/design.md` § *Consensus phase* and the *Found routes* gap now reflect the
new reality (gap closed for the settled lift's route; discovery's other found plans stay markers-only).

**Edge/error/regression tests — adequate as a floor.** Core specs cover path + circular resolver, commit/void/
stall, backward-scrub identity, unresolved key, discovery-only. Overlay specs cover flash in/out of window,
isolate suppression, vote preview, consensus-over-spread. No fix needed.

**Tripwires (no ticket — recorded in place):**
- `createLiftResolver` keys edges by unordered entity pair, so a route traversing the *same* pair on two
  different tallies collapses to the last one. For simple path/cycle lifts this is only the degenerate 2-node
  loop `[A,B,A]`; it bites only if multi-tally pairs ever appear on a real route. Parked as a `NOTE:` at the
  fold loop in `core/trace-index.ts` (key by `(pair, hopIndex)` if it ever trips).
- `refreshFound` derives the selected session's active set a third time per rebuild (for the outcome badge), on
  top of the twice-per-frame derive. Fine for planned trace sizes. Parked as the `NOTE:` already at
  `renderFrame`/`refreshFound` in `controls.ts`; derive-once-and-thread if large traces ever stutter.
