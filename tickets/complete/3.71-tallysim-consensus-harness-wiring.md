Phase 1 of the former `tallysim-consensus-core` work: the mechanism that lets the tally-network simulator
drive `tallynet`'s real promise/commit consensus engine. Nothing drives an end-to-end *payment* lift yet —
that is the sibling ticket `tallysim-consensus-drive-settle` (`prereq: tallysim-consensus-harness-wiring`),
which owns the full behavioural matrix (refusal / void / stall under crooked peers) and the CBOR-sanitise
fix for unlimited-capacity signing.

## What landed

- **tallynet harness — exact-link `routeLinkIds`** (`testing/network.ts`). `LiftSpec` gained an optional
  `routeLinkIds?: string[]` (one graph link id per route hop, length `route.length - 1`; `buildLift` throws
  on mismatch). `addLiftLink(..., linkId?)` resolves the edge by `id === linkId && neighbour === b` when a
  `linkId` is given, else the prior first-neighbour `.find`. Fixes mis-selection when **parallel tallies**
  exist between the same node pair. `extraLinks` keep the name-pair fallback.
- **tallysim deterministic identity** (`sim/identity.ts`). `makeSimSigner(identitySeed, name)` derives an
  ed25519 key from `sha256("<seed>:<name>")` on its own seed stream (never a shared RNG). `signerForSeed`
  is the per-node factory; `simVerifier` wraps `ed25519.verify` to return `false` (never throw) on garbage.
  Added `@noble/curves@^2.4.0` to tallysim `dependencies`.
- **tallysim failure-injecting resource port** (`sim/consensus-resource.ts`). `makeSimResources(specs)`
  keyed by entity id; lazily mints one handle per id; records `promiseCtxs` / `releaseSuccesses` as the
  observation contract (mirrors tallynet's doubles).
- **`buildSimNetwork` consensus opt-in** (`sim/harness.ts`). Optional 6th param `consensus?: { identitySeed,
  resourceFor? }`; a `consensusPorts()` helper passes `signerFor`/`verifier` (and an entity-id→name adapted
  `resourceFor`) when present, `{}` when absent so the discovery-only path is byte-for-byte unchanged.
- **Supporting.** `sim/index.ts` re-exports the two new modules; new `src/globals.d.ts` types `TextEncoder`
  for the neutral build (mirrors tallynet); `tallynet/docs/design.md` notes `routeLinkIds`.

## Review findings

**Checked:** implement diff read first with fresh eyes (every touched file); the two new modules and the
harness wiring against `InMemoryNetwork`'s consensus config and tallynet's exemplar doubles; the nonce
parity between the new test and `buildLift`; the neutrality guard's coverage of the new `globals.d.ts`;
lint, build, and both test suites; and the docs the change touched *and* should have touched.

- **Correctness — sound.** The `routeLinkIds` path, the entity-id→name `resourceFor` adaptation, the
  discovery-only no-op (`consensusPorts` returns `{}`), and the deterministic identity derivation are all
  correct and genuinely exercised end-to-end (the cooperative-commit and shouldPromise-void smoke tests do
  real `start` + `clock.runUntilIdle()` runs, asserting per-node outcomes, empty `deliveryErrors`, zero
  `pendingTimers`). No defects found.
- **Docs — one stale signature, FIXED inline (minor).** `packages/tallysim/docs/design.md` § Running one
  query wrote `buildSimNetwork(network, conditions, conditionsSeed, trace?, options?)` — missing the new
  `consensus?` param, and the doc never mentioned the `identity.ts` / `consensus-resource.ts` modules
  (`sim/index.ts`'s module list *was* updated, the design doc was not). Updated the signature and added a
  short consensus-opt-in paragraph pointing at the two modules and the sibling ticket. (The roadmap table at
  line ~33 still lists "Discovery / consensus … later" — that row is about the *experiment/measurement*
  layer, not this harness wiring, and the full consensus experiment is indeed still later; left as-is.)
- **Test coverage — adequate floor, no inline additions needed.** The `shouldCommit:false` referee-void
  path is **not** re-driven end-to-end at the sim level, but it is already proven end-to-end in tallynet's
  own `consensus.test.ts` (referee votes `NC` ⇒ `['void','void','void']`), and the sim's `shouldPromise`
  void-route test already proves both engine void-propagation *and* the entity-id→name adaptation. A sim-
  level `shouldCommit` test would be duplicative; the sibling ticket owns the full behavioural matrix. Not
  added — padding tests that re-prove tallynet's engine would be noise.
- **Source hygiene — clean.** New files are small, single-purpose, well-named; comments are purposeful.
  The new `globals.d.ts` mirrors tallynet's precedent, passes the `no-node-globals` guard, and its only
  runtime use (`new TextEncoder()` on ASCII `"<n>:<digits>"`) is cross-platform (browser + Node). Comfortable
  with it over a hand-rolled ASCII encoder — byte-equivalent, and consistent with the sibling package.
- **Deferred latent defect (not this ticket).** A lift over an **unlimited** (`Infinity`) credit limit still
  throws at signing (DAG-CBOR rejects non-finite numbers) — tracked as `[[lift-record-no-infinity-terms]]`,
  owned by `tallysim-consensus-drive-settle`. Confirmed nothing here depends on it working: the smoke
  network's `line()` helper uses **finite** symmetric limits (`1000`), so `capStockToFoil`/`capFoilToStock`
  stay finite and the signed record is CBOR-safe.
- **Tripwires — none parked.** The one conditional concern (unlimited-capacity signing) is a real latent
  defect tracked for the sibling, not a tripwire.
