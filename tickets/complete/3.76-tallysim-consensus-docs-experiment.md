### Tripwires / conditional concerns (recorded, not filed)

The handoff's "Known gaps" are all genuinely conditional ("fine now; would strengthen coverage if X"), already
parked as prose in `experiments/commit-vs-found/README.md`, so recorded here as index entries rather than
tickets or new code comments:

- **Unlimited capacity ⇒ depletion path runs but never bites.** The sequential-lift balance mutation executes
  on every commit, but no later query is ever gated by a depleted tally. A finite-capacity consensus sweep
  would exercise that interaction. Conditional, not a defect (same scope choice `found-vs-oracle` made). The
  one genuine cost tripwire — rebuild-per-query keygen — is already the `NOTE:` at `consensus-runner.ts:132`.
- **Two void reasons unexercised by the committed sweeps.** `voted-no-commit` (a referee `NC`) and `expired`
  (a code outliving its TTL) never appear — the specs use no `shouldCommit:false` referee and zero latency.
  Both are covered by `consensus-metrics.test.ts` unit tests. A latency sweep (under the 600 000 ms TTL
  ceiling the README documents) would drive `expired`; an `R`-role refuser would drive `voted-no-commit`.
- **`timeToSettleMs` trivially 0** under instant delivery. The column is present and exercised; non-trivial
  settle-time data needs a latency sweep.
