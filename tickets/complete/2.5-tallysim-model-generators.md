# Complete — tallysim network model + generators

First of three chained tickets standing up the `tallysim` package. This one built everything needed to
**construct** a tally network as plain serialisable data (model, capacity model, distributions, four seeded
generators, structural utilities). It does not search the network — that is `tallysim-oracle` (next, in
`implement/`, depends on this via `prereq: tallysim-model-generators`).

See the implement commit `ba90483` (`ticket(implement): tallysim-model-generators`) for the full build.

## Review findings

Reviewed the implement diff with fresh eyes against every aspect (correctness, DRY, modularity, resource
cleanup, error handling, type safety, source hygiene) and ran all gates. **Build clean, lint clean, tests
76 → 81 pass** after the inline fixes below.

### Correctness — checked, no defects
- **Generators.** Traced each algorithm independently of its test:
  - `scaleFree` (Barabási–Albert): the repeated-nodes bag samples proportional to degree; targets for a new
    node are computed in the *prior* iteration from a bag that excludes it, so no self-loops; `randomSubset`
    cannot infinite-loop (the bag always holds ≥ `m` distinct ids by the time it is called). Correct.
  - `smallWorld` (Watts–Strogatz): ring lattice builds forward-only with canonical dedup keys, so no
    duplicate/lattice edges even at large even `k < n`; rewiring deletes the old undirected key and adds the
    new one, keeping the `existing` set consistent; bounded attempts prevent a hang on dense graphs. The
    generator's rewiring logic is correct independent of how the β tests *measure* rewiring (the handoff's
    measurement-undercount caveat is a test-measurement artifact only — confirmed).
  - `clustered`: bridges are inter-community by construction (`ci !== cj`) and intra edges are within one
    community, so "exactly bridgeCount inter-community edges" holds structurally — not seed-luck. The test's
    `communityOf` partition rule was checked against `clustered.ts:partition`; they agree (earlier blocks take
    the remainder).
  - `uniform` (Erdős–Rényi): edge count `round(n·k/2)`, distinct endpoints, parallel edges allowed. Correct.
- **Model serialize/deserialize.** `Infinity ↔ null` sentinel round-trips exactly (finite, unlimited,
  one-sided, empty); fixed field order gives byte-identical output; `formatVersion` mismatch rejected. Correct.
- **Capacity model.** Identity `cap(F→S)+cap(S→F) = L_stock+L_foil` holds for any balance; both directions
  non-negative for an in-range balance; a bound gives exactly 0; `Infinity` propagates. Correct.
- **Structure utilities.** Union-find (path compression, union-by-size, deterministic tie-break) and
  component/degree math verified against the stated fractions (1, 0.5, 1/n). Correct.
- **Determinism & platform neutrality.** Generators draw only from the injected `SeededRandom`, iterate in
  defined order, and the `no-node-globals` grep guard is sound (it is a greppable guard, not an AST proof —
  self-documented). Same seed ⇒ byte-identical network holds within one engine.

### Minor — fixed inline (this pass)
- **Seed-sensitivity tested for only one generator.** Only `uniform` had a "different seed ⇒ different
  network" test; a regression making `scaleFree`/`clustered`/`smallWorld` ignore `params.seed` (e.g.
  hardcoding a constant rng) would have slipped through, since the reproducibility test passes regardless.
  → Extended the different-seed assertion to all four generators (`generators.test.ts`).
- **`randomizeBalance` never exercised end-to-end.** Non-zero starting balances were tested only at the
  distribution layer, never threaded through a generator into the tallies.
  → Added a test that runs `uniform` with `{kind:'uniform', randomizeBalance:true}` and asserts non-zero
  balances appear and every balance stays within its tally's own credit bounds (`generators.test.ts`).
- **`constant` distribution accepted an out-of-range `balance`.** `drawCapacity({kind:'constant', limit,
  balance})` did not check `balance ∈ [-limit, +limit]`, so a caller-supplied balance beyond the limit would
  silently produce a **negative directed capacity** downstream — breaking the capacity model's documented
  non-negativity invariant the oracle will rely on.
  → Added a range guard in `distributions.ts` (mirrors the existing `limit` validation) + a test.

### Tripwire — recorded, not ticketed
- **Lognormal cross-engine determinism.** The `lognormal` distribution uses Box–Muller
  (`Math.log/cos/sqrt/exp`), whose last-ULP results are not guaranteed bit-identical across JS engines. Within
  one engine a seed replays exactly and the integer `round()` absorbs nearly all drift, so it is fine now; it
  only matters *if* a scenario must reproduce byte-identically across Node and the browser. Parked as a
  `NOTE:` at the site in `src/distributions.ts` (near `lognormalSample`).

### Observations — no action (intentional / in scope elsewhere)
- **Production code imports `SeededRandom` from the `tallynet/testing` subpath.** A mild smell (shipped code
  depending on a sibling's "testing" export), but it is a real published export with types/dist, and the
  choice is explicitly documented in `docs/design.md` § PRNG and the handoff. Accepted.
- **`deserialize` does no runtime structural validation** (`JSON.parse ... as SerializedNetwork`). Acceptable
  for a simulator reading its own `serialize` output; it would throw an unhelpful `TypeError` on malformed or
  foreign JSON. Not a current defect (no path feeds it foreign data) — flagged here so the oracle/runner
  tiers add validation *if* they ever load externally-sourced scenario files.
- **Capacity magnitude precision (`number` above 2^53).** Already owned by the `tallysim-oracle` tripwire
  (stores capacities in a `Float64Array`); the model layer does not need a duplicate NOTE — planned scenarios
  keep units small. Agreed with the handoff.

### Not needed — stated explicitly
- **No major findings → no new `fix/`/`plan`/`backlog` tickets filed.** The generators are algorithmically
  sound; the only gaps were test-floor coverage and one invariant guard, all fixed inline.
- **Degenerate-config behaviour (return-smaller vs throw)** was reviewed and left as-is: returning a smaller
  graph (complete graph for `scaleFree n<=m`, no bridges for `<2` communities, no edges for `uniform n=1`) is
  documented and tested, and is the right default for a sweep runner that should not crash mid-sweep. If the
  oracle/runner later *needs* a hard failure for "asked for bridges, got none", that is their call to make.
