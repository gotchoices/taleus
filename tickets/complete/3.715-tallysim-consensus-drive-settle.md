## What landed

The consensus phase of the discovery+consensus simulation. After discovery returns `QueryOutcome.plans`,
the simulator picks one plan (`selectPlan`), inverts the plan's anonymised edge nonces back to a concrete
tally route (`reconstructRoute`), drives the real `tallynet` promise/commit engine over that exact route on
the virtual clock (`runLiftForOutcome`), reads **commit / void / stall (`pending`)**, and — on commit —
moves each tally's balance along the route (`applyLiftToBalance` / `settleRoute`) so the next query sees the
changed capacity. `cloneNetwork` lets a caller holding a by-reference network run mutating lifts without
contaminating the next run. The three sim modules are re-exported from `sim/index.ts`; `docs/design.md`
gained a **Consensus simulation** section and flipped the Discovery/consensus tier row to **built**.

The `tallynet` consensus engine and the `buildSimNetwork` consensus opt-in were already wired by the prereq
(`tallysim-consensus-harness-wiring`); this ticket composed that wiring into one call and added the
plan-pick, route-reconstruction, money-movement, and clone helpers around it.

## Review findings

Reviewed the full implement diff first (source, tests, docs), then the handoff. Final state: tallysim lint
clean, `yarn workspace tallysim test` **334 passed / 28 suites**, `yarn workspace tallysim build` exit 0.
No pre-existing failures surfaced.

### Checked — correct, nothing to change

- **Balance direction / sign.** `applyLiftToBalance` keys on `tally.stock === payer`, not on entity-id
  order, so a route where the payer is the tally's foil (higher-id originator) consumes `cap(F→S)`
  correctly. Symmetric and internally consistent with the directed-capacity formulas discovery used to
  build the graph. Verified against the capacity tests.
- **Nonce hasher parity.** `route.ts` recomputes nonces with `makeNonce`'s default `nobleHasher`;
  `buildSimNetwork` constructs `InMemoryNetwork` without a custom hasher, so both sides agree. Would break
  silently if the sim ever passed a custom hasher — see Tripwires.
- **Intent sanitisation does not touch shared adjacency.** `sanitiseRecordIntents` **reassigns**
  `record.topology.links[nonce].intents` to a fresh finite copy rather than mutating in place, so the
  shared graph `edge.terms` (and the pinned byte-identical discovery sweep) are untouched. The module's
  claim holds.
- **Outcome type.** `ConsensusNode.outcome()` returns exactly `'commit' | 'void' | 'pending'`, matching
  `LiftResult.outcome`.
- **Parallel-tally disambiguation.** `routeLinkIds: tallyPath.map(linkIdForTally)` selects the
  discovery-chosen tally, not the first edge; covered by an end-to-end test.
- **Docs.** The new `design.md` Consensus simulation section accurately reflects every touched file
  (plan-pick, route reconstruction, CBOR-safe intents, balance movement + conservation, rebuild-to-see-
  capacity, determinism). Current, not stale.

### Found and fixed inline (minor)

- **Off-route voter silently dropped → confusing stall.** `options.voters` entries not on the route were
  never emitted as members by `liftMembers`, so an off-route voter carried no referee role, leaving the
  lift with too few (possibly zero) voters and an inexplicable `pending`. Added a guard in
  `runLiftForOutcome` that throws when a voter is not on the route (consistent with the module's
  fail-loudly style in `route.ts` / `settleRoute`), plus a test.
- **`pending` outcome and `options.voters` override were untested end-to-end** (handoff gaps 2 & 3). Added
  a split-voter-set test: two voters (the originator + the target, via the override) that split 1 commit /
  1 void reach no strict majority → `pending`, with balances unchanged and nothing left in flight. Closes
  both gaps' happy paths in one case.

### Tripwires (recorded, no ticket)

- **`settleRoute` bound-assert** (handoff gap 4): `-foilCreditLimit ≤ balance ≤ stockCreditLimit` after each
  hop cannot fire for a single lift over a found route (discovery guaranteed capacity). It is load-bearing
  for the parallel-tally test. Left as an assertion at the site; correct now, only a route-reconstruction
  bug would trip it.
- **Circular routes are driven but never shown to arise from real discovery** (handoff gap 1): the
  end-to-end circular test hand-builds a ring plan; whether `tallynet` discovery returns a `from === to`
  plan in this harness is unverified. Fine today — the normal workload draws distinct `(from, to)` pairs,
  so circular routes do not arise. The circular test already carries a comment stating it drives the
  reconstruction + balance walk directly, not discovery. If a future sweep needs natural circular routes,
  confirm discovery produces them first.
- **Nonce hasher parity** (above): if the sim is ever reconfigured to build `InMemoryNetwork` with a
  non-default hasher, `route.ts` must be passed the same one or reconstruction fails. Parked here as the
  index; both sites use the default today.

### Out of scope (next tickets)

- Sweep-level determinism across many cells/seeds (handoff gap 5) belongs to
  `tallysim-consensus-metrics-trace`, which owns the sweep runner.
- Consensus metrics + trace-header extension (`tallysim-consensus-metrics-trace`); viewer animation
