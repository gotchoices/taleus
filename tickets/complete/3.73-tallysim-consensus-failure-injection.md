## What was built (implement summary, verified against the diff)

Consensus failure-injection knobs in the scenario model, plus one new selection helper:

- **`scenario.ts`** — `ConsensusSpec { refuserFraction?; identitySeed? }` (presence on a `SimScenario` is
  the "run consensus" switch), `DEFAULT_CONSENSUS_IDENTITY_SEED = 1` (forward hook, no consumer in this
  diff), and optional `SimScenario.consensus` / `SimScenario.consensusSeed` (dedicated refuser-selection
  stream).
- **`sim/conditions.ts`** — `ConsensusConditionsSpec`, `CompiledConsensusConditions { refusers: Set<number> }`,
  and `compileConsensusConditions(network, spec, seed)`, reusing the existing private `range` + `pickFraction`
  partial-shuffle machinery so the refuser selector is byte-identical in rule/determinism to the
  sleeping/late selectors. Re-exported automatically via `sim/index.ts` (`export * from './conditions.js'`).
- The other three failure modes the parent ticket names (sleeping / dropped / late) are the **existing**
  `ConditionsSpec` knobs — no new code, as claimed.

## Review findings

**Checked:** diff read first with fresh eyes, then the handoff; source hygiene (file size, comment
placement, function size/naming, DRY); type safety; determinism; export wiring; the `shouldPromise`
mechanism claim; test coverage (happy/edge/empty/determinism); lint + build + tests.

- **[minor — FIXED inline] Orphaned doc comment / misplaced insertion.** The new consensus block
  (`ConsensusConditionsSpec` + `CompiledConsensusConditions` + `compileConsensusConditions`) was inserted
  **between** `compileConditions`'s multi-paragraph doc comment and its function body. That detached the
  doc comment from the function it documents (JSDoc would have bound it to the new interface instead).
  Relocated the whole block to **after** `compileConditions` at the end of `conditions.ts`, so the doc
  comment reattaches. No behaviour change; verified by clean `tsc` + passing tests.

- **[verified, no action] `shouldPromise: false` wiring claim.** The handoff says the runner turns
  `refusers` into `{ shouldPromise: false }` resource specs. Confirmed `sim/consensus-resource.ts:56-57`
  implements exactly that gate (`resource.shouldPromise = () => spec.shouldPromise`). The forward reference
  is accurate; actually threading it is the runner ticket's job, correctly out of scope here.

- **[verified, no action] Determinism & reuse.** `compileConsensusConditions` draws once from a fresh
  `SeededRandom(seed)` via the shared `pickFraction` (`round(fraction · pool)` clamp), independent of the
  conditions/network/workload streams. Correct DRY reuse, no second copy of the shuffle. Entity-id domain
  (`range(entityCount)`) matches `compileConditions`.

- **[test coverage — adequate for this tier] ** 3 new tests cover: exact count (`round` incl. 2.5→3 and
  fraction 1 ⇒ full pool), empty set for 0/undefined, and same-seed-identical / different-seed-differs.
  This is the pure-selection floor. **End-to-end seeded route outcomes** ("a refuser on a taken route voids
  the lift", "a dropped push on a cut route edge stalls") are **not** tested here and legitimately belong to
  the runner ticket (`tallysim-consensus-runner-cli`) which drives real lifts — not a gap in this unit.

- **[tripwire — recorded here, not a ticket] Probabilistic determinism assertion.** The
  "different seed differs" test asserts seeds 11 vs 12 over a 20-node / 6-pick draw give different sets; it
  passes but is not a hard guarantee for arbitrary seed pairs. Left as-is to match the existing sibling
  `compileConditions` determinism test's style. Only matters if a future seed-pair change makes it flake —
  then pin specific known-distinct seeds. No code change warranted now.

- **[no action] Unused export `DEFAULT_CONSENSUS_IDENTITY_SEED`.** Defined for the runner to apply the
  identity-seed default; tsc does not flag unused exports and it is documented as a forward hook. Correct.

- **[out of scope, no action] Docs.** `docs/design.md` updates for the consensus experiment are explicitly
  the sibling `tallysim-consensus-docs-experiment`'s job; no doc file is touched by this diff and none
  should be. The v1 asymmetry ("a refuser only hurts its own incident lift" deferred) is cross-referenced
  to `tallynet-propagation-timeouts` and is a scoped simplification, not a defect.
