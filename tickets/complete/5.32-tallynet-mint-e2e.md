## What landed

Part 3 of 3 of the mint/proceed work (Parts 1 `mintRecord` and 2 `proceed`/`abort` already complete):
the end-to-end proof that a `dependsOn`-nominated voter travels **a real `discover` plan → topology →
the vote count**, with no `buildLift` spec shortcut for the voter set.

- **Harness (`src/testing/network.ts`):** `RefereeNomination` + `nomineesFor?` config knob (a node's
  `self` Match carries voter-only referees as `dependsOn`, which `prependMatch` folds in as `V` members);
  `mintFromPlan` (the discovery-plan analogue of `buildLift`): translates the name-keyed plan into
  ed25519-key space (`translatePlanToKeys`, stamping the originator a physical contact point so a
  link-less referee's vote can return), runs Part 1's `mintRecord` with the query's reused session code,
  and re-derives every node's live nonce→linkId map from the graph edges (`populateNonceMaps`).
- **Tests (`src/testing/consensus.test.ts`):** five e2e tests through a real `discover` O→A→B→Z plus an
  edge-less referee R — referee reaches the vote count and its lone C commits the route; its NC voids the
  route; nominated by two participants it folds in once (de-dup); **two participants nominating distinct
  referees assemble a two-voter set through the real search and commit** (added in review); and a
  hand-built two-link ring settles.
- **Docs (`docs/design.md`):** final `mintRecord`/`proceed`/`abort` signatures and the implemented abort
  semantics (verified against `consensus/participant.ts` — abort signs `NP` only on a record it seeded
  without having promised; refused once the promise phase is complete and, strictly earlier, the moment it
  has signed its own `P`).

Validation: `yarn build && yarn test && yarn lint` all green in `packages/tallynet` — **380 tests pass**
(39 in `consensus.test.ts`), lint exit 0.

## Review findings

**Diff read first, with fresh eyes** (implement commit `6a7aaed`), then the handoff. Checked from every
angle below.

- **Correctness of the mint path** — `mintFromPlan` → `translatePlanToKeys` → `mintRecord` → `buildLinks`
  → `populateNonceMaps` traced end to end. The participant-order ↔ path-order alignment `buildLinks`
  relies on holds (voter-only referees are filtered out of `participants`, so they never shift link
  endpoints); the parallel-edge ring resolves correctly because `populateNonceMaps` disambiguates edges
  **by nonce**, not by neighbour alone. **No issue.**
- **No shared-object mutation** — `translatePlanToKeys` mutates only the fresh `{...member}` copy
  (`translated.physical`), never the plan's member object; `mintRecord`'s own shallow-copy NOTE already
  covers member immutability. **No issue.**
- **Referee reachability** (the crux the handoff flagged) — a link-less voter-only referee is physical,
  the originator is stamped physical, so referee↔originator is the sole return path. Confirmed by the
  tests settling: single referee commits/voids, and the two-distinct-referee set reaches a 2/2 majority.
  **No issue.**
- **Docs accuracy** — read the abort implementation (`consensus/participant.ts:225`) against the refreshed
  design.md paragraph; the "refused the moment it signed its own `P`" and "refused once the promise phase
  is complete" claims match the `weHaveSigned` / `promisePhaseComplete` guards exactly. **Accurate.**
- **Type safety / hygiene / lint** — no `any`; new imports all used; methods small and single-purpose;
  JSDoc informative. Lint clean. **No issue.**
- **Test coverage — one reachable gap closed inline (minor).** The implementer honestly flagged that a
  *multi-voter set assembled through a real `discover`* was untested — the single-referee tests cover only
  a 1/1 majority, and "nominated by two" covers two participants → the **same** referee (de-dup/upgrade
  path). The distinct case — two participants nominating **different** referees, exercising `prependMatch`'s
  `missing`/append branch twice on one return trip and a 2/2 majority count over discovered voters — was
  genuinely uncovered (no `prependMatch` unit test covers multi-distinct-dependent folding either). Added
  the test; it passes. The *stall* side of multi-voter counting (a 1/2 split settling neither way) is
  already covered by the `buildLift` "voter set sizes" tests, so it was not re-proven through `discover`.
- **Not a correctness hole (noted, not filed).** A genuinely *mixed* voter set — participants that also
  vote (`[P,V]`) alongside referees — remains unreachable through a real `discover`, because
  `makeFindAddress` emits every discovered member as `[P]`-only and the only voter a real search can
  introduce is a voter-only `dependsOn` referee. Mixed sets are covered by the `buildLift` spec tests by
  design. This is a harness limitation, not a defect in what landed; no ticket filed.
- **Error paths** — `mintRecord`'s throws (no participant / no voter / bad path-link count /
  digest-safety) are covered in `consensus/mint.test.ts`. `mintFromPlan`'s own throws (unknown link
  endpoint, no edge matching a path nonce) are defensive harness invariants; no unit test warranted.
- **No pre-existing failures** — baseline clean; 379 → 380 all green. No `.pre-existing-error.md` written.

### Tripwire (carried forward, not a ticket)

`populateNonceMaps` (`network.ts`) re-derives each link's nonce by scanning the source's adjacency,
O(links × degree) per mint. Recorded as a `NOTE:` at the method with the fix (index the per-session
nonce→linkId at graph-build time). Fine at lift scale; only trips if a sim ever mints over large
discovered topologies.
