## What shipped

The tallysim-viewer renders the **voter model** on top of the existing sign-and-settle consensus animation.
"Voter model" = the lift's voting phase: members vote `C` (commit) / `NC` (no-commit); a member the push could
not reach recovers by **pulling** the settled outcome from a reachable peer; equivocation (a signer emitting
both faces) and contradiction (a member whose outcome disagreed with a peer's) are surfaced; and a lift that
never settles reads as **"unsettled"** rather than a spinner. All of it is driven by the consensus trace events
the prerequisite milestone (`tallynet-record-pulled-event`, seq 5.61) added to `tallynet`'s `TraceEvent` union.

The reducer (`core/timeline.ts`) classifies each `voter-vote` into a **participant** (its member key resolves to
a route entity via the lift's `memberKeys` map, so it is drawn on the graph) or an off-route **referee** (does
not resolve — counted in the side panel, never drawn, and deliberately kept out of the `unresolved`
malformed-trace sentinel). It records three member sets — `pulled`, `equivocators`, `contradictions` — that
`paint.ts` turns into node accents (new palette roles in `theme.ts`) and `controls.ts`/`routes.ts` turn into a
text side-panel breakdown below the chosen route.

The implementation matched its handoff: all claims verified against the diff. Work is headless +
hand-built-fixture tested; it consumes the trace *format* (landed in 5.61), not a simulator that emits
voter-model traces yet.

## Review findings

Reviewed the full implement diff (`a1668c7`) with fresh eyes before the handoff, scrutinised every touched file
plus the ones it should have touched (`styles.ts`), and re-ran lint / tests / build.

- **Correctness (core reducer) — checked, clean.** The `voter-vote` classification uses
  `resolver.entityOfMember` **directly** (not the polluting `resolveMember`), so an off-route referee stays out
  of `unresolved`; the pre-existing `badKey` record-pushed test still proves a genuine route-member miss *does*
  pollute. Confirmed all four new event cases (`record-pulled`, `equivocation-proof-kept`,
  `contradiction-detected`, `voter-vote`) reference real `TraceEvent` fields in `tallynet/src/trace.ts`
  (`from`/`ok`, `signer`, `nodeId`+`ourOutcome`/`peerOutcome`, `decision`). Pull dedup (ok:true only, Set),
  voter dedup (re-vote latest-wins), and deterministic ordering (participants-by-id then referees-by-key) are
  correct and tested.
- **Paint layer — checked, clean.** `markNode` recolours a node while preserving any settled size boost; on a
  node with no underlying consensus style it degrades to a bare `{color}`, which `OverlayNodeStyle` (all-optional
  fields) handles safely — the node keeps its base size. Referee voters carry no entity id and are never keyed.
  Marker precedence (pulled → equivocator → contradiction) is deliberate and tested.
- **Minor finding — FIXED inline.** The three new voter-summary DOM classes
  (`.tsv-replay-voters`, `.tsv-replay-voter-list`, `.tsv-replay-voter-line`) had **no CSS**, while every sibling
  panel class (`.tsv-replay-routes`, `.tsv-replay-note`) does — the `<ul>` would have rendered with default
  browser bullets, ~40px indent, and default text colour, clashing with the panel's language. Added styling to
  `app/styles.ts` (list reset + `--tsv-text-secondary` / `0.8rem`, matching `.tsv-replay-note`). This matters
  because the side-panel text is the stated non-colour channel for every member's state — it has to be legible.
- **Tests — adequate as a floor, no gaps filed.** Happy path, the key edge cases (off-route referee, all-failed
  pulls, signer-vs-keeper, misbehaving-beats-recovery precedence, re-vote dedup), and the `unresolved` discipline
  are all covered. `controls.ts` remains jest-untested by its own module contract (touches `document`); its pure
  logic (`liftVoterSummary`, `liftOutcome`) is tested in `routes.test.ts`, and the new DOM is type-checked +
  `vite build` only. No manual click-through was run — no real voter-model trace fixture exists yet (same
  honest gap the handoff flagged). Not a defect; eyes-on needs a hand-built v2 trace loaded in the browser.
- **Docs — checked, current.** `docs/design.md` § Consensus phase matches the shipped behaviour (voter
  classification, pull recovery, equivocation/contradiction, "unsettled", and the two format gaps). Theme palette
  doc comments match the actual hex values and roles.
- **Tripwires (recorded, not filed as tickets):**
  - *`memberKeys` = route members assumption.* The participant/referee split trusts that a lift's `memberKeys`
    map contains only route members (so a non-resolving key is genuinely off-route). True in the current format.
    Already documented inline at `core/timeline.ts` (`ConsensusVoter` doc) and in the design doc's format-gap
    note; no code change needed.
  - *Polluting resolve for pull/equiv/contra keys.* `record-pulled`/`equivocation-proof-kept.signer`/
    `contradiction-detected.nodeId` resolve through the polluting `resolveMember`, on the assumption those keys
    are always route members (they are today). If a future simulator emits an off-route one it surfaces in
    `unresolved`. Documented inline at the three case blocks.
  - *Palette CVD separation.* The three new accents (indigo pulled / magenta equivocator / purple contradiction)
    were asserted by hex value but not run through the dataviz palette validator for colour-blind separation.
    Left as-is: every mark is backed by side-panel **text**, so colour is never the sole channel — perceptual
    separation is polish, not correctness. Noted in the theme doc comment.

## Not in scope (documented format gaps, not bugs)

Off-route **referee** voters and the **nominator links** that produced them are not carried into the lift record
(a simulator-side gap tracked as `debt-voter-nomination-on-path-composition`): referees are **counted**
("+N referee-only voters (stacked)"), never drawn, and nominator links are not shown. **Per-member contact
points** are likewise not in the format, so "settles vs stalls on a linear lift with a refuser" is shown as its
observable consequence (pull-recovered vs stuck-pending), not a per-member flag. Both are documented in
`docs/design.md` § Consensus phase. No new trace fields, no format bump.
