## Review findings

**What was checked, and what was found:**

- **The central trusted invariant — verified at the source, not just taken on faith.** mint's modular link
  formula (`source = participants[i]`, `target = participants[(i+1) % n]`) is only correct if the folded
  member array really carries participants in route order and path link `i` really joins participant `i` to
  `i+1`. I read `prependMatch` (`discovery/participant.ts:714`): it prepends each matched participant at the
  **front** (`[asDependent, ...upgraded, ...missing]`) on the return trip and appends nominated voters at the
  **tail**, so after the full return the participant sublist is origin-first/target-last and `participants[i]
  → participants[i+1]` lines up with `path[i]` (which grows origin→target). It also rejects any match that is
  not a participant and any participant-match that depends on a participant (`:715`,`:718`), so every
  participant is a path node and participant-count equals path-node-count — exactly the linear (`n−1`) /
  circular (`n`) shapes the count guard allows. **The fold invariant holds; the formula is sound.** True
  end-to-end proof (a nominated voter surviving discovery → the final vote count) is still Part 3
  (`tallynet-mint-e2e`) — that remains the real regression check, not re-litigated here.

- **Output vs. the real new-record RuleSet.** I read `buildNewRecordRules` (`participant.ts:787`): the ten
  rules are TransactionCode, SessionCode, NoDuplicateMembers, LinksReferenceMembers, NonEmptyParticipantSet,
  NonEmptyVoterSet, ConsensusMethod, LiftContract, SelfConsistent, CoreEncodable. mint's output satisfies the
  structural ones by construction — links only ever reference participant keys (a subset of members, so
  `LinksReferenceMembers` holds), members are carried through un-duplicated, `liftContract` is omitted-not-
  undefined, `promises`/`commits` are empty. The code-time ones (valid tx/session codes, valid method) are
  the caller's inputs, correctly out of mint's scope. mint.test.ts still asserts duplicate-freedom against a
  *local mirror* of `hasDuplicateMemberKey` rather than driving the record through a real participant's first
  sight. Not re-filed as a ticket: **Part 2 (`tallynet-originator-proceed`) exercises `update` directly** and
  is the natural home for that integration coverage.

- **Type safety / purity / resource cleanup / error handling.** mint reads no clock and no CSPRNG (tx code
  passed in, session code reused) — pure as documented. No `any`, no eaten exceptions; the three throws are
  fail-early with explainable messages. Nothing to allocate or release. Source hygiene is good: 101 lines, two
  small functions, doc comments that explain *why* (nonce symmetry, omit-don't-undefine) without padding.

**Minor (fixed inline this pass):**

- **No DAG-CBOR round-trip on the minted record** (honest-gap #3). Added a `mintRecord — the minted record is
  digest-safe` describe to `mint.test.ts`: asserts `canonicalEncode(record)` does not throw, both with and
  without a `liftContract`. This closes the omit-don't-undefine invariant end-to-end — a regression that
  always stamped `liftContract` would throw on the no-contract case. While adding it I hoisted the shared
  `linearPlan()` helper to module scope to avoid duplicating it across describes (a DRY smell the addition
  would otherwise have introduced).

**Known edges (recorded, not filed — out of scope and caught downstream):**

- The path/participant-count guard permits two **degenerate single-participant shapes**: a circular self-loop
  (`path.length == 1 == n`, yielding `source === target`) and a linkless linear route (`path.length == 0 ==
  n−1`, yielding empty `links`). Neither is producible by real discovery (a route has origin ≠ target and ≥ 1
  edge), and both are rejected downstream by `update`'s `SelfConsistent` rule (a participant that rides no
  link, or — for the self-loop — a nonsensical edge). So these are degenerate-but-harmless, not latent defects
  reachable now; no ticket. The implementer flagged the self-loop case already; the linkless-linear case is
  its linear twin and has the same disposition.

**Tripwire (already parked by the implementer; indexed here per the rules):**

- `mint.ts` carries a `NOTE:` at the `[...plan.members]` line: the member *array* is copied but the member
  *objects* are shared with the plan — safe while members are immutable (the codebase treats them so);
  deep-clone only if a caller ever mutates plan members after minting. Left as-is; it is a correct conditional
  concern, not current work.
