The graph-tier renderer (`render.ts`) and the app shell (`app/**`) landed: a sigma 4 WebGL view of a built
`TallyGraph` (reducer-based styling, edge-capacity encoding with a distinct unlimited style, hover tooltips,
node search, WebGL-absent fallback), driven by a shell that loads a trace file or an in-page sample, runs the
seeded ForceAtlas2 worker layout, and toggles light/dark. The headless model + layout orchestrator already
existed from the prior split of this ticket.

## Review findings

**Scope reviewed.** Full implement diff (`9bdf719`) read first, then every touched file and its collaborators:
`render.ts`, `shell.ts`, `styles.ts`, `sample-network.ts`, `main.ts`, plus `graph/{model,layout,layout-worker}.ts`,
`app/theme.ts`, `core/trace-index.ts`, and the `tallysim` interfaces consumed (`Network`/`meta.seed`,
`entityName`, `capStockToFoil`/`capFoilToStock`, `scaleFree`, `parseTrace`). `docs/design.md` cross-checked
against the code and found accurate.

**Correctness — one real defect, fixed inline.**
- **Worker resource leak (fixed).** `layout.ts`'s `settle()` called `worker?.stop()`, which (per the worker
  handle's own docs) only *pauses* ForceAtlas2 iteration and leaves the Web Worker thread alive. The handle's
  `kill()` — documented "Call on teardown" — was defined but **never called anywhere**. Every network load
  (sample or file) spawns a fresh FA2 worker while the previous one is only paused, so orphaned worker threads
  accumulate on repeated loads. This is exactly the lifecycle risk the handoff flagged as "confirm no orphaned
  worker after several loads." Fixed by making `settle()` call `worker?.kill()`: settle is terminal (budget
  elapsed, or shell teardown) and the worker is never resumed, so releasing the thread is correct. The handle's
  `stop()` pass-through is left in place as an available (now-unused) capability — a thin 1:1 wrapper over the
  supervisor, not misleading dead code.

**Edge-capacity encoding math — checked, correct.** `isUnlimited` = non-finite total swing (one-sided
`Infinity` ⇒ unlimited, as designed). `logNormalize` uses `log1p`, clamps `[0,1]`, and returns `0.5` on an
empty/degenerate finite range (`min==max`, or no finite edge). Capacities are provably non-negative
(`capacity.ts`), so `log1p` never sees a negative. The headline invariant `UNLIMITED_SIZE (3) < FINITE_SIZE_MAX
(5)` is a compile-time constant relation, not a runtime computation — it cannot be violated. Tooltip renders
`Infinity` as `∞`.

**Security / safety — checked, clean.** Tooltips build text via `textContent`/`createTextNode` and `<br>`
nodes (no `innerHTML`), so entity labels/capacities can't inject markup. `localStorage` access is wrapped
(disabled storage can't break the app). Parse errors surface in the panel status, never swallowed to console.

**Interaction / lifecycle — checked.** `teardown()` stops layout then destroys the view (`sigma.kill()`), clears
the container, and nulls the refs before each load; the settle timer is cleared in `settle()`. WebGL-absent
path correctly skips `runLayout` (no worker spawned when nothing renders). Search by typed id works because
`entityName(id) === String(id)` — the node key is the id the user types.

**Tests.** Viewer jest 33/33, root sweep 285/33 across 23+5 suites — all green after the fix. Viewer + root
lint clean (exit 0). `vite build` green (one informational >500 kB chunk warning — sigma; accepted below).

**Not covered by automated tests (unchanged gate).** Everything in `render.ts`/`app/**` is browser-only (WebGL +
a Web Worker) and gated only by the build + a manual interactivity check. The manual cases in the review ticket
(sample load smoothness, degenerate/edgeless/unlimited-only/parallel/zero-cap networks, theme switch,
WebGL-absent, bad file) were **not** executed here — no headless browser in this environment — and remain the
real acceptance gate for a human. The worker-leak fix in particular is best confirmed by the "no orphaned
worker after several sample loads" manual case.
