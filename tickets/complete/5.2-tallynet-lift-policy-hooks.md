# Complete: tallynet lift policy hooks

Added the four per-node decision points the voter model needs ("no global rules; each node decides"),
plus an originator-only way to rank the routes a search returns. The protocol still enforces only
verified signatures and the strict-majority+threshold invariant; every "which voter set / method /
contract do I accept" judgment lives in host hooks that default to today's permissive behaviour.

Implemented across two seams:
- **promise-time** — `acceptsProposal(ctx)` on `TrxParticipantResource` (first gate, before `shouldPromise`).
- **discovery-time** — `acceptsQuery(query)` (gate at `enter`) and the now-documented `negotiatePlan(plan)`
  (refuse a plan by its voter-set-so-far on the return trip) on `DiscoveryHooks`; `scorePlan(plan, query)`
  on `OriginatorConfig` (originator-only ranking, result `plans` returned best-first).

### Checked — correctness

- **`promiseDecision` ordering & throw-handling** (consensus/participant.ts). Verified the ordering
  expiry → `acceptsProposal` → `shouldPromise` → hold, and that the two gates share one try (a `false`
  or a throw from either → `NP`, logged) while the hold has its own try. The behavioural refinement the
  implementer flagged — a *throwing* gate is now caught→`NP` rather than propagating out of `update` —
  was confirmed intentional, logged (satisfies the "don't eat exceptions without logging" rule), aligns
  the code with the hooks' documented "return false to refuse" contract, and is strictly safer (a
  declined promise can no longer crash the state machine). No existing test or in-repo caller depended
  on the old propagation. **Accepted, no change.**
- **`acceptsQuery` gated at `enter` only** (discovery/participant.ts). Confirmed sound: the gate keys on
  `query.method` / `query.liftContract`, which are fixed per `sessionCode`, so a node that accepts at
  `enter` needs no re-gating at `reenter` (which has only the stored context, never the full query). The
  refusal path returns a well-formed empty `QueryResponse` (`stats` shape matches `makeResponse`), no
  plans and no reentrance, so the upstream node prunes it via the existing `no-reentrance` path — no new
  machinery, no throw. Verified the refusal returns after `validateNewQuery` (a read-only check that
  mutates nothing) and before `saveContext`, so a refused node leaves no stored context.
- **Documented `ResourceContext` surface is real.** Confirmed `ctx.record.topology.members`,
  `ctx.record.method`, `ctx.record.liftContract`, `ctx.record.transactionCode` all exist on `TrxRecord`
  — the `acceptsProposal` docs are accurate, not aspirational.
- **`rankPlans` scoring** (discovery/originator.ts). The reject test `score > -Infinity` correctly drops
  both `-Infinity` and `NaN` while admitting `+Infinity`; the sort is deterministic with an explicit
  original-index tiebreak (no reliance on sort stability). `defaultScorePlan`'s single-scalar domination
  is safe because `query.maxDepth` is always set in `discover` (never `undefined` → never `NaN`).
- **Public surface.** `ScorePlan` / `defaultScorePlan` (via `originator.js`), `acceptsQuery` (via
  `hooks.js`) and `acceptsProposal` (via `resource.js`) are all re-exported through the package barrels.

### Tripwires (recorded, not ticketed)

- **`plan-found` trace count can exceed returned `plans.length`.** `discover` traces one `plan-found`
  per satisfying plan *before* `rankPlans` may drop some/all by score. Fine today (trace is
  informational). Parked as a `NOTE:` at the trace site in `discovery/originator.ts` — a future viewer
  that counts `plan-found` to show "route found" should reconcile against the returned plans, not the
  trace. (Relates to [[trace-found-route-paths-gap]].)
- **`defaultScorePlan` single-scalar domination** relies on the discovery invariant `path.length <= maxDepth`
  (keeps the hop penalty `< 1` so "fewer voters" strictly dominates "shorter path"). Cannot trip today;
  reasoning already lives in the function's own JSDoc.
