## What shipped

The on-disk NDJSON trace format went from version 1 to version 2. A simulated payment run can now be
recorded with its **consensus phase** (not just route discovery) and replayed byte-for-byte. The header
gained one optional field, `lifts[]` — one `TraceLiftEntry` per recorded query that found a route, carrying
the lift's `transactionCode`, `route`, `tallyPath`, a `memberKey → entityId` map, and `amount`. The field
is needed because a consensus event addresses nodes by **member key** (an ed25519 public key), not by the
simulator's integer entity id, and the route a lift actually took is not recoverable from the discovery
event stream — so that information has to ride in the header for the viewer to place consensus events on the
graph. Events themselves were unchanged (the `TraceEvent` union already spanned consensus), so only the
header moved; `parseTrace` now reads both v1 and v2.

Consensus recording is opt-in, keyed off the presence of a `scenario.consensus` block. A discovery-only run
stays byte-identical to before (bar the version number). `consensusConfigFor(scenario, network, runSeed)`
was extracted from the metrics runner and is now shared by the runner and the trace recorder, so both derive
the same identities + refusers for a given `(scenario, runSeed)`.

## Review findings

Adversarial pass over the implement diff (commit `7d4ca97`). Validated the whole change against SPP/DRY,
determinism, type safety, resource cleanup, error handling, docs, and test coverage.

**Checked and sound (no change):**

- **Determinism / join invariant.** The header `lifts[]` come from pass 1; the consensus events come from
  pass 2. Confirmed the join holds regardless of the shared resource port's accumulated state: a lift's
  `transactionCode` is minted in `buildLift` *before* the port's promise/commit gate runs, and the route
  comes from discovery, not the port — so even a (hypothetical) stateful gate cannot break the
  `transactionCode`/`route` join, only shift which void/commit events pass 2 emits, which is exactly what a
  replay should show. Each `recordTrace` call builds a fresh port and accumulates pass 1 + pass 2
  identically, so the full-run byte-identity test is a genuine guard. Confirmed consensus events carry the
  reused discovery `sessionCode` (`participant.ts` `traceBase`), so the writer's session filter records them
  for selected queries.
- **`memberKeys` map direction + collisions.** `memberKey → entityId` is the direction the viewer needs.
  Member keys are per-node ed25519 pubkeys; the tallynet harness itself keeps a 1:1 `nameByMemberKey` map,
  so there is no realistic collision that would silently drop a route entity.
- **Narrowing consistency.** `--query` narrows `lifts[]` the same way it narrows `queries[]`
  (`liftEntries` indexed by original query index, undefined-filtered); pass 2 runs every query's lift but
  the session filter keeps only the selected ones. Verified consistent; covered by the selected-query test.
- **Resource cleanup / error paths.** File descriptor lifecycle stays in `recordTrace`'s `finally`; lift
  exceptions propagate (not eaten) and `main` reports them. SPP/DRY good — `consensusConfigFor` dedups the
  identity/refuser derivation, `recordLift`/`distinctEntities` are small and focused.

**Found and fixed inline (minor):**

- **Stale design doc.** `packages/tallysim/docs/design.md § Trace & replay format` still described the v1
  shape (header with only `queries[]`, "consensus needs no bump"). Updated the header-line bullet, the
  Versioning paragraph, and the Byte-identical determinism paragraph to describe v2, the `lifts[]` field,
  the member-key rationale, and the one-sim/no-depletion trace model vs. the depletion-modelling metrics
  sweep. (The handoff mislabeled this file as `docs/design.md`; the repo root has no such file.)
- **Untested void-lift trace path.** The implementer flagged (honestly) that driving a *trace* through a
  voiding/pending lift was unexercised — a lift that voids still found a route, so it still records a
  `TraceLiftEntry` and still emits (void) consensus events. Added a test
  (`a voiding lift (every entity refuses) still records its entry and joined consensus events`, using
  `consensus: { refuserFraction: 1 }`) confirming the entry is recorded and every consensus event joins back
  by `transactionCode`. Test count 380 → 381.

**Major findings (new tickets):** none.

**Tripwires (recorded, not ticketed):** one pre-existing `NOTE:` in `cli/trace.ts` `recordLift` — it clones
the whole network per lift so the throwaway balance move never touches the snapshot; fine for planned trace
sizes, and the inline note already says to reuse one scratch clone if a traced scenario ever has very many
queries over a huge network. Left as-is (correctly parked at the site). No new tripwires.

**Not done (out of scope, as the handoff noted):** the `tallysim-viewer` does not yet *place* consensus
events using `lifts[]` — the field is additive and the viewer currently ignores it; wiring the viewer to
consume it is future viewer work, not this ticket.
