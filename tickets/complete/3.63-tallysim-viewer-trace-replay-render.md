The implement stage built the **browser-only rendering + shell wiring + docs** on top of the already-landed
pure core (`clock.ts`, `routes.ts`, `core/timeline.ts`, the de-anonymiser). Review confirmed the work is sound:
build, 57 viewer tests, and lint all green, and the one correctness claim that could silently mis-render — the
conditions seed the viewer recompiles to recover the sleeping/late node sets — was verified end to end against
the actual trace producers (see findings). No bugs found; no inline fixes were needed.

## What shipped

- **`app/theme.ts`** — the shared `Palette` gained replay colours (light + dark): `roundScale` (a warm ordinal
  ramp separating from the cool-blue capacity edges), `pruned`, `sleeping`, `late`, `dimmed`.
- **`replay/paint.ts`** (+ `paint.test.ts`, 9 tests) — pure, sigma-free. `buildOverlay` turns an `ActiveSet` +
  the compiled `{sleeping, late}` sets + an optional isolate into a plain `ReplayOverlay`; `mergeOverlays`
  combines per-session overlays (last-wins).
- **`graph/render.ts`** — `GraphView.setReplayOverlay(overlay | undefined)`; the node/edge reducers compose
  three layers in order (resting capacity → overlay keyed-style-or-dim → built-in hover/selection accent, which
  wins on top and never leaves a hovered edge hidden). The edge tooltip appends the overlay `note`.
- **`replay/controls.ts`** — browser-only transport + panel: the rAF loop, play/pause, speed (0.25×–8×), scrub,
  session picker + colour-by-session, the found panel (markers-only for a loaded trace, full routes list with
  isolate-on-select when a `ReplayRouteSource` supplies paths). `mountDisabledReplayControls` for the no-trace
  path.
- **`app/shell.ts`** — on a real trace load, builds the `Deanonymiser`, compiles conditions once, mounts the
  live panel wired to the `GraphView`; teardown stops the loop and clears the overlay; theme toggle re-paints.
- **`docs/design.md`** — new Replay tier section (one clock/one seek path, precise de-anonymised edge lighting,
  conditions-derived sleeping/late incl. the seed note, the found-route reconstruction and the trace-format gap).
- **`tickets/backlog/feat-trace-plan-found-path.md`** — the deferred cross-package clean fix for the found-path
  trace gap.

## Review findings

**Correctness — checked, verified sound.**
- **Conditions seed matching (the one claim that could silently mis-mark nodes): verified correct end to end.**
  The shell recompiles `compileConditions(index.network, scenario.conditions ?? {}, scenario.conditionsSeed ?? 0)`
  to recover the sleeping/late sets a trace does not record. I traced both trace producers: `cli/trace.ts`
  `recordTrace` compiles with `conditionsSeed = scenario.conditionsSeed ?? 0` (no runSeed offset), and
  `cli/simulate.ts --trace` reuses that same `recordTrace`. `buildSimNetwork` calls
  `compileConditions(network, conditions, conditionsSeed)` on the *same* materialised network that is snapshotted
  into the trace (which the viewer reads back as `index.network`). `compileConditions` is deterministic, and the
  sleeping/late sets depend only on `entityCount` + seed (not tally order), so the viewer's sets are byte-for-byte
  the sets the run was recorded under. The sweep runner's `(conditionsSeed ?? 0) + runSeed` offset does **not**
  apply — it is used for the metrics sweep, never for trace writing. Claim holds.
- **Edge/node key spaces agree.** `buildGraph` keys edges `edgeKeyForTally(i)` (= `linkIdForTally`) and nodes
  `entityName(id)`; `paint.ts` keys the overlay the same way, and `render.ts`'s `enterEdge` note lookup uses the
  sigma edge key = `edgeKeyForTally`. If these diverged, nothing would light up — they match.
- **Transport/loop lifecycle.** rAF start is guarded against double-schedule; auto-pause at end does not
  re-schedule; scrub pauses then seeks the same single seek path; teardown stops the loop and clears the overlay
  *before* the view is destroyed (correct order in `shell.ts` `teardown`); listeners are GC'd with the removed
  DOM. No orphan loop survives a re-load.
- **Docs verified against the code**, not assumed: the Replay tier section (seek path, de-anonymised lighting,
  the seed note, the found-route gap) matches the shipped modules.

**Test coverage — adequate; a known, deliberate gap, not filed.**
- The pure modules are unit-tested: `paint.test.ts` (this ticket, 9), plus the pre-landed `clock.test.ts` (8),
  `routes.test.ts` (9), `timeline.test.ts`. `render.ts`'s three-layer compositing and `controls.ts`'s transport
  are browser-only and manual-gated — **consistent with the established pattern** for `render.ts`/`app/**` set in
  the prior graph-view ticket and documented in `docs/design.md` § Testing. Not a regression; not filed. (The
  pure half of the compositing — overlay precedence — already lives in `paint.ts` and is tested.) The manual dev
  check (`yarn dev` → load a trace with conditions → play/scrub/hover-pruned-edge/colour-by-session) remains the
  functional gate for the browser-only code and was **not** run here (no headless WebGL in the ticket env).

**Tripwires (conditional; recorded in-code, not ticketed).**
- Per-frame double-derive of the selected session's active set — `controls.ts` `renderFrame` `NOTE:`. O(events)×2
  per frame; fine for planned trace sizes; derive once if a large trace stutters.
- Sleeping/late are colour-only marks on the whole conditioned set — `paint.ts` `NOTE:` at the spread overlay.
  A dashed/ringed mark or a reached-only subset would need a custom sigma node program / second overlay, not a
  recolour.

**Deferred cross-package work (filed as backlog, not blocking).**
- Found-route paths are absent from trace format v1, so a loaded trace shows found **markers** only (finder +
  time + count) with an honest note; the full routes list + isolate-on-select is reachable only via a
  `ReplayRouteSource` (live-run/test). Clean fix filed as `backlog/feat-trace-plan-found-path.md` (originator's
  `plan-found` carries its own path nonces; bumps `TRACE_FORMAT_VERSION`).

**Minor observation (not fixed — reserved API, harmless).**
- `OverlayEdgeStyle.hidden` and its `render.ts` handling have no current producer (`paint.ts` never sets it); the
  hover branch's `hidden = false` un-hide guard is cheap defensive insurance for a future overlay that does. Left
  in place as forward API rather than churned out.
