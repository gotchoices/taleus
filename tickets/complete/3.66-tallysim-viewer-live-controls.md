## What shipped

The final piece of the **live-run tier** of `tallysim-viewer` (a static, server-less browser dev tool that draws
a simulated tally network and animates a payment search across it). This run added the **panel** that ties the
prior live-run pieces together (worker, pure scenario/run translation, click-to-pick, replay autoplay), plus the
shell wiring, CSS, and docs.

- **`src/live/controls.ts` (new)** — `mountLiveControls(host, liveHost)`. Builds the generate → pick → run →
  download form, owns the one `Worker`, defines the `LiveRunHost` contract the shell implements.
- **`src/app/shell.ts`** — split `loadNetwork` into `renderNetwork` + `setReplay`, added a **File | Live-run**
  Source tab toggle, implemented `LiveRunHost`, mounted the live controls, invalidates them on file/sample load.
- **`src/app/styles.ts`**, **`src/graph/render.ts`** (click-to-pick + picked-pair node marks),
  **`src/replay/controls.ts`** (autoplay flag), **`docs/design.md`** (new Live-run tier section).

## Review findings

Adversarial pass over the implement diff (`91f8f7a..72037c0`), read before the handoff summary. Scrutinised the
panel state machine, the worker/page `postMessage` contract, the download/trace-reuse determinism, click-to-pick
registration, replay autoplay, styling, and doc accuracy.

### Correctness — 2 defects found, both fixed inline (minor)

- **Generate was enabled during an in-flight run.** `updateButtons` gated Generate only on `generating`, not
  `running`. Clicking Generate mid-run posted a fresh `generate`, whose `network` reply ran `renderNetwork` →
  `teardown()`, destroying the running view/replay out from under the still-streaming run — a direct violation of
  the documented *one-run-at-a-time* contract. **Fixed:** added `|| running` to the Generate disable condition
  (`controls.ts`). Cancel-then-Generate is the intended path to re-generate.
- **A file/sample load mid-run mounted the live replay over the newly-loaded graph.** `invalidate()` (called by
  the shell on a file/sample load) nulls the panel's `view` but does not stop the worker run. When the orphaned
  run's `done` arrived, `onDone` still passed its guard and called `mountReplay`, which the shell mounts over
  `state.view` — now the *file's* view — producing a live-run animation over an unrelated network. **Fixed:**
  `onDone` now bails when `view === undefined` (the invalidated case), dropping the orphaned run. `generated`/
  local-field invalidation (which keeps `view`) is unaffected, so a normal run still mounts.

### Hygiene — 1 fixed inline (minor)

- **`buildLiveRun`'s doc comment was wrong.** It claimed "the controls call this on Run"; the panel actually
  calls `buildScenario`/`buildQuery` separately (it must override `scenario.network` with the generated source
  and catch a missing-pick error). The function is used only by its own unit test. **Fixed:** corrected the
  comment to describe it as a tested convenience bundle the panel deliberately does not use on Run
  (`build-scenario.ts`). Kept the function + test rather than delete.

### Tripwire recorded (not ticketed)

- **Synchronous `URL.revokeObjectURL` after `anchor.click()`** in `onDownload`. Works in the Chrome dev target;
  some browsers can abort a download if the blob URL is revoked before the download starts. Parked as a `NOTE:`
  at the site (`controls.ts`) — defer the revoke (e.g. `setTimeout`) only if a browser is ever seen aborting.

### Checked and accepted (no change)

- **`readParams` reads generator params with bare `Number(input.value)`.** A cleared `<input type=number>`
  yields `''` → `Number('') === 0` (not `NaN`), and an out-of-range `0` is rejected by `materializeNetwork`
  *inside the worker* → a clear "generate failed: …" error line, not a blank page. Intentional (the worker is
  the validation point for a dev tool). The handoff's "a cleared field yields NaN" is slightly inaccurate (it's
  `0`), but the user-facing behaviour is the same.
- **Fresh `buildSimNetwork` per Run** and **Cancel → silent re-generate** — deliberate, documented decisions
  (session-code RNG restart for byte-matching; graph+picks survive a Cancel). No cross-run mutable state in this
  read-only tier. Accepted.
- **Worker message ordering.** A `run` posted before the silent-regen `network` arrives is safe: the worker
  processes messages sequentially and `handleGenerate` is synchronous, so `network` is always set before
  `handleRun`'s synchronous `buildSimNetwork(network, …)` runs.
- **`onNodeClick` registration.** Registered once per freshly-created `GraphView` (new sigma instance each
  `renderNetwork`), so no listener accumulation across renders.
- **Download trace format.** `[header, snapshot(kind:'network'), …events(kind:'event')]` matches
  `makeTraceWriter`'s emit order exactly; the kept snapshot is reused verbatim, so a reload round-trips.
