description: The simulator's fake clock decides that pending work has finished by counting a fixed number of idle steps, a guess that was already too small once and silently produced wrong results; replace it with a check that can't be fooled by a longer chain of work.
files: packages/tallynet/src/testing/clock.ts, packages/tallynet/src/testing/, packages/tallysim/src/sim/
----

`tallynet/testing`'s `VirtualClock` fires the next timer only after the work triggered by the previous one has settled. It detects "settled" by waiting a fixed number of quiet promise-continuation hops (`DRAIN_QUIET`). At 16 that was shorter than discovery's per-level completion chain (17–23 hops), so a budget timer fired early. That made the simulator report discovery reaching half its real depth, and made concurrent and sequential sweeps disagree (fixed by raising it to 64: `tallynet-discovery-depth-reach`, `tallysim-sim-runner-concurrent-divergence`).

64 is a margin, not a guarantee: a longer chain (more hooks, async stores, the voter-model and timeout work) can exceed it again, and the failure is silent: results shift, nothing errors.

Options:
- Yield a real macrotask (e.g. `setTimeout(0)` / `MessageChannel`, available in Node, browsers and React Native) between virtual timer fires; all pending promise continuations run before a macrotask. This lives only in the `testing` module, so it doesn't break the no-global-timers rule for the engine.
- Keep the hop count but detect overrun: fail loudly (in tests) if a drain ends with work still scheduling.

Either way add a regression test with a deliberately long continuation chain (e.g. 200 hops) that must complete before the next timer fires.
