## What landed

Everything stayed inside `src/graph/render.ts` (new code) + `src/app/styles.ts` (new CSS classes) +
`docs/design.md` (new "Camera controls" subsection under the Graph tier), exactly as scoped. `src/app/shell.ts`
was **not** touched — no new `GraphView` method was needed.

- **On-screen control cluster** (`render.ts:354` `createCameraControls`): six `<button type="button">`s with
  `aria-label`s — zoom in (`+`), zoom out (`−`), Fit, Reset, rotate left (`↺`), rotate right (`↻`) — absolutely
  positioned bottom-right inside the graph container (`.tsv-camera-controls` in `styles.ts`), reusing the
  existing `#tsv-app button` chrome.
- **Camera actions** (`render.ts:332` `CAMERA_CONTROLS`, `render.ts:406` `handleCameraKeydown`): Fit =
  `camera.animate({x:0.5,y:0.5,ratio:1})`, Reset = `camera.reset()`, zoom in/out = `camera.zoomIn()`/`zoomOut()`
  (sigma's own settings, so identical feel to wheel zoom), rotate = `camera.animate({angle: ±15°})`, pan =
  `camera.animate({x/y: ± 0.1 * camera.ratio})`. All use a 200ms `duration` so repeated presses feel snappy.
- **Keyboard shortcuts, scoped to the graph** (`render.ts:515` `container.tabIndex = 0`, `render.ts:556`
  listener attach): `+`/`=` zoom in, `-`/`_` zoom out, `0` reset, arrow keys pan, `[`/`]` rotate. The listener
  is attached to `container` itself (not `document`), so it only fires when the container or a descendant (a
  control button) has focus — automatically inert while the search box, file input, or any panel control is
  focused, with no boolean state tracking. Every handled key calls `preventDefault()`.
- **Dismissible mouse-gesture hint** (`render.ts:372` `createCameraHint`): bottom-left overlay, "Drag to pan.
  Scroll or pinch to zoom." + a `×` dismiss button. Persisted via `localStorage` key
  `tallysim-viewer:camera-hint-dismissed` (same try/catch pattern as `theme.ts`'s `storeTheme`/`safeGetStored`)
  — once dismissed it does not reappear on reload or on a later network load.
- **Cleanup** (`render.ts:606` `destroy()`): the `keydown` listener added directly to `container` is explicitly
  `removeEventListener`'d (container persists across loads; `shell.ts`'s `teardown()` only clears its
  children), alongside the pre-existing `sigma.kill()`/`tooltip.remove()`. The control cluster and hint
  elements are also explicitly `.remove()`'d for symmetry with the tooltip, though `shell.ts`'s
  `graph.textContent = ''` would clear them anyway.
- **`styles.ts`**: `.tsv-camera-controls`, `.tsv-camera-hint`, `.tsv-camera-hint-dismiss`, and a
  `#tsv-graph:focus-visible` outline (visible keyboard-focus indicator on the now-focusable container).

## Gap: no manual browser pass was done

This sandbox has no way to run `yarn dev` and click around, so **none of the manual checks the ticket calls
for were performed**. That is the main thing to verify in review:

- Each button and each keyboard shortcut does what it says (zoom in/out, Fit, Reset, rotate left/right, pan).
- Shortcuts are inert while the search box or file input has focus, and work again after clicking back on the
  graph (confirms the focus-scoping actually behaves as designed, not just compiles).
- **The cleanup gotcha specifically**: load the sample twice (or load a trace file after the sample), then
  press `0` once — confirm exactly one reset's worth of movement, not two or more. A regression here is silent
  (no error, just an N-fold repeated action per keypress) and easy to miss casually.
- Hint dismiss persists across a reload.
- Switch to Sweep mode and back while the graph had focus; confirm no stray keystroke effects reach the graph
  while hidden (relies on the browser's own auto-blur-on-`display:none`, not any code added here).
- Rotate the view, then hover a node/edge — tooltip still appears at the right spot, labels still read
  horizontally (sigma's own label-layer behavior; nothing here should affect it, but unverified in a browser).
- Both light and dark themes — buttons/hint should pick up the shared `#tsv-app button`/CSS-variable chrome
  with no new styling needed; unverified visually.
- Arrow-key pan direction (`ArrowUp` → `dy = -1`, etc. in `render.ts:425`) was chosen by convention, matching
  typical map/camera panning (up arrow reveals content above). Not verified to *feel* right in a running app —
  easy to flip the sign in `panCamera`/`handleCameraKeydown` if it reads backwards on manual test.
- WebGL-unavailable stub path: confirmed by code inspection only (`createGraphView` returns `stubView()` before
  any camera code runs, same branch the tooltip/WebGL-missing message already use) — not exercised on an
  actual no-WebGL2 browser/profile.

## Design decisions worth knowing for review

- Fit vs. Reset: `0` is bound to Reset (the more complete action — it subsumes Fit when the view isn't
  rotated) rather than Fit, per the ticket's resolved design. Fit is reachable only via its on-screen button.
- Fit's axis-aligned re-frame can clip the corners of a rotated, non-square graph — an accepted trade-off
  documented in `docs/design.md`'s new subsection, not a bug.
- No manual bounding-box math anywhere: both Fit and Reset are literal camera-state assignments that lean on
  sigma's own `DEFAULT_CAMERA_STATE` auto-rescale, exactly as the ticket's design section specified.
