The implement stage built the **browser-only rendering + shell wiring + docs** on top of the already-landed
pure core (`clock.ts`, `routes.ts`, and the `core/` reducer/de-anonymiser). Build, viewer tests (57), and lint
are all green. This is a starting point for review, not a finished line — the renderer, the transport loop and
the shell are **browser-only and were NOT exercised at runtime** here (no headless WebGL), so the manual check
below is the real functional gate.

## What landed

- **`app/theme.ts`** — the shared `Palette` gained the replay colours (light + dark): `roundScale` (a warm,
  colour-blind-safe ordinal ramp, chosen to separate from the cool-blue capacity edges), `pruned`, `sleeping`,
  `late`, `dimmed`.
- **`replay/paint.ts`** (+ `paint.test.ts`, 9 tests) — **pure, sigma-free**. `buildOverlay(input)` turns an
  `ActiveSet` + the compiled `{sleeping, late}` sets + an optional isolate into a plain `ReplayOverlay`
  (`{nodes, edges, dim?}`). Round-coloured lit nodes/edges; pruned edges fade + carry the reason as a hover
  `note`; whole sleeping/late sets marked distinct (sleeping wins over late); isolate keys only the route and
  sets `dim`; `sessionColor` overrides the round colour for colour-by-session; `mergeOverlays` combines
  per-session overlays (last-wins on a shared key).
- **`graph/render.ts`** — `GraphView.setReplayOverlay(overlay | undefined)`. The node/edge reducers now compose
  three layers **in order**: resting capacity style → overlay (keyed style, or `dim` for the rest when an
  isolate is active) → built-in hover/selection accent, which **wins on top** and never leaves a hovered edge
  hidden. The edge tooltip appends the overlay `note` (e.g. the prune reason).
- **`replay/controls.ts`** — browser-only transport + panel. The rAF loop (`advanceClock` → `seek` → `paint`),
  play/pause, speed (0.25×–8×), scrub over `timeBounds`; session picker + colour-by-session; the found panel
  (explicit `SessionFoundState`; the full routes list with hops + terms + isolate-on-select **when a
  `ReplayRouteSource` supplies paths**, else markers-only + the honest note). `mountDisabledReplayControls` for
  the no-trace / sample path.
- **`app/shell.ts`** — on a real trace load, builds the `Deanonymiser`, compiles conditions once (CLI-matching
  seed: `scenario.conditionsSeed ?? 0`, no runSeed offset), and mounts the live replay panel wired to the
  `GraphView`; teardown stops the loop and clears the overlay; the sample path mounts the disabled panel; the
  theme toggle re-paints the panel.
- **`docs/design.md`** — new **Replay tier** section (one clock/one seek path, precise de-anonymised edge
  lighting, conditions-derived sleeping/late incl. the seed note, the found-route reconstruction **and the
  trace-format gap**); tier list + Testing section updated.
- **`tickets/backlog/feat-trace-plan-found-path.md`** — the deferred clean fix (originator's `plan-found`
  carries its plan path nonces; bumps `TRACE_FORMAT_VERSION`).

## How to validate

- **Automated (ran green here):** `yarn workspace tallysim-viewer build` (tsc + vite), `… test` (57 pass incl.
  `paint.test.ts`), `… lint` (clean). Root `yarn build` is `--topological`, so tallysim rebuilds before the
  viewer (note: tallysim's `dist/` was stale — missing the `late` field — and was rebuilt; `dist/` is
  gitignored, so this is build output, not a tracked change).
- **Manual dev check (NOT run here — the real gate for the browser-only code):**
  `yarn workspace tallysim-viewer dev`, then load a trace **with conditions**. Produce one with
  `yarn workspace tallysim trace <scenario.json>` using a scenario that sets `conditions` (a `sleepingFraction`
  / `lateFraction`) and a `conditionsSeed`. Then: Play; Scrub to t=0 (clean empty) and t=end (full final);
  hover a pruned edge (reason shows); toggle colour-by-session (several queries in distinct hues); change speed.
  Confirm sleeping vs late nodes read distinctly and a `late-answer-folded` edge lights at its later round.

## Known gaps / where to look hardest

- **Nothing browser-side was run.** Overlay compositing, the rAF loop, scrub/seek, colour-by-session merge, and
  teardown are unverified at runtime. Treat the manual check as mandatory, not optional.
- **The found-routes full list (hops + terms + isolate-on-select) has NO runtime path for a loaded trace** — a
  trace carries no plan paths (the documented gap), so shell never passes a `ReplayRouteSource`. That code
  (`controls.ts` `currentIsolate` → `routes.ts` → the isolate overlay) is reachable only with a route source
  (live-run/test). `paint.ts`'s isolate branch is unit-tested; the `controls.ts` wiring around it is not
  exercised anywhere yet. Worth a close read.
- **`roundScale` / condition colours are hand-picked**, not run through the dataviz validator; CVD-safety and
  on-surface contrast are best-effort. Verify legibility in the manual check, light and dark.
- **Sleeping/late is colour-only** (sigma's default node program has no dash); marked whole-set, so on a large
  graph a conditioned-node fraction paints many dots — judge whether that reads as signal or noise. (`NOTE:` in
  `paint.ts`.)
- **Per-frame double-derive:** the selected session's active set is derived twice per frame (overlay +
  found-panel). Fine for planned sizes; a tripwire `NOTE:` marks the site in `controls.ts` (derive once if play
  ever stutters). This is parked as a tripwire, not a ticket.
- **A no-event session** classifies as `no-route` at t=min (sessionEnd falls back to bounds.min). Edge case;
  confirm it is acceptable.

## Review findings

- Parked tripwire — per-frame double-derive of the selected active set (`controls.ts` `renderFrame`, `NOTE:` at
  the site): O(events)×2 per frame, fine now; derive once if a large trace stutters.
- Parked tripwire — sleeping/late are colour-only marks on the whole conditioned set (`paint.ts` `NOTE:` at the
  spread overlay): if a dashed/ringed mark or a reached-only subset is wanted later, it needs a custom node
  program / second overlay, not a recolour.
- Deferred cross-package work — found-route paths are absent from trace format v1; filed as
  `backlog/feat-trace-plan-found-path.md` (originator `plan-found` carries its path; bumps
  `TRACE_FORMAT_VERSION`). The viewer shows markers-only for a loaded trace until then.
