## What landed

The tallysim-viewer replay tier now animates a payment's **consensus (sign-and-settle) phase** on top of the
existing discovery spread, driven entirely by the v2 trace header's `lifts[]` entries (no inference). Implemented
across the pure core + overlay tiers (unit-tested) and the browser-only transport/panel (build + manual-gated).

**All automated gates pass:** `yarn workspace tallysim-viewer test` → **117 passed / 11 suites**;
`tsc --noEmit` clean; `vite build` clean (the >500 kB chunk warning is pre-existing and unrelated);
`eslint ./src` clean. No pre-existing test failures surfaced.

### Tier-by-tier

- **`core/trace-index.ts`** — `createLiftResolver(lift)`: `entityOfMember(memberKey)` reads the header's
  `memberKeys` map; `tallyOfEdge(from,to)` folds the index-aligned `route` + `tallyPath` into an
  **order-independent** unordered-pair map (a circular lift's repeated originator sits on two distinct pairs →
  unambiguous). `TraceIndex` gained `lifts()`/`liftFor(sessionCode)`/`liftByTransaction(txCode)`; a v1 /
  discovery-only v2 trace ⇒ `lifts()` is `[]`.
- **`core/timeline.ts`** — consensus types + reducer. A `Timeline` optionally binds a `ConsensusBinding`
  `{lift, resolver}`; when bound, `deriveActiveSet(t)` gains a `ConsensusState` recomputed-from-scratch (so a
  backward scrub un-settles). Discovery loop guards `isConsensusEvent` out (a consensus event's `nodeId` is a
  member key, not an entity id). Edge phases from the decision: **commit ⇒ every `tallyPath` hop `committed`**;
  **void ⇒ only promised hops `released`**; **no decision ⇒ promised hops `promised`**. Unresolvable member
  keys surface in `consensus.unresolved` (never dropped). No binding ⇒ **no** `consensus` key (discovery byte-
  for-byte unchanged).
- **`app/theme.ts`** — three palette roles added to light **and** dark: `promised` (teal/cyan), `committed`
  (solid green), `voidFlash` (crimson).
- **`replay/paint.ts`** — `PaintInput` gained `consensus?` + `currentTime?`; the consensus layer composes
  **over** the spread and is **suppressed in isolate mode**. Exports `VOID_FLASH_MS` (400 virtual-time ms).
  Edge: promised→colour+zIndex2 (keeps thickness); committed→colour+size6+zIndex3; released→voidFlash during
  the flash window else *not keyed* (falls back to resting/discovery). Node: promised→colour; voted→committed
  (`C`) / voidFlash (`NC`); settled→committed on commit, voidFlash-while-flashing on void.
- **`replay/routes.ts`** — `liftRoute(lift)` (`path`|`loop` + exact nodes/tallies/hops/txCode, straight from
  the header — no decode), `liftOutcome(decision)` (`committed`|`voided`|`stalled`), `liftIsolate(lift)`.
- **`replay/controls.ts`** (browser-only) — binds `consensus` per session with a lift; threads
  `consensus`+`currentTime` into `buildOverlay` on both the selected and colour-by-session paths; the found
  list shows the lift's chosen route + an outcome **badge**, and clicking it isolates the route (`liftIsolated`
  boolean). Multiple lifts ⇒ each session animates its own; discovery's *other* found plans stay markers-only.
- **`docs/design.md`** — new *Consensus phase* subsection (resolvers, reducer, overlay+palette, side list +
  closed-loop case) and the *Found routes* gap now marked **closed for the settled lift's route**.

## Honest gaps / where to look hard (reviewer: treat tests as a floor)

- **No manual/visual verification happened.** The entire `controls.ts` wiring and the overlay-on-screen
  (compose order over discovery, colour-by-session + consensus interaction, the side-list badge, isolate-on-
  click) were validated only by typecheck/build — **not by eye.** This is the highest-risk area; please run the
  manual recipe above. In particular verify: (a) consensus colours visibly win over discovery on settled hops;
  (b) the void flash is actually brief and then the hop returns to resting; (c) colour-by-session still reads
  (the consensus layer overrides the session hue on settled hops **by design** — confirm that is acceptable, or
  flag it).
- **Palette CVD separation is reasoned, not validated.** `promised`/`committed`/`voidFlash` were chosen for
  colour-blind separation and distinctness from the existing roles, but **not** run through the dataviz palette
  validator. The one risky pair (committed-green vs voidFlash-red) never co-occurs (commit XOR void) and is
  backed by the badge text — but a reviewer may want to run the validator and/or eyeball both themes.
- **`VOID_FLASH_MS = 400` is a guess** in virtual-time units. If traces compress time differently than assumed,
  the flash could be too short/long on screen — a manual tunable. Documented at its export site.
- **Perf: `refreshFound` now derives the active set a 3rd time** (at `sessionEnd`, for the outcome badge), on
  top of the existing twice-per-frame NOTE in `renderFrame`. Fine for planned trace sizes; it's a tripwire, not
  a defect (see findings).
- **Not re-verified end-to-end against a real v2 `lifts[]` header shape** beyond the hand-built fixtures — the
  resolver/reducer assume the exact `TraceLiftEntry` shape from `tallysim/src/sim/trace-format.ts` (read during
  implement, matches). The manual trace run is what closes this loop.
