## What landed

This ticket was implemented as **one atomic change** (a rename of an exported wire code + API, plus two new **required** record/query fields — these cannot land in separate commits without an intermediate broken build). The build, the full test suite, and lint are all green across the monorepo.

### 1. Terms rename: referee → voter

- `MemberType` wire code `'R'` → `'V'`; `MemberTypes.referee` → `MemberTypes.voter` (`discovery/types.ts`). `'P'`/`participant` and the signature faces `'C'`/`'NC'` (commit/void) are unchanged. **A "referee" is now defined as simply a voter (`'V'`) that is not also a participant** — there is no distinct code for it.
- All identifiers swept in `consensus/participant.ts` (the `voters`/`voterKeys` locals, `countVerifiedCommits`'s param, `MAX_PENDING_COMMITS_PER_VOTER`, the `NonEmptyVoterSet` rule, log/rule messages) and every other `src/` file.
- Trace event `'referee-vote'` → **`'voter-vote'`** (`trace.ts`), renamed in lockstep with its consumers (`tallysim/consensus-metrics.ts`, `tallysim-viewer/core/timeline.ts`).
- `tallysim`/`tallysim-viewer` consumers swept (`REF` → `VOTER` constants, comments). Behaviour identical.
- **Deliberately NOT touched: `packages/taleus-core/**`.** `taleus-core`'s "referee" (`lift/referee.ts`, `SingleReferee`, schema identifiers) is an independent domain concept renamed later by `feat-tallynet-bind-taleus-core`; it does not import from `tallynet`, so leaving it does not break the build. A few doc references in `tallynet/docs/design.md` that name that taleus-core schema (lines 16, 48, 125, 131's "legacy single referee per edge") were **kept** as "referee" on purpose.

### 2. Proposal parameters: consensus method + optional lift-contract CID

New shared type in `discovery/types.ts`:
```ts
interface ConsensusMethod { weighting: 'distinct-voter'; thresholdNum: number; thresholdDen: number }
const DEFAULT_CONSENSUS_METHOD = { weighting: 'distinct-voter', thresholdNum: 1, thresholdDen: 2 }
function consensusMethodError(method): string | undefined   // one shared validator, naming the bad field
```
- `TrxRecord` gains `method: ConsensusMethod` (required) + `liftContract?: string` (optional, "omit, don't undefine"), both part of the **immutable, promise-signed core**.
- `UniQuery` gains the same two fields, so a node can refuse a method/contract during discovery before it promises. The originator stamps them from `OriginatorOptions` (default `DEFAULT_CONSENSUS_METHOD`).

### 3. The digest binding (the subtle, high-risk part)

`recordDigest` (`consensus/digest.ts`) builds its preimage from an **explicit field list**, not a spread — so adding fields to `TrxRecord` does **not** auto-bind them. The preimage now includes `mt: record.method`, and `lc: record.liftContract` **only when present** (omitted entirely otherwise, matching the existing `pr` key's DAG-CBOR discipline). The `Pick<>` on the `record` param was widened to include `'method' | 'liftContract'`. Without this, `coreEqual` would not detect a method/contract change. **The digest-vector test (`digest.test.ts`) is the tripwire that fails if this binding is ever removed** — it is the single most important edit to verify.

### 4. Threshold settlement (behaviour change behind an unchanged default)

In `getRecordState` (`consensus/participant.ts`), the two hard-coded `> voters.length / 2` tests were replaced with:
```ts
const totalWeight = voters.length           // v1 weighting 'distinct-voter' ⇒ total weight = voter count
const { thresholdNum, thresholdDen } = record.method
const settles = (count) => count * 2 > totalWeight && count * thresholdDen >= thresholdNum * totalWeight
```
Integer arithmetic only (exact, deterministic). The strict-majority floor (`count*2 > W`) keeps commit and void mutually exclusive for **any** threshold; the threshold only raises the bar. At the default `1/2` the threshold test is implied by the floor, so the outcome is `> W/2` — **byte-identical to before** (proven: every pre-existing consensus test passes unchanged, modulo `R`→`V` fixture substitutions).

### 5. Validation

- Consensus new-record rules gained `ConsensusMethod` (method present + `distinct-voter` + positive-integer threshold + `1/2 ≤ t ≤ 1`) and `LiftContract` (non-empty string when present). `NonEmptyRefereeSet` → `NonEmptyVoterSet`.
- The **same** `consensusMethodError` validator is wired into the discovery query rules (`discovery/participant.ts`), so a node refuses a bad method during the search too.

## How to test / validate (use cases)

Build + test + lint all pass (`yarn build`, `yarn test`, `yarn lint` from repo root — all streamed, all green). Key behavioural cases now covered by tests:

- **Default method reproduces today.** Every existing consensus scenario passes with only `R`→`V` fixture edits. The "a set of one/two/three" end-to-end cases in `testing/consensus.test.ts` are the regression floor.
- **Threshold `2/3` on 3 voters** settles with 2 commits; **`3/4` on 4 voters** settles with 3, and the **no-settle band** (2 of 4) stays `pending` — asserted in `participant.test.ts` → `describe('threshold settlement …')`.
- **Threshold `1` (unanimity)** needs every voter; one short does not settle.
- **A lone voter** under the default settles on its own commit.
- **Validation rejects** a threshold `< 1/2`, a zero/non-integer denominator, a threshold `> 1`, and a reserved `weighting` — `describe('consensus-method validation')`.
- **Digest binding:** two records differing only in `method` (or only in `liftContract`) produce different digests — `digest.test.ts` → `describe('binds the consensus method and lift contract')`.

## Known gaps / what a reviewer should scrutinise (tests are a floor, not a ceiling)

1. **Query→record consistency is not wired end-to-end.** The ticket's edge case "minting must stamp the record's core from the query's values so the two agree" belongs to the **future** `tallynet-originator-proceed` ticket (the plan→topology minting step). Today `method`/`liftContract` ride on `UniQuery` and on `TrxRecord` **independently** — the originator stamps the query, and the test harness `buildLift` stamps the record from its own `LiftSpec`. There is no code path yet that folds a query's method into a minted record, so the "mismatch reads as core-mismatch" scenario cannot be exercised here. Confirm this is acceptable scoping (it matches the design: originator-proceed owns the fold).
2. **No dedicated test for the discovery-side method rejection.** The `ConsensusMethod` rule in `discovery/participant.ts` is exercised only indirectly (every discovery test query now carries a valid `DEFAULT_CONSENSUS_METHOD`). A test that a discovery query with a reserved weighting / out-of-range threshold is refused *before promising* would harden this. Low risk (same validator as the consensus side, which **is** directly tested), but it is untested in isolation.
3. **`liftContract` has a shape rule but no rejection test.** The `LiftContract` rule (non-empty string when present) is not covered by a test. Trivial to add.
4. **The blanket `referee`→`voter` rename used `replace_all` over whole files.** This is mechanical and the build/lint would catch a bad identifier, but a reviewer may want to spot-check that no comment lost meaning (e.g. the reworded `tallysim` "voter model" note that previously read "lift voters, not referee").
5. **`consensusMethodError` accepts `thresholdNum/thresholdDen` as `number`.** It rejects non-integers and non-positives, but a reviewer should confirm there is no overflow concern in `count * thresholdDen` / `thresholdNum * totalWeight` at realistic lift scale (voter counts and thresholds are tiny; not a concern, but noted).

## Tripwires parked (knowledge, not tickets)

- Pre-existing `NOTE:` in `countVerifiedCommits` ("re-verifies every commit per classification pass; cache if voter sets grow large") and `canonicalPromiseSet` (digest re-maps/re-sorts per verify) are **unchanged** by this ticket and still accurate after the rename. No new tripwire was introduced — the threshold comparison is O(1) integer arithmetic.
- The `taleus-sereus` test suite emits `console.warn` noise about offline external catalog fetches (`test.invalid`, `sereus.org`). This is **pre-existing and unrelated** to this ticket (that package does not import `tallynet`); its tests pass. Not re-reported.

## Pointers for the reviewer

- The win-condition math lives in `consensus/participant.ts` `getRecordState` (the `settles` closure) — verify the integer arithmetic is exact and that the default reduces to `> W/2`.
- The binding is `consensus/digest.ts` (`mt`/`lc` in the preimage + the widened `Pick`). Verify `lc` is omitted (not `undefined`) when absent.
- The shared validator is `discovery/types.ts` `consensusMethodError`; both rule sites call it.
