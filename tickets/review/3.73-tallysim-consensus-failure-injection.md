## What landed

The consensus **failure-injection** knobs in the scenario model, plus the one genuinely new selection
helper. Only the **refuser** is new code; the other three failure modes the parent ticket names are the
*existing* `ConditionsSpec` knobs (sleeping / dropped / late), which already degrade the consensus phase
because the harness's per-link conditions map is reused by consensus pushes — no new code was needed for
them.

**`scenario.ts`** — added:
- `ConsensusSpec { refuserFraction?: number; identitySeed?: number }`. Its **presence** on a `SimScenario`
  is the "run consensus" switch; absence ⇒ discovery-only.
- `DEFAULT_CONSENSUS_IDENTITY_SEED = 1` — the fallback identity seed. **Note: nothing applies this default
  yet** — it is defined here for the runner (sibling ticket) to use. See Gaps.
- `SimScenario.consensus?: ConsensusSpec` and `SimScenario.consensusSeed?: number` (the dedicated
  refuser-selection stream, same seed-isolation discipline as `conditionsSeed`). Both optional + absent on a
  discovery-only scenario, so `SimScenario` still round-trips through a trace header unchanged.

**`sim/conditions.ts`** — added `ConsensusConditionsSpec`, `CompiledConsensusConditions { refusers:
Set<number> }`, and `compileConsensusConditions(network, spec, seed)`. It **reuses** the existing private
`range` + `pickFraction` (the `round(fraction · poolSize)` seeded partial-shuffle machinery) rather than
inlining a second copy, so the refuser selector behaves byte-identically to the sleeping/late selectors
(same `round` rule, same determinism). `ConsensusSpec` is structurally assignable to
`ConsensusConditionsSpec`, so the runner can call `compileConsensusConditions(network, scenario.consensus,
consensusSeed)` directly.

## How the four failure modes map (for the reviewer's mental model)

| Failure mode | Where it lives | How it bites consensus |
|---|---|---|
| **A refuser** (signs `NP`) | **NEW**: `consensus.refuserFraction` → runner builds `{ shouldPromise: false }` via `makeSimResources` | a refuser on a taken route voids that lift |
| **A node that sleeps mid-transaction** | existing `conditions.sleepingFraction` | both incident links `drop`; a consensus push to/from it never delivers → lift **stalls** (`pending`) |
| **A dropped push** | existing `conditions.dropFraction` | those links `drop`; a push over a cut route edge stalls |
| **A slow voter / late fold** | existing `conditions.lateFraction` + `lateLatencyMs` | the late link delays the push; record folds in late → `timeToSettleMs` grows but the lift still settles |

The key mechanism (documented more fully by sibling `tallysim-consensus-docs-experiment`): a sleeping/dropped
**target** is still *found* by discovery (a neighbour resolves the peer-match terminus without delivering to
the target), but consensus needs that target to promise and the push to it drops → the lift stalls.
Discovery succeeds, consensus stalls, on **one** degraded network build — no separate clean-discovery /
dirty-consensus build needed.

## Gaps / what the reviewer should probe (honest)

- **End-to-end seeded outcomes are NOT tested here** — "one refuser on a route voids it" and "a dropped push
  on a cut route edge stalls" are behavioural assertions that need the runner driving real lifts. They live
  in the **runner ticket** (`tallysim-consensus-runner-cli`), not this one. This ticket's tests only cover
  the *pure selection* helper. Do not expect route-outcome coverage in `conditions.test.ts`.
- **`DEFAULT_CONSENSUS_IDENTITY_SEED` is defined but unused** in this diff. Applying the default (and
  threading `identitySeed` / `resourceFor` into `buildSimNetwork`) is the runner's job. Flagged so a reviewer
  does not read the unused export as dead code — it is a forward hook for `tallysim-consensus-runner-cli`.
- **`consensus` / `consensusSeed` on `SimScenario` have no consumer in this diff.** Same reason: the runner
  and trace (sibling tickets) consume them. Verify only that they are optional and don't perturb the
  existing discovery-only shape (they don't — both are added as optional fields).
- **v1 asymmetry (documented, out of scope):** a dropped push on a *needed* route edge stalls that lift, but
  phase-2 "a refuser only hurts itself (its own incident lift)" is out of v1. Cross-referenced to
  `tallynet-propagation-timeouts`. Not a defect — a scoped simplification for this tier.
- **"Different seed differs" is probabilistic.** The determinism test asserts seeds 11 vs 12 give different
  refuser sets over a 20-node / 6-pick draw; it passed, but like the sibling `conditions` determinism test
  it is not a hard guarantee for arbitrary seed pairs. Left as-is to match the existing test's style.
