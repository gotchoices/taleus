## What this was (one paragraph)

The simulator measured route discovery reaching only ~half as far as its depth ceiling: an **L-hop**
route surfaced only at `maxDepth ≥ 2(L − 1)`. The fix stage root-caused this to the **virtual clock**,
not the protocol: the `VirtualClock`'s microtask-drain constant `DRAIN_QUIET` (16) was smaller than
discovery's per-level **completion cascade** (~17–23 quiet microtask hops), so the drain quiesced
*mid-cascade* and the run loop fired a round-budget timer that was about to be cleared — advancing
virtual time to full budget and folding an instant answer one round **late**. That late fold is the
extra round per level, i.e. the `2(L − 1)`. The protocol's true reach is `maxDepth = L` (one round per
level). Fix: raise `DRAIN_QUIET` 16 → **64** (measured threshold 24; 64 is ~3× margin), then correct
every test and doc that had codified the `2(L − 1)` artifact as if it were real.

## What changed

- **`packages/tallynet/src/testing/clock.ts`** — `DRAIN_QUIET` 16 → 64. Rewrote the `DRAIN_QUIET` NOTE
  and the class-doc paragraph to name the completion cascade as the binding constraint (constant in
  depth, ~20 hops/level) and to record why "return the query promise" (the consensus trick) deadlocks
  for discovery (a discovery `query` awaits nested budget/delivery timers that only fire in the
  runUntilIdle loop, never during a drain).
- **`packages/tallynet/src/testing/discovery.test.ts`** — replaced the single-point `maxDepth boundary`
  describe (which asserted the artifact: missed@3, found@4 for a 3-hop chain) with an **exact boundary
  sweep** over chains L = 2..6: found at exactly `maxDepth = L`, missed at `maxDepth = L − 1`. Corrected
  the module-doc `path.length <= maxDepth - 1` narrative to the true tight bound.
- **`packages/tallynet/docs/design.md`** (§ Protocol design) — added the reach note: `maxDepth` counts
  hops; L-hop route found at `maxDepth = L`; peer-match terminus resolves the last hop at no extra
  round; the `2(L − 1)` claim withdrawn; pointer that the sim's `DRAIN_QUIET` must exceed the cascade.
- **`packages/tallysim/docs/design.md`** — rewrote § "Rounds ↔ hops" (dropped "reach is ~half the
  ceiling"): no depth doubling; `found ⊆ oracle` kept, but the *systematic* 2× undercount is gone so any
  remaining gap is real protocol loss (what the degradation experiment measures).
- **`packages/tallysim/src/sim/harness.test.ts`** — this file (NOT in the original ticket's file list)
  also enshrined the artifact and **broke** under the fix. Its `rounds↔hops boundary` describe asserted
  a 3-hop chain was *missed* at depth 3; the fix makes it *found* at depth 3. Rewrote both hand-built
  boundary tests to the corrected reality (found at depth = hop count, missed one shallower; the
  protocol now matches the oracle at the same depth).
- **`packages/tallysim/src/sim/sim-runner.test.ts`** — reworded the `varies workload.depth` comment;
  see the big interaction below.

## ⚠️ Big interaction — this fix also resolved a *different* open ticket

Raising `DRAIN_QUIET` **also removed the root cause of `fix/tallysim-sim-runner-concurrent-divergence`
(seq 3.535, downstream of this one).** That ticket documents concurrent vs sequential sweep runs
disagreeing on `roundsUsed`/timing. Its root cause is the *same* premature-budget-timer fire: under the
old drain, the interleaving of concurrent sessions' cascades changed *which* budget timers fired early,
so the two modes diverged. With the cascade fully draining, budget timers are always cleared before
firing and **the two modes now produce byte-identical records**.

I verified this is genuine, not seed-luck: a throwaway sweep over line lengths 3–8 × 5 seed-groups × 3
latency ranges was **75/75 identical** (throwaway deleted). Given that, I:
- tightened the characterization test (`sim-runner.test.ts`, now "produces identical full records in both
  modes under real latency") from `.not.toBe` to full `.toBe` equality, and
- corrected the three now-false caveat sites that called the divergence a "known limitation": the
  `sim-runner.ts` module header, its `runProtocolQueries` NOTE, and `docs/design.md` § discovery sweep
  runner.

**I deliberately did NOT make `tallysim-sim-runner-concurrent-divergence`'s remaining decision** — that
ticket also has to choose whether to *keep* `concurrent` as a feature (now equivalent + a touch faster)
or *drop* it. I left that open and said so in all three caveats. **I left that ticket file in place**
(it is downstream; a human may be curating it). Reviewer: that ticket is now reduced to a keep-vs-drop
call with no bug left to fix — consider routing it to `complete/` or `blocked/` (human decision) rather
than a fresh fix/implement cycle.

## How to validate (reviewer)

- `cd packages/tallynet && yarn test` — 316 pass (was green). The exact-boundary sweep is the key new
  coverage; `maxDepth boundary` proves found@L / missed@(L−1) for L = 2..6.
- `cd packages/tallysim && yarn test` — 273 pass. **Note the build coupling:** tallysim imports the
  **compiled** `tallynet/dist`, not source. You MUST `cd packages/tallynet && yarn build` after any
  `clock.ts` change or tallysim will silently test the stale `DRAIN_QUIET`. (This bit me once —
  tallysim failed until I rebuilt tallynet.)
- `yarn lint` in both — clean.
- Reproduce the core claim yourself: a straight peer-match chain `N0..N{L}` is found at `maxDepth = L`
  and not `L − 1`. Flip `DRAIN_QUIET` back to 16 and the tallynet boundary sweep + the tallysim
  harness/sim-runner tests should fail in the artifact direction — a quick way to confirm the tests
  actually bite.

## Use cases this protects

- **Simulator reach fidelity:** the degradation experiment's `found ⊆ oracle` gap now reflects real
  protocol loss, not a fixed clock undercount layered on top. A depth sweep no longer needs to "budget
  double the hop distance."
- **Concurrent sweep mode** is now metric-faithful (was throughput-only, round/timing-unsafe).

## Known gaps / things to scrutinize (treat tests as a floor)

- **Margin, not proof.** 64 is empirical headroom over a *measured* ~20-hop/24-threshold cascade, not a
  derived bound. The cascade is constant in depth (per-level harvest is its own fire/drain cycle), so it
  does not scale with `maxDepth` — but if `reenter` ever grows more `await`s, the cascade could creep up.
  Parked as a tripwire **in the `DRAIN_QUIET` NOTE at the code site** (`clock.ts`), greppable `NOTE:`.
- **Convergence is empirical (75/75), not theoretical.** I cannot *prove* no exotic config hits a
  genuine budget==delivery virtual-time tie that would re-diverge the two sweep modes; the broad sweep
  found none. If `tallysim-sim-runner-concurrent-divergence` is formally closed, that residual should be
  acknowledged there (it owns the keep-vs-drop decision and the tie analysis).
- **harness.test.ts was out of the original scope** — I pulled it in because it broke. Double-check I
  didn't miss any *other* sim assertion that merely *passed by luck* under both old and new behavior
  (e.g. ample-depth tests like the diamond @depth 3, which find more now but still assert `found`).
  I grepped `depth`+found/oracle across the sim tests and believe harness + sim-runner were the only two
  with tight boundary expectations, but a second set of eyes on the diamond/scale tests is cheap.
- **Memory already corrected.** The `tallynet-peer-match-depth` memory already reads "reach = maxDepth =
  L … the 2(L−1) was a VirtualClock DRAIN_QUIET artifact" — no upkeep needed.
