**This is the review handoff for the first of three split tickets.** The siblings `tallysim-discovery-metrics-io` (serialisers + `cli/simulate.ts`) and `tallysim-discovery-metrics-experiment` (checked-in experiment + `design.md` findings) are chained after it and are **not** built here. Treat the code below as a starting point: the tests are a floor, not a ceiling.

## What landed

The discovery tier already had the harness (runs the real `tallynet` route-discovery protocol over a simulated network on compressed virtual time) and a trace recorder. This ticket adds the **measurement** layer on top and a sweep runner that mirrors the oracle runner.

### `src/sim/protocol-metrics.ts` (new, pure — no network/oracle/clock/fs)
- `analyzeQuery(events, outcome, routeExists, { startMs, endMs })` → `ProtocolQueryResult`. Filters `events` by `outcome.sessionCode` **internally** (so it works on one session's events or a whole concurrent batch's). Derives: `found`/`plansFound` from the outcome; `messages` = count of `query-sent` events (not deliveries); `nodesTouched` = distinct `nodeId`; `roundsUsed` = max `round` over `round-started`+`query-sent` (0 if none); `timeToFirstPlanMs` = first `plan-found` time − start (undefined if none); `timeToCompletionMs` = (last event time, else `endMs`) − start; `pruneReasons` = per-reason count over `candidate-pruned`, zero-initialised for all six reasons.
- `summarizeProtocolMetrics(results, structural)` → `ProtocolRunMetrics`. The headline is `pFoundGivenExists` = `foundAndExistsCount / routeExistsCount` (0, never NaN, when none exist). `falseFoundCount` (found but oracle says no route) is a **guardrail that must be 0**. Distributions reuse `summarizeDistribution` from `metrics.ts`. `timeToFirstPlanMs` is distributed over found queries only; the rest over all queries.
- `ALL_PRUNE_REASONS` + `zeroPruneReasons()` — the value-level mirror of tallynet's type-only `PruneReason` union (`cycle | failed | timed-out | max-depth | expired | no-reentrance`).

### `src/sim/sim-runner.ts` (new) — mirrors `runner.ts`
- `runSimSweep(spec, deps?)` is an **`async` generator** (`runUntilIdle()` must be awaited); `runSimSweepToArray` collects it. One `SimRunRecord` per (cell × seed), same provenance shape as the oracle `RunRecord`.
- Per run: materialise the network, build the oracle on the **full, undegraded** network (conditions degrade only the protocol run, never ground truth), draw payment queries, run the protocol, pair each query's trace+outcome with the oracle verdict via `analyzeQuery`, then summarise.
- Three-stream seed scheme mirrors the oracle runner: network via `materializeNetwork`, workload = `workload.seed + runSeed`, conditions = `(conditionsSeed ?? 0) + runSeed`.
- `SimRunnerDeps.concurrent` (default sequential): sequential settles one query at a time; concurrent issues every query (session codes mint in call order) before a single `runUntilIdle()`. Both produce **identical** per-query metrics — verified in tests and analytically (only session-code minting consumes the shared random; nonces are hash-derived; capacity hooks are pure).
- `entityCount < 2`: emits `workload.queries` degenerate zeroed results (same guard the oracle runner uses).

### Supporting changes
- `src/sim/harness.ts`: split `runQuery` into `issueQuery` (arms `discover`, returns the pending outcome **without** driving the clock) + `runQuery` (= `issueQuery` + `runUntilIdle` + await; observably identical, existing harness tests still pass). Added `drawPaymentQueries(workload, entityCount, rng)` (pair-then-amount, caller owns rng seeding; empty for `entityCount < 2`).
- `src/scenario.ts`: added `SimSweepSpec { base: SimScenario; vary: VarySpec[]; seeds: number[] }`. Oracle `ScenarioSpec`/`SweepSpec` untouched.
- `src/runner.ts`: **refactored** to import `cartesian`/`coordsOf`/`setByPath`/`requireNonEmptyValues` from the shared `sweep-vary.ts` (created by the prior interrupted run) instead of its private copies. Error messages preserved; the runner determinism test is the regression floor and still passes.
- `src/sim/index.ts`: exports `protocol-metrics.js` + `sim-runner.js` (re-exported by `src/index.ts`).

### Test coverage (the floor)
- `protocol-metrics.test.ts` — pure unit tests with hand-built synthetic traces: exact extraction of messages/nodes/rounds/times/prunes; session-code filtering; empty-session `endMs` fallback; **folded-late-answer no-double-count**; mixed-results summarise; false-found counting; zero-query / zero-route → `pFoundGivenExists = 0` not NaN.

## Reviewer attention / known gaps (honest)
- **Provenance `generator` for a materialised network reports `network.meta.generator`, not the literal `"materialized"`** — this exactly mirrors `runner.ts`'s existing code, but both record types' doc comments say "(or 'materialized' for a pre-built network)", which is misleading. A pre-existing doc/code mismatch now mirrored in `SimRunRecord`; worth a decision on which to fix (doc or code) — out of scope here.
- **`SimScenario.workload.kind` is not validated to be `'payment'`.** `drawPaymentQueries` ignores `kind` and always draws payment pairs, so a `'clearing'` scenario would be silently treated as payment. **Tripwire** (parked, not a ticket): clearing discovery is explicitly deferred this tier (see `scenario.ts` `SimScenario.workload` doc); `drawPaymentQueries`'s doc already says it draws payment pairs. Becomes real work only if/when a clearing discovery workload is introduced — at which point the runner should branch on `kind` rather than assume payment.
- **Timing distributions (`timeToFirstPlanMs`/`timeToCompletionMs`) are exercised but their exact ms values are not pinned** in runner tests (they depend on round-budget scheduling); only the integer counts are asserted to exact values. If tighter timing guarantees matter, a reviewer could pin representative ms values.
- **Concurrent/sequential equivalence** rests on the invariant that nonces are hash-derived (`makeNonce(sessionCode, edge.id)`) and the only shared-random consumer is session-code minting. If a future change makes discovery draw from the shared random mid-run, that equivalence (and the determinism test) would break — the test would catch it.
- `cli/trace.ts` still has its private `drawQueries` copy; the **io** sibling ticket switches it to `drawPaymentQueries` (left as-is per this ticket's scope; draw order already matches).
- NOTE tripwires in code: per-query route discovery is ~O(network), far costlier than the oracle BFS (`sim-runner.ts`) — sample/cap for large N; and the network/workload seed streams are independent only when their base seeds differ (mirrors the oracle runner's NOTE).
