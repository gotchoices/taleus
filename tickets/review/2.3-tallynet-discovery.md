Finalizer for the `tallynet-discovery` milestone. The originator loop + linear budget (`originator.ts`), the per-node `DiscoveryNode` bundle (`engine.ts`) and the in-memory harness (`src/testing/`) already existed and compiled; this ticket wired them into the public surface, wrote the end-to-end discovery tests, recorded the time-budget decision in the design doc, and got the whole package green.

**Slug kept** (`tallynet-discovery`): four downstream plan tickets name it as a prereq — `tallynet-consensus`, `tallynet-bind-taleus-core`, `tallynet-multi-denomination`, `tallysim-discovery`.

## Use cases a reviewer should re-exercise / probe

The tests are the floor, not the ceiling. Where to push:

- **The 6-node ChipNet happy path** (`N1-L1-N2, N2-L2-N3, N2-L3-N4, N4-L4-N5, N3-L5-N6`, originator N1 → target N6, want `L:{balance:100}`) uses **custom min-balance hooks** (filter to `L`; same-sign + `abs(link) >= abs(want)` → `sign(want)*min(...)`; else drop). Asserts exactly one plan, path length 3, every link `L` at balance **100** (not the raw 500 — this is what the default pass-through hooks would wrongly carry), members `[N1,N2,N3,N6]`, and `storeOf('N1').getNonceToLinkMap(session)[plan.path[0].nonce] === 'L1'`. Worth re-checking the sign logic on the inverted back-links.
- **maxDepth boundary — read this, the invariant is subtle.** The ticket predicted `path.length <= maxDepth` is tight (target at length 3 found at `maxDepth: 3`). **That is wrong.** Empirically a peer-match terminus at path length 3 is **missed at `maxDepth: 3` and found at `maxDepth: 4`** — the tight relationship is `path.length <= maxDepth - 1` for a peer-match terminus (a neighbour of a relay, reached without entering that neighbour). `assertValidPlan` asserts only the loose, always-true `path.length <= maxDepth`. If a reviewer wants the exact round→depth accounting pinned down in the engine (it currently is only characterised by test), that is a reasonable follow-up — but it is **behaviour, not a bug**: nothing over-runs a ceiling.
- **Latency / drop / sleeping** — a 10 s latency on the only route spans rounds 1-3 (cumulative budgets 3.5 s / 8.5 s / 15 s) so the answer folds in via `late-answer-folded` and the plan surfaces **exactly once**; a dropped link arms no timer and yields empty plans with nothing leaked. Reviewer could add intermediate latencies and multi-slow-link cases.
- **Not-found / disconnected / self-is-target / direct-peer / diamond (two distinct routes) / concurrent originators** — all covered; `pendingTimers === 0` asserted after each (the leaked-timer floor).
- **1,000-node scale** — seeded `randomGraph(1000, 2000)` + a guaranteed 4-hop route (`N0→N250→N500→N750→N999`) so a plan is always found; asserts completion, plan validity, no leaked timers. The guaranteed route makes the search conclude shallowly — a reviewer wanting to stress breadth could deepen the guaranteed path or raise the link count, watching wall time.

## Honest gaps / flags for the reviewer

- **Budget constants (2000 / 1500 ms) are coarse guesses.** No adaptive tuning in v1 — parked as `feat-tallynet-adaptive-budget`.
- **The harness drop/sleep model is deliberately simple** (`drop` = eternally-sleeping delivery, no timer; `latencyMs` = request-leg only). Richer failure/timing models belong in `tallysim`, not here.
- **The taleus-core adapter is only *described*** in `engine.ts` (a comment block): `LiftQuery → Target + intents + maxDepth`; `negotiateIntent/negotiatePlan → hooks`; `DiscoveryResult.plans → CandidateRoute[]`. It is implemented by `tallynet-bind-taleus-core`, which must verify that mapping against the real taleus-core shapes when it runs.
- **Trace-event overlap on the originator node** is intentional: `UniOriginator.discover` emits `round-started`/`plan-found` from the search loop, and the node's *own local participant* emits the same for its local sub-query rounds. Tests assert **presence**, never counts.
- **Scale assertion `nonceToLinkMap(session)` is O(nodes)** — a test/sim helper only, never on the discovery control path (a node reads only its own store). Called once per plan-validity check; fine for assertions, do not let it leak into engine code.
