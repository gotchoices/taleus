This is the review handoff for the final ticket of the `tallynet-consensus` chain (core → participant → **this**). The record model, signing, store (core) and the per-node state machine (participant) were already built and unit-tested. This ticket did the **wiring + end-to-end proof**: put the consensus engine on the public surface, extended the in-memory network harness to push records between members, and proved atomic settlement across whole routes under adversarial/failing peers.

## What shipped (all committed except the run-4 harness fix below)

- **Public per-node API** — `packages/tallynet/src/consensus/engine.ts`: `ConsensusNode` (mirrors discovery's `DiscoveryNode`), a thin wrapper over `TrxParticipant` with three methods a host uses:
  - `start(record)` — originator role: seed the transaction with our own freshly-built record (just `update` with no `from`).
  - `update(record, from?)` — participant role: what a peer's push delivers into us.
  - `outcome(transactionCode)` → `'commit' | 'void' | 'pending'` — read the settled result from the store.
- **`TrxParticipant.outcome()`** — `participant.ts`: a small DRY addition that reuses the private classifier (`getRecordState`); its terminal states (`consensus`/`rejected`) are role-independent, so a relay or a polling simulator reads the same commit/void a member does.
- **Public barrel** — `consensus/index.ts` re-exports `engine.js`; `src/index.ts` exports the consensus surface and its module doc no longer says "the consensus engine remains a later ticket".
- **Harness extension** — `testing/network.ts`: consensus nodes built **only when `signerFor` + `verifier` are injected** (discovery scale tests pay no keygen); a name↔member-key bijection (consensus addresses by base64url ed25519 pubkey, not node name); a **fire-and-forget** `updatePeer` honouring `LinkCondition` (`drop`, `latencyMs`); `deliveryErrors: Error[]`; a default cooperative resource; `consensusNode()`/`consensusStoreOf()`/`memberKey()` accessors; and `buildLift(spec)` which resolves a route + `extraLinks` to real graph edges, derives per-session nonces, and fills each node's live `nonceToLinkId` map. **No `@noble/curves`, no Node import** — platform-neutral (passes `no-node-globals.test.ts`).

### Run-4 fix (the only uncommitted diff) — the convergence root cause

Runs 1–3 wrote correct source + all 17 tests, but **13 of 17 failed** on first run. The root cause was **one** harness bug, not thirteen, and it was **not** in the consensus engine (unit tests + the dense fully-connected cases always proved classify/merge/release correct). It was in the test harness's `VirtualClock`:

- `VirtualClock.drainMicrotasks()` declared quiescence after `DRAIN_QUIET = 16` quiet microtask hops — a heuristic tuned for **discovery's** short (~2-5 hop) query chains. A consensus `update()` runs a *long* await chain (validate → merge → verify every signature → advance state → sign) and schedules its onward pushes only at the **very end**, far more than 16 hops after the delivery timer fired. So the drain gave up mid-`update`, `runUntilIdle` saw an empty heap, and exited **before the echo propagated** — every multi-hop commit/void stalled at `pending`. The dense fully-physical referee-set-of-two passed only by luck (many concurrent updates kept the heap non-empty). The determinism test failed because premature quiescence is interleaving-sensitive.
- **Fix:** the `Clock.setTimer` callback may now be **async** (`() => void | Promise<void>`). `VirtualClock.fire` tracks the returned promise in a `pending` counter and the drain never quiesces while a callback is in flight; the network's push callback returns the receiver's `update` promise. So the drain waits for each delivery to fully settle (and queue its own pushes) before firing the next. Discovery callbacks still return `void`, leave `pending` at 0, and are byte-for-byte unaffected (all 301 tests green, incl. discovery determinism). Touched: `src/clock.ts` (interface + realClock), `src/testing/clock.ts` (tracking + doc), `src/testing/network.ts` (push callback), `src/sequencing.test.ts` (mock-clock type).

## Use cases proven by the suite (your testing floor, not ceiling)

Each scenario asserts the headline invariant: **every node's `outcome` agrees**, `clock.pendingTimers === 0` at quiescence, `deliveryErrors === []`, and each resource double released **exactly once**.

- **Linear commit, 3/5/8 members** — all promise, sole referee votes C, commit diffuses back over link reachability to every node.
- **Refusal → void everywhere** — a participant whose gate declines signs `NP`; every node voids and releases as failure, nothing was ever held at the refuser, no `signature-rejected` (an `NP` is valid).
- **Referee no-commit → void everywhere.**
- **Circular lift** (ring A→B→C→A, A the sole referee) — commits and releases once at every node.
- **Dropped push, diamond** — the A—B arm is dropped; the record still reaches referee D over A→C→D; all commit, no double-release.
- **Dropped push, sole path → stall** — all `pending`, nobody releases, no false commit, no leaked timer.
- **Sleeping node** — a node reached only over a slow link; `advance(partial)` shows all `pending`, then `runUntilIdle` wakes it and the whole route commits.
- **Referee sets** — set of 1 commits; set of 2 both-C commits; set of 2 split (1 C / 1 NC) **stalls** (even split → no strict majority); set of 3 commits on 2 fast votes while the third is still asleep, then that one folds in.
- **Re-delivering a settled record** — a no-op, no second release.
- **Adversarial** — a post-commit equivocating referee (opposite face over the same promise set) is refused (`equivocation`), the settled commit stands, no re-release; a forged referee commit (corrupted byte) is dropped (`forged`), the genuine 2-of-3 majority still reads commit.

## What a reviewer should scrutinise (honest gaps)

- **Fire-and-forget convergence is hand-traced, not proven.** The claim "signature sets grow monotonically, so the echo terminates and every node converges" is argued in the `participant.push` doc and `network.ts` `makeUpdatePeer` doc, and the suite exercises linear/ring/diamond. It is **not** tested on larger or irregular topologies, nor fuzzed over delivery orderings. The strongest adversarial target: find a topology or `LinkCondition` ordering where the `sameSignatureSets` push-suppression skips an echo some node still needs, leaving it `pending` while others commit. The dropped-push and sleeping-node cases probe this but do not exhaust it.
- **The `VirtualClock` async-callback change is load-bearing for every consensus test.** Confirm it has not perturbed discovery: the whole point is that discovery callbacks return `void` (pending stays 0). Worth a skim of `discovery/*.test.ts` determinism expectations and the `pending`/`mutations` interplay in `fire`/`drainMicrotasks`.
- **`outcome()` role-independence.** It returns `pending` for an unseen record and for every non-terminal state. Confirm a pure relay (non-member, e.g. node X in the forgery test) classifies commit/void identically to a member — the forgery test is the only relay proof.
- **Latency vs. code-expiry constraint (a real, documented limit).** `buildLift` mints codes with the default 600_000 ms TTL at `clock.now()`. The sleeping-node / slow-referee tests use a 50_000 ms latency precisely so no code expires mid-run — an expired code makes the woken node sign `NP`/`NC` and would **void** the lift (a different outcome). This is noted in the `consensus.test.ts` header and `network.ts` `LiftSpec` doc. A test wanting a genuinely huge horizon must pass custom `sessionCodes` with `maxTtlMs: Infinity`. This is a constraint of the *tests*, not the engine.

## Tripwires recorded (NOT tickets — knowledge parked at the site)

1. **Forged-commit-before-promise-phase liveness edge** — `participant.ts` `mergeSignature`, the commit-retain branch (tagged `NOTE:`). A forged commit carrying a referee's `address` but a garbage `value`, arriving *before* the promise phase completes, is retained unverified, occupies that referee's commit slot, and the genuine vote is then refused as `equivocation` → the lift **stalls**. This is **safety-preserving** (the forged value never verifies, so `countVerifiedCommits` never counts it — no wrong settlement), which is all this ticket must prove. It is a liveness-only edge that `feat-tallynet-propagation-timeouts` would eventually void. Not reachable as an outcome *flip*, so not a filed defect. The network forgery tests deliberately stay on the clean safety cases so they don't trip it.
2. **Clock drain heuristic vs. discovery's void callbacks** — `testing/clock.ts`, `NOTE:` at `DRAIN_QUIET`. Only async (promise-returning) timer callbacks are `pending`-tracked and awaited unconditionally; discovery's callbacks return `void` and still rely on their whole query chain fitting inside 16 quiet hops. If discovery ever grows a longer `void` chain that under-drains, either have its timer callbacks return their promise (as consensus does) or raise `DRAIN_QUIET`.

## Review findings

- Convergence root cause (13/13 failures) was a **harness clock** bug, not the engine — fixed by async-callback tracking in `VirtualClock` (run-4 diff). See above.
- Tripwire #1 (liveness: forged-commit-before-promise stall, safety-preserving) parked as a `NOTE:` at `participant.ts` `mergeSignature`.
- Tripwire #2 (clock drain heuristic relies on discovery's short void chains) parked as a `NOTE:` at `testing/clock.ts` `DRAIN_QUIET`.
- Honest gap: fire-and-forget convergence is hand-traced + scenario-tested, not proven or fuzzed over arbitrary topologies/orderings — the prime adversarial target for this review.
