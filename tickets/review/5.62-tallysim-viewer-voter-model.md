## What landed

The tallysim-viewer now renders the **voter model** on top of the already-working consensus (sign-and-settle)
animation. "Voter model" = the lift's voting phase: members vote `C` (commit) / `NC` (no-commit), a member the
push could not reach can **recover by pulling** the outcome from a reachable peer, and misbehaviour
(equivocation, contradiction) is surfaced. All of it is driven by consensus trace events the prerequisite
milestone (`tallynet-record-pulled-event`, seq 5.61) added; this ticket maps those events to graph marks + a
side panel. The work is **headless + hand-built-fixture tested** — it builds on the trace *format* (landed), not
on the simulator actually producing voter-model traces yet.

### The change, module by module

- **`core/timeline.ts`** — `ConsensusState` gained four fields (all sorted/deduped, default `[]`): `voters`
  (`ConsensusVoter = { key; node?; role:'participant'|'referee'; vote? }`), `pulled`, `equivocators`,
  `contradictions` (each `number[]` of entity ids). `deriveConsensus`'s event loop was restructured from a
  single top-of-loop `resolveMember(nodeId)` to per-case resolution, adding `record-pulled`,
  `equivocation-proof-kept`, `contradiction-detected` cases and classifying `voter-vote`.
- **`app/theme.ts`** — three new palette roles (`pulled` indigo, `equivocator` magenta, `contradiction`
  purple), light + dark, interface + both palettes + role doc comment.
- **`replay/paint.ts`** — in `applyConsensus`, the three markers recolour settled nodes (via a new `markNode`
  that preserves the settled size). Off-route referee voters have no node → never painted.
- **`replay/routes.ts`** — new `liftVoterSummary(consensus)` → `{ participants, refereeOnlyCount, pulled,
  equivocators, contradictions }`. `liftOutcome(undefined)` still returns `stalled` (unchanged).
- **`replay/controls.ts`** — `renderLiftRoute` now renders the voter summary below the route; the outcome badge
  word `stalled` is displayed as **"unsettled"** (`outcomeWord`). DOM-only module (see gaps).
- **`docs/design.md` § Consensus phase** — added the voter-model rendering + the two documented format gaps.

## Use cases to validate (reviewer's floor, not ceiling)

**Pure-core (jest, hand-built fixtures) — the tested surface:**

- `timeline.test.ts` — an on-route `voter-vote` → `voters` role `participant` **and** a `voted` graph node;
  an off-route key → role `referee`, **no** graph node, and crucially **stays out of `unresolved`** (the key
  property: an off-route referee is a format gap, not a malformed event). `record-pulled` ok:true → `pulled`;
  all-failed pulls → not pulled. `equivocation-proof-kept.signer` → `equivocators`;
  `contradiction-detected.nodeId` → `contradictions`. Voter ordering (participants-first by id, referees by
  key) + re-vote dedup. The two whole-`ConsensusState` `.toEqual`s were updated with the new empty fields.
- `paint.test.ts` — pulled keeps its settled size while taking the accent; equivocator/contradiction accents;
  a "misbehaving wins over recovery" precedence case; a referee-only voter produces **no** graph key.
- `routes.test.ts` — `liftVoterSummary` participant/referee split, pull/equiv/contra passthrough, all-empty.

**Worth an adversarial look:**

- **The `unresolved` discipline.** The whole point of the voter classification is that off-route voters must
  **not** pollute `unresolved` (reserved as a malformed-trace sentinel). Confirm `voter-vote` uses
  `resolver.entityOfMember` **directly**, while `record-pushed` still uses the polluting `resolveMember` (the
  pre-existing `badKey` test at `timeline.test.ts` must stay green — it does).
- **Edge cases from the ticket, as rendered:** linear lift with an interior non-relayer — *with* contact points
  the far member recovers (`pulled` mark), *without* it stays `promised`/stuck-pending (greyed, not errored);
  circular lift routing around a refuser (route `loop`, settles, no pull); equivocating voter (marked, settled
  `decision` shows which face won); tie/no-settlement → **"unsettled"**, never a spinner. These are the
  *observable-consequence* framing — the format carries no per-member contact-point flag.

## Known gaps / honest flags (treat the tests as a floor)

- **`controls.ts` is NOT jest-tested** — it touches `document`, so (per its own module contract) its gate is
  `vite build` + a manual check, same as the renderer. The new voter-summary DOM (`renderVoterSummary`), the
  `stalled`→"unsettled" label mapping, and the signature fingerprint are **type-checked only** — no runtime
  assertion. The underlying *logic* (`liftVoterSummary`, `liftOutcome`) is pure and tested in `routes.test.ts`.
  **A manual click-through has NOT been run** (no real voter-model trace fixture exists yet). If a reviewer
  wants eyes-on, it needs a hand-built v2 consensus trace with voter/pull/equiv events loaded in the browser.
- **Palette colours are hand-picked, not run through the data-viz validator.** They are chosen distinct from the
  existing roles and from each other, and — like the existing committed/void triad — each is backed by the side
  panel's per-member **text**, so colour is never the sole channel even where two marks co-occur. A reviewer
  with the `dataviz` palette validator could double-check CVD separation of the pulled/equivocator/contradiction
  trio on both surfaces; I asserted the hex values in tests but not their perceptual separation.
- **Design decision worth a second opinion:** `record-pulled`, `equivocation-proof-kept`, and
  `contradiction-detected` resolve their member key through the *polluting* `resolveMember` (so an unresolvable
  key lands in `unresolved`), on the assumption those keys are **always route members** (they are, in the
  current format — pullers/signers/detectors sit on the route). Only `voter-vote` is exempted, because only
  voters can legitimately be off-route. If a future simulator ever emits an off-route equivocator/detector, it
  would surface in `unresolved`. Documented inline; flagged here as a deliberate choice, not an oversight.
- **No new trace fields, no format bump** — everything round-trips through the existing `serializeTraceLine`.
  The headless/WebGL smoke coverage (`debt-tallysim-viewer-headless-webgl-smoke`) is untouched.

## Not in scope (documented format gaps, not bugs)

Off-route **referee** voters and the **nominator links** that produced them are not carried into the lift
record (a simulator-side gap, tracked as `debt-voter-nomination-on-path-composition`), so all placeable voters
are route participants; a referee is **counted** ("+N referee-only voters (stacked)"), never drawn, and
nominator links are not shown. **Per-member contact points** are likewise not in the format, so "settles vs
stalls on a linear lift with a refuser" is shown as its observable consequence (pull-recovered vs
stuck-pending), not a per-member flag. Both are documented in `docs/design.md` § Consensus phase.
