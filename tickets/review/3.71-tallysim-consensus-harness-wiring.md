This is the implement→review handoff for Phase 1 of the former `tallysim-consensus-core` work (the
mechanism only; nothing drives an end-to-end *payment* lift yet — that is the sibling ticket
`tallysim-consensus-drive-settle`, which has `prereq: tallysim-consensus-harness-wiring` and builds on
exactly what landed here). Treat the code as a starting point and the tests as a floor.

## What was built

**1. `tallynet` harness — exact-link `routeLinkIds` (`testing/network.ts`).**
`LiftSpec` gained an optional `routeLinkIds?: string[]` — one exact graph link id per **route** hop, in
order, length `route.length - 1`. `buildLift` throws on a length mismatch, then passes `routeLinkIds[i]` to
`addLiftLink` for each route pair (`extraLinks` always pass `undefined`). `addLiftLink(..., linkId?)` now
resolves the edge by `candidate.id === linkId && candidate.neighbour === b` when a `linkId` is given (the
neighbour check is kept, so a stale/foreign id throws a clear error), else the prior first-neighbour `.find`.
This fixes mis-selection when **parallel tallies** exist between the same node pair — the old `.find(c =>
c.neighbour === b)` always picked the first edge. Nonce derivation and everything downstream are unchanged.

**2. `tallysim` deterministic identity (`sim/identity.ts`).**
`makeSimSigner(identitySeed, name)` = `secret = nobleHasher.sha256(TextEncoder().encode("<seed>:<name>"))`,
`publicKey = ed25519.getPublicKey(secret)`, `sign = ed25519.sign(digest, secret)` — a byte-for-byte mirror of
the exemplar in `tallynet/testing/consensus.test.ts`. `signerForSeed(identitySeed)` is the per-node factory
`InMemoryNetwork` takes; `simVerifier` wraps `ed25519.verify` try/catch → `false`. Keys derive from the
`(identitySeed, name)` pair directly — a **dedicated** seed stream, never a shared RNG whose draw order could
shift and rebind keys. `@noble/curves@^2.4.0` was added to tallysim `dependencies` (it was a tallynet
devDep only; already hoisted at the repo root).

**3. `tallysim` failure-injecting resource port (`sim/consensus-resource.ts`).**
`makeSimResources(specs: Record<number, SimResourceSpec>)` → `{ resourceFor, handles }`, keyed by **entity
id** (the sim's native id, not the node name). Lazily mints one handle per id (default spec `{}` =
cooperative). `SimResourceSpec` = `{ shouldPromise?, promiseThrows?, shouldCommit? }`. Each handle records
`promiseCtxs` (holds seen) and `releaseSuccesses` (`[true]`=committed once, `[false]`=voided once, `[]`=never
released) — the same observation contract as the tallynet exemplar's doubles.

**4. `buildSimNetwork` consensus opt-in (`sim/harness.ts`).**
Added a 6th optional param `consensus?: ConsensusConfig` (`{ identitySeed, resourceFor? }`). When present, a
module helper `consensusPorts()` passes `signerFor: signerForSeed(identitySeed)`, `verifier: simVerifier`, and
(iff `consensus.resourceFor`) an **entity-id→name adapted** `resourceFor`. When absent it returns `{}` so the
discovery-only config is byte-for-byte unchanged (the pinned discovery sweep is untouched). The shared
adjacency link terms were **not** altered.

**5. Supporting.** `sim/index.ts` re-exports the two new modules; `packages/tallysim/src/globals.d.ts` was
added (mirrors `tallynet/src/globals.d.ts`) to type `TextEncoder` for the neutral build (`lib: ES2022`,
`types: []` — `TextEncoder` is otherwise untyped there); `packages/tallynet/docs/design.md` § Testing approach
notes the `routeLinkIds` convenience (harness-only, not a protocol change).

## How to exercise it (tests = the floor)

- `packages/tallynet/src/testing/consensus.test.ts` → `describe('buildLift — routeLinkIds disambiguates
  parallel tallies')`: two parallel A–B edges with distinct terms; `routeLinkIds: ['ab2']` selects ab2 (not
  the first ab1); default selects ab1; length-mismatch throws; a non-matching id throws. The **existing**
  consensus suite (all 320 tallynet tests) is the regression floor for the `addLiftLink` change.
- `sim/identity.test.ts` — same `(seed,name)` ⇒ same key; distinct names/seeds ⇒ distinct keys; 32-byte key;
  sign verifies against own key and fails against another; `simVerifier` returns `false` (no throw) on
  garbage; `signerForSeed` binds the seed.
- `sim/consensus-resource.test.ts` — lazy per-id minting + instance reuse; default has no gate hooks;
  promise/release recording; `shouldPromise:false` / `shouldCommit:false` gates return `false`;
  `promiseThrows:true` throws and holds nothing; specs keyed by entity id.
- `sim/consensus-harness.test.ts` — the wiring proof: (a) no consensus config ⇒ `consensusNode` throws
  "consensus is not configured"; (b) `consensus: { identitySeed: 7 }` + a hand-built lift over a cooperative
  3-node line (`route ['0','1','2']`, `routeLinkIds ['T0','T1']`, string payload `{ amount: '5' }`) commits at
  every node, `deliveryErrors === []`, `pendingTimers === 0`; (c) a `shouldPromise:false` resource on entity 1
  voids the whole route and proves the entity-id→name adaptation; (d) same `identitySeed` ⇒ same `memberKey`,
  a different seed ⇒ a different key.

## Known gaps / where to look hard (reviewer, scrutinize these)

- **Finite-capacity smoke test by design.** The smoke test uses finite credit limits. A lift over an
  **unlimited** (`Infinity`) credit limit still throws at signing today: `recordDigest` canonical-encodes the
  link intents and DAG-CBOR rejects non-finite numbers. This is the known `[[lift-record-no-infinity-terms]]`
  finding; the parent ticket's "never serialised here" claim was **wrong**. The fix (sanitise a lift record's
  link intents to CBOR-safe finite values before `start`) is the **sibling ticket's** job, not this one — but
  confirm nothing here accidentally depends on it working, and that the smoke network truly has finite limits.
- **End-to-end coverage of the failure modes is partial here.** Only `shouldPromise:false` is driven through
  the real engine in this ticket (the void-route test). `promiseThrows:true` and `shouldCommit:false` are
  unit-tested at the factory level but not end-to-end — the sibling ticket owns the full behavioural matrix
  (refusal/void/stall under crooked peers). Check the factory semantics are right so the sibling inherits a
  sound base (esp. `promiseThrows` recording *nothing* in `promiseCtxs`).
- **New ambient-globals file.** `packages/tallysim/src/globals.d.ts` is a new file in a package that had
  deliberately avoided one (see `trace-writer.ts`'s hand-rolled UTF-8 length). It mirrors tallynet's precedent
  and the `no-node-globals` guard scans and passes it. Confirm you are comfortable with that choice vs. a
  manual ASCII encoder — the inputs are always ASCII (`<number>:<digits>`), so either is byte-equivalent.
- **Entity-id→name adaptation seam.** `consensusPorts()` adapts an entity-id-keyed `resourceFor` to the
  harness's name-keyed port via `entityId(name)`. `entityName`/`entityId` are `String(id)` / `Number(name)`;
  a node name that is not a decimal id would map to `NaN`. All sim node names are decimal ids, so this is
  safe today — worth a glance that no caller passes a non-numeric name.
- **`routeLinkIds` neighbour check.** A supplied `linkId` must match both the id and the neighbour, else it
  throws (tested). Confirm the error messages are clear and the `extraLinks` fallback path is genuinely
  unchanged.

No tripwires were parked in code for this ticket (the one conditional concern — unlimited-capacity signing —
is a real latent defect tracked for the sibling ticket, not a tripwire).
