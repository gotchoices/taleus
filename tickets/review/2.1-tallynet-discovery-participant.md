## What this delivers

The participant half of unidirectional (route) discovery in `tallynet` — the logic that runs at
**every node a query passes through** (the originator side and end-to-end wiring are a later
ticket). It is a port of ChipNet's `unidirectional/participant.ts` with every defect from
`docs/chipnet-review.md` § *Discovery defects* fixed. The data model, hooks, and durable/in-flight
store split were written in a prior run (build verified green, no tests). **This run added the full
test suite, re-verified build/test/lint, and fixed four real serialisability defects the tests
surfaced** (see *Deviations* below).

Surface (all re-exported from `src/discovery/index.ts` → `src/index.ts`):

- **`types.ts`** — data model, generic over `TTerms` (host link terms) and `TPayload` (host value
  carried end-to-end). `Address` (key-only), `Member`/`IdentifiedMember`/`DependentMember`, `Link`,
  `Plan`, `Target`, `UniQuery` (carries authoritative `maxDepth`), `Reentrance`, `QueryStats`,
  `QueryRequest`/`QueryResponse` (`budgetMs`), `PrivateLink`/`Match`/`PeerMatch`/`FindResult`,
  `QueryPeerFunc`/`FindAddressFunc`, `appendPath`, `addressesMatch`.
- **`hooks.ts`** — `DiscoveryHooks` (`negotiateIntent` with hop context, per-plan `planSatisfies`,
  optional `annotateReturn`, optional `negotiatePlan`) + `defaultHooks` (single-unit behaviour).
- **`store.ts`** — `StoredCandidate`, `StoredContext`, `ParticipantStore`, `contextKey` (the single
  NUL-delimited key used by validate/get/save — the fix for ChipNet's nesting bug), and
  `MemoryParticipantStore`.
- **`participant.ts`** — `Participant` class: in-flight `Map` (non-durable), `query` → `enter` /
  `reenter`, candidate negotiation, budgeted fan-out, harvest/fold/prune, conclusion paths,
  `prependMatch`.

## How to exercise / validate it

Build + test + lint (all green as handed off):

```
yarn workspace tallynet build && yarn workspace tallynet test && yarn workspace tallynet lint
```

The two new test files are the **floor**, not the ceiling — treat them as a starting point:

- **`store.test.ts`** — `StoredContext` round-trips through both `JSON.stringify`/parse **and**
  DAG-CBOR `canonicalEncode`/`digest` (proving it holds no function/promise/class instance); the
  single-key invariant across `validateNewQuery`/`getContext`/`saveContext` (duplicate rejected,
  same-session-different-path allowed, different-session-same-path independent); `contextKey`
  non-collision; `getNonceToLinkMap` unions within a session and excludes others.
- **`participant.test.ts`** (24 tests, one per defect/edge, each fails on a naive port) — self is
  the target (returns the self plan + one per matching peer link); target is a direct peer
  (peer-match at depth 1 with `[self, target]` members); **cycle** candidate removed and never
  re-queried; **failed** sub-query pruned; duplicate first visit rejected; same-session/different-
  path allowed; inbound-nonce/plan-tail/empty-plan validation (errors disclose **no** link id);
  **real budget** honoured (round ends at `budgetMs`, not the old hard-coded 1000, with a
  `round-budget-expired` trace; driven by fake timers); **no leaked timers**; **late answer** from a
  sleeping peer folded next round (`late-answer-folded`); session **expired** mid-search; session
  mismatch; **max-depth** conclusion; target unreachable (plans empty, reentrance only while
  candidates remain, never throws); **stray `sessionCode`** absent from returned plans + they
  canonical-encode; payload rides a plan and stays encodable; **live Pending never reaches the
  store** (every save is `canonicalEncode`-checked in a spy store); **participant restart** between
  rounds (new instance, same store, empty in-flight table → re-issues from durable `lastResponse`,
  no plan lost or double-counted); concurrent sessions keep independent contexts. The suite runs on
  the `realClock` under jest fake timers; `afterEach` asserts `jest.getTimerCount() === 0` for every
  test.

## Deviations & known gaps the reviewer should scrutinise

**New this run — four serialisability fixes (the tests surfaced these; they are real, not cosmetic):**
The engine was emitting `undefined`-valued optional keys (`plans: undefined`, `payload: undefined`,
`reentrance: undefined`) into `StoredContext`, `Plan`, and `QueryResponse`. `JSON.stringify` silently
drops those, but DAG-CBOR `canonicalEncode` (the canonical wire/digest encoding, `digest.ts`
`assertEncodable`) **throws** on an `undefined`-valued key — so any context with no accumulated
plans, or any plan with no host payload (the common case), was **not** persistable by a SQL-backed
store, defeating the module's whole durable/in-flight premise. Fixed by omitting those keys via
conditional construction (matching the existing `prependMatch` style) at four sites in
`participant.ts`: `createContext`, `foldPlans`, `buildMatchPlans` (self + peer), and `makeResponse`.
**Worth a close look:** confirm no consumer relied on the key being present-but-undefined (none in
this package; all read sites use optional access / `?? []`), and that this is the right layer for
the fix versus stripping at the store/transport boundary.

**Carried from the prior run (still true):**
- `negotiatePlan` lives only in `DiscoveryHooks`, not in `ParticipantOptions` (one home for
  negotiation; DRY). `ParticipantOptions` is `{ maxQueryAgeMs, maxDepth, minSessionMs }`.
- `annotateReturn` runs at **both** `enter` (self/peer-match plans) and `reenter` (sub-query plans)
  — everywhere this node prepends itself.
- **Accumulate-and-dedupe plan model.** `context.plans` is the node's durable concluding set (self
  already prepended), deduped by path-nonce via `planKey`; the durable per-candidate `lastResponse`
  is the single source of truth, the in-flight table only an optimisation. `planKey` dedupes by
  **path alone** — there is a `NOTE:` tripwire at the function (`participant.ts`) for the day two
  plans share a path but differ in members/payload (fine for single-denomination v1).
- **Prune-reason map:** `cycle` at enter; `failed` (errored) and `no-reentrance` (completed, no
  reentrance) per round; `max-depth` on the depth ceiling; `expired` on a bad reentrance ticket;
  `timed-out` for still-outstanding candidates when concluding on satisfaction. Sleeping peers are
  **kept** across rounds (so late folding works), never pruned mid-search.
- `maxDepth` **concludes** (no throw) when `context.depth >= query.maxDepth` (depth = 1 after enter,
  +1 per advancing reenter). ChipNet threw.
- **`random` (`RandomSource`) is accepted but unused** — the participant's logic is deterministic
  (candidates sorted by nonce). Held for the engine/tie-breaking. Confirm this is acceptable or that
  it should be wired where a seed is genuinely needed.

**Gaps / things not covered (floor, not ceiling):**
- The `Session code mismatch` branch in `validateQueryState` is **unreachable with the default
  store** (`MemoryParticipantStore` keys by `query.sessionCode`, so a lookup under session B never
  returns a context whose stored session is A). It is tested via a hand-built stub store that
  returns a mismatched context — i.e. the test proves the branch's logic, not a real store path. A
  reviewer may judge whether the defensive branch earns its keep.
- `maxQueryAgeMs` is declared but **not enforced** (ChipNet declared-but-unused too) — reentrance
  age is not yet bounded. Intentional per the field's doc comment; flag if the engine ticket needs
  it sooner.
- Tests drive a **single node** over stub `findAddress`/`queryPeer`; there is no multi-hop
  integration test here (that belongs with the originator/engine ticket, which has ChipNet's 6-node
  happy path to port). Multi-node interaction, real transport framing, and the originator's budget
  accounting are unverified by this ticket.
- No property/fuzz testing of `prependMatch` member-upgrade merging or of deep candidate graphs;
  coverage is example-based.
