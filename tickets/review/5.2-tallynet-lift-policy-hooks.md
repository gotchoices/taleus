# Review: tallynet lift policy hooks

Adds the four decision points principle 0 ("no global rules; each node decides") needs for the voter
model, plus a way for the payer to score the routes a search returns. TallyNet stays policy-free: the
protocol enforces only verified signatures, the strict-majority+threshold invariant and (later) the
deadline. All "which voter set / method / contract do I accept" judgment lives in host hooks that
default to today's permissive behaviour.

**Gate = green.** `yarn build`, `yarn test` (21 suites, 347 tests), `yarn lint` all pass from
`packages/tallynet`. No `.pre-existing-error.md` written (nothing pre-existing surfaced).

## What landed (the four decision points)

| Point | Phase | Mechanism | Change |
|---|---|---|---|
| Accept the record's voter set / method / contract | promise | **new** `acceptsProposal(ctx)` on `TrxParticipantResource` | added |
| Accept the search's method / contract | discovery `enter` | **new** `acceptsQuery(query)` on `DiscoveryHooks` | added |
| Refuse a plan by its voter-set-so-far | discovery return trip | **existing** `negotiatePlan(plan)` (already returns `Plan \| undefined`) | documented |
| Rank / choose among returned plans | originator | **new** `scorePlan(plan, query)` on `OriginatorConfig` | added |

### 1. `acceptsProposal` (promise-time resource gate) — `consensus/resource.ts`, `consensus/participant.ts`
- New optional hook, runs **first** at promise time (only an expired code refuses ahead of it), before
  `shouldPromise`. `false` **or a throw** → sign `NP` (which voids the lift); default accept.
- `castPromise` was refactored to a new `promiseDecision(record, ctx)` that encodes the ordering
  **expiry → acceptsProposal → shouldPromise → promise**. The first `false`/throw from either gate, or
  a throwing hold, signs `NP` and holds nothing.
- **Deliberate refinement to flag:** a *throwing* gate is now **caught → NP** (logged). Previously a
  throwing `shouldPromise` propagated out of `castPromise`. No existing test made a gate throw, so this
  changed no behaviour under test — but a reviewer should confirm no caller depended on that throw
  propagating. Rationale: a declined promise must never leave value held nor crash the state machine.
- The shared `ResourceContext` already exposed everything needed (voter set via
  `ctx.record.topology.members`, method via `ctx.record.method`, deadline via `expiresAt(...)`,
  contract CID via `ctx.record.liftContract`, our edge terms via `inLinks`/`outLinks`) — so the only
  new surface here is the gate itself plus docs.

### 2. `acceptsQuery` (discovery `enter` gate) — `discovery/hooks.ts`, `discovery/participant.ts`
- New optional **synchronous** hook (the other discovery hooks are sync). `false` → the node answers an
  **empty response (no plans, no reentrance), never a throw**; upstream prunes it `no-reentrance`.
- Gated at `enter` only (after the `query-received` trace, before `createContext`). `reenter` has no
  access to the full query — only the stored context — and a refused node never builds one, so there is
  nothing to gate there. A node that accepts at `enter` participates for the whole fixed-per-search query.
- Added to `defaultHooks()` as `() => true`.

### 3. `negotiatePlan` (return-trip voter-set refusal) — `discovery/hooks.ts` (doc only)
- Already functional (`returnPlan` honours an `undefined` return by dropping that one plan). This ticket
  only rewrote the doc to spell out that `plan.members` is the **voters-so-far** (partial during the
  search) and that returning `undefined` is how a node refuses a plan whose voter set it rejects.

### 4. `scorePlan` (originator ranking) — `discovery/originator.ts`, `discovery/engine.ts`, `testing/network.ts`
- New optional `OriginatorConfig` field (threaded through `DiscoveryNodeDeps` → `UniOriginator`).
  **Deliberately NOT a `DiscoveryHooks` entry** — it never crosses a hop; it is originator-only.
- Default `defaultScorePlan`: **fewer voters, then shorter path, then first-found**, as one scalar
  `-(voters + hops/(maxDepth+1))`. Higher = better.
- In `discover`, the satisfying plans of the first round that finds any are ranked (`rankPlans`):
  score each, **drop any whose score is not `> -Infinity`** (drops `-Infinity` *and* `NaN`; `+Infinity`
  passes), sort descending with an explicit original-index tiebreak (first-found wins ties). The result
  `plans` come back **best-first — winner at `plans[0]`, passed-over routes after** — which is how a
  sim/viewer reads which plan won without any `trace.ts` change (trace.ts was out of scope). All plans
  rejected ⇒ empty `plans`, no throw.
- **No keep-searching-on-all-rejected logic** was added (that would be a retry policy the ticket
  forbids baking in): the loop still stops the round it first finds satisfying plans; scoring ranks/drops
  within that set.

## How to exercise / validate it

Primary driver is the unit suite — run `yarn test` from `packages/tallynet`. The new cases:

- **`src/consensus/participant.test.ts`** → `describe('TrxParticipant — promise phase')`:
  - `acceptsProposal=false` signs `NP` **before** `shouldPromise` is consulted (ordering proof), holds
    nothing, voids.
  - a **throwing** `acceptsProposal` signs `NP`, logs, voids, and short-circuits `shouldPromise`.
  - an accepted proposal consults both gates in order then holds, signing `P`.
  - Harness: `makeResource({ acceptsProposal, proposalThrows, shouldPromise })` + an
    `acceptsProposalCtxs` recorder on the resource double.
- **`src/testing/consensus.test.ts`** → `describe('a refusal voids the whole route')`: a **middle**
  participant with `acceptsProposal:false` voids the whole linear route (every node releases once as a
  void; no `signature-rejected` — an `NP` is a valid signature). Mirrors the existing
  `shouldPromise:false` void test.
- **`src/testing/discovery.test.ts`** → `describe('voter-model policy hooks')`:
  - default `scorePlan` ranks a **lean** voter set ahead of a **stacked** one on a symmetric diamond
    (both 2 hops; a per-node hooks factory staples extra `V` members onto one arm) — winner at `plans[0]`.
  - a `scorePlan` returning `-Infinity` for all plans yields `plans == []` with no throw (a baseline run
    confirms the route IS found without it).
  - `acceptsQuery:false` at the sole intermediate node drops the only route (a control run confirms it is
    found when the node accepts).
  - `negotiatePlan` returning `undefined` for a plan carrying a rejected voter drops **just that plan**,
    leaving the lean sibling route.
  - Harness wiring: `InMemoryNetworkConfig.scorePlan` (one scorer for all nodes — see gap below) and
    `config.hooks` now also accepts a `(nodeId) => DiscoveryHooks` factory in the discovery test's `makeNet`.

## Gaps & things to probe (treat tests as a floor)

- **Harness `scorePlan` is one scorer for all nodes, not a per-node factory.** A `ScorePlan` is itself a
  function, so a factory could not be told apart from a scorer at runtime (the same ambiguity `trace`
  has on `InMemoryNetworkConfig`). Fine for the tests (one node originates per `discover`), but a future
  test needing distinct scorers per originator would have to add an unambiguous wrapper.
- **`defaultScorePlan`'s single-scalar domination relies on the `maxDepth` invariant.** The hop penalty
  is `hops/(maxDepth+1)`, which stays `< 1` only because a returned plan's `path.length <= maxDepth`
  (the discovery invariant asserted in `discovery.test.ts`). If that invariant were ever broken, "fewer
  voters strictly dominates shorter path" could invert. It can't trip today; the reasoning is in the
  function's doc. Not filed as a ticket (genuinely conditional, and currently impossible).
- **The discovery scoring/refusal tests use *synthetic* `V` members** stapled on by a hooks factory —
  they exercise the discovery layer's counting/ranking/dropping, not an actual consensus settlement with
  those voters. End-to-end "a stacked set actually votes and settles" is covered separately by the
  consensus suite + `tallysim-voter-model`, not here.
- **The `negotiatePlan`-drop test rejects at the originator** (the originator applies its own
  `negotiatePlan` when folding returned plans). That is real behaviour but a slightly indirect path; a
  reviewer may want an added case where a *non-originator* intermediate drops a plan by voter set.
- **Caught-gate-throw refinement** (see §1) — the one behavioural change to an existing code path worth a
  second look.

## Out of scope (left as seams, per the design)
- `trace.ts` untouched — the winner is surfaced by result ordering (`plans[0]`) + docs, not a new event.
- No retry/keep-searching policy on all-rejected rounds.
- Adaptive budget, deadline-as-explicit-field, multi-path lift — all still their own backlog/tickets.
