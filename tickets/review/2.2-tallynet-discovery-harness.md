## What shipped

Four shipped modules under `packages/tallynet/src/testing/`, built alongside `src/` and exported behind the new `"./testing"` subpath in `package.json` (so `tallysim` and the viewer import `tallynet/testing`). They are **not** re-exported from the main `src/index.ts` barrel — `testing` is a separate subpath by design.

- **`clock.ts` — `VirtualClock implements Clock`.** Simulated time; `now()` moves only when a timer fires. Binary min-heap keyed `(time asc, seq asc)` with `seq` a monotonic insertion counter (the tie-break). `clearTimer` is lazy deletion (marks `cancelled`; the heap skips it on pop). `advance(ms)` / `runUntilIdle(maxSteps?)` drive the queue. The crux is the **microtask drain** between fires: a `mutations` counter bumps on every setTimer / clearTimer-of-a-live-timer / fire, and `drainMicrotasks` yields until that counter is unchanged for `DRAIN_QUIET = 16` consecutive hops — so every timer a just-fired promise continuation will schedule is queued before the next fire, and virtual time never advances out of order. Read the class doc for why clears (not just new timers) must be counted (the `budgetedStep` early-clear cascade).
- **`random.ts` — `SeededRandom implements RandomSource`.** mulberry32 (`Math.imul` only, no `Math.random`). `randomBytes(n)` reproducible per seed; also `nextFloat()` / `nextInt(maxExclusive)` for the graph generator. Seeds a non-zero constant when `seed === 0`.
- **`network.ts` — `InMemoryNetwork<TTerms,TPayload>` + `randomGraph` + `negateNumericTerms`.** One `DiscoveryNode` per graph node (own `MemoryParticipantStore` each), all sharing one clock and one random. Adjacency + a per-node `linkId → neighbour` lookup are precomputed in the constructor, so `findAddress`/`queryPeer` cost is O(degree), never O(total nodes).
- **`index.ts`** — the subpath barrel.

## How to exercise it (use cases for review)

The driving pattern — **nothing progresses until the clock is driven**, because the search awaits virtual timers:

```ts
const net = new InMemoryNetwork<Terms, string>({ graph, clock: new VirtualClock(), random: new SeededRandom(7) })
const resultP = net.discover('A', { address: { key: 'C' } }, { L: { balance: 50 } })
await net.clock.runUntilIdle()     // fires every delivery + budget timer, in order
const { plans } = await resultP
```

Key behaviours worth probing:

- **Shared link ids are intentional.** A link `{ id, node1, node2, intents }` uses the **same id from both endpoints**; terms are inverted for the `node2→node1` view. Because `makeNonce(session, linkId)` is identical at both ends, the participant's cycle check fires on the back-link automatically. Confirm this is sound, not a shortcut (it mirrors ChipNet and the `nonce.ts` design).
- **Three link knobs** via `conditions` (map or function): `latencyMs` (request-leg delay — a latency larger than a round's budget makes the answer fold into a later round), `drop: true` (a never-resolving delivery; no timer armed → pruned at max-depth), and "sleeping node wakes late" = just a finite `latencyMs` spanning rounds.
- **Determinism**: session codes drawn at `discover()` call time in call order; concurrent originators keep independent stores. Same seed + same graph ⇒ identical run.

## Tests written (the floor)

- `clock.test.ts`: `(time, seq)` fire order; insertion-order tie-break reproducible across runs; a timer scheduled by a firing timer fires later; cleared/foreign/undefined handles; `advance` fires the budget; `runUntilIdle` drives a `budgetedStep` to completion and leaves `pendingTimers === 0` (no leaked budget timer); the `maxSteps` guard throws on a self-rescheduling timer.
- `random.test.ts`: same-seed byte stream; divergence across seeds; long-stream reproducibility; `randomBytes(0)` empty; length and bound validation; seed-0 non-degeneracy; `nextInt`/`nextFloat` range.
- `network.test.ts`: one node per graph node; a direct `node('A').query(entrance)` reaches a neighbour over the shared link id (path nonce = `makeNonce(session, 'L0')`, neighbour a member); a linkId with no neighbour → **rejected** sub-query (not a crash); numeric-balance inversion on the reverse view; and one driven **one-hop discovery** (A→B→C) that completes on the virtual clock and leaves no live timers.
- The existing `no-node-globals.test.ts` scans `src/` recursively and now covers `src/testing/` — the harness passes it (no `setTimeout`/`Date.now`/`Math.random`/`Buffer`/`node:` imports; `Math.imul` and `Promise.resolve` are permitted).

## Review-handoff honesty — known gaps & deviations

**Gaps (coverage floor, not ceiling):**
- `network.test.ts` is **wiring-only** plus a single one-hop discovery smoke. The real stress — latency folding a late answer into a later round, `drop` pruned at max-depth, multi-path dedupe, the **1,000-node seeded scale test** — is deliberately the sibling `tallynet-discovery` ticket's job. The heap + drain are **built** for scale but **unproven at 1,000 nodes** in this ticket. If the reviewer wants one scale assertion here before the sibling lands, that is a reasonable ask.
- The `drop` (never-resolving) and `latencyMs` (late-fold) code paths exist and are documented but are **not asserted** at harness level here — only the basic instant-delivery hop is.

**Deviations from the ticket's API sketch (all intentional, flag if unwanted):**
- **`trace` is a single shared `TraceSink`, not `TraceSink | ((nodeId)=>TraceSink)`.** A `TraceSink` is itself a function, so a per-node factory cannot be told apart from a sink at runtime (`typeof` can't disambiguate). Every `TraceEvent` already carries `nodeId`, so a shared sink switching on `event.nodeId` gives per-node behaviour without the ambiguity. (`hooks` keeps the object-or-factory union — an object is distinguishable from a function.)
- **Added `hasher?: Hasher` to the config** (default `nobleHasher`). `DiscoveryNode` requires a hasher; the sketch omitted it. One shared hasher so both ends of a link agree on nonces.
- **Added `InMemoryNetwork.deliver(from, request, linkId)`** — the raw single-hop delivery primitive (what a node's wired `queryPeer` uses), exposed so a test can exercise the no-neighbour rejection directly and for the sibling ticket to probe one hop.
- **Added `VirtualClock.pendingTimers` getter** (diagnostic; counts live timers) for leak assertions.
- **Added a self-reschedule guard to `advance`** (throws past `DEFAULT_MAX_STEPS`), symmetric with `runUntilIdle`; not in the spec but defensive against an infinite same-instant reschedule.

**Tripwires (recorded in-code; listed here as the index, not re-analysed):**
- `DRAIN_QUIET = 16` is a **margin'd guess** (gap between a fire and its consequent mutations is ~2–5 hops here). If a future deeper promise chain under-drains, raise it or switch to an explicit quiescence signal — noted at the constant in `clock.ts`.
- **Duplicate link ids** across the graph: `linkLookup` keeps the last (the same id on both endpoints does *not* collide — it is keyed by node *and* id). `NOTE:` comment at the site in `network.ts`; revisit only if parallel edges sharing an id are ever modelled.
- Term inversion defaults to **identity**; `negateNumericTerms` (the `{ balance }` case) is opt-in via `invertTerms`.

**Observation for the reviewer (belongs to the sibling, not this ticket):** `src/discovery/index.ts` exports `types`/`hooks`/`store`/`participant` but **not** `engine`/`originator`, so `DiscoveryNode`, `DiscoveryResult`, and `OriginatorOptions` are not reachable from the main `tallynet` package barrel. This harness imports them directly from their module files, so it is unaffected and `.d.ts` emission is fine — but a consumer of plain `tallynet` cannot name `DiscoveryNode`. That looks like a loose end in the sibling `tallynet-discovery` (engine) work; worth a glance there rather than a fix here.
