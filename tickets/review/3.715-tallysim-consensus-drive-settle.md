## What landed

The consensus phase of the discovery+consensus simulation. After discovery returns `QueryOutcome.plans`,
the simulator now picks one plan, drives the real `tallynet` promise/commit engine over that exact route on
the virtual clock, reads whether it **committed / voided / stalled (`pending`)**, and — on commit — moves
each tally's balance along the route so the next query sees the changed capacity.

The `tallynet` consensus engine and the `buildSimNetwork` consensus opt-in were **already wired** by the
prereq (`tallysim-consensus-harness-wiring`). This ticket composes that wiring into one call and adds the
plan-pick, route-reconstruction, money-movement, and clone helpers around it.

### New / changed modules

- **`sim/plan-select.ts`** (new) — `selectPlan(plans, policy='shortest')`. `PlanPolicy` is an open type;
  only `shortest` ships (fewest `path.length`, ties → first-found via strict `<`). Empty ⇒ `undefined`.
- **`sim/route.ts`** (new) — `reconstructRoute(network, sessionCode, from, plan) → { tallyPath, route }`.
  Inverts the plan's anonymised edge nonces back to concrete tallies (recompute `makeNonce(sessionCode,
  linkIdForTally(i))` per tally, walk from `from` across `{stock, foil}`). **Throws** on an unresolvable
  nonce or non-contiguous walk (the viewer's `deanonymise.ts` returns a sentinel for the same case; here the
  sim built the network, so either is a bug).
- **`sim/consensus-harness.ts`** (new) — `runLiftForOutcome(sim, network, outcome, q, options?) →
  LiftResult | undefined`. Assembles a `LiftSpec` (members = distinct route entities as `['P']`; voter set
  default `[route[0]]` adds `['R']`; `routeLinkIds` from `tallyPath`; reuse `outcome.sessionCode`; string
  payload), **sanitises link intents to finite values before signing** (DAG-CBOR throws on the `Infinity`
  an `unlimited` tally carries), drives the lift, reads the outcome, and moves money on commit. Returns
  `undefined` when there is no plan (phase skipped).
- **`capacity.ts`** — added `applyLiftToBalance(tally, fromIsStock, amount)`: `b += fromIsStock ? -amount :
  amount`. The directed inverse of the `cap(S→F)` / `cap(F→S)` formulas.
- **`model.ts`** — added `cloneNetwork(network)` (shallow-clone tallies + meta/params; `Infinity` copies
  fine) so a caller that holds a `materialized`-by-reference network can run mutating lifts without
  contaminating the next run.
- **`sim/index.ts`** — exports the three new sim modules.
- **`docs/design.md`** — new **Consensus simulation** section (plan-pick, route reconstruction, the lift
  drive, the CBOR-safe-intents note, balance-movement + conservation, the rebuild-to-see-capacity note, the
  identity-seed determinism rule); flipped the Discovery/consensus Tiers row to **built**.

### Interfaces

```ts
interface LiftRoute  { tallyPath: number[]; route: number[] }          // route = entity ids [from,…,to]
interface LiftResult { transactionCode: string; sessionCode: string; route: number[]; tallyPath: number[]
                       amount: number; outcome: 'commit' | 'void' | 'pending' }
```

### Tests added (the floor — treat as a starting point)

- `sim/plan-select.test.ts` — shortest pick, tie→first, empty→undefined, single plan.
- `sim/route.test.ts` — line walk, empty path (just originator), **circular** walk, throw on unresolvable
  nonce, throw on non-contiguous walk.
- `capacity.test.ts` (extended) — both pay directions consume exactly the directed capacity; self-inverse;
  `Infinity` tally moves a finite balance and keeps the limit.
- `model.test.ts` (extended) — `cloneNetwork` is an independent equal-by-value copy (no write-back).
- `sim/consensus-harness.test.ts` (extended) — the headline end-to-end cases: all-cooperative commit with
  balances moved the right way; one refuser voids with no money moved; **conservation** (payer −amt, payee
  +amt, intermediaries net 0); **capacity change between lifts** (rebuild between; a committed lift prunes a
  now-zero-capacity edge so the next query finds nothing); **parallel-tally disambiguation** (the lift
  settles over the capacity-bearing tally, not the first edge); **`Infinity`-capacity route commits** (proves
  the intents sanitisation); **determinism** (same scenario twice ⇒ identical `LiftResult` + byte-identical
  `serialize(network)`); **circular lift** commits and nets zero around the loop.

## Reviewer focus / honest gaps

1. **Circular lift is only driven, never discovered.** The end-to-end circular test **hand-builds** a ring
   plan (its nonces computed from a real session code) rather than relying on discovery to surface a
   `from === to` plan. I did **not** verify that the `tallynet` discovery protocol actually returns circular
   routes for `from === to` in this harness — so whether `runLiftForOutcome` is ever handed a real circular
   plan by a sweep is unverified. The *drive + balance-walk* for a circular route is proven; the *discovery*
   of one is not. If the metrics/trace ticket or a sweep ever needs circular routes to arise naturally,
   confirm discovery produces them first. (Not a latent bug — the normal workload draws distinct `(from,to)`
   pairs, so circular routes don't arise there today.)

2. **`pending` is surfaced but not exercised end-to-end.** `LiftResult.outcome` includes `'pending'` and the
   driver skips the money move for it, but no consensus-harness test drives a *stall* (dropped push on the
   only path, or an even voter-set tie). tallynet's own `consensus.test.ts` proves the engine produces
   `pending`; here the "no money on non-commit" path is covered only via `void`. A `pending` end-to-end case
   (e.g. a `conditions` drop on the sole route, or `options.voters` of two that split) would close this.

3. **`options.voters` override is implemented but untested.** Only the default originator-self-vote path is
   exercised. A multi-voter or alternate-voter test would cover the override and, combined with gap 2, a
   voter-tie stall.

4. **The bound-assert in `settleRoute` is a tripwire, not a tested failure.** `-foilCreditLimit ≤ balance ≤
   stockCreditLimit` after each hop can't fire for a single lift over a found route (discovery guaranteed
   capacity). It *is* load-bearing for the parallel-tally test: if `routeLinkIds` selected the wrong tally the
   assert would throw. Left as an assertion at the site in `consensus-harness.ts` (`settleRoute`); recorded
   here per the tripwire rule. No ticket — it is correct now and only a route-reconstruction bug would trip it.

5. **Determinism is a 2-run tiny-line comparison, not a sweep.** It pins the seed-reproducibility contract on
   one small scenario. The full sweep-level determinism (many cells/seeds) belongs to the next ticket
   (`tallysim-consensus-metrics-trace`), which has the sweep runner.

Out of scope here (next tickets): consensus metrics + the trace-header extension
(`tallysim-consensus-metrics-trace`); the viewer animation (`tallysim-viewer-consensus`).
