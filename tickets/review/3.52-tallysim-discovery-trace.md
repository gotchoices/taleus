Implement stage done for `tallysim-discovery-trace`. Reviewer: treat the tests as a floor, not a finish line — the **known gaps** below are real and are where to push hardest.

## What shipped

A versioned NDJSON **trace file format** for a discovery simulation run, plus the streaming writer and lazy reader, and a Node CLI driver.

- **`sim/trace-format.ts`** — the `TraceLine` union (`header` | `network` | `event`), `TRACE_FORMAT_VERSION = 1`, `buildTraceHeader`, `makeNetworkSnapshot`, `serializeTraceLine`, and `parseTrace`. The header carries the format + both package versions, the full `SimScenario`, the run seed, and one `queries[]` entry per recorded query. Version + shape are checked on read with clear, actionable errors.
- **`sim/trace-writer.ts`** — `makeTraceWriter(header, snapshot, out, options?)`: emits header + network up front, then one line per event **as it arrives** (never accumulates the event list). `options.sessions` filters to selected session codes. `stats()` reports running line/byte counts. Platform-neutral (`LineSink`, no `node:fs`).
- **`cli/trace.ts`** — the one Node-specific file (excluded from the neutral build + the `no-node-globals` guard, like `cli/sweep.ts`). Reads a `SimScenario` JSON, runs the workload, and streams the trace to stdout or `--out <path>`. Added the `trace` package script.
- **`model.ts`** — extracted `networkToSerialized` / `networkFromSerialized` (+ exported the `SerializedNetwork` / `SerializedTally` types); `serialize`/`deserialize` now delegate to them. **No behaviour change** — one encoding, reused by the snapshot, not a second one.
- **`scenario.ts`** — added `SimScenario` (network + workload + conditions + budget + conditionsSeed). See the coordination note for ticket 3.53 below.
- **`docs/design.md`** — replaced the § *Trace & replay format* stub with timeless prose (line kinds, ordering, versioning, streaming both ways, selected-query recording, byte-identical determinism, and the CLI's two-pass reason).

## How to validate / exercise it

Build + lint + test, then a live CLI run:

```
yarn workspace tallysim build && yarn workspace tallysim lint && yarn workspace tallysim test
```
**216 tests, 18 suites, 0 failures** (was 199; +17 from the two new suites). No `.pre-existing-*` files written — nothing unrelated broke.

CLI smoke test (what I ran by hand during implement — see *known gaps*, it has no automated test):

```
# a 3-entity line 0—1—2, amply capitalised; two payment queries
node packages/tallysim/dist/cli/trace.js <scenario.json> --out /tmp/t.ndjson
node packages/tallysim/dist/cli/trace.js <scenario.json> --out /tmp/t2.ndjson
diff /tmp/t.ndjson /tmp/t2.ndjson            # byte-identical across runs
node packages/tallysim/dist/cli/trace.js <scenario.json> --out /tmp/sel.ndjson --query 0   # records only query 0
```
Verified by hand: line order is `header, network, event…`; every event's `sessionCode` appears in `header.queries[]`; `--query 0` writes a self-consistent file (header lists only the recorded query, only its events are present); two runs are byte-identical.

### Use cases the format must serve (what the reviewer should probe)

- **Replay:** `parseTrace(lines)` → `{ header, network, events() }`; `network` deserialises byte-identically to the one the run searched; `events()` is a single-pass lazy generator (don't iterate it twice).
- **Join events to queries:** every event carries `sessionCode`; `header.queries[]` maps each session to `(from, to, amount, depth)`. No stream-splitting needed for concurrent queries.
- **Forward-compat with consensus (ticket 3.7):** the writer/reader pass the whole `TraceEvent` union through unchanged — a hand-built `settled` event round-trips (tested). No format bump for consensus events; bump `TRACE_FORMAT_VERSION` only for a change to the three line envelopes.
- **Large runs:** writing is append-only streaming; reading is lazy. `stats()` reports the size.

## Known gaps (push here)

- **`cli/trace.ts` has no automated test.** Only the manual smoke test above. I deliberately exported `parseArgs` and `recordTrace(scenario, args, versions, open)` (the latter takes an injectable `open()` yielding an in-memory `LineSink`) so both are unit-testable without touching the filesystem — a `trace.test.ts` mirroring `sweep.test.ts` is the obvious add. This is the biggest coverage hole.
- **The CLI runs discovery twice (two-pass).** The header must list session codes and is line 1, but a session code is minted *inside* `discover()` and isn't knowable until the query runs — so pass 1 learns the codes (codes only, memory stays flat) and pass 2 streams the events. It's correct and leans on the determinism guarantee, but it's 2× runtime for the CLI. Reviewer should sanity-check the tradeoff; the metrics ticket's sim-runner won't need two passes (it can collect per-session events in memory rather than writing a header-first file).
- **`stats().bytes` assumes exactly one newline per line.** The `LineSink` contract is "no trailing newline; the owner adds the separator," and `bytes` counts each line + 1. That matches an on-disk NDJSON file (the CLI appends `\n`); an in-memory accumulator that joins without newlines would see `bytes` overcount by `lines`. Documented as "on-disk NDJSON size" — flagging in case the viewer's accounting cares.
- **`utf8ByteLength` reimplements UTF-8 length** (code-unit scan) rather than using `TextEncoder`, because the neutral build compiles with `types: []` and a global encoder isn't guaranteed on every target (NativeScript, etc.). Correct for well-formed strings and lone surrogates; worth a glance. All trace lines are ASCII JSON in practice, so the path that matters is trivially exercised.
- **Determinism is tested over a tiny 3-node line, not a large/generated network.** The byte-identical test runs the real harness twice on a hand graph. A reviewer wanting more confidence could add a generator-sourced scenario (the metrics ticket will stress this harder with its sweeps).

## Tripwire (conditional — no ticket)

- **Network snapshot held in memory while serialising.** The snapshot is one line; the *event stream* is what grows without bound, so this is fine for planned sizes. Parked as a `NOTE:` comment at the serialisation site — `sim/trace-format.ts`, in `makeNetworkSnapshot`'s doc ("if entity counts ever dwarf event counts, consider chunking the snapshot across several lines"). Not a defect now; only trips if a network ever dwarfs its own event count.
