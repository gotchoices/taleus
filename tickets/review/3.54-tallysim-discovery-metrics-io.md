**Second of three split discovery-metrics tickets** (core landed in `complete/`; `tallysim-discovery-metrics-experiment`, seq 3.55, depends on this). This ticket serialises the discovery sweep's `SimRunRecord`s and ships the Node CLI that drives the sweep to files.

Implementation detail is in the implement commit and the module/doc comments. This file is the reviewer's starting map — **treat the tests as a floor, not a finish line.**

## What was built

- **Generic serialiser core** (`serialize-records.ts`). The CSV/JSON machinery is now generic over the metrics payload: `MetricsRecord<M>`, `metricsRecordToJsonLine`, `metricsRecordsToJsonLines`, `parseMetricsJsonLine`, `createSweepCsvAccumulator(metricColumns)`, `metricsRecordsToCsv`, plus the now-exported `distributionColumns`. The oracle's `RunRecord`-typed functions (`recordToJsonLine`, `recordsToJsonLines`, `parseJsonLine`, `createCsvAccumulator`, `recordsToCsv`) are kept as **thin wrappers** that pin `RunMetrics` and the oracle `METRIC_COLUMNS` — so their byte output is unchanged.
- **Sim serialiser** (`serialize-sim-records.ts`, new): `simRecordToJsonLine`, `simRecordsToJsonLines`, `parseSimJsonLine`, `createSimCsvAccumulator`, `simRecordsToCsv`. Reuses the generic core; its only new data is the sim CSV column order (found-vs-oracle scalars → six cost/timing distributions → six prune-reason tallies). Exported from `index.ts`.
- **`cli/simulate.ts`** (new): reads a `SimSweepSpec`, iterates the **async** `runSimSweep` with `for await`, streams JSON-lines to stdout/`--jsonl`, builds the CSV on the same pass (`--csv`), `--concurrent` sets `SimRunnerDeps.concurrent`. `--trace <path>` (+ repeatable `--query <i>`, `--seed <n>`) dumps a replayable trace of the **unvaried base scenario** by reusing `cli/trace.ts`'s `recordTrace`. `runToOutputs` takes injectable in-memory sinks (like `cli/trace.ts`); `main`/`fileSinks` do the `node:fs` wiring. `"simulate"` script added to `package.json`.
- **`cli/trace.ts`** refactor: private `drawQueries` replaced with the core's `drawPaymentQueries(workload, entityCount, new SeededRandom(workload.seed))` — same draw order, workload seed **not** offset by the run seed, byte-identical. `packageVersions` exported so `simulate.ts` reuses it.

## Validation performed

`yarn workspace tallysim build`, `lint`, `test` all green — **273 tests, 23 suites** (up from 255; +2 new suites). Also ran the compiled CLI end-to-end against a tiny generator spec: stdout streaming, `--jsonl`/`--csv`/`--concurrent`/`--trace --query 0` all produced correct output; CSV header matched the ticket's canonical column order exactly; the trace header carried the base scenario (entityCount 8, meanDegree 2 — vary not applied).

## Use cases to exercise / verify

- **Oracle byte-identity (the main regression surface).** `serialize-records.test.ts` is the automated floor and passes unchanged. The refactor keeps the oracle functions as pure wrappers, so output is identical by construction — but I did **not** run `experiments/route-existence/regenerate.sh` (multi-spec, N up to 10 000 — wall-clock too long to be agent-runnable). **If the reviewer wants full certainty, run that script and confirm `git diff` on `route-existence.jsonl` is empty.** This is the biggest unverified claim.
- **Sim round-trip + CSV shape.** `serialize-sim-records.test.ts`: finite `SimRunRecord` round-trips JSON-lines; CSV emits header + one row per record; every distribution expands to its 7 sub-columns; `pruneReasons.*` (all six, hyphenated keys) present; non-finite → empty cell; the streaming accumulator matches the one-shot helper.
- **CLI smoke.** `cli/simulate.test.ts`: `parseArgs` (all flags + error cases); `runToOutputs` streams JSON-lines, builds CSV, runs `--concurrent`, and `--trace` produces a parseable trace of the base scenario (and of selected query indices).
- **Trace byte-identity.** `cli/trace.test.ts` (unchanged) still green after the `drawPaymentQueries` swap, including its byte-identical-across-runs test.

## Known gaps / where to look hardest

- **`main`/`fileSinks` (the actual `node:fs` wiring in `simulate.ts`) has only the manual end-to-end smoke above — no unit test.** This matches `cli/sweep.ts`/`cli/trace.ts`, whose `main` is likewise untested, but it is a gap: a mistake in the fd lifecycle or stdout-vs-file branch would not be caught by the suite.
- **The simulate test spec is deliberately tiny** (8 entities, 3 queries, 2 cells, 1 seed) to stay fast. It does **not** exercise network `conditions`, a `budget`, a materialised-network base, or large N. The tier's conditions/budget handling is covered by the core/harness tests, not here.
- **`--concurrent` + `--trace` interaction is untested together** and `--concurrent`'s round/timing divergence is a known, documented limitation (`fix/tallysim-sim-runner-concurrent-divergence`, top priority). The CLI exposes `--concurrent`; callers wanting round/timing-accurate output should stay sequential until that fix lands. Confirm the simulate docs/help don't over-promise here.
- **`--trace` traces the base scenario, not a swept cell** — a deliberate design choice (documented in the CLI header, README, and design.md). Worth a sanity check that this is the behaviour a reviewer expects, since "trace of the sweep" could be misread.

## Tripwire recorded (not ticketed)

- **`flattenMetrics` descends exactly one level** (number, or an object of numbers). Every current metrics shape is flat or one-deep (`DistributionSummary`, `pruneReasons`); a future **two-level-nested** numeric object would be silently dropped from the CSV. Parked as a `NOTE:` at the flatten site in `serialize-records.ts` — recurse (and widen the column-order lists) if that shape ever appears.
