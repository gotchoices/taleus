## What this delivered

The final piece of the **live-run tier** of `tallysim-viewer` (a static, server-less browser dev tool that draws
a simulated tally network and animates a payment search across it). Prior runs landed the worker, the pure
scenario/run translation, click-to-pick in the renderer, and replay autoplay. This run added the **panel** that
ties them together, plus the shell wiring, CSS, and docs.

New/changed:
- **`src/live/controls.ts` (new)** — `mountLiveControls(host, liveHost)`. Builds the generate → pick → run →
  download form, owns the one `Worker`, and defines the `LiveRunHost` contract the shell implements.
- **`src/app/shell.ts`** — refactored `loadNetwork` into `renderNetwork` (draw a network, mount a disabled
  replay) + `setReplay` (swap the replay panel), added a **File | Live-run** Source tab toggle, implemented
  `LiveRunHost`, mounted the live controls, and calls `liveControls.invalidate()` on file/sample load.
- **`src/app/styles.ts`** — `input[type='number']`, `.tsv-source-tabs` (+ active), `.tsv-live*` form/button/
  readout/status/error styles.
- **`docs/design.md`** — a new **Live-run tier** section (worker split, header-from-first-event determinism,
  trace-envelope reuse, host contract) and the intro paragraph updated.

## How to exercise it (the manual gate — jsdom has no WebGL/Worker)

`yarn workspace tallysim-viewer dev`, then:
1. Source → **Live-run** tab. Default is `scale-free`, 200 entities, `constant` capacity.
2. Click **Generate** → the graph draws. Status: "Network ready. Pick a payer and a payee, then Run."
3. Click two nodes (payer → payee); or type ids into the `payer`/`payee` number inputs (source of truth). The
   readout and the graph marks update; **Run** enables.
4. **Run** → watch it animate (autoplays from t=0). Open a found route in the replay panel to isolate its exact
   path (the live source is the only path that lights up the *full* found-routes list with exact-path isolate).
5. **Download trace** → reload the file via the **File** tab → confirm the animation is identical.
6. **Cancel** mid-run (use a larger network to have time): the graph + picks survive; Run stays usable.

Edge cases to probe: `from === to` (self-payment loop status); `< 2` entities or an edge-less network (zero
events → disabled replay panel + terse status, no throw); bad generator params (e.g. `edgesPerNode = 0` →
`materializeNetwork` throws *inside the worker* → surfaces as a "generate failed: …" error line, not a blank
page); a theme toggle mid/post-run (picked marks + replay re-theme for free).

## Known gaps / things to scrutinise (reviewer: treat tests as a floor)

- **No automated coverage of this file.** `controls.ts`, the worker, streaming, click-to-pick, and the whole
  form are **build-plus-manual only** — jsdom has neither WebGL nor Worker. Only `build-scenario.ts` and
  `sim-run.ts` (the pure translation) have jest coverage. The manual flow above is the real gate. A
  headless-WebGL smoke test (Playwright) remains deferred (see design.md § Testing).
- **Decisions to evaluate deliberately** (both carried from the worker ticket / this ticket, flagged so review
  weighs them, not rubber-stamps):
  - **Fresh `buildSimNetwork` per Run** (vs. one long-lived `InMemoryNetwork` serving many queries). Shipped
    because it restarts the session-code RNG at its fixed seed, so a live run byte-matches a `tallysim trace`
    single-query trace. Trade: no cross-run state (fine — read-only tier).
  - **Cancel → silent re-generate** (vs. invalidate-and-force-manual-regen). Shipped the silent regen so the
    drawn graph + picks survive a Cancel. The `silentRegen` flag gates the next `network` message to refresh
    scope only (no re-render). Alternative was simpler but loses the graph on every cancel.
- **`readParams` reads generator/capacity param inputs with bare `Number(input.value)`** (no per-field
  fallback): a cleared field yields `NaN`, which `materializeNetwork` rejects inside the worker → a clear
  "generate failed" error. Intentional (dev tool, worker is the validation point), but a reviewer may prefer a
  fallback-to-default. `entityCount`/`seed`/`amount`/`depth` *do* fall back (`readNum`).
- **Live replay mounts regardless of `webglAvailable`** (the host's `mountReplay` guards only
  `state.view === undefined`, per the ticket) — so the found-routes list + transport work even on the WebGL-
  missing stub view (which no-ops the overlay). The *file* path still guards `webglAvailable` (unchanged). Minor
  deliberate asymmetry; confirm it reads correctly.
- **Defaults chosen by the implementer** (not specified): generator `scale-free`, 200 entities, seed 1,
  capacity `constant` limit 100, amount 1, depth 6. Sanity-check these produce a routable small network quickly
  in a worker.
