Part 1 of 3 of the original `tallynet-originator-proceed` split. This implements the **pure core**:
`mintRecord`. Parts 2 (`tallynet-originator-proceed`: proceed/abort) and 3 (`tallynet-mint-e2e`: real
discovery → topology → vote, plus docs) are still in `implement/` and build on this. Reviewer: treat the code
as a starting point and the tests as a floor — the honest-gaps section below says exactly where the floor is.

## What landed

A new pure function `mintRecord<TTerms, TPayload>(args)` in **`src/consensus/mint.ts`**, re-exported via
`export * from './mint.js'` at `consensus/index.ts:15`. It turns the ONE chosen `Plan` into the `TrxRecord`
every node merges and settles. Signature:

```ts
mintRecord({ plan, query, payload, transactionCode }) -> TrxRecord<TTerms, TPayload>
```

What it does, and the three invariants it rests on:

- **Members carried through as-is.** `topology.members = [...plan.members]` — mint never invents, reorders,
  or de-dupes. It trusts that discovery's return-trip fold (`prependMatch`, `discovery/participant.ts:714`)
  already put participants in route order (origin-first, target-last) and de-duplicated voters by key. A
  `[P,V]` node is one member with both roles; a circular originator is one member riding two links.
- **Links by the modular formula.** `participants = members.filter(includes 'P')`; for path link `i`,
  `source = participants[i].key`, `target = participants[(i+1) % n].key`. The `% n` wraps only on a circular
  lift's closing link; a linear path never reaches it. Each link is keyed by `plan.path[i].nonce`.
- **Session code reused, not minted.** `record.sessionCode = query.sessionCode`. This is load-bearing: the
  link keys are the path nonces, which are `makeNonce(sessionCode, linkId)` — a fresh session code would make
  every participant's `nonceToLinkId` lookup miss. `transactionCode` is passed in (so mint reads no
  clock/random and stays pure). `method = query.method`; `liftContract` is **omitted** when the query has
  none (never set to `undefined` — DAG-CBOR rejects undefined-valued keys). `promises`/`commits` start empty.

It **throws** (fail-early, explainable) on three unsettleable shapes: no participant members, no voter
members (would be rejected by the `NonEmptyVoterSet` rule at `participant.ts:805` on first `update` anyway),
and a path whose link count fits neither linear (`n−1`) nor circular (`n`).

## Honest gaps (the floor)

- **No end-to-end — the fold invariants are trusted, not re-verified here.** The three claims above
  (route order, voter de-dupe, nonce symmetry) rest on reading `prependMatch` and discovery invariants. This
  ticket's tests feed mint hand-built plans; they do **not** run a real search. Proving a nominated voter
  actually survives discovery → topology → the final vote count is **Part 3** (`tallynet-mint-e2e`) — that is
  the real regression check, and it is still open.
- **The minted record is never fed through the real new-record RuleSet.** mint.test.ts asserts duplicate-key
  freedom with a *local mirror* of `hasDuplicateMemberKey`, and never constructs a `TrxParticipant` to run
  the output through `update`'s `buildNewRecordRules` (`participant.ts:787`). So "passes the new-record
  rules" is argued from the rules' text, not demonstrated. A stronger test would mint a record and drive it
  through a real participant's first-sight validation (needs a clock/store/valid codes — see
  `consensus/participant.test.ts` for the harness). Worth a reviewer's call on whether to add now or leave to
  Part 2, which exercises `update` anyway.
- **No `CoreEncodable` / DAG-CBOR round-trip on the output.** mint.test.ts never calls `canonicalEncode` /
  `recordDigest` on the minted record. In production the members come from a plan that already round-tripped,
  so this is low-risk, but a one-line "the minted record canonically encodes" assertion would close it.
- **Two guards exceed the ticket's explicit ask** (it named only the voterless throw): the empty-participant
  throw and the path/participant-count mismatch throw. They mirror `NonEmptyParticipantSet` and catch a
  silently-malformed topology, but a reviewer should confirm they reject nothing legitimate. In particular
  the count guard *allows* a degenerate single-participant circular self-loop (`source === target`); that is
  out of scope and no rule forbids it, but flag it as a known edge.

## Review findings

- Tripwire parked as a `NOTE:` at `mint.ts` (the `[...plan.members]` line): the member array is copied but
  the member objects are shared with the plan — safe while members are treated as immutable; deep-clone if a
  caller ever mutates plan members after minting.
