# Review — tallysim oracle

Second of three chained network-model-tier tickets (`tallysim-model-generators` → **oracle** →
`tallysim-runner`). The oracle sees the *whole* compiled graph and searches it directly; it is the **ground
truth** the later `tallysim-discovery` tier measures the real `tallynet` protocol against ("found vs.
oracle"). Platform-neutral (the viewer runs it live in a page): no Node globals, no `Math.random`, no
result depending on unordered-key iteration — all enforced by the existing `src/no-node-globals.test.ts`
guard, which now also scans the two new source files.

## What was built

- **`src/graph-view.ts`** — `buildGraphView(network): GraphView`. Compiles a `Network` into a directed
  capacity graph in **CSR** (compressed-sparse-row) form over **typed arrays**: `offsets` (`Int32Array`,
  `entityCount + 1`), `targets` (`Int32Array`), `capacities` (`Float64Array`, so `Infinity` is
  representable). Each tally → two directed edges (`stock→foil` = `cap(S→F)`, `foil→stock` = `cap(F→S)`).
  Deterministic build (edges in tally order; neighbour slices in incident-tally order).
- **`src/oracle.ts`** — `class Oracle` wrapping one `GraphView`, reusing scratch buffers (generation-stamped
  `visited` cleared in O(1) per query) across queries. `Oracle.fromNetwork(net)` compiles + wraps.
- **Barrel**: `src/index.ts` re-exports both. **Docs**: `docs/design.md` § Oracle fully written (was a
  stub); README status updated.

## Public API (what the runner tier will call)

- `routeExistence(from, to, amount, maxDepth): { exists, shortestLength? }` — bounded BFS over edges with
  `capacity ≥ amount`. `shortestLength` = BFS level `to` is first reached. `from === to` **delegates to
  `selfPayment`** (a self-payment is a cycle, not a length-0 path).
- `selfPayment(node, amount, maxDepth): { exists, shortestLength? }` — shortest directed cycle through
  `node`; never length 0 (min cycle is length 2).
- `maxFlow(from, to): number` — Edmonds–Karp max value payable; **not depth-bounded**. `Infinity` when an
  all-unlimited path exists; `0` when `from === to`.
- `clearingCycles(node, amount, maxDepth, maxCount): { count, capped, shortestLength? }` — count of
  distinct directed cycles (capped at `maxCount`); `shortestLength` is **exact regardless of the cap**
  (computed by a separate BFS, not from the capped DFS).

## Conventions the discovery tier must match (verify these are exact)

- **`maxDepth` counts hops.** A 1-hop path is length 1. A `to` reachable only at `maxDepth + 1` reports
  `exists: false`. (Tested: `oracle.test.ts` depth-boundary cases.)
- **Capacity filter is `≥`.** `capacity === amount` qualifies; `capacity === amount − 1` does not.
  Zero-capacity directions are pruned once `amount > 0`.
- **`amount ≤ 0` is rejected (throws).** The ticket allowed "any edge qualifies" or "reject" — I chose
  reject (a payment of ≤ 0 is a programming error, not a query). Documented in design.md + `oracle.ts`.
- **Cycles are directed and counted by distinct edge-sequence** — the two ways round a loop are two
  cycles; parallel tallies yield distinct cycles. (A fully bidirectional triangle has 4 cycles through a
  node within depth 3: two 2-cycles + two 3-cycles.)
- **`maxFlow(X, X) = 0`** (no distinct sink; self-clearing is `clearingCycles`, not an s–t flow).

## Verification — scrutinise the harness as hard as the oracle

`src/oracle-brute-force.test.ts` is the correctness anchor: an **independent exhaustive enumeration** on
small seeded graphs (≤ 9 nodes), cross-checking route existence, shortest length, self-payment cycle,
clearing-cycle count, and capacity/depth respect; **max-flow is checked against a min-cut subset
enumeration** (≤ 6 nodes), a genuinely different computation via the max-flow/min-cut theorem. 40 seeds ×
6 trials each per query type.

**A bug shared between oracle and brute force would pass both.** Specific things to re-derive yourself:

- The brute-force `adjacency()` / `bruteMaxFlow()` use the *same* capacity formula as `graph-view.ts`
  (`cap(S→F) = balance + foilCreditLimit`, `cap(F→S) = stockCreditLimit − balance`). That is intentional —
  it's the *definition* of the capacity model, not an independent re-derivation — but it means a wrong
  capacity **formula** would not be caught by the cross-check. The small hand-built capacity tests in
  `graph-view.test.ts` (e.g. balance 2, limits 10/5 ⇒ caps 7/8) are the independent anchor for the formula
  itself; confirm those numbers by hand.
- `selfPayment` uses **BFS** (shortest cycle = `min_u(dist(node,u)+1)` over `u` with an edge back), while
  the brute force uses **DFS** cycle enumeration. The BFS argument is in the method comment — check the
  reasoning holds (e.g. that the shortest path `node→u` plus the closing edge is always a *simple* cycle).
- The `maxDepth − 1` guard in the clearing DFS (`len + 1 <= maxDepth - 1`) is an easy off-by-one; confirm
  a cycle of length exactly `maxDepth` is counted and one of `maxDepth + 1` is not.

## Known gaps / limits (honest handoff — treat tests as a floor)

- **Max-flow `Infinity` handling is only hand-tested**, not cross-checked against the brute min-cut (the
  seeded brute graphs use finite capacities 0–4). The single `returns Infinity when an all-unlimited path
  exists` test and `maxFlow(X,X) = 0` test cover the special paths. A reviewer could add an unlimited-graph
  min-cut cross-check if wanted (min-cut with `Infinity` edges works: `Math.min` ignores finite cuts).
- **Performance smoke covers BFS only** (10k entities × mean degree 10, 1,000 `routeExistence` queries, a
  generous 30s ceiling — actual is sub-second). Max-flow at scale is *deliberately* not perf-tested: it is
  `O(V·E²)` and the runner must sample it — see the cost guidance below.
- **No perf/scale test for `clearingCycles`** — cycle enumeration can explode; correctness is covered on
  small graphs, and the `maxCount` cap is the scale guard. The runner must pass a sensible cap.
- `clearingCycles` counts **directed** cycles including both orientations and both directions of a
  bidirectional tally (a 2-cycle `node → v → node` over one tally's two directions is economically a no-op
  but is a valid graph cycle). If the clearing *metric* should exclude such degenerate same-tally 2-cycles,
  that is a modelling decision for the runner/trading tiers, not fixed here. Flagged, not changed.

## Tripwires recorded (conditional concerns — not tickets)

- **2^53 capacity precision** — `NOTE` at the `capacities` allocation in `graph-view.ts` and in design.md
  § Oracle. Capacities are `Float64Array`; a capacity above 2^53 loses integer precision. Fine now
  (simulated units stay small); if ever needed, switch to `BigInt64Array` + `bigint` arithmetic.
- **Max-flow `O(V·E²)` cost** — `NOTE` on `Oracle.maxFlow` and in design.md. The runner tier must compute
  max-flow on a **sampled** subset of queries (or on request), never per-query on a 10k sweep.
