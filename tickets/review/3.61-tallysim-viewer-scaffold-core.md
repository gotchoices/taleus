## What was built

New unscoped Yarn-workspace package **`packages/tallysim-viewer`** — a static, server-less browser dev tool
to *view* a simulated tally network. This ticket added the scaffold + the platform-neutral, headlessly-tested
**core** only; it renders nothing yet.

- **Scaffold:** `package.json` (deps `tallysim`/`tallynet` `workspace:^`, `graphology` 0.26.0,
  `graphology-types` 0.24.8, `sigma` 4.0.6, `uplot` 1.6.32; devDep `vite` 6.4.2 + sibling toolchain),
  `tsconfig.json` (ES2022 + DOM libs, jest/node types), `vite.config.ts` (`base:'./'`, static `dist/`),
  `jest.config.ts` (mirrors `tallysim`), `index.html`, `src/main.ts` (app-shell stub — DOM only).
- **Core (`src/core/`, no browser imports):**
  - `trace-index.ts` — wraps `tallysim`'s `parseTrace`; per-session time-ordered event buckets + global
    time bounds; incremental builder (`createTraceIndex`) for the live-run streaming case; `indexTrace`
    whole-file convenience.
  - `deanonymise.ts` — the load-bearing decoder. Rebuilds `nonce → tally index` per session by recomputing
    `makeNonce(sessionCode, linkIdForTally(i))` over every tally (lazy + cached). `tallyOfNonce`,
    `nodePathOfPlanPath`.
  - `timeline.ts` — pure playback: `PlaybackState` + reducers (`seek`/`play`/`pause`/`setSpeed`/`step`) and
    `deriveActiveSet(currentTime)` (recompute-from-scratch → correct both scrub directions).
  - `sweep-data.ts` — parses sweep **JSON-lines** (via `parseSimJsonLine`) and **CSV** to a shared flat-row
    shape, then `rowsToSeries` into tidy `{seriesKey, points}`; includes a full RFC-4180 CSV reader.
- **Docs/wiring:** `docs/design.md` (purpose, stack decision + rationale, core map, de-anonymiser insight),
  `README.md`; added one line each to `AGENTS.md` package list and `docs/index.md`.

## Where to look hardest (use cases + known gaps)

- **De-anonymiser correctness** is the keystone — if `tallyOfNonce` / `nodePathOfPlanPath` are wrong, every
  later render is wrong. The test computes expected nonces from the *real* `makeNonce` and walks a 2–3 hop
  path both directions. Worth adversarial probing: multi-edge-between-same-pair (two tallies on one node
  pair → two distinct link ids → two distinct nonces; confirm no aliasing), self-loop tallies (generators
  avoid them, but a hand-built trace could have one), and a node that appears at both ends mid-walk.
- **Sentinel vs. throw:** `nodePathOfPlanPath` returns `number[] | undefined` (undefined = sentinel) for an
  unresolvable nonce or non-contiguous walk, rather than throwing. The ticket said "sentinel **or** throw";
  confirm the sentinel choice is acceptable to the renderer (it must not silently drop a route it should
  have drawn).
- **Found-plan representation is intentionally shallow here.** The trace file carries no found-plan *path* —
  `plan-found` events are bare markers (time + finder node), and `plan-returned` events only carry a single
  inbound nonce with no plan id, so a full highlighted route **cannot** be reconstructed from a file trace
  alone. `timeline.deriveActiveSet` therefore surfaces found plans as markers and lights the explored edges;
  the actual route-as-node-path (`nodePathOfPlanPath`) is fed a `Plan.path` from the **live-run**
  `QueryOutcome` (a later ticket), not from the file. **Confirm this split is the intended design** before
  the graph/replay ticket assumes file-replay can draw a single found route.
- **Active-set semantics:** nodes/edges accumulate (explored subgraph grows); each keeps *max* round/depth,
  edges keep *last* event kind by time; `late-answer-folded` updates an edge in place (tested: no duplicate,
  later round wins). A reviewer should sanity-check whether "accumulate and never un-light" is what the
  replay wants, or whether some events should expire from the active set.
- **Sweep non-finite handling:** `Infinity`→`null` (JSONL) / empty cell (CSV) is read as **absent** (point
  omitted), never `0` — tested against both formats producing identical series. Probe mixed/garbage CSV cells
  and a metric path that doesn't exist.

## Tripwires recorded (index only — not tickets)

- `deanonymise.ts`, at the reverse-map build site: `NOTE:` — the map is O(tallies) per session; lazy +
  per-session keeps it cheap; evict-current-session only if a trace ever has very many sessions over a huge
  graph.
- `timeline.ts`, in `deriveActiveSet`: `NOTE:` — recompute is O(events) per seek; switch to an incremental
  cursor only if scrubbing a large trace shows slow.
