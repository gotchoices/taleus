## What this closes

The regression check's "untested end-to-end in TallyNet" gap: a `dependsOn`-nominated voter now
travels **discovery → topology → the vote count through a REAL `discover` plan**, not a `buildLift`
spec shortcut. Part 3 of 3 (Parts 1 `mintRecord` and 2 `proceed`/`abort` already landed).

## What was built (all green: `yarn build && yarn test && yarn lint` in `packages/tallynet`)

Two test-harness additions in `src/testing/network.ts`, plus four new e2e tests in
`src/testing/consensus.test.ts`, plus a docs refresh. **379 tests pass (38 in consensus.test.ts).**

### Harness: referee nomination (`network.ts`)
- New exported `RefereeNomination { name; physical? }` and a `nomineesFor?: (nodeId) => RefereeNomination[]`
  config knob. When a node resolves its own `self` Match, `makeFindAddress` attaches
  `dependsOn: [...]` listing voter-only referees (physical by default). `prependMatch` folds each as a
  `V` member onto every plan the node rides — exactly a real participant nominating a referee. The
  name-keying of discovery is untouched (every existing discovery test still passes).
- **Why this is the crux:** every member a real `discover` emits is `[P]` (participant). So the ONLY way
  a `[V]` member enters a discovered plan is a `dependsOn` nomination — which makes the nominated referee
  the **sole** voter. That is both what makes the e2e meaningful and what gives clean outcome control.

### Harness: `mintFromPlan` (`network.ts`)
The discovery-plan analogue of `buildLift` (which stays unchanged). It:
- **translates** the plan's member keys (and `dependsOn` addresses) from discovery NAME space into
  ed25519-key space (`translatePlanToKeys`), and **stamps the originator a `physical` contact point** so a
  voter-only referee's vote can return (design.md § Contact points — the referee rides no tally link);
- runs Part 1's `mintRecord` with the query's **reused** session code (so path nonces still resolve);
- **re-derives and populates** every involved node's live nonce→linkId map from the graph edges
  (`populateNonceMaps`), matching each link **by nonce** (disambiguates parallel edges).

### Docs (`docs/design.md` § Lift proposal and settlement)
The proceed/abort paragraph now states the final `mintRecord`/`proceed` signatures and the **resolved,
implemented abort semantics**: abort signs the originator's `NP` only before it has signed its own `P`;
refused after (the atomicity guard) and once the promise phase is complete (principle 3) — stricter than
principle 4's literal "abort before every participant has promised," because `proceed` signs our `P`
immediately so a `proceed`-then-`abort` is correctly refused.

## Use cases to validate (what each test proves — treat as a floor)

1. **Referee reaches the vote count (headline).** `src/testing/consensus.test.ts` → "a referee nominated
   mid-search is a V member riding no link, and its lone C commits the whole route". REAL `discover`
   O→A→B→Z (R has no edge, nominated by A). Asserts R is a `V` member of `topology.members`, R rides **no**
   link, R is the sole voter, and every node commits (1/1 C is a majority).
2. **NC flips the outcome at the threshold.** "the referee's NC flips the outcome…". Same graph,
   `R: { shouldCommit: false }` → R's NC is a 1/1 void majority → every node **voids**.
3. **Nominated by two, counted once.** "nominated by two participants, the referee is folded in once…".
   A and B both nominate R → `prependMatch` de-dups → exactly one `V` member → commit (proves single
   weight: a double-weighted R would be 1/2, no majority, stuck `pending`).
4. **Circular originator (hand-built).** "a circular originator (payee = self) mints a valid two-link
   ring…". A real `discover` toward self degenerates to a round-0 self-match (path:[], members:[O]) with no
   ring path, so the ring is built by hand (two PARALLEL edges — `makeNonce` depends only on link id) and
   fed through `mintFromPlan`. Proves the two-link mint shape settles (O the sole voter, both commit).

## Known shape, flagged honestly (NOT a gap papered over)

- **The "flips at the threshold" nuance (test 2) is proven with R as the SOLE voter**, not as a
  tie-breaker inside a larger mixed voter set. This is deliberate and unavoidable through a *real*
  `discover`: all discovered members are `[P]`, so the only voter a real search can introduce is a
  `dependsOn` referee, and a single nomination yields a one-voter set. A genuinely multi-voter mixed set
  (participants that also vote **plus** referees) isn't reachable through a real `discover` without a
  second, different nomination path. Multi-voter mixed sets **are** already covered by the `buildLift`
  "voter set sizes" tests (set of one/two/three, split-settles-neither) — those use the spec shortcut by
  design. So the coverage is: real-plan single-referee (new, this ticket) + spec-built multi-voter
  (existing). The reviewer may consider whether a real-`discover` multi-voter case (e.g. two interior
  nodes each nominating a distinct referee, or a `[P,V]` participant that both rides a link and votes) is
  worth adding; it is a *new shape*, not a correctness hole in what landed.

## Tripwire recorded (not a ticket)

- `populateNonceMaps` (`network.ts`) re-derives each link's nonce by scanning the source node's adjacency,
  O(links × degree) per mint. Fine at lift scale; parked as a `NOTE:` at the method with the fix (index the
  per-session nonce→linkId at graph-build time) if a sim ever mints over large discovered topologies.
