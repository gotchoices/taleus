### Experiment (stretch — done, not skipped)

`experiments/commit-vs-found/` mirrors `found-vs-oracle/`. Two one-dimensional sweeps, scale-free
`edgesPerNode=3` (mean degree ≈6), **unlimited** capacity, `N=100`, `D=6`, 50 queries, seeds `[1,2]`,
consensus on:

- `refuser-sweep`: `consensus.refuserFraction ∈ {0..0.5}` → `pCommitGivenFound` 1.00→0.09, all voids
  `refused-promise`, `liftCount` flat at 50 (confirms the independent refuser seed stream).
- `drop-sweep`: `conditions.dropFraction ∈ {0..0.5}` → routes found 50→33.5 **and** stalls (`pending`/`stalled`)
  0→14.5; `pCommitGivenFound` 1.00→0.57.

`./regenerate.sh` rebuilds tallysim and reproduces `out/` + `commit-vs-found.jsonl` **byte-identically**
(verified: ran twice, all sha256 match). Runs in ≈2 min (streams progress; wrap in `| tee` for a log).

## Known gaps / limitations (honest)

- **Unlimited capacity ⇒ the depletion path runs but never bites.** The sequential-lift balance mutation
  executes on every commit, but with unlimited capacity no later query is ever gated by a depleted tally. A
  finite-capacity consensus sweep would exercise that interaction; it was deliberately left out here to keep
  each swept failure mode clean (same choice `found-vs-oracle` made). Natural follow-up, not filed as a ticket
  (it's a "would strengthen coverage", not a defect) — flag if you think it warrants a `debt-` backlog item.
- **Two void reasons are not exercised by the committed experiment.** `voted-no-commit` (a referee `NC`) and
  `expired` (a code that outlived its TTL) never appear in either sweep — the specs use no `shouldCommit:false`
  referee and zero latency. Both are covered by `consensus-metrics.test.ts` unit tests, not by the experiment.
  A latency sweep (respecting the 600 000 ms TTL ceiling documented in the README) would drive `expired`; an
  `R`-role refuser would drive `voted-no-commit`. Deliberate scope limit, documented in the README.
- **`timeToSettleMs` is trivially 0 in the experiment** (instant delivery). The metric/CSV column is present
  and exercised, but non-trivial settle-time data needs a latency sweep (see above).
- **Sweep-plumbing duplication** between `consensus-runner.ts` and `sim-runner.ts` is pre-existing and already
  tracked as follow-up tech debt in the design doc (not this ticket's to resolve).

## Review findings

- Experiment limitations (unlimited-capacity-so-no-depletion; `voted-no-commit`/`expired` void reasons and
  non-trivial `timeToSettleMs` not exercised by the committed sweeps) are parked in
  `experiments/commit-vs-found/README.md` and the "Known gaps" above — conditional "would strengthen coverage"
  items, not defects, so recorded as prose rather than tickets or code tripwires. The existing rebuild-per-query
  keygen-cost `NOTE:` in `consensus-runner.ts` already covers the one genuine cost tripwire.
