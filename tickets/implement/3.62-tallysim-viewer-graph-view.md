Second viewer ticket. The scaffold-core ticket built the headless logic (trace index, deanonymiser, timeline
reducer, sweep parser); this ticket builds the **static graph view and the app shell** that renders a loaded
trace's network. No animation yet (that is the replay ticket) — this ticket draws the network at rest and
makes it navigable.

## Architecture

### App shell (`src/app/`)

- A single-page layout: a main graph canvas, a left/side control panel, a top bar. Plain TS + small DOM
  helpers (no framework, per the settled stack).
- **Theme**: light + dark toggle, persisted (localStorage). All colours come from a single theme/palette
  module so the replay and sweep tickets reuse it; use colour-blind-safe scales (the dataviz skill's palette
  is a good starting point).
- **Source picker**: load a trace file (`<input type=file>` → text → `trace-index`). The live-run and sweep
  tickets add their own source tabs; this ticket wires the file-load path and leaves clearly-marked seams for
  the others. Reject a bad file with the `parseTrace` version/format message shown in the UI (not console).

### Graph model (`src/graph/model.ts`)

Build a `graphology` graph from a tallysim `Network`:

- One graph node per entity (`entityName(id)` for the key, or the integer id directly — keep a single
  convention and document it). Entity detail on hover: id, degree.
- One graph edge per tally. Compute **directed capacity** with tallysim's `capStockToFoil` / `capFoilToStock`
  (from `capacity.ts`) — never recompute the formula here. Edge styling encodes capacity **per direction**:
  thickness and/or colour from the directed capacities, and an **arrowhead for the lift direction**
  (stock↔foil orientation). An `Infinity` (unlimited) capacity needs a distinct, non-saturating style (do not
  map `Infinity` onto a max-thickness that a merely-large finite value also hits).
- Parallel tallies between the same pair are distinct edges (the model allows multi-edges); render them so
  they are visually separable (graphology multi-graph + sigma edge curvature).

### Rendering (`src/graph/render.ts`)

- `sigma.js` over the graphology graph, WebGL. Zoom, pan, hover tooltips for a node (entity details) and an
  edge (the tally's two directed capacities, orientation). A **search box** to find an entity by id and
  centre/highlight it.
- Hover/selection highlighting is local state on top of the sigma reducers; keep it separate from the
  timeline-driven "lit" state the replay ticket adds, so the two compose rather than fight.

### Layout (`src/graph/layout-worker.ts` + `src/graph/layout.ts`)

- Run **ForceAtlas2 in a Web Worker** (`graphology-layout-forceatlas2/worker`) so the main thread stays
  responsive while a large graph settles. Stream positions back to the main thread and apply them to sigma.
- **Seed the initial positions deterministically** (seeded circular or random init keyed off the network's
  `meta.seed`) so re-loading or replaying the *same* network gives a **stable** layout — the replay animation
  must not reshuffle the cloud. Document the seeding in design.md.
- Provide a "layout settled" signal so the replay ticket can wait for a stable layout before animating.

## Edge cases & interactions

- **Thousands of nodes**: this is the headline target. Keep layout off the main thread; do not attach
  per-node DOM. Verify interactivity (pan/zoom/hover) stays smooth on a generated ~2–5k-node network (a
  `scale-free`/`uniform` network materialised in-page via tallysim, or a saved trace of one).
- **Empty / tiny network**: 0 entities, 1 entity (no edges), 2 entities / 1 tally — all render without
  throwing; the layout worker must not hang on a trivial graph.
- **Unlimited-capacity networks**: every edge `Infinity` in one or both directions — styling stays legible
  (distinct unlimited style, not a saturated finite style).
- **Parallel edges and zero-capacity directions**: a tally with `cap == 0` one way is a valid state — its
  arrowhead/thickness must still read correctly (zero is not "missing").
- **Theme switch mid-view**: re-themes without a full reload or layout recompute (positions are theme-independent).
- **WebGL unavailable**: detect and show a clear message rather than a blank canvas / thrown error.
