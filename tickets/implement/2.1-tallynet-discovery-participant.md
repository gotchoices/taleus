The **participant** side of unidirectional discovery: the code that runs at every node a query passes through. The originator side and the end-to-end wiring are the next ticket (`tallynet-discovery`); this ticket delivers the data model, the durable/in-flight state split, and the participant's `enter`/`reenter` logic with every ChipNet discovery defect fixed, each covered by a unit test driven through a stub `queryPeer`.

Read `packages/tallynet/docs/chipnet-review.md` § *Discovery* and § *Discovery defects*, and `docs/design.md` § *Protocol design*. Upstream source to port (read, don't depend): `../chipnet/src/unidirectional/{participant,participant-state,query-context,active-query,find-result,query}.ts` and `../chipnet/src/{plan,member,intent,target,query-struct,reentrance,address}.ts`. All known defects and exact line references are in the review table; the originator's `participant.ts:102` hardcoded `1000` ms budget belongs to the next ticket but the participant must accept and honour a real budget argument now.

## Data model (`src/discovery/types.ts`)

Generic over link terms `TTerms` and plan payload `TPayload`. TallyNet never inspects either; it hands them to the host's callbacks. Intent codes are `string`.

```ts
/** A party authorised at a link: whoever holds the private key registered there. */
export interface Address { key: string }          // base64url public key; no cuid (ChipNet's optional narrowing dropped)

export type MemberType = 'P' | 'R'                 // participant (must promise) | referee (votes)
export interface Member { types: MemberType[]; physical?: string; secret?: string; noCache?: boolean }
export interface IdentifiedMember extends Member { address: Address }
export interface DependentMember extends IdentifiedMember { dependsOn?: Address[] }

/**
 * One link shape only (ChipNet had two: PlanLink's record vs Link.intents array — collapsed here).
 * `intents` maps an intent code to that code's terms.
 */
export interface Link<TTerms> { nonce: string; intents: Record<string, TTerms> }

export interface Plan<TTerms, TPayload> {
	path: Link<TTerms>[]            // grows outward, one link per hop
	members: DependentMember[]      // filled on the way back, participants first
	payload?: TPayload
}

export interface Target { address: Address; physical?: string; secret?: string }

export interface UniQuery<TTerms> {
	target: Target
	sessionCode: string
	intents: Record<string, TTerms>
	maxDepth: number               // carried on the query so every node agrees on the ceiling
}

export interface Reentrance { sessionCode: string; path: string[] }

/** Minimal, informational timing. NOT trusted for control flow (see § Time budget in the engine ticket). */
export interface QueryStats { earliest: number; latest: number; gross: number; outstanding: number }

export interface QueryRequest<TTerms, TPayload> {
	entrance?: { query: UniQuery<TTerms>; plan: Plan<TTerms, TPayload> }
	reentrance?: Reentrance
	budgetMs: number
}

export interface QueryResponse<TTerms, TPayload> {
	plans?: Plan<TTerms, TPayload>[]
	reentrance?: Reentrance
	stats: QueryStats
}

/** What the host's findAddress returns for one node. */
export interface PrivateLink<TTerms> { id: string; intents: Record<string, TTerms> }
export interface Match { member: IdentifiedMember; dependsOn?: IdentifiedMember[] }
export interface PeerMatch<TTerms> { match: Match; link: PrivateLink<TTerms> }
export interface FindResult<TTerms, TPayload> {
	self: Match
	selfIsMatch: boolean
	peerMatch?: PeerMatch<TTerms>[]     // a neighbour IS the target (list: may be >1 link to it)
	candidates?: PrivateLink<TTerms>[]  // links worth searching further
	payload?: TPayload
}

export type QueryPeerFunc<TTerms, TPayload> =
	(request: QueryRequest<TTerms, TPayload>, linkId: string) => Promise<QueryResponse<TTerms, TPayload>>

export type FindAddressFunc<TTerms, TPayload> =
	(query: UniQuery<TTerms>, inLinkId?: string) => Promise<FindResult<TTerms, TPayload>>
```

### Negotiation hooks (`src/discovery/hooks.ts`)

These replace ChipNet's `NegotiateIntentFunc` / `intentsSatisfied` / `prependMatch`-callback and carry the hop context the multi-denomination ticket needs — **without** implementing any conversion here. Ship ChipNet's single-unit behaviour as the defaults.

```ts
export interface DiscoveryHooks<TTerms, TPayload> {
	/**
	 * Constrain one candidate link's terms for one intent code, given the hop.
	 * `inboundTerms` is that code's terms on the inbound link (the last path link); undefined at the originator.
	 * Returns the outbound link's terms as constrained, or undefined to drop this code on this candidate.
	 * Default: pass linkTerms through when the query carries `code`, else undefined (single-unit; context ignored).
	 */
	negotiateIntent(ctx: { code: string; linkTerms: TTerms; inboundTerms?: TTerms; query: UniQuery<TTerms> }): TTerms | undefined

	/**
	 * Does this whole plan satisfy the query? Replaces ChipNet's per-link uniform intentsSatisfied.
	 * Default: for every code in query.intents, every link of the plan carries that code (ChipNet's shape,
	 * with a trivially-true per-term predicate). Document that the default ignores term *values*.
	 */
	planSatisfies(query: UniQuery<TTerms>, plan: Plan<TTerms, TPayload>): boolean

	/**
	 * Return-path hook, called where ChipNet calls prependMatch, once per plan this node is about to
	 * prepend itself onto. `inboundNonce` is the nonce of the link this node was reached by (undefined
	 * at the originator). Return the (possibly amended) plan, or undefined to drop it. This is where the
	 * multi-denomination ticket will later compute req_in from req_out with a private quote.
	 * Default: identity (no annotation).
	 */
	annotateReturn?(ctx: { plan: Plan<TTerms, TPayload>; self: Match; inboundNonce?: string }): Plan<TTerms, TPayload> | undefined

	/** Optional plan vetting/extension (e.g. add referees). Default: identity. ChipNet's NegotiatePlanFunc. */
	negotiatePlan?(plan: Plan<TTerms, TPayload>): Plan<TTerms, TPayload> | undefined
}

export function defaultHooks<TTerms, TPayload>(): DiscoveryHooks<TTerms, TPayload>
```

The engine still owns the actual member-prepend (ChipNet's `prependMatch` body: build the `DependentMember`, upgrade existing members with physical/secret from `dependsOn`, append missing dependents, and reject a non-participant match or a participant appearing in `dependsOn`). `annotateReturn` runs **before** that prepend; if it returns undefined the plan is dropped. Keep `prependMatch` as an internal engine function, not a hook.

## State split (`src/discovery/store.ts`)

The core correction over ChipNet: **durable context holds only serialisable data; in-flight requests live in an in-memory table.** ChipNet stored live `Pending<QueryResponse>` promises inside the context it handed to `saveContext` (`query-context.ts:12`, `active-query.ts:14`) — a SQL-backed store cannot persist that.

```ts
/** A candidate edge under consideration, fully serialisable. No live promise. */
export interface StoredCandidate<TTerms> {
	linkId: string
	nonce: string
	depth: number
	intents: Record<string, TTerms>   // negotiated outbound terms for this candidate
	lastResponse?: QueryResponse<TTerms, TPayload>  // the most recent completed answer, if any
}

/** The durable per-(session, path) query context. Everything here round-trips through JSON/CBOR. */
export interface StoredContext<TTerms, TPayload> {
	query: UniQuery<TTerms>
	plan: Plan<TTerms, TPayload>        // the under-construction plan as this node received it
	self: Match
	candidates: StoredCandidate<TTerms>[]
	nonceToLinkId: Record<string, string>
	plans?: Plan<TTerms, TPayload>[]    // concluding plans, once satisfied
	depth: number
	complete: boolean                   // true once a concluding response was given (no activeQuery)
}

export interface ParticipantStore<TTerms, TPayload> {
	/** Throw iff a context already exists for (sessionCode, path). FIX ChipNet's nesting bug: key must
	 *  match between validateNewQuery and getContext/saveContext (ChipNet checked a flat `s:path` key
	 *  against a map nested by session, so it never fired — memory-participant-state.ts:25,32). */
	validateNewQuery(sessionCode: string, path: string[]): Promise<void>
	getContext(sessionCode: string, path: string[]): Promise<StoredContext<TTerms, TPayload> | undefined>
	saveContext(context: StoredContext<TTerms, TPayload>, path: string[]): Promise<void>
	/** Union of every stored context's nonceToLinkId for this session (used by the later commit engine). */
	getNonceToLinkMap(sessionCode: string): Promise<Record<string, string>>
}

/** Reference in-memory store for tests and the simulator. Keyed consistently by `${sessionCode}\u0000${path.join(',')}`. */
export class MemoryParticipantStore<TTerms, TPayload> implements ParticipantStore<TTerms, TPayload> { … }
```

- Drop ChipNet's `reportCycles` / `reportTimingViolation` / `getPeerOverhead` / `reportOverhead` store methods: cycle pruning is now a **trace event** (`candidate-pruned` reason `cycle`), and peer timing is no longer trusted (see engine ticket), so there is nothing to report. If the engine still wants a learned-overhead hint later, that is a backlog concern, not a store method.
- The in-flight table is **not** in the store. It is an in-memory map the participant holds, keyed by `(sessionCode, path, linkId)` → `Pending<QueryResponse>`. Define it in `src/discovery/participant.ts`. A restart loses it (see below).

## Participant (`src/discovery/participant.ts`)

Construct with: options, a `ParticipantStore`, the `Clock`, a `RandomSource`, a `TraceSink` (default `noopTraceSink`, wrap with `safeTraceSink`), the host `Hasher` (for nonces via `makeNonce`), the session-code validators, a `nodeId` (its own id, for trace stamping), `findAddress`, the `DiscoveryHooks`, and `queryPeer`. Expose `query(request, inLinkId?)` dispatching to `enter`/`reenter`.

**`enter(plan, query, budgetMs, inLinkId?)`** — first visit (depth 1):
1. Validate with a `RuleSet` (port ChipNet's): session code valid; session long-lived enough (`getExpiration >= now + minSessionMs`, now from the Clock); **empty plan iff no inbound link**; inbound link's nonce matches the plan tail. Error messages must **not disclose link ids** (ChipNet's own note at `participant.ts:320`).
2. `validateNewQuery` — reject a duplicate visit for this (session, path). (Now actually fires.)
3. Build the context: call `findAddress`; compute nonces for candidates, peer-match links, and the inbound link; negotiate candidate intents via `hooks.negotiateIntent` (hop context: `inboundTerms` from the plan tail's matching code); build plans for self-match / peer-match; **remove cycles** — a candidate whose nonce already appears in `plan.path` is dropped, not merely reported (FIX `participant.ts:233-244`), emitting `candidate-pruned`/`cycle`; drop candidates left with no eligible intents.
4. Save the context (durable; `complete=false` if candidates remain, else the concluding plans with `complete=true`). Emit `query-received`.
5. Return plans found so far (each run through `negotiatePlan`, dropped if it returns undefined) plus a reentrance ticket **iff** candidates remain.

**`reenter(reentrance, budgetMs, inLinkId?)`** — search one level deeper:
1. Validate the ticket: session not expired (`expired` prune reason + trace if it is); load the context (throw "query already complete" if `complete`/no candidates — don't disclose ids); re-validate inbound link nonce against the plan tail; **enforce maxDepth** against `query.maxDepth` (prune reason `max-depth`).
2. **Reconcile in-flight with durable.** For each candidate: if there is a live `Pending` for it, read its settled/outstanding state; if there is none (fresh, or **lost to a restart**), fall back to its durable `lastResponse`. Harvest completed answers: fold any that arrived since last round into `lastResponse` (emit `late-answer-folded` for answers that completed out-of-phase). If the completed plans already satisfy the query (`hooks.planSatisfies`), conclude early.
3. Otherwise issue the next batch: a candidate never tried (no `lastResponse`, no live Pending) gets an **entrance** with this hop's link appended to the plan; a candidate whose `lastResponse` carried a reentrance gets a **reentrance**. A sleeping candidate (a live Pending still outstanding) is left in place — its budget is what it is.
4. Await them with `budgetedStep(clock, budgetMs - elapsed, requests)` — **the real remaining budget**, computed from the Clock (FIX the hardcoded `1000`), always clearing the timer (the scaffold's `budgetedStep` already does). Emit `round-budget-expired` when the budget cuts the step short.
5. **Prune** candidates that show no promise: errored, or returned neither a plan nor a reentrance, are dropped (FIX `participant.ts:113`, whose `!r || !r.isError || !r.isResponse || …` kept nearly everything), each with a `candidate-pruned` trace carrying the right reason (`failed` / `no-reentrance` / `timed-out`). A candidate with a reentrance survives.
6. Persist: write each completed request's response into its candidate's durable `lastResponse`, drop pruned candidates, bump depth, `complete=true` iff satisfied. **The durable context never holds a live Pending.**
7. Return: plans (each `annotateReturn`-ed then self prepended via `prependMatch`, dropped if `annotateReturn` returns undefined), plus the reentrance ticket iff surviving candidates remain. Emit `plan-returned` per link a plan goes back on.

### Options (`src/discovery/participant.ts`)
Port ChipNet's `UniParticipantOptions`: `maxQueryAgeMs` (default 10 000), `maxDepth` (default 7; the query's `maxDepth` is authoritative per-search), `minSessionMs` (default 30 000), `negotiatePlan?`. Drop `timingStatBuckets`/`debugBudget` (no histogram; see engine ticket). All defaults documented.

## Determinism

No `Math.random` (draw from the injected `RandomSource`). Where candidate **iteration order** would otherwise be decided by `Record` key order (e.g. assembling `nonceToLinkId`, ordering the next batch of sub-queries), sort by a stable key (nonce) so a seeded run is reproducible. No `Date.now`/global timers — everything through the `Clock` (the `no-node-globals` test from the ports ticket already enforces this; keep it green).

## Edge cases & interactions (write a test for each)

- **Cycle**: a candidate whose nonce is already in the path is *removed* (not just reported), with a `candidate-pruned`/`cycle` trace. (ChipNet only reported it.)
- **Prune**: failed / errored / timed-out candidates are dropped; a candidate with no remaining reentrance and no plan is dropped.
- **Duplicate query, same path**: `validateNewQuery` throws (now actually fires). **Same session, different path** (arrived by two routes): allowed — distinct context per path key.
- **Inbound nonce ≠ plan tail** → reject. **Empty plan with an inbound link, or non-empty plan with none** → reject. **Reentrance whose session ≠ stored context session** → reject. Error strings disclose **no** link ids.
- **Max depth reached** → prune `max-depth`, no further entrance. **Session code expired mid-search** → refuse, `expired`. **Session with too little life left** (`< minSessionMs`) → refuse at `enter`.
- **Self is the target** (circular lift: originator is also the payee) → self-match plan; a member may appear on more than one link, so return *all* matching links, not one. **Target is a direct peer** → peer-match plan at depth 1. **Target unreachable** → empty plans, a reentrance only while candidates remain, never a throw.
- **Participant restart between rounds**: durable context present, in-flight table empty. A reenter re-issues entrance/reentrance for candidates whose live Pending is gone, driven by their durable `lastResponse`; no plan is double-counted (the durable `lastResponse` is the single source of truth) and none is lost (a candidate with no stored response is simply re-queried).
- **Sleeping peer** (never answers): skipped by the budget each round; if it answers late, the next `reenter` folds that answer in (`late-answer-folded`), not lost, not double-counted.
- **Concurrent sessions on one participant** do not share state (keyed by session+path); **no leaked timers** (every `budgetedStep` clears).
