		const state = await this.getRecordState(record)

	/** Responder: our current merged record for `transactionCode`, or undefined. Safe to serve anyone (self-authenticating; union merge makes a stale/dup reply harmless). docs/design.md § Record availability. */
	serveRecord(transactionCode: string): Promise<TrxRecord<TTerms, TPayload> | undefined> {
		return this.store.getRecord(transactionCode)
	}

	/** Requester: pull the record from each reachable peer and update() every reply (idempotent), then return our outcome. No stored record ⇒ `pending`, pull nothing (no topology ⇒ can't address a pull; the timer-driven recovery loop is tallynet-propagation-timeouts, a seam). reachablePeers read ONCE (topology immutable). */
	async fetchOutcome(transactionCode: string): Promise<'commit' | 'void' | 'pending'> {
		const record = await this.store.getRecord(transactionCode)
		if (!record) { return 'pending' }
		for (const peer of this.reachablePeers(record)) {
			const reply = await this.fetchRecord(transactionCode, peer)
			if (reply) { await this.update(reply, peer) } // peer as fromAddress → primes skip-test, no echo back
		}
		return this.outcome(transactionCode)
	}

	/** Surface a settled-outcome contradiction (we committed while a reachable copy voided, or vice versa — only possible when voters equivocated). Flag + trace; remedy is host policy (ChipNet § Lying referees), not built here. */
	private async detectContradiction(received: TrxRecord<TTerms, TPayload>, merged: TrxRecord<TTerms, TPayload>): Promise<void> {
		const ours = await this.recordOutcome(merged)
		if (ours !== 'commit' && ours !== 'void') { return }
		// NOTE: recordOutcome(received) reads the RAW incoming record. Its commit/void-by-majority signal is verified
		// (countVerifiedCommits re-verifies), but its promise-phase void signal (an NP in received.promises) is NOT
		// verified here — a hostile peer could set this flag spuriously with a forged NP. Observational only
		// (settlement untouched; consumer is future feat-tallynet-hostile-peers); if that ticket acts on the flag, verify received's NP first.
		const theirs = await this.recordOutcome(received)
		const contradicts = (ours === 'commit' && theirs === 'void') || (ours === 'void' && theirs === 'commit')
		if (!contradicts || (await this.store.hasContradiction(merged.transactionCode))) { return }
		await this.store.setContradiction(merged.transactionCode)
		const peerOutcome: 'commit' | 'void' = ours === 'commit' ? 'void' : 'commit'
		this.traceSink({ ...this.traceBase(merged), type: 'contradiction-detected', transactionCode: merged.transactionCode, ourOutcome: ours, peerOutcome })

### Design gotchas the next run must respect
- A linear lift has all-participant interiors, so a refuser that NEVER pushes stalls the promise phase (its own `P` never propagates). The `refuseRelay` model therefore relays **promise-phase** records and only drops **commit-phase** ones — that is why the promise phase still completes and only the commit evidence is blocked.
- Why a pull is genuinely needed: a plain cooperating neighbour (e.g. the originator) would bridge the commit to a cut-off node, so the cut-off node (`F`) must have **no contact point** and its only neighbour must be the refuser; then push can't reach it and the pull (to a voter's/originator's contact point) is the only path.
- `fetchOutcome` must compute `reachablePeers` from the node's OWN stored record (topology is immutable, so it is stable across the merges it triggers). No record ⇒ no pull.
- Only **verified** contradicting faces become proof; the authoritative sets and settlement are untouched. The proof cap is unreachable by honest/verified faces (≤2 per phase); it is a hostile-growth guard only.

## Record availability — the pull

Push-to-reachable (both link directions) is built. Add a **pull** so a node can obtain the record from anywhere that holds it:

```ts
/** Host port: ask `from` for its current record for this transactionCode. Returns undefined if it has none. */
export type FetchRecordFunc<TTerms, TPayload> =
	(transactionCode: string, from: Address) => Promise<TrxRecord<TTerms, TPayload> | undefined>

// The participant gains:
//   - a responder: given a transactionCode, return our merged record (or undefined) — safe to serve to anyone,
//     the record is self-authenticating (every signature verifies); union merge makes a stale/duplicate reply harmless.
//   - a requester: fetchOutcome(transactionCode), which pulls from the reachable set (contact points + neighbours)
//     and update()s each reply (idempotent merge), so a node that was cut off catches up when it reconnects.
```

Who a node can pull from: any member with a published `physical` contact point, plus its direct link neighbours — the same reachable set `reachablePeers` already computes. A node that published no contact point can still pull from, and be pushed to by, its neighbours.

**The guarantee to prove.** With **at most one** non-cooperating member (refuses to sign and/or relay) and contact points on the **originator and every voter**, every cooperating member obtains the outcome: the deciding majority assembles at some voter, pushes to every contact point, and any cooperating member that a refuser sat between pulls the settled record directly from a voter. State and test this. At **k > 1**: the guarantee holds only while the cooperating members plus published contact points keep a voter-majority assembled and every cooperating member reachable from it; a cut isolating a cooperating member from all voters' contact points *and* every alternate path leaves it pending until any single cross-partition link returns (ChipNet § Network splits). Record this precisely in design.md (already drafted there — confirm it matches what ships).

## Equivocation proof kept

Today a voter signing both faces has its second face dropped (`rejectSignature`, log-and-discard). Keep **both** faces as proof, without changing settlement:

- Add a durable **proof store** keyed by `(transactionCode, signerKey)` holding every distinct signed face seen from a signer (both `C` and `NC`, or both `P` and `NP`). This is side state, like the pending-commit pool: **never** merged into the authoritative sets, never pushed, never digested.
- The authoritative `promises`/`commits` sets still keep only the **first** verified face (settlement is unchanged — the equivocation-vs-changed logic in `mergeSignature`/`promoteCommit` stays). When a second, *contradicting* face from the same signer verifies, store it as proof **in addition to** logging the `equivocation` rejection.
- Expose the proof: a method to read a signer's retained faces for a transaction, so `feat-tallynet-hostile-peers` and `feat-lift-healing` can act on it, and the simulator can count equivocations.
- **Contradiction surfacing.** When a member's own settled outcome contradicts a neighbour's (it voided while a reachable member committed, or vice versa — observable because the record a node holds can show a deciding majority the opposite way for a stored vs. pulled copy), surface the contradiction (a trace event + a queryable flag). The **remedy** is host policy, not protocol (a voided-but-downstream-committed member stays voided and may join a correcting lift; a committed-but-downstream-voided member builds a compensating reversal — ChipNet § Lying referees). Do not build the remedy here; build the detection + the proof it needs.

## Edge cases & interactions

- Linear 4-node lift, interior node refuses to relay, contact points on originator + voters: the far member pulls and settles. Same topology **without** contact points: the far member stays pending (assert the gap, documenting why — this is the k with no contact points case).
- Circular lift, one refuser: the ring routes around it with no contact points (already works via the diamond test; add the linear contrast).
- A pull reply carrying **less** than the puller already knows: union merge adds nothing (idempotent) — assert no regression and no echo storm.
- A pull reply carrying a **forged** signature: dropped by the existing verify-on-merge path; the pull cannot inject unverified state (principle: nothing unverified blocks a verified vote).
- Equivocation: a voter signs `C` to one neighbour and `NC` to another. Both faces reach some node; the first verified face settles, the second is stored as proof + logged. Assert both faces are retrievable and settlement matches the first face.
- Proof store growth: cap per signer (like the pending-commit pool's `MAX_PENDING_COMMITS_PER_VOTER`) so a hostile peer cannot grow it unbounded; a genuine signer contributes at most two faces per phase.
- The payee going silent after word reached the originator: the originator already holds the full plan (minting happened), so this does not block settlement — assert.
- The originator unreachable after promises: any voter that holds a majority still pushes/serves it; cooperating members pull from voters. Assert a lift settles with the originator offline post-promise.
- Interplay with the forged-vote side pool: the pull and the proof store are both side state; neither may promote an unverified signature into the counted sets.
- Timeouts are out of scope (`tallynet-propagation-timeouts`); the pull is on-demand here, not yet driven by a timer — leave that seam (the recovery loop that calls `fetchOutcome` periodically is the next ticket).
