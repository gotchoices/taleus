## Scenarios to add (harness/runner + tests)

Model these on the existing direct-lift test harness in `packages/tallysim/src/sim/voter-harness.test.ts` (it
builds multi-voter lifts and drives them), not necessarily as new sweep `ConsensusSpec` knobs — most are lift-shaped
assertions, not sweep cells.

- **Stalled by a silent/sleeping minority voter → voids by the deadline.** A multi-voter lift with one (or a
  minority of) voters made sleeping (`conditions.sleepingFraction`, or a targeted silent member). Under
  `runUntilIdle` the deadline fires and the lift **voids** by itself. Assert outcome `void`, `voidReason`
  `'voted-no-commit'` (per 6.31's taxonomy check), balances unchanged, `net.deliveryErrors === []`.

- **Dropped commit-push (interior non-relayer) → recovers by the loop.** A line/ring lift with a non-relayer cut
  off from the commit push. Assert every cooperating member reaches `commit` (`cooperatingCompletion === 1`) via
  the protocol's own recovery loop — with the manual `recoverStrandedByPull` gone (6.31), the loop must do it.

- **Network split → `pending` while split, convergence after rejoin.** Partition the route's links via conditions
  (drop) to isolate a cooperating member or split the voter set; assert `pending` while split, then **rejoin** and
  assert convergence. **Design note / open problem:** the harness's conditions map is static per `buildSimNetwork`,
  so "rejoin" needs a mechanism to change link conditions mid-lift. Weigh: (a) a dedicated test that drives the lift
  under split conditions to `pending`, then rebuilds the sim with healed conditions and re-drives the *same*
  transaction to convergence (the record is in the per-node stores; a pull/push after healing settles it) — mirror
  the tallynet E2E "network-split rejoin heal" test the 6.2 review cites; or (b) a conditions surface that can be
  mutated between `runUntilIdle` passes. Prefer (a) if it works without new harness plumbing. Document whatever you
  pick.

- **Permanently-stuck (needed party never returns) → stays `pending`, recovery abandons after the ceiling; count
  it.** Use a small `ConsensusSpec.recoveryGiveupMs` (6.31's knob) so the loop abandons quickly instead of polling
  a virtual hour. Assert outcome `pending`, `voidReason` `'stalled'`, and that the run's `permanentlyPendingCount`
  / `permanentlyPendingFraction` (6.31's metrics) count it. A `recovery-abandoned` trace event should be present.

## Measurements to confirm end-to-end (metrics already defined in 6.31)

Drive a runner sweep (or direct-harness aggregation) that exercises the above and assert the 6.31 metrics read
sensibly: `timeToSettleMs` (time-to-resolution) includes the timeout-driven void settlements; `creditHeldMsPerLift`
reflects how long each lift tied up credit; `permanentlyPendingCount`/`Fraction` counts the never-resolved lifts.

## Determinism / seed-stability

Add a **seed-stability test over the added timers**: two runs at one seed produce identical time-to-resolution and
credit-held distributions (and identical outcomes). The deadline + recovery timers must not read the shared
session-code random — confirm the independence holds with the new scenarios in the mix.

## Edge cases & interactions

- **Balance safety.** A timeout void leaves balances unchanged (only a commit moves them); a split that later
  commits moves them exactly once. Assert `net.deliveryErrors === []` on clean runs and conservation of balance
  across the route.
- **No regression of the pinned discovery sweep.** Only the lift record / consensus config are driven; the shared
  discovery adjacency stays byte-identical (the finite-ification caveat).
- **Tripwire parking.** The 6.2 handoff noted the stale comment "v1 has no propagation-timeout loop" in
  `consensus-harness.ts` and the `O(members²)` pull-pass NOTE — both are superseded once the manual pull is gone
  (6.31). If any conditional concern remains (e.g. "split-rejoin re-drives the whole lift; if routes get large,
  batch the re-drive"), park it as a `NOTE:` at the site and index it in the review's `## Review findings`, not as a
  ticket.
