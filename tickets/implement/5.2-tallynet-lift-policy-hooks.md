Principle 0 (no global rules; each node decides) needs decision points. Some already exist — `DiscoveryHooks` (discovery) and `TrxParticipantResource.shouldPromise` (promise time). This ticket adds the voter-model-specific ones, with simple default policies the simulator (`tallysim-voter-model`) uses, and keeps TallyNet itself policy-free: the protocol enforces only verified signatures, the threshold invariant and (later) the deadline.

### Key facts about the current code

- **`ResourceContext`** (`consensus/resource.ts:42-47`) already carries `member`, `inLinks`, `outLinks`, `record`. The `record` (`consensus/types.ts:94-105`) carries `topology.members` (DependentMember[] with `types` incl `'V'`), `method` (`ConsensusMethod` = `{weighting, thresholdNum, thresholdDen}`), optional `liftContract` (CID string), `transactionCode` (deadline via `expiresAt`). So **`shouldPromise`/`acceptsProposal` already see everything principle 0 needs** — only the doc is missing.
- **`castPromise`** (`consensus/participant.ts:544-561`) today: `anyCodeExpired` → NP; else `shouldPromise?.() ?? true` false → NP; else `try promise()` catch → NP; else P. A **throwing** `shouldPromise` currently *propagates* (not caught). The ticket wants the ordering `acceptsProposal → shouldPromise → promise` where the first **false OR throw** signs NP. So gate throws must be caught → NP (a deliberate, safe refinement; no existing test makes a gate throw).
- **`SignatureTypesLocal`** (`consensus/participant.ts:843`) = `{ promise: 'P', noPromise: 'NP' }`. `promise-signed` trace already carries `signatureType: 'P'|'NP'` — that IS the "trace the NP". The "logged reason" is an extra `this.log(...)` line; **no new trace field/type needed**.
- **Discovery hooks** (`discovery/hooks.ts`): `negotiateIntent` + `planSatisfies` required; `annotateReturn` + `negotiatePlan` optional. `defaultHooks()` (`:74-85`) returns all four as ChipNet/identity behaviour. `negotiatePlan(plan)` already receives the whole plan incl `plan.members` (voters-so-far) and **can already drop a plan by returning `undefined`** — the participant's `returnPlan` (`discovery/participant.ts:479-489`) honours it. So voter-set-refusal at return-trip is a **doc-only** change on `negotiatePlan`.
- **`enter`** (`discovery/participant.ts:188-209`): validates query (`queryRules.runAndCheck`, throws on malformed), `validateNewQuery` (throws on dup), traces `query-received`, builds+saves context, returns response (reentrance iff candidates). `reenter` has **no access to the full query** (only session+path; the query lives in the stored context) — so `acceptsQuery` must gate at **`enter` only**. A refused node must **return an empty response (no plans, no reentrance), never throw** — the originator's own round-0 `enter` runs here too and the originator never throws for "not found" (`originator.ts:120` doc). Upstream then prunes it `no-reentrance`.
- **`validateNewQuery`** only checks for a duplicate (`store.ts:92-97`); it persists nothing. Safe to run `acceptsQuery` either side of it; recommended placement is **after** `query-received` trace so a viewer still sees the node received the query.
- **Originator `discover`** (`discovery/originator.ts:140-159`): per round, `satisfying = plans.filter(planSatisfies)`; if any, trace one `plan-found` each and `return { sessionCode, plans: satisfying }`. This is where `scorePlan` ranks+filters. **Do NOT add keep-searching-on-all-rejected logic** (that's a retry policy; ticket forbids baking it in). The loop still stops the round it first finds satisfying plans; scoring then ranks/drops within that set.
- **Default discovery harness** (`testing/network.ts:564-577`) makes every `self`/`peerMatch` member a **participant only** (`types: [P]`), no voters. So in the existing end-to-end tests every plan has **0 voters** → default `scorePlan` falls through to path-length then first-found. Ordering-sensitive assertions: the diamond test (`testing/discovery.test.ts:359`) compares a **set** of path keys (order-independent, stays green); most others expect exactly 1 plan. **Sorting plans best-first keeps all existing tests green.**
- **No dedicated originator test file**; the originator is covered by `src/testing/discovery.test.ts` (end-to-end). Consensus hooks are covered by `src/consensus/participant.test.ts` (single-node, hand-built records; `makeResource(opts)` double at `:166-207`, promise-phase tests at `:480-548`). /**
```ts
 * Proposal gate — the FIRST policy check at promise time (only an expired code refuses ahead of it),
 * before {@link shouldPromise}. Accept the record's **proposal parameters for OUR participation**: its
 * voter set, its consensus method, and its lift contract, weighed together. `false` → we sign `NP`
 * (no-promise) and nothing is held; any `NP` voids the lift. Default when omitted: `true` (accept —
 * today's behaviour). A thrown error is treated exactly as `false` (NP, logged).
 *
 * Pure host **policy**: TallyNet enforces only verified signatures, the strict-majority+threshold
 * invariant and (later) the deadline. "Refuse a thin/stacked voter set" lives HERE (e.g. the sim's
 * voter-model policy), never in the protocol — the protocol will settle a lone-voter set per the
 * threshold.
 *
 * The {@link ResourceContext} (shared with {@link shouldPromise}) exposes everything principle 0
 * ("no global rules; each node decides") needs:
 *   - full **voter set** — `ctx.record.topology.members` with `types` incl `'V'` (a referee is `V` not also `'P'`);
 *   - **consensus method + threshold** — `ctx.record.method` (`{ weighting, thresholdNum, thresholdDen }`);
 *   - **deadline** — `expiresAt(ctx.record.transactionCode)`;
 *   - **lift contract CID** — `ctx.record.liftContract` (absent when none);
 *   - our **own edge terms** — negotiated per-intent terms on `ctx.inLinks` / `ctx.outLinks`.
 */
acceptsProposal?(ctx: ResourceContext<TTerms, TPayload>): boolean | Promise<boolean>
```

### 2. `consensus/participant.ts` — wire the gate ordering into `castPromise`

Refactor `castPromise` to a small `promiseDecision` that preserves `this.resource` binding (call through `this.resource.x?.()`, do not detach the method) and catches gate throws as NP:

```ts
private async castPromise(record: TrxRecord<TTerms, TPayload>): Promise<void> {
  const context = this.resourceContext(record)
  const decision = await this.promiseDecision(record, context)
  await this.sign(record, decision, 'promises')
  this.traceSink({ ...this.traceBase(record), type: 'promise-signed', transactionCode: record.transactionCode, signatureType: decision })
}

/** P vs NP: expiry first, then acceptsProposal, then shouldPromise, then the hold. The first refusal —
 *  a false result OR a throw from either gate, or a throwing hold — signs NP and holds nothing. */
private async promiseDecision(record, context): Promise<SignatureType> {
  if (this.anyCodeExpired(record)) { return SignatureTypesLocal.noPromise }
  try {
    if (!(await (this.resource.acceptsProposal?.(context) ?? true))) {
      this.log('tallynet consensus: proposal refused (voter set / method / contract) on transaction %s', record.transactionCode)
      return SignatureTypesLocal.noPromise
    }
    if (!(await (this.resource.shouldPromise?.(context) ?? true))) { return SignatureTypesLocal.noPromise }
  } catch (error) {
    this.log('tallynet consensus: a promise gate threw on transaction %s; signing NP: %o', record.transactionCode, error)
    return SignatureTypesLocal.noPromise
  }
  try { await this.resource.promise(context) }
  catch (error) { this.log('tallynet consensus: promise refused on transaction %s: %o', record.transactionCode, error); return SignatureTypesLocal.noPromise }
  return SignatureTypesLocal.promise
}
```

Signature:
```ts
/** Score a returned plan; the originator drives the highest score. Lower-is-worse; -Infinity ⇒ never pick.
 *  Default: fewer voters, then shorter path, then first-found (deterministic). */
scorePlan?(plan: Plan<TTerms, TPayload>, query: UniQuery<TTerms>): number
```

Default implementation (single scalar so "fewer voters strictly dominates shorter path"; path length ≤ maxDepth so the fraction never overflows an integer):
```ts
function defaultScorePlan(plan, query): number {
  const voters = plan.members.filter((m) => m.types.includes('V')).length
  const hops = plan.path.length
  return -(voters + hops / (query.maxDepth + 1))   // higher = fewer voters, then shorter path
}
```

In `discover`, replace `return { sessionCode, plans: satisfying }` with a rank step:
- score each satisfying plan;
- drop any plan whose score is NOT `> -Infinity` (this cleanly drops `-Infinity` AND `NaN`; `+Infinity` passes);
- sort survivors by score **desc**, ties broken by original index **asc** (explicit index tiebreak — don't rely on sort stability) → first-found wins ties;
- `return { sessionCode, plans: ranked }`. `ranked[0]` is the **winner**; `ranked[1..]` are the passed-over plans, best-first. Empty `ranked` (all `-Infinity`) ⇒ caller sees "no acceptable route" (no throw).

Keep the per-plan `plan-found` traces (emit before ranking, over `satisfying`). Document in `discover`'s doc that the result's `plans` are returned **best-first (winner at index 0, passed-over after)** — that is how a sim/viewer reads which plan won and which were passed over (surfacing requirement met without touching `trace.ts`).

## Edge cases & interactions (unchanged from original spec)

- `acceptsProposal` false on a middle participant → signs `NP` → lift voids in the promise phase (any `NP` voids). Assert it.
- A voter set of 1 or 2 the default should arguably refuse: keep the **protocol** permissive (settles per threshold); put "refuse a thin set" in the **default sim policy** (`acceptsProposal`/`scorePlan`), not the protocol. Document the split.
- `scorePlan` returning `-Infinity` for every plan → originator returns empty `plans` → caller treats as "no acceptable route" (not a crash).
- A stacked voter set: default `scorePlan` ranks it below a lean set; a test asserts the lean plan wins.
- Promise-time hook ordering: `acceptsProposal` → `shouldPromise` → `promise`; first false/throw signs `NP`, holds nothing (ChipNet ordering fix must not regress).
- Discovery hooks stay **synchronous**; promise-time hooks may be async (every call site already awaits).
- No hook may let unverified input change verified state — these hooks gate only *our own* signing and *our own* plan choice; never admit a peer signature.
