Build the **mechanism** the consensus simulation stands on, with nothing that drives an end-to-end lift yet
(that is the sibling ticket). Three pieces: an exact-link extension to the lift builder in `tallynet`'s test
harness, a deterministic identity (signer/verifier) layer in `tallysim`, and an opt-in on `buildSimNetwork`
that wires consensus without disturbing the discovery-only path. End state: a simulated network can be built
*with consensus on*, and a hand-driven lift over a cooperative route commits — proven by a small test.

## Background already established (do not re-discover)

- **The harness already supports consensus.** `packages/tallynet/src/testing/network.ts`'s `InMemoryNetwork`
  builds `ConsensusNode`s **only when `signerFor` + `verifier` are both passed** (discovery-only runs pay no
  keygen). It already exposes `buildLift(spec)`, `consensusNode(name)` (`.start`/`.update`/`.outcome`),
  `consensusStoreOf(name)`, `memberKey(name)`, `resourceFor` injection, `deliveryErrors`, and per-link
  `conditions` that govern consensus pushes (`pushCondition` → `resolveCondition`). The name↔member-key
  bijection lives inside the harness; **every `buildLift`/`consensusNode` call takes the node NAME**, not the
  key.
- **The exemplar is `packages/tallynet/src/testing/consensus.test.ts`** — read it. Its `makeSigner(seed,
  name)` = `secret = sha256(seed ‖ name)`, `ed25519.getPublicKey(secret)`, `sign(digest) =
  ed25519.sign(digest, secret)`; its `verifier` is `ed25519.verify(sig, digest, pub)` wrapped try/catch →
  `false`. Driving pattern: `net.buildLift(spec)` → `net.consensusNode(route[0]).start(record)` →
  `await net.clock.runUntilIdle()` → `consensusNode(name).outcome(tx)`.
- **Imports from `tallysim` (platform-neutral core).** `@noble/hashes` is **not** a tallysim dep; use
  `nobleHasher` (exported from the `tallynet` barrel — `crypto.js`) for sha256 (`nobleHasher.sha256(bytes)`
  returns 32 bytes). ed25519 comes from `@noble/curves/ed25519.js` — **add `@noble/curves` (`^2.4.0`, match
  tallynet's devDep) to `packages/tallysim`'s `dependencies`** (it is a devDependency of tallynet only). It
  is pure JS and already hoisted into the repo's root `node_modules/@noble/curves`. `base64url.ts` is **not**
  in the tallynet barrel — you do **not** need it (member keys are derived internally by the harness).
- **`no-node-globals` guard** (`packages/tallysim/src/no-node-globals.test.ts`) scans non-test `src/` files
  for `Buffer`, `node:`/builtin imports, `require`, `Math.random`, `Date.now`, timers. `new TextEncoder()`,
  `nobleHasher.sha256`, and the `@noble/curves` import are all allowed. Verify with `yarn workspace tallysim
  test`.
- **Determinism (load-bearing).** ed25519 signing is deterministic, so a `(identitySeed, name)` pair always
  yields the same key pair, signatures, and trace stream. Derive signer secrets from a **dedicated identity
  seed stream**, independent of the network/workload/conditions seeds (a shared RNG whose draw order shifts
  would desync keys). See the "lift voters, not referee" project memory: lifts settle by a **voter set**
  (`R`-role members), default a set of one — the originator voting itself.

**`tallynet` harness — exact-link `routeLinkIds` (fixes parallel-tally mis-selection)**

`addLiftLink` resolves a route pair to a graph edge by neighbour name via `.find((c) => c.neighbour === b)`,
which picks the **first** tally between a pair and so mis-selects when **parallel tallies** exist (the sim
needs the exact tally discovery used).

- Add optional `routeLinkIds?: string[]` to `LiftSpec` in `packages/tallynet/src/testing/network.ts` — one
  link id per **route** hop, in order, length `route.length - 1` (throw if present and length mismatches).
  `extraLinks` always keep the name-pair fallback.
- In `buildLift`, pass `spec.routeLinkIds?.[i]` to `addLiftLink` for each route pair; `extraLinks` pass
  `undefined`.
- In `addLiftLink(links, sessionCode, a, b, linkId?)`: when `linkId` is given, resolve
  `(adjacency.get(a) ?? []).find((c) => c.id === linkId && c.neighbour === b)` (keep the neighbour check so a
  mismatched id/pair throws a clear error); otherwise the existing first-neighbour `.find`. The nonce is
  still `makeNonce(sessionCode, edge.id, hasher)`; the rest is unchanged.
- **Unit test** (add to `consensus.test.ts`): a graph with two parallel edges between `A` and `B` carrying
  *distinct* link terms. With `routeLinkIds: ['<second edge id>']`, assert the built record's

**`tallysim` — sim resource port (`sim/consensus-resource.ts`)**

The cooperative default already lives in the harness (`cooperativeResource`), used when no `resourceFor` is
passed. This module supplies **failure-injecting** resources for the behavioural tests (sibling ticket uses
them; ship + unit-test the factory here).

- `interface SimResourceSpec { shouldPromise?: boolean; promiseThrows?: boolean; shouldCommit?: boolean }`
  — `shouldPromise: false` ⇒ node signs `NP` (gate declines, nothing held); `promiseThrows: true` ⇒
  `promise` throws (refuses, holds nothing — the engine catches it, signs `NP`); `shouldCommit: false` ⇒ an
  `R` member signs `NC` (votes void). Mirror the exemplar's `ResourceOpts`/`makeResource`.
- `interface SimResourceHandle { resource: TrxParticipantResource<LiftTerms, unknown>; promiseCtxs:
  ResourceContext<LiftTerms, unknown>[]; releaseSuccesses: boolean[] }` — `promise` pushes its ctx,
  `release` pushes `ctx.success`, so a test reads `releaseSuccesses` (`[true]` = committed once, `[false]` =
  voided once, `[]` = never released) exactly as the exemplar does.
- `makeSimResources(specs: Record<number, SimResourceSpec>): { resourceFor: (entityId: number) =>
  TrxParticipantResource<LiftTerms, unknown>; handles: Map<number, SimResourceHandle> }` — lazily mints one
  handle per entity id (default spec `{}` = cooperative). Keyed by **entity id** (the sim's native id), not
  node name.

## Critical finding to honour (affects the smoke test here, resolved fully in the sibling ticket)

**Unlimited (`Infinity`) capacity breaks DAG-CBOR record signing.** `recordDigest`
(`packages/tallynet/src/consensus/digest.ts`) encodes `tp: record.topology` — including
`topology.links[nonce].intents` = `{ L: { capFwd, capBack, amount } }` — through `canonicalEncode`, which
**throws on any non-finite number** (DAG-CBOR rejects `Infinity`). A tally with an `Infinity` credit limit
(the `unlimited` capacity distribution — which the committed `found-vs-oracle` experiment uses) yields
`Infinity` in `capFwd`/`capBack`, so a lift over it throws at signing. The parent ticket's claim "never
serialised here (no CBOR `Infinity` path)" is **wrong**. For this ticket's smoke test, use a network with
**finite** credit limits so you never hit it. The general fix (sanitise the lift record's link intents to
CBOR-safe finite values before `start` — TallyNet never interprets terms, so this is safe) lives in the
sibling ticket's consensus-harness.
