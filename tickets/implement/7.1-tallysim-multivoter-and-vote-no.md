## Why

The parent plan wants to show that **majority voting stops a minority of voters from breaking a lift**, and to **compare consensus methods** (strict-majority `1/2` vs a raised `2/3`) under that attack. Today the simulator cannot express it: the only voter set the sweep runner can build is a **single** voter (`self`, the originator) or `self` plus **one** well-known hub (`voterNomination: 'well-known'` nominates exactly one node — see `ConsensusSpec` in `scenario.ts` and the voter-model section of `docs/design.md`). A single or two-voter set cannot demonstrate "a minority of voters cannot break the lift." And there is no dial for a voter that **promises then votes no-commit** — the active defence we want to measure.

This ticket adds the two missing *swept* mechanisms (so they run inside the atomic `runLiftForOutcome` drive and across many random networks, unlike the hand-driven attacks in `tallysim-hostile-consensus-scenarios`), plus the two aggregate metrics the measurement needs. The experiment that *uses* them is the next ticket (`tallysim-hostile-experiment-and-findings`).

## What to build

**1. Multi-voter nomination.** Extend the voter model so a lift can carry an odd voter set of size `k ≥ 3`. Two options — pick the simpler that fits the existing wiring and document the choice:
- extend `voterNomination: 'well-known'` to nominate the top-`k` well-known hubs (a `voterCount`/`refereeCount` knob on `ConsensusSpec`), reusing `wellKnownEntities` (`sim/well-known.ts`) which already returns a degree-ranked list; or
- add an explicit `voterCount` that selects `k` off-route hubs as `[V]` referees.

Respect the **known composition gap** documented in `docs/design.md` (§ Voter model): a nominee that is itself on the money path is *not* upgraded to `[P,V]` — its referee vote is silently dropped — so, exactly as `well-known` does today, pick hubs that are typically **off** the taken route. Do not try to fix the on-path composition gap here (that is `backlog/debt-voter-nomination-on-path-composition`); work within it and keep `k` small.

**2. No-commit-voter dial: `voteNoFraction`.** A new `ConsensusConditionsSpec`/`ConsensusSpec` fraction (drawn on the dedicated consensus seed, *after* the existing refuser/non-relayer/silent draws so those stay byte-identical — mirror `compileConsensusConditions` in `sim/conditions.ts`). A selected entity that lands in a lift's **voter** set promises normally but signs `NC`, via the existing `SimResourceSpec.shouldCommit: false` port (`sim/consensus-resource.ts`) — no new resource mechanism, just the selection + wiring in `consensus-runner.ts`. A `voteNoFraction` node that is *not* a voter on a given lift has no effect (it still promises and relays), which is correct.

**3. Metrics.** Add to `sim/consensus-metrics.ts` / `ConsensusRunMetrics` and the serializer (`serialize-consensus-records.ts`, as new trailing columns, matching the existing append-only column discipline):
- `inconsistentSettlementCount` — lifts where the route members do **not** all settle the same way (some `commit`, some `void`). Compute it from the per-member `outcome(tx)` the harness **already gathers** in `countCommitted` (`sim/consensus-harness.ts`): surface unanimity, don't re-query. This must be **0 on every honest and every minority-attack sweep** — it is the correctness floor the parent plan names, and the guard a reviewer checks. (The hand-driven majority-equivocation scenario in the prereq ticket is the only place it is non-zero; the sweep never injects equivocation.)
- `equivocatorCount` — Σ over lifts of `equivocators(tx).length` (reads the engine's existing proof store via `ConsensusNode.equivocators`). Always 0 in these sweeps (no swept equivocation); carried so the experiment and viewer have the column and so a future swept-equivocation dial has a home.

## Edge cases & interactions

- **Determinism / stream order.** `voteNoFraction` and the larger voter nomination must not shift which network/queries/conditions a run draws — new draws come from the consensus/identity streams only, and after the existing consensus draws. Prove the pinned sweeps are byte-identical.
- **A voteNo node that is also a refuser / non-relayer.** Selection sets can overlap (independent fractions). Define precedence: a refuser never promises, so its `NC` never arises (refusal wins); a non-relayer promises but strands — it can still be a voteNo voter. State the resolution and test one overlap.
- **Even vs odd voter counts, and ties.** An even voter set can tie (no strict majority either way) → `pending`, not an inconsistent settlement. Keep `k` odd by default; test that an even set's tie is counted as `pending`, **not** `inconsistentSettlementCount` (unanimity-of-settled is the test, and a tie settles nowhere so all members agree on `pending`).
- **Voter not on route.** Keep the harness's existing "voter must be reachable as a member" guard; a nominated referee that fails composition (lands on-path) is silently a plain participant — assert the voter set actually realised is what the metric denominator uses, so a dropped nominee does not silently shrink the quorum unnoticed.
- **`consensusMethod` interaction.** The same voteNo set must flip outcome between `1/2` and `2/3` (the comparison the next ticket sweeps). Cover one cell of each in a unit test so the experiment is not the first place the interaction runs.
- **Credit held / completion metrics unchanged.** A voided-by-NC lift releases every hold as failure; assert `creditHeldMs` and the completion counts still behave (no new permanently-pending path introduced).
