**This is the UI half of the former single `3.64-tallysim-viewer-live-run` ticket** (split under a budget
limit). Its `prereq` `tallysim-viewer-live-worker` delivers `sim-worker.ts` + `sim-protocol.ts` and the tested
`build-scenario.ts`. This ticket wires the form, the click-to-pick, the graph/replay plumbing, and the docs.
Assume the worker ticket has landed; design against its `WorkerToMain`/`MainToWorker` message union.

The flow: **generate** (worker builds the network; main thread renders it + settles the layout) → **click two
nodes** to set payer/payee → **Run** (worker streams the discovery trace; main thread feeds it into the
incremental `trace-index` builder → timeline replay, auto-playing) → optionally **download** the run as a trace
file the file-source path reloads identically.

## TODO: `src/graph/render.ts` — add click-to-pick to the `GraphView`

The current `GraphView` exposes no node-click hook, so add two methods (and no-op them in `stubView`):
- `onNodeClick(callback: (nodeKey: string) => void): void` — register a `sigma.on('clickNode', ({node}) => …)`
  handler (sigma 4 emits `clickNode`). The node key is `entityName(id)` (the entity id as a string), the same
  key `search()` uses.
- `setPicked(from: string | undefined, to: string | undefined): void` — store the two picked keys in a closure
  var and `sigma.refresh()`. Thread `picked` into the node reducer: mark the payer (e.g. `palette.highlight`)
  and payee (e.g. `palette.found`) at `NODE_SIZE_LIT`, composed **after** the replay overlay but **below** the
  built-in hover/selection accent (hover still wins on top). On a theme switch the existing `setPalette` →
  `refresh` re-runs the reducer, so picked colours re-theme for free — no extra wiring.

## TODO: `src/replay/controls.ts` — an `autoplay` option

`mountReplayControls` reads `index.timeBounds()`/`index.sessions()` **once** at mount and captures `bounds`, so
mount it only when the run's events are all in (on the worker's `done`), not incrementally. Add an optional
`autoplay?: boolean` param; after the initial `renderFrame()`, if set, call `setPlaying(true)` so a finished
live run plays from `t = min` automatically. This is also where the live source first supplies a
`ReplayRouteSource` (`routesForSession(code) => RouteInput[]`), lighting up the full found-routes list +
exact-path isolate that the loaded-trace path cannot.

## TODO: `src/live/controls.ts` — the live-run panel (browser-only; gate is build + manual)

A `mountLiveControls(host, liveHost)` that builds the form and drives one `Worker`. Keep it DRY with small
field helpers (`numberField`, `selectField`). Sections:
- **Generator**: select (`uniform`/`scale-free`/`clustered`/`small-world`) with the per-generator numeric
  params shown dynamically — `uniform: meanDegree`; `scale-free: edgesPerNode`; `clustered: communityCount,
  meanIntraDegree, bridgeCount`; `small-world: neighbors, rewireProbability`. Plus `entityCount` and `seed`.
- **Capacity**: select (`unlimited`/`constant`/`uniform`/`lognormal`) with its params (`constant: limit`;
  `uniform: min,max`; `lognormal: mu,sigma`); `unlimited` has none → `{ kind:'unlimited' }`.
- **Conditions** (optional): `sleepingFraction`, `lateFraction`, `dropFraction`, `lateLatencyMs`,
  `conditionsSeed`, and a simple constant `latency`. These feed `ConditionsSpec`; the live header carries them so
  the replay tier's sleeping/late styling + prune-reason display work unchanged.
- **Budget** (optional): `initialBudgetMs`, `perHopBudgetMs`.
- **Query**: `amount`, `depth`; `from`/`to` as read-only readouts populated by click-to-pick. Provide numeric
  `from`/`to` inputs too as a robustness fallback (so it still works if WebGL is missing / clicking is
  unavailable) — clicks write into them; Run reads them as the source of truth. `from === to` is allowed.
- **Buttons**: **Generate**, **Run** (enabled only when a network is generated **and** both from/to set),
  **Cancel** (during a run — `worker.terminate()` then re-create the worker; this is the ticket's cancel path),
  **Download trace** (after a run).

Controls behaviour:
- Read DOM → `LiveRunParams`; `buildScenario(params)` for generate, `buildLiveRun(params)` for run. Snapshot the
  network-source params at Generate and reuse them in the Run scenario so the header's network source matches
  the materialised network. **Invalidate** the generated state (disable Run until re-Generate) whenever a
  structural field (generator / entityCount / capacity / seed) changes, and expose an `invalidate()` the shell
  calls when a file/sample load replaces the view out from under the live tab.
- On worker `network`: keep the `TraceNetworkSnapshot`; `const network = networkFromSerialized(snapshot.network)`
  (import from `tallysim`); call `liveHost.renderNetwork(network)` (returns the `GraphView`); wire
  `view.onNodeClick(pick)`; `view.setPicked(from, to)` on each pick.
- On Run: `index = createTraceIndex(header, network)` on the `header` msg; `index.add(event)` per `event`; on
  `done`, build `createDeanonymiser(network)` + `compileConditions(network, scenario.conditions ?? {},
  scenario.conditionsSeed ?? 0)`, then — **if `index.timeBounds()` is defined** — `liveHost.mountReplay({ index,
  deanon, conditions, routeSource, autoplay: true })`; **else** (zero-event degenerate run)
  `liveHost.mountDisabledReplay()` and show a terse status (route count / "no route" / self-payment loop).
- **Download trace**: serialise `[serializeTraceLine(header), serializeTraceLine(keptSnapshot),
  ...events.map(e => serializeTraceLine({ kind:'event', event: e }))].join('\n') + '\n'` into a `Blob` →
  `URL.createObjectURL` → a click on a hidden `<a download>`. Reuse the **kept** snapshot object (byte-identical
  to the worker's) and `index.header` + `index.allEvents()`. Reloading this file via the file source must
  animate identically.
- **Worker creation**: `new Worker(new URL('./sim-worker.ts', import.meta.url), { type: 'module' })`. Use the
  `.ts` extension so Vite resolves it directly (it is a plain string to `new URL`, so `tsc` NodeNext does not
  apply import-extension rules; the worker file is still compiled because it is under `src/**`). Guard
  `typeof Worker === 'undefined'` and a thrown `new Worker` (module-worker unsupported) → show a clear error in
  the panel, not a blank page (the ticket's "unsupported environment" edge case).

## Edge cases & interactions (same as the original ticket)
- **Determinism**: same generator + params + seed ⇒ byte-identical network and trace; a live run downloaded and
  reloaded animates identically (the reload replays recorded events, it does not re-run).
- **Large live networks**: generation + discovery are in the worker; show a "running…" state and allow Cancel
  (terminate the worker). Discovery is ~O(network) per query.
- **from === to**, **< 2 entities / no edges**: must render the closed-loop / empty result without throwing
  (handled by the worker; the UI shows the honest outcome).
- **Worker failure / unsupported environment**: clear error, never a blank page.
