## Facts confirmed against source (do not re-investigate)

- **`ConsensusMethod`** lives in `tallynet` `src/discovery/types.ts:95` and is re-exported from the
  `tallynet` package root (via `discovery/index.js`). Shape: `{ weighting: 'distinct-voter';
  thresholdNum: number; thresholdDen: number }`; `DEFAULT_CONSENSUS_METHOD` = `1/2`. `consensusMethodError`
  validates `1/2 ≤ num/den ≤ 1` (throws below half). Import into tallysim with
  `import type { ConsensusMethod } from 'tallynet'`.
- **Settlement rule** (tallynet `consensus/participant.ts`): a side settles when `count*2 > W` (strict
  majority floor) **and** `count*thresholdDen ≥ thresholdNum*W`, `W` = voter count. At `1/2` the two
  reduce to `count*2 > W`.
- **`buildLift`** (tallynet `testing/network.ts:195`+, `LiftSpec.method?` at :211) defaults
  `spec.method ?? DEFAULT_CONSENSUS_METHOD` at :472 — so passing `method: undefined` is byte-identical to
  omitting it.
- **Originator drops a plan scored `-Infinity`/`NaN`** — confirmed in `discovery/originator.ts`
  `rankPlans` (filters `score > NEGATIVE_INFINITY`). The scorer is called **once per satisfying plan**
  per query (`rankPlans` maps over the satisfying set). So the counting scorer increments once per
  dropped plan.
- **`drawPaymentPair`/`drawAmount`** are in `packages/tallysim/src/workload.ts` (pair-first, then
  amount). `drawPaymentQueries` (harness.ts:276) draws distinct pairs; circular needs its own
  single-origin draw (a distinct pair is impossible for from===to).
- **`buildCircularOutcome(network, sessionCode, origin)`** (route.ts:82) → one-plan `QueryOutcome`
  (`plans[0].members === []`) or `undefined` (origin on no cycle). The ring test pattern
  (`voter-harness.test.ts` :124) mints a real sessionCode via `runQuery(sim, {from:origin, to:origin,…})`
  first. `runQuery` never throws for `from === to`.
- **Composition gap (load-bearing):** `liftMembers(route, voters, contactPoints)` in `consensus-harness.ts`
  builds lift members purely from route + voters — it never reads `plan.members`. So nominated/stapled
  referees reach the **discovery** layer only, never the lift record. ⇒ `'self'` nomination needs no
  wiring (default `voters:[route[0]]` already makes the originator `[P,V]`); stacked-voter refusal must be
  measured at the **discovery scorer**, not the promise-time `acceptsProposal` gate (which never sees them).
  The real `[P,V]`-on-path fix is `backlog/debt-voter-nomination-on-path-composition` — work WITHIN the gap.
- **Helpers to reuse:** `wellKnownEntities(network, fraction)` + `makeNomineesFor(network, wellKnown,
  'well-known')` (well-known.ts); `voterAwareScorePlan(wellKnown)` (plan-select.ts); `refusesStackedVoterSet
  (members, policy)` + `StackedVoterPolicy` (consensus-resource.ts). `plan.members` is assignable to
  `DependentMember[]`; discovery-plan `memberEntity` is `(m) => Number(m.address.key)` (non-numeric key ⇒
  NaN ⇒ obscure).
- **`consensusConfigFor(scenario, network, runSeed): ConsensusConfig`** is exported and used by
  `cli/trace.ts` — keep that exact signature. Both it and the sweep path build the config through the
  private `consensusConfigFromCompiled`. The trace CLI does **not** handle circular route shape (out of
  scope — note the deferral in the handoff; the stacked/nomination wiring still rides along so a trace
  replays its discovery identically).

## Concrete implementation plan

### 1. `scenario.ts` — `ConsensusSpec` knobs
Add `import type { ConsensusMethod } from 'tallynet'` and a `RouteShape` type. Add to `ConsensusSpec`:
`routeShape?: 'linear' | 'circular'` (default `'linear'`), `voterNomination?: 'self' | 'well-known'`,
`wellKnownFraction?: number`, `stackedVoters?: number`, `consensusMethod?: ConsensusMethod`. Document each
(JSON-serialisable). Export `type RouteShape = 'linear' | 'circular'`.

### 2. `consensus-harness.ts` — thread the method
Add `consensusMethod?: ConsensusMethod` to `RunLiftOptions` (import the type). In the `net.buildLift({…})`
call add `method: options?.consensusMethod` (undefined ⇒ default, byte-identical). Extend the module/field
docs.

### 3. `consensus-runner.ts` — the big one
Imports to add: `buildCircularOutcome` (route.js), `wellKnownEntities`/`makeNomineesFor` (well-known.js),
`voterAwareScorePlan` (plan-select.js), `refusesStackedVoterSet`/`StackedVoterPolicy` (consensus-resource.js),
`drawCircularOrigins` (harness.js — new, see §3a), `RunLiftOptions`/`SimNetwork`/`QueryOutcome` (harness/
consensus-harness), `type ConsensusMethod` + `MemberTypes`/`DependentMember`/`DiscoveryHooks`/`ScorePlan`
(tallynet), `type RouteShape` (scenario), `type LiftTerms` (terms.js), `cloneConsensus` already local.

- **`cloneConsensus`** (currently `{ ...consensus }`): deep-clone `consensusMethod` when present
  (`clone.consensusMethod = { ...consensus.consensusMethod }`) — it is the one non-scalar knob.

- **New `ConsensusWiring` + `consensusWiring(scenario, network, compiled, runSeed)`** wrapping the existing
  `consensusConfigFromCompiled` (keep that private helper for the base config). Returns
  `{ config: ConsensusConfig; planRefusals: { count: number }; wellKnown?: Set<number> }`:
  - nomination: if `voterNomination === 'well-known'`, `wellKnown = wellKnownEntities(network,
    wellKnownFraction ?? 0)`, set `config.nomineesFor = makeNomineesFor(network, wellKnown, 'well-known')`
    and `config.scorePlan = voterAwareScorePlan(wellKnown)`.
  - stacked: if `(stackedVoters ?? 0) > 0`, set `config.negotiatePlanFor = stackingNegotiateFor(stackedVoters)`
    and **override** `config.scorePlan = countingRefusalScorer(wellKnown ?? new Set(), planRefusals)`.
  - `consensusConfigFor` becomes `consensusWiring(scenario, network, compiled, runSeed).config`.

- **`stackingNegotiateFor(count)`**: `(entityId) => entityId % 2 === 0 ? (plan) => ({...plan, members:
  [...plan.members, ...stackedVoterMembers(entityId, count)]}) : undefined`. `stackedVoterMembers` builds
  `count` `{ types:[VOTER], address:{ key: \`sv${entityId}_${i}\` } }` (non-numeric key ⇒ obscure). The
  even-id subset is deterministic, non-empty (node 0), and **every line route of ≥1 hop spans consecutive
  integers so it always contains an even node** ⇒ every line route gets stapled ⇒ reliably refused in the
  sweep test. Document that rationale in a comment.

- **`countingRefusalScorer(wellKnown, refusals)`**: `const rank = voterAwareScorePlan<LiftTerms,
  unknown>(wellKnown); const policy = { wellKnown, memberEntity: (m) => Number(m.address.key) }; return
  (plan, query) => refusesStackedVoterSet(plan.members, policy) ? (refusals.count++, NEGATIVE_INFINITY) :
  rank(plan, query)`. The cell is shared across per-query rebuilds ⇒ sums every refused plan. **Why the
  scorer, not the promise-time gate:** the composition gap — document inline.

- **`runOne`**: compute `routeShape = scenario.consensus?.routeShape ?? 'linear'`; draw
  `queries = routeShape === 'circular' ? drawCircularOrigins(workload, entityCount, rng) :
  drawPaymentQueries(workload, entityCount, rng)`. Destructure `{ liftMetrics, planRefusalCount } = await
  runConsensusQueries(...)` and pass `planRefusalCount` as the 4th arg to `summarizeConsensusMetrics`.
  Degenerate (<2) branch stays `summarizeConsensusMetrics([], structural, 0)`.

- **`runConsensusQueries`** → return `{ liftMetrics: ConsensusLiftMetrics[]; planRefusalCount: number }`.
  Build `wiring = consensusWiring(scenario, network, compiled, runSeed)`; `consensus = wiring.config`.
  Hoist `liftOptions: RunLiftOptions = { contactPoints, nonCooperating, ...(consensusMethod ?
  {consensusMethod} : {}), ...(wiring.wellKnown ? {wellKnown: wiring.wellKnown} : {}) }`. In the loop
  replace `const outcome = await runQuery(sim, query)` with `const outcome = await resolveOutcome(sim,
  network, query, routeShape); if (!outcome) continue;`. After the loop return
  `{ liftMetrics, planRefusalCount: wiring.planRefusals.count }`.

- **`resolveOutcome(sim, network, query, routeShape)`**: circular ⇒ `const base = await runQuery(sim,
  query); return buildCircularOutcome(network, base.sessionCode, query.from)` (undefined ⇒ caller skips,
  no lift); linear ⇒ `return runQuery(sim, query)`.

- Add `// NOTE:` at the `wellKnownEntities` call site: recomputes degree per run → cache if a grid grows
  large (the tripwire).

### 3a. `harness.ts` — `drawCircularOrigins`
Add next to `drawPaymentQueries`: `drawCircularOrigins(workload, entityCount, rng): QuerySpec[]` — for
`workload.queries` iterations draw `origin = rng.nextInt(entityCount)` then `amount = drawAmount(...)`,
push `{ from: origin, to: origin, amount, depth: workload.depth }` (origin-then-amount mirrors pair-then-
amount). Empty for `entityCount < 2`. (Named per the ticket though it returns full single-origin
`QuerySpec`s — doc that.)

### 4. Metrics — `consensus-metrics.ts` + `serialize-consensus-records.ts`
Add to `ConsensusRunMetrics` (after `recoveredTotal`): `planRefusalCount: number`, `planRefusalShare:
number`. `summarizeConsensusMetrics(lifts, structural, queryCount, planRefusalCount = 0)` sets
`planRefusalCount` and `planRefusalShare = queryCount > 0 ? planRefusalCount / queryCount : 0` (guard
0/0 ⇒ 0). Append `'planRefusalCount', 'planRefusalShare'` to `CONSENSUS_METRIC_COLUMNS` after
`...distributionColumns('pullMessagesPerLift')`. Scope note for the doc: this counts **discovery-time**
voter-set refusals (plans the scorer dropped); the voter-aware *reordering* is a ranking not a refusal and
is intentionally not counted; the promise-time path is unreachable (composition gap).
