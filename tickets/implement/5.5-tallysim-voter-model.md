Exercise the voter model at scale on the existing consensus-simulation infrastructure (`sim/consensus-*`, `plan-select.ts`, `consensus-resource.ts`). This is the measurement step that keeps the consensus-method and policy defaults honest before `taleus-core` binds, and the input to `tallysim-hostile-actors`.

## What to add

- **Voter nomination + acceptance policies.** Extend `plan-select.ts` (which already has `PlanPolicy`) to score plans by their voter set using TallyNet's `scorePlan` hook (from `tallynet-lift-policy-hooks`): fewer/better-known voters preferred. Add a nomination policy (what a participant nominates: itself, or a well-known voter from the generated network) and a `acceptsProposal` policy that **refuses stacked voter sets** (a set padded with obscure `V`-only members). Mark some generated nodes "well-known" so "trusted" means something measurable.
- **Phase-2 refusers and non-relayers.** `consensus-resource.ts` already has `shouldPromise:false` / `promiseThrows` / `shouldCommit:false`. Add a **non-relayer**: a node that receives the record but does not push it onward (distinct from the drop-link condition, which is a lossy link; a non-relayer is a hostile/dead *node*). Wire it so the harness can place one at a chosen route position.
- **Runs with and without contact points.** A scenario flag that sets `Member.physical` on the originator + voters (or on no one). This is the knob that makes principle 3 hold or fail for linear lifts.
- **Linear and circular lifts.** Drive both route shapes (a linear payment and a circular clearing lift) through the same consensus path.

## What to measure (`consensus-metrics.ts`, surfaced in the CLI/CSV)

- **Cooperating members completed vs. number of refusers** — the principle-3 curve; expect 100% with ≤1 refuser **and** contact points, and a visible cliff without contact points on linear routes.
- **Time to settle** (virtual-clock ticks from mint to every cooperating member settled).
- **Messages per lift** (pushes + pulls; the pull from `tallynet-record-availability` should show up as extra messages that *recover* otherwise-stuck members).
- **Share of plans refused or passed over** because of their voter set (`acceptsProposal` refusals + `scorePlan` non-selections).

Add these as columns on the existing `ConsensusRunRecord`/CSV so a sweep can vary refuser count, contact-point on/off, route shape and voter-set size.

## Edge cases & interactions

- Voter sets of 1, 2 (tie → no settlement under default threshold; the sim must record "unsettled", not hang), 3, many.
- A non-relayer that is also a voter; a refuser next to the payee; the payee silent after the originator minted (should still settle — the originator holds the plan).
- With contact points off and a single interior non-relayer on a linear route: members beyond it stay pending until a pull reaches them — but with contact points off there is no one to pull from, so they stay unsettled. The metric must capture this as the expected gap, not a test failure.
- A threshold above `1/2` (e.g. `2/3`): more voters must vote commit; measure the extra messages and the larger unsettled band.
- Determinism: everything through the seeded `RandomSource` + virtual clock (no `Math.random`); a run is replayable (the harness already enforces this — keep it).
- Keep the simulator on `tallynet`'s public API only (no test-only forks); non-relayer is a harness wiring choice, not a protocol change.
