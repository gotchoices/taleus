Part 3 of 3 (split from the original `5.3-tallynet-originator-proceed`). This closes the regression check's
"untested end-to-end in TallyNet" gap: a `dependsOn`-nominated voter travels **discovery → topology → vote
count through a REAL plan**, not a `buildLift` spec shortcut. Depends on Part 1 (`mintRecord`) and Part 2
(`proceed`/`abort`).

## Why this needs new harness wiring (confirmed)

Two seams, both real work:

**1. The name-vs-key seam.** Discovery's `makeFindAddress` (`network.ts:572`) uses the node **NAME** as its
member `address.key` (`{ key: name }`). So `net.discover(...)` returns a `Plan` whose `members` and target
are **name-keyed**, but consensus members must be **ed25519 keys** (`memberKeyByName`; a `TrxParticipant`
rejects a `self.key` that is not its signer's key, `participant.ts:136`). The path **nonces need no
translation** — `makeNonce(sessionCode, linkId)` is independent of names/keys, so a plan's path nonces
already equal the consensus link nonces **as long as the session code is reused** (it is — `mintRecord`
reuses `query.sessionCode`). So a new harness helper must translate the plan's member keys (and
`dependsOn` addresses) **name→key** before minting. Chosen approach: **the harness translates** (keeps
discovery name-based and every existing discovery test's `{ key: 'Z' }` targets working; isolates the seam
to the new helper). Do **not** teach `makeFindAddress` to emit consensus keys.

**2. Referee nomination.** `makeFindAddress` returns **no `dependsOn`** today, so a real search never
produces a voter-only nominee. Extend the harness to let a node nominate a `V`-only referee.

## Harness additions (`testing/network.ts`)

- **Referee nomination.** Add an optional config (e.g. `nomineesFor?: (nodeId) => LiftMemberSpec[]` or a
  simpler `{ nominee: refName }` per node) so a chosen interior node's `self` `Match` carries
  `dependsOn: [{ types: ['V'], address: { key: refName } }]`. `prependMatch` (`participant.ts:714,739`)
  then folds it into `plan.members` as a `V` member (`missing` → appended), and **requires** the nominee
  be voter-only (it throws if a `dependsOn` entry is a participant) — so nominate `[V]` only. The referee
  must still be a **graph node** (so it has a consensus signer + member key and can vote) and should be
  given a **`physical`** contact point so the record reaches it and its vote returns (reachability fans to
  `physical` members, `participant.ts:685`); it needs no tally link.
- **`mintFromPlan`.** Add a method that mints a real lift record from a discovered plan and wires the
  nonce maps — the discovery-plan analogue of `buildLift` (keep `buildLift` unchanged):
  ```ts
  mintFromPlan(originatorName: string, query: UniQuery<TTerms>, plan, payload, opts?: { ttlMs?; transactionCode? })
    : { record; sessionCode; transactionCode }
  ```
  It (a) **translates** `plan.members` name→key (`memberKeyByName`), including each member's `dependsOn`
  addresses, producing a key-space `Plan`; (b) calls Part 1's `mintRecord` on the translated plan +
  `query` + a minted transaction code (reuse `query.sessionCode`); (c) **populates every involved node's
  `nonceToLinkIdByName` map** for each path nonce (the same `nonceToLinkIdByName.get(name)![nonce] =
  linkId` step `addLiftLink` does at `network.ts:456-457`) so each participant's resource context resolves
  real link ids — resolve each path nonce back to its link id via the nodes' discovery stores
  (`nonceToLinkMap(session)`, `network.ts:336`) or by re-deriving from the known graph edges. Feed the
  returned `record` to `consensusNode(originatorName).start(record)` (or call Part 2's `proceed`).

## The end-to-end test (new block in `testing/consensus.test.ts`, or a new `testing/mint-e2e.test.ts`)

Use the `makeNet` + `runDiscovery`/`runLift` + `net.clock.runUntilIdle()` idioms already in
`consensus.test.ts` and `discovery.test.ts`. The harness builds BOTH a `DiscoveryNode` and a
`ConsensusNode` per name when `signerFor`+`verifier` are passed (`network.ts:263`), so one network drives
discovery then consensus.

- **Referee reaches the vote count (headline).** Graph where an interior participant nominates a `V`-only
  referee `R` (physical). Run a **real `discover`** from the payer to the payee; take `plans[0]`;
  `mintFromPlan`; `start`. Assert: `R` is a `V` member of `topology.members`; `R` rides **no** tally link;
  after the promise phase, `R`'s `C` **counts** toward the majority (route commits); and a missing/`NC`
  vote from `R` **flips the outcome** at the threshold (e.g. make `R` the deciding vote, then give `R`
  `shouldCommit:false` → the route no longer settles commit).
- **Nominated by two** participants → `R` appears once in `members` and is counted once (still commits /
  still the single deciding vote, not double-weighted).
- **Circular originator.** A ring where originator = payee mints a valid **single-member-entry / two-link**
  topology and commits. NOTE (from investigation): a *real* `discover` toward literally-self degenerates to
  a round-0 self-match (`path:[] members:[O]`, see `discovery.test.ts` "self is the target") that has **no
  ring path** — so the circular case is best built as a **hand-made two-link `Plan`** (O↔X, both `P`, O
  also `V`) fed through `mintFromPlan`/`mintRecord`, not through `discover`. The headline referee case is
  what satisfies the ticket's real-plan requirement; the circular case proves the two-link mint shape.
