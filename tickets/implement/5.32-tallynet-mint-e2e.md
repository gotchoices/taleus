## Resolved design (investigation complete — implement from here)

### Facts confirmed by reading the code (don't re-derive)

- **Discovery keys members by NAME.** `makeFindAddress` (`testing/network.ts:573`) returns
  `self.member.address = { key: name }` and peer-match members `{ key: edge.neighbour }` (also a name).
  So `net.discover(...)` returns a `Plan` whose members + path are **name-keyed**. Consensus needs
  **ed25519 keys** (`TrxParticipant` ctor throws if `self.key` ≠ its signer's key, `participant.ts:153`).
  The harness keeps the bijection: `memberKeyByName` / `nameByMemberKey` (`network.ts:230-231`), read via
  `memberKeyFor(name)` (`network.ts:519`). Path **nonces need no translation** — `makeNonce(session,
  linkId)` ignores names/keys, and `mintRecord` reuses `query.sessionCode`, so the plan's path nonces
  already equal the consensus link nonces. **Translate in the new helper; do NOT touch `makeFindAddress`'s
  name-keying** (every existing discovery test depends on it).
- **Every discovered member is `[P]` (participant only).** `makeFindAddress` stamps
  `types: [MemberTypes.participant]` on `self` and on every peer-match. Discovery NEVER produces a `[V]`
  member. **Therefore the ONLY voter in a discovered lift is a `dependsOn`-nominated referee.** This is the
  crux that makes the e2e meaningful AND makes the referee the *sole* voter (clean outcome control):
  `mintRecord` throws "plan has no voter members" (`mint.ts:57`) unless a referee is nominated.
- **`prependMatch` (`discovery/participant.ts:714`) folds `self.dependsOn` into `plan.members`.** It
  requires each dependent be voter-only (throws on a participant dependent, `:718`), appends a not-yet-present
  nominee to members (`missing`, `:739`), and de-dups one already present (`upgraded`, `:727`). `returnPlan`
  (`:488`) calls `prependMatch(annotated, self)` every time a node prepends itself — on its own target-find
  (`buildMatchPlans`) and on the return-trip fold (`foldPlans`). So attaching `dependsOn` to a node's `self`
  Match makes its referee ride every plan that node is on. **Dedup across two nominators is automatic**:
  the second nominator finds the referee already in `members` → `upgraded`, not re-appended.
- **Consensus reachability = lift links ∪ physical members, independent of the graph.**
  `reachablePeers` (`consensus/participant.ts:762`) = members with `physical` + the far end of each
  `record.topology.links` entry we ride. `makeUpdatePeer` (`network.ts:470`) delivers to a `physical`
  member with **no graph edge** instantly (`pushCondition` returns `undefined` → not dropped). A graph edge
  that is NOT a lift link does nothing for consensus push.
- **A voter-only referee rides no lift link**, so its reachablePeers = { other physical members } only.
  **If the referee is the only physical member, its vote cannot return** and the route never commits. The
  fix (below): give the **originator** a physical contact point too, so `referee → originator → (links) →
  whole chain`. This matches design.md principle 4 / § Contact points ("the originator and every voter must
  publish a contact point" on a linear lift). This is why `mintFromPlan` stamps the originator physical.

### Harness change 1 — referee nomination (`testing/network.ts`)

Add a config knob + type and thread it into `makeFindAddress`:

```ts
/** A voter-only referee a node nominates during discovery (folded into the plan by prependMatch). */
export interface RefereeNomination {
	/** The referee's node NAME. Must be in `graph.nodes` so it gets a consensus signer + member key and can vote. */
	name: string
	/** Give it a `physical` dial address so every record-holder reaches it and its vote can return. Default true. */
	physical?: boolean
}
```

In `InMemoryNetworkConfig`:
```ts
/**
 * Optional per-node referee nomination. When node `nodeId` resolves its own `self` Match, it attaches
 * `dependsOn: [...]` listing voter-only referees — exactly a real participant nominating a referee in
 * discovery. prependMatch folds each into the plan's `members` as a V member on the return trip. A
 * nominee MUST be voter-only and SHOULD be a graph node with a physical contact point. Returns [] for
 * a node that nominates nobody.
 */
nomineesFor?: (nodeId: string) => RefereeNomination[]
```

Store `this.nomineesFor = config.nomineesFor` in the constructor **before** the `buildNode` loop
(`network.ts:259`), since `makeFindAddress` reads it at construction time. Then in `makeFindAddress`
(`network.ts:573`), compute `dependsOn` once (outside the returned closure) and attach to `self`:
```ts
private makeFindAddress(name: string, adjacency: AdjacencyEntry<TTerms>[]): FindAddressFunc<TTerms, TPayload> {
	const nominees = this.nomineesFor?.(name) ?? []
	const dependsOn: IdentifiedMember[] | undefined = nominees.length
		? nominees.map((n) => ({
			types: [MemberTypes.voter],
			address: { key: n.name },
			...((n.physical ?? true) ? { physical: `dial:${n.name}` } : {}),
		}))
		: undefined
	return (query, _inLinkId) =>
		Promise.resolve<FindResult<TTerms, TPayload>>({
			self: { member: { types: [MemberTypes.participant], address: { key: name } }, ...(dependsOn ? { dependsOn } : {}) },
			selfIsMatch: query.target.address.key === name,
			peerMatch: /* unchanged */,
			candidates: /* unchanged */,
		})
}
```
Add `IdentifiedMember` to the `discovery/types.js` import. (`Match` is the type of `self`; no explicit
annotation needed — `FindResult` types it.)

### Harness change 2 — `mintFromPlan` (`testing/network.ts`)

New method, the discovery-plan analogue of `buildLift` (keep `buildLift` unchanged). Add imports:
`mintRecord` from `'../consensus/mint.js'`, and `Plan` + `UniQuery` from `'../discovery/types.js'`.

```ts
mintFromPlan(
	originatorName: string,
	query: UniQuery<TTerms>,
	plan: Plan<TTerms, TPayload>,
	payload: TPayload,
	opts?: { ttlMs?: number; transactionCode?: string },
): { record: TrxRecord<TTerms, TPayload>; sessionCode: string; transactionCode: string } {
	this.requireConsensus()
	const sessionCode = query.sessionCode
	const ttlMs = opts?.ttlMs ?? 600_000
	const transactionCode = opts?.transactionCode ?? generate(ttlMs, { now: this.clock.now(), random: this.random })
	const translated = this.translatePlanToKeys(originatorName, plan)
	const record = mintRecord({ plan: translated, query, payload, transactionCode })
	this.populateNonceMaps(record, sessionCode)
	return { record, sessionCode, transactionCode }
}

/** Translate a discovery NAME-keyed plan into ed25519-key space; stamp the originator a contact point. */
private translatePlanToKeys(originatorName: string, plan: Plan<TTerms, TPayload>): Plan<TTerms, TPayload> {
	const originatorKey = this.memberKeyFor(originatorName)
	const members: DependentMember[] = plan.members.map((member) => {
		const key = this.memberKeyFor(member.address.key) // member.address.key is a NAME
		const translated: DependentMember = {
			...member,
			address: { key },
			...(member.dependsOn ? { dependsOn: member.dependsOn.map((a) => ({ key: this.memberKeyFor(a.key) })) } : {}),
		}
		// The originator publishes a contact point so a voter-only referee's commit can return to it
		// (design.md § Contact points). The referee's own physical rides through from the nomination.
		if (key === originatorKey && !translated.physical) {
			translated.physical = `dial:${originatorName}`
		}
		return translated
	})
	return { ...plan, members }
}

/** Populate every involved consensus node's live nonce→linkId map, re-deriving each from the graph edges. */
private populateNonceMaps(record: TrxRecord<TTerms, TPayload>, sessionCode: string): void {
	for (const [nonce, link] of Object.entries(record.topology.links)) {
		const sourceName = this.nameByMemberKey.get(link.source)
		const targetName = this.nameByMemberKey.get(link.target)
		if (!sourceName || !targetName) {
			throw new Error(`mintFromPlan: link endpoint is not a known consensus node (${link.source} -> ${link.target})`)
		}
		const edge = (this.adjacency.get(sourceName) ?? []).find(
			(c) => c.neighbour === targetName && makeNonce(sessionCode, c.id, this.hasher) === nonce,
		)
		if (!edge) {
			throw new Error(`mintFromPlan: no graph edge ${sourceName}--${targetName} matching a path nonce`)
		}
		this.nonceToLinkIdByName.get(sourceName)![nonce] = edge.id
		this.nonceToLinkIdByName.get(targetName)![nonce] = edge.id
	}
}
```
Notes: `mintRecord` reads only `query.sessionCode`/`method`/`liftContract` (verified in `mint.ts:61-74`)
— it never reads `query.target`, so no target translation is needed. `nonceToLinkId` being unpopulated
does NOT break settlement (`ourLinks` treats `linkId` as optional, `participant.ts:820`); populate it
anyway per the realism requirement. Matching the edge **by nonce** (not just neighbour) disambiguates
parallel edges and works for both discovered and hand-built plans.

### Why this needs new harness wiring (confirmed)

Two seams, both real work:

**1. The name-vs-key seam.** Discovery's `makeFindAddress` (`network.ts:572`) uses the node **NAME** as its
member `address.key` (`{ key: name }`). So `net.discover(...)` returns a `Plan` whose `members` and target
are **name-keyed**, but consensus members must be **ed25519 keys** (`memberKeyByName`; a `TrxParticipant`
rejects a `self.key` that is not its signer's key, `participant.ts:136`). The path **nonces need no
translation** — `makeNonce(sessionCode, linkId)` is independent of names/keys, so a plan's path nonces
already equal the consensus link nonces **as long as the session code is reused** (it is — `mintRecord`
reuses `query.sessionCode`). So a new harness helper must translate the plan's member keys (and
`dependsOn` addresses) **name→key** before minting. Chosen approach: **the harness translates** (keeps
discovery name-based and every existing discovery test's `{ key: 'Z' }` targets working; isolates the seam
to the new helper). Do **not** teach `makeFindAddress` to emit consensus keys.

**2. Referee nomination.** `makeFindAddress` returns **no `dependsOn`** today, so a real search never
produces a voter-only nominee. Extend the harness to let a node nominate a `V`-only referee.

### Harness additions (`testing/network.ts`)

- **Referee nomination.** Add an optional config (e.g. `nomineesFor?: (nodeId) => LiftMemberSpec[]` or a
  simpler `{ nominee: refName }` per node) so a chosen interior node's `self` `Match` carries
  `dependsOn: [{ types: ['V'], address: { key: refName } }]`. `prependMatch` (`participant.ts:714,739`)
  then folds it into `plan.members` as a `V` member (`missing` → appended), and **requires** the nominee
  be voter-only (it throws if a `dependsOn` entry is a participant) — so nominate `[V]` only. The referee
  must still be a **graph node** (so it has a consensus signer + member key and can vote) and should be
  given a **`physical`** contact point so the record reaches it and its vote returns (reachability fans to
  `physical` members, `participant.ts:685`); it needs no tally link.
- **`mintFromPlan`.** Add a method that mints a real lift record from a discovered plan and wires the
  nonce maps — the discovery-plan analogue of `buildLift` (keep `buildLift` unchanged):
  ```ts
  mintFromPlan(originatorName: string, query: UniQuery<TTerms>, plan, payload, opts?: { ttlMs?; transactionCode? })
    : { record; sessionCode; transactionCode }
  ```
  It (a) **translates** `plan.members` name→key (`memberKeyByName`), including each member's `dependsOn`
  addresses, producing a key-space `Plan`; (b) calls Part 1's `mintRecord` on the translated plan +
  `query` + a minted transaction code (reuse `query.sessionCode`); (c) **populates every involved node's
  `nonceToLinkIdByName` map** for each path nonce (the same `nonceToLinkIdByName.get(name)![nonce] =
  linkId` step `addLiftLink` does at `network.ts:456-457`) so each participant's resource context resolves
  real link ids — resolve each path nonce back to its link id via the nodes' discovery stores
  (`nonceToLinkMap(session)`, `network.ts:336`) or by re-deriving from the known graph edges. Feed the
  returned `record` to `consensusNode(originatorName).start(record)` (or call Part 2's `proceed`).
