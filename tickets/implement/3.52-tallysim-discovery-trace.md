Second of the three discovery tickets (after `tallysim-discovery-harness`, which can run a payment query on simulated time and collect each node's `TraceEvent`s through a shared `TraceSink`). This ticket defines and documents the **trace file format** and the machinery to write one as a stream and read it back. The viewer (`tallysim-viewer`) and the metrics ticket (`tallysim-discovery-metrics`) both read exactly this format; any recorded run must replay identically.

A `tallynet` `TraceEvent` (`packages/tallynet/src/trace.ts`) is already JSON-safe and already carries its emitting node's id, the session code, the clock time, a depth/round, and for `candidate-pruned` a `PruneReason`. The one union spans discovery *and* consensus events (consensus arrives with ticket 3.7); this ticket records whatever events the sink receives and must not fork the union or assume only discovery events — it round-trips the whole union.

## The format (versioned, JSON lines)

One file, newline-delimited JSON, three record kinds in order. Every line is one JSON object with a `kind` discriminant:

```ts
// sim/trace-format.ts
export const TRACE_FORMAT_VERSION = 1

export interface TraceHeader {
	kind: 'header'
	traceFormatVersion: number        // TRACE_FORMAT_VERSION
	tallysimVersion: string           // from tallysim package.json
	tallynetVersion: string           // from tallynet package.json
	scenario: SimScenario             // the sim scenario that produced the run (generator/params/capacity/conditions/workload/seeds)
	runSeed: number
	/** One entry per query issued in this run, so a reader can join events (by sessionCode) back to the query. */
	queries: Array<{ sessionCode: string; from: number; to: number; amount: number; depth: number }>
}

export interface TraceNetworkSnapshot {
	kind: 'network'
	/** The serialised Network (tallysim serialize: Infinity ↔ null), so the reader rebuilds the exact graph. */
	network: SerializedNetwork
}

export interface TraceEventLine {
	kind: 'event'
	event: TraceEvent                 // the tallynet union, verbatim
}

export type TraceLine = TraceHeader | TraceNetworkSnapshot | TraceEventLine
```

Order on disk: line 1 `header`, line 2 `network`, lines 3+ `event` (in emission order, which is time order because the `VirtualClock` fires in `(time, seq)` order). The header and network come first so a streaming reader can set up before events arrive. `scenario` embeds the full `SimScenario` (defined fully in the metrics ticket; here it is whatever the harness was built from — generator recipe or materialised ref, capacity, `ConditionsSpec`, workload, the seeds) so the run is reproducible from the file alone.

**Versioning:** `traceFormatVersion` is checked on read; an unknown/newer version is rejected with a clear message (the viewer relies on this). Bump it whenever the line shapes change (consensus events in 3.7 do **not** need a bump — they are already in the `TraceEvent` union; a bump is only for a change to the line envelopes above).

**Network serialisation:** reuse tallysim's existing `serialize`/`deserialize` (`src/model.ts`) with its `Infinity ↔ null` convention; do not invent a second encoding. A saved snapshot `deserialize`s back to a byte-identical `Network`.

## Writing as a stream (platform-neutral core + Node CLI)

The core must stay platform-neutral (no Node fs) — the viewer runs simulations live in a page. Split writing into a sink the core owns and a Node file target in `cli/`:

```ts
// sim/trace-writer.ts
/** Receives already-serialised NDJSON lines (one string per line, no trailing newline). */
export type LineSink = (line: string) => void

export interface TraceWriterOptions {
	/** If set, record events only for these session codes (selected-query recording). Omitted ⇒ all. */
	sessions?: Set<string>
}

/**
 * Serialise header + network up front, then one line per event as it arrives. Returns a TraceSink to hand
 * the harness and a small stats accessor. Never buffers the whole event list — each event is serialised and
 * handed to the LineSink immediately, then dropped.
 */
export function makeTraceWriter(header: TraceHeader, snapshot: TraceNetworkSnapshot, out: LineSink, options?: TraceWriterOptions): {
	sink: TraceSink
	stats(): { lines: number; bytes: number }
}
```

- The returned `sink` is passed to `buildSimNetwork(..., trace)`. It serialises each `event` to one NDJSON line and calls `out`. It filters by `options.sessions` when set (the **selected-query** option the parent ticket asked for — a 10,000-node run can record only a handful of queries). It must obey `tallynet`'s trace invariant that a throwing sink never breaks the engine — wrap with `safeTraceSink` (or document that the engine already wraps the injected sink; it does) and keep the writer's own work non-throwing where possible.
- `stats()` reports line and byte counts so a run can **report its trace size** (the parent ticket's requirement) and a caller can decide whether to cap recording.
- The CLI target (`cli/trace.ts`, the one Node-specific area, excluded from the neutral build like `cli/sweep.ts`) wires `out` to a streamed file write (append each line + `\n`), so memory stays flat regardless of run size. Stream to stdout or `--out <path>`; **never** silently buffer.

## Reading back

```ts
// sim/trace-format.ts
export interface ParsedTrace {
	header: TraceHeader
	network: Network                    // deserialised
	/** Lazy: a generator over events in file order, so a large trace is not fully materialised. */
	events(): Iterable<TraceEvent>
}
/** Parse NDJSON lines (an iterable of strings). Throws a clear error on an unknown traceFormatVersion or a malformed/missing header/network. */
export function parseTrace(lines: Iterable<string>): ParsedTrace
```

Reading is pure and platform-neutral (the caller supplies the line iterable; the CLI reads the file). The metrics ticket consumes `parseTrace` to analyse events; the viewer consumes the same.

## Edge cases & interactions

- **Determinism (byte-identical):** same seed + same `SimScenario` ⇒ byte-identical trace file (header, network snapshot, and every event line in the same order). This is the headline guarantee — the `VirtualClock`'s `(time, seq)` ordering and deterministic session-code minting make it hold; test it by running twice and comparing the full byte stream.
- **Concurrent queries in one run:** several originators at once share one file; events interleave in time order but stay separable by `event.sessionCode`. The header's `queries[]` maps each session to its `(from,to,amount,depth)`. A reader never needs to split the stream to attribute an event.
- **Late answers:** a `late-answer-folded` event appears in the stream at its (late) clock time with its round, so a reader sees it was folded into a later round — not dropped, not duplicated. (The metrics ticket must not double-count it.)
- **Selected-query recording:** with `options.sessions` set, only those sessions' events are written; the header still lists all issued queries (or document that it lists only recorded ones — pick the recorded-only variant so the file is self-consistent with its events). State the choice in the doc.
- **Unknown/newer version on read:** rejected with a clear, actionable message naming the found vs supported version.
- **Empty run / empty result:** a query that finds nothing still yields a valid file (header + network + its query/round events, possibly ending without a `plan-found`). A run with zero events (e.g. all queries filtered out) is still a valid header+network file.
- **Large trace:** writing is append-only streaming; reading is a lazy generator. A 10,000-node run's size is reported via `stats()`; neither write nor read holds all events in memory. (NOTE tripwire: the header's `network` snapshot is one line and is held in memory while serialising — fine for planned sizes; if entity counts ever dwarf event counts, consider chunking the snapshot. Record this as a `NOTE:` comment at the snapshot serialisation site.)
- **Consensus events (forward-compat):** the writer/reader pass the whole `TraceEvent` union through unchanged, so ticket 3.7's consensus events need no format bump — verify a consensus-shaped event round-trips.

## Tests to plan

- Round-trip: build header+network+events, write to an in-memory `LineSink`, `parseTrace` the lines back, assert header equal, network `deserialize` byte-identical, events equal in order.
- Byte-identical determinism: two runs of the same scenario+seed produce identical line strings.
- Version rejection: a line with a bumped/garbage `traceFormatVersion` throws the clear error.
- Session filtering: a two-query run recorded with `sessions = {one}` writes only that session's events; the other session's events are absent; stats reflect it.
- Streaming: a run with many events calls the `LineSink` incrementally (assert it is called before the run completes, e.g. via a counting sink) and never materialises an all-events array in the writer.
- A consensus-shaped `TraceEvent` (hand-built) round-trips unchanged.
