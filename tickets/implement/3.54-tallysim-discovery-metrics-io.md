**Second of three tickets split from `tallysim-discovery-metrics`.** The core ticket (`tallysim-discovery-metrics-core`) builds `ProtocolRunMetrics` + `SimRunRecord` + `runSimSweep`. This ticket serialises those records and ships the Node CLI. The experiment ticket (`tallysim-discovery-metrics-experiment`) depends on this one.

## Serialise `SimRunRecord`

The existing `serialize-records.ts` serialises the oracle's `RunRecord` to JSON-lines + a CSV summary. A `SimRunRecord` shares the exact provenance shape (`{ generator, capacity, params, seed, metrics }`) but carries `ProtocolRunMetrics` instead of `RunMetrics`, so it needs its own canonical CSV column order (and the `pruneReasons` nested object).

**Stay DRY without risking the oracle's byte-identical output.** Refactor `serialize-records.ts` so the CSV/JSON machinery is generic over the metrics shape, then keep the current `RunRecord`-typed functions as thin wrappers (so `cli/sweep.ts` and the committed route-existence experiment stay byte-identical — the `serialize-records.test.ts` + route-existence regen are the regression floor). Concretely:
- The JSON-lines path (`JSON.stringify` with the non-finite→`null` replacer) is already shape-agnostic — expose a generic form and keep `recordToJsonLine(record: RunRecord)` as a wrapper.
- `flattenMetrics` already iterates the metrics object generically (numbers + nested `DistributionSummary`s); `pruneReasons` (a nested object of numbers) flattens to `pruneReasons.cycle`, `pruneReasons.timed-out`, … for free under the same logic.
- Make the CSV accumulator take the canonical metric-column order as a parameter (`createSweepCsvAccumulator(metricColumns)`); the oracle wrapper passes its current `METRIC_COLUMNS`, the sim one passes the sim order below.

New `src/serialize-sim-records.ts` (or sim-specific exports) with `simRecordToJsonLine`, `simRecordsToJsonLines`, `parseSimJsonLine`, `createSimCsvAccumulator`, `simRecordsToCsv` — reusing the generic core. **Sim CSV metric-column order** (only columns actually present are emitted; `distributionColumns(prefix)` = the 7 `count/mean/min/max/p50/p90/p99` columns):
```
queryCount, meanDegree, largestComponentFraction,
routeExistsCount, foundCount, foundAndExistsCount, pFoundGivenExists, falseFoundCount,
…distributionColumns('timeToFirstPlanMs'), …distributionColumns('timeToCompletionMs'),
…distributionColumns('messages'), …distributionColumns('nodesTouched'),
…distributionColumns('roundsUsed'), …distributionColumns('plansFound'),
pruneReasons.cycle, pruneReasons.failed, pruneReasons.timed-out,
pruneReasons.max-depth, pruneReasons.expired, pruneReasons.no-reentrance
```
Keep the same non-finite → `null`/empty-cell convention. Export the new serialiser(s) from `src/index.ts`.

## `src/cli/simulate.ts` — mirror `cli/sweep.ts`

A Node-only driver (excluded from the neutral `tsconfig.build.json` and the `no-node-globals` guard; compiled by `tsconfig.cli.json`, which already globs `src/cli/**`). It reads a `SimSweepSpec` JSON file and **streams** JSON-lines `SimRunRecord`s to stdout (or `--jsonl <path>`), building the CSV summary on the same pass (`--csv <path>`). Because `runSimSweep` is an **async** generator, the run loop is `for await (const record of runSimSweep(spec, deps))`.

Flags (mirror `cli/sweep.ts`'s `parseArgs` style — a pure, unit-tested parser):
- positional `<spec.json>`
- `--jsonl <path>` / `--csv <path>`
- `--concurrent` — boolean; sets `SimRunnerDeps.concurrent` (issue a cell's queries before one `runUntilIdle`).
- `--trace <path>` + repeatable `--query <i>` + `--seed <n>` — optionally dump a full replayable trace of the sweep's **base** scenario (vary NOT applied) at the given run seed (default 0), for the selected 0-based query indices, via the trace writer. **Reuse `recordTrace` from `./trace.js`** (it already takes an injectable `open()` yielding a `LineSink` + package versions) against `spec.base`; document plainly that `--trace` traces the unvaried base scenario, not a swept cell. Keep the trace output on simulated time and byte-identical.

```
node dist/cli/simulate.js <spec.json> [--jsonl <out.jsonl>] [--csv <out.csv>] [--concurrent] \
    [--trace <trace.ndjson> [--query <i> ...] [--seed <n>]]
yarn workspace tallysim simulate <spec.json> ...
```

Add a `"simulate": "node dist/cli/simulate.js"` script to `package.json` (next to `sweep`/`trace`).
