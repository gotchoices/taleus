## What this ticket delivers

The discovery tier already has: the harness (`sim/harness.ts`: `buildSimNetwork` + `runQuery` over a `VirtualClock`), the conditions compiler (`sim/conditions.ts`), and the versioned trace format/writer (`sim/trace-format.ts`, `sim/trace-writer.ts`). This ticket adds the **measurement** layer: for each query, combine the ground-truth oracle (does a route exist on the full, undegraded network?) with the real protocol's trace events + outcome, to answer *out of the routes that exist, how many did the protocol find, how fast, how many messages, how many rounds, and why did candidates get pruned?* Then a sweep runner mirroring `runner.ts`'s `runSweep` streams one record per cell × seed.

### `src/sim/protocol-metrics.ts` — pure module (like `metrics.ts`)

```ts
import type { PruneReason, TraceEvent } from 'tallynet'
import { type DistributionSummary, summarizeDistribution, type StructuralMetrics } from '../metrics.js'
import type { QueryOutcome } from './harness.js'

export interface ProtocolQueryResult {
	routeExists: boolean
	found: boolean
	plansFound: number
	timeToFirstPlanMs?: number
	timeToCompletionMs: number
	messages: number
	nodesTouched: number
	roundsUsed: number
	pruneReasons: Record<PruneReason, number>
}

export interface ProtocolRunMetrics {
	queryCount: number
	meanDegree: number
	largestComponentFraction: number
	routeExistsCount: number
	foundCount: number
	foundAndExistsCount: number
	pFoundGivenExists: number          // foundAndExistsCount / routeExistsCount, 0 if none exist (never NaN)
	falseFoundCount: number            // found AND oracle says no route — MUST be 0 (guardrail; assert in tests)
	timeToFirstPlanMs: DistributionSummary   // over found queries only
	timeToCompletionMs: DistributionSummary  // over all queries
	messages: DistributionSummary
	nodesTouched: DistributionSummary
	roundsUsed: DistributionSummary
	plansFound: DistributionSummary
	pruneReasons: Record<PruneReason, number>  // summed over the run
}

export function analyzeQuery(
	events: readonly TraceEvent[],
	outcome: QueryOutcome,
	routeExists: boolean,
	timing: { startMs: number; endMs: number },
): ProtocolQueryResult

export function summarizeProtocolMetrics(
	results: readonly ProtocolQueryResult[],
	structural: StructuralMetrics,
): ProtocolRunMetrics
```

`analyzeQuery` **filters `events` by `outcome.sessionCode` internally** (so it works whether handed one session's events or a whole concurrent batch's). From the filtered events:
- `found` = `outcome.found`; `plansFound` = `outcome.plans.length`.
- `timeToFirstPlanMs` = min `time` over `plan-found` events − `startMs` (undefined if none).
- `timeToCompletionMs` = (max event `time`, or `endMs` if no events) − `startMs`. (Using the last event time makes per-session completion correct even in concurrent mode; `endMs` is the fallback for a session with zero events.)
- `messages` = count of `query-sent` events (NOT deliveries — so a `late-answer-folded` adds no phantom message).
- `nodesTouched` = distinct `nodeId`.
- `roundsUsed` = max `round` over `round-started` and `query-sent` events (0 if none). Reading round counters (not delivery counts) keeps a folded-in late answer from inflating it.
- `pruneReasons` = count per reason over `candidate-pruned` events, zero-initialised for all six reasons.

The six `PruneReason` values (literal list to initialise the record — `PruneReason` is a type-only export from tallynet): `'cycle' | 'failed' | 'timed-out' | 'max-depth' | 'expired' | 'no-reentrance'`. Define `ALL_PRUNE_REASONS` + a `zeroPruneReasons()` helper.

`summarizeProtocolMetrics` reuses `summarizeDistribution` from `metrics.ts`; `pFoundGivenExists` guards 0/0 → 0 exactly as `metrics.ts` does; `pruneReasons` sums each query's record. `timeToFirstPlanMs` distribution is over found queries whose `timeToFirstPlanMs` is defined; the other distributions are over all queries. `StructuralMetrics` (`{ meanDegree, largestComponentFraction }`) and `DistributionSummary` come from `metrics.ts` unchanged — do **not** overload the oracle's `RunMetrics`.

### `src/sim/sim-runner.ts` — mirror `runner.ts`

```ts
export interface SimRunRecord {       // same provenance shape as RunRecord
	generator: string
	capacity: string
	params: Record<string, number>
	seed: number
	metrics: ProtocolRunMetrics
}
export interface SimRunnerDeps { concurrent?: boolean }  // default sequential

export async function* runSimSweep(spec: SimSweepSpec, deps?: SimRunnerDeps): AsyncGenerator<SimRunRecord>
export async function runSimSweepToArray(spec: SimSweepSpec, deps?: SimRunnerDeps): Promise<SimRunRecord[]>
```

**It is an `async` generator** (the oracle runner is sync; this one must await `clock.runUntilIdle()`). Per cell × seed, `runOne`:
- `materializeNetwork(scenario.network, runSeed)` (reuse `workload.ts`; offsets the network seed by the run seed).
- Oracle on the **full** network: `new Oracle(buildGraphView(network))` (or `Oracle.fromNetwork`). Conditions degrade only the protocol run, never the oracle.
- `structuralMetrics(network)` = `{ meanDegree, largestComponentFraction }` — copy the 3-line helper from `runner.ts` (uses `structure.ts`).
- Draw queries with `drawPaymentQueries(workload, entityCount, new SeededRandom(workload.seed + runSeed))` — **mirror the oracle runner's three-stream seed scheme**: network seed via `materializeNetwork`, workload seed `workload.seed + runSeed`, conditions seed `(conditionsSeed ?? 0) + runSeed`. Add the same NOTE `runner.ts` carries about streams being independent only when base seeds differ.
- Build one `SimNetwork` via `buildSimNetwork(network, conditions ?? {}, conditionsSeed, sink, budgetOptions)` where `sink` is a simple in-memory `TraceSink` that pushes every `TraceEvent` into an array (do NOT use `makeTraceWriter` — no need to serialise for metrics), and `budgetOptions = scenario.budget` (maps straight onto the `{ initialBudgetMs?, perHopBudgetMs? }` subset of `OriginatorOptions`; `maxDepth` rides on each query's `depth`, passed by `issueQuery`).
- **Sequential (default):** for each query — `startMs = clock.now()`; `const p = issueQuery(sim, q)`; `await clock.runUntilIdle()`; `const outcome = await p`; `endMs = clock.now()`. Record `(outcome, startMs, endMs)`.
- **Concurrent (`deps.concurrent`):** `startMs = clock.now()` (one value, all queries); issue all `issueQuery` promises in query order (session codes mint in call order → deterministic); `await clock.runUntilIdle()`; `await Promise.all(...)`; `endMs = clock.now()`. Same per-query results as sequential because the network is static and per-session state is isolated (verified during investigation: identical session codes and outcomes in both modes; relative timing identical because every session starts at the same clock instant and the VirtualClock fires each timer at its own scheduled time).
- Per query, `analyzeQuery(allEvents, outcome, oracle.routeExistence(from, to, amount, depth).exists, { startMs, endMs })`.
- `entityCount < 2`: no `SimNetwork`, no queries drawn; emit `workload.queries` degenerate `ProtocolQueryResult`s (`routeExists:false, found:false, plansFound:0, timeToCompletionMs:0, messages:0, nodesTouched:0, roundsUsed:0, pruneReasons zeroed, timeToFirstPlanMs undefined`) — the same guard the oracle runner uses.
- `summarizeProtocolMetrics(results, structural)` → yield `{ generator, capacity, params: coords, seed: runSeed, metrics }` (`generator`/`capacity` resolved exactly as `runner.ts` does from the `NetworkSource`).
- Add a `NOTE:` at the per-query loop: route discovery is ~O(network) per query, far costlier than the oracle BFS; if a sweep ever needs large N, record only sampled queries and/or cap concurrency.

Reuse `cartesian`/`coordsOf`/`requireNonEmptyValues`/`setByPath` from `sweep-vary.ts`. Write a `cloneSimScenario` (deep enough to set varied leaves without touching the base; keep a materialised `Network` by reference like `runner.ts`) and a `validateSimSweep` (non-empty seeds; `requireNonEmptyValues`; reject a non-`workload.*` vary path for a materialised network, same as `runner.ts`). **Refactor `runner.ts` to import the three helpers from `sweep-vary.ts`** instead of its private copies (identical logic — the determinism test is the regression floor).

## Design decisions already resolved (do not re-investigate)

- **`PruneReason` (tallynet)** = `'cycle' | 'failed' | 'timed-out' | 'max-depth' | 'expired' | 'no-reentrance'` (from `packages/tallynet/src/trace.ts`). Distinct from taleus-core's accumulator `PruneReason`.
- **`TraceEvent` fields used:** `query-sent { nonce, depth, round }`, `plan-found {}`, `round-started { round, budgetMs }`, `candidate-pruned { nonce, reason }`, `late-answer-folded { nonce, round }`. Every event has `TraceBase { time, nodeId, sessionCode }`.
- **`discover` mints the session code synchronously** (via `generate()`) before its first await, but it is only observable when the returned promise resolves — hence capture start times by **query order/index**, not by session code, in concurrent mode.
- **Oracle uses the same depth as the protocol** (`query.depth`). Because the protocol's reach ≈ ⌊maxDepth/2⌋+1 hops (see `docs/design.md` § "Rounds ↔ hops"; `found ⊆ oracle`, never `found iff oracle`), `pFoundGivenExists < 1` at matched depth is the *reach cadence*, not a connectivity failure. This matters for the experiment ticket's write-up, not for the engine here — the engine just reports the numbers honestly.
- **`concurrent` is a runner dep, NOT a `SimScenario` field** — keeps `SimScenario` (which is embedded verbatim in trace headers, written sequentially by `cli/trace.ts`) clean, and both modes stay deterministic.
- Default originator `sessionTtlMs` (600_000) and budgets suffice for the planned grids; the harness passes `budget` through as `options`. Late answers fold in at depth ≥ 8 with the default TTL (confirmed against the existing harness late-answer test).

## Edge cases to cover (tests in this ticket)

- Hand-built single-route graph, ideal conditions: `pFoundGivenExists = 1`, `falseFoundCount = 0`, and `messages`/`nodesTouched`/`roundsUsed` match a hand trace.
- Seeded random graphs: `foundAndExistsCount ≤ routeExistsCount`; `falseFoundCount = 0`; and since `found ⊆ oracle`, `foundCount === foundAndExistsCount`.
- A sleeping-node scenario: `pFoundGivenExists < 1` while the oracle still confirms routes exist (the gap); the missed queries are `routeExists=true, found=false`. (The existing harness test shows `line(4)` with `sleepingFraction: 0.25`, seed 0 sleeps the relay node 1 and blocks `0→3`.)
- Late-node counts: a `late-answer-folded` scenario's `messages`/`roundsUsed` match a hand-computed expectation (no double count).
- Concurrent vs sequential: identical per-query metrics for independent queries (≥ 2 originators); both byte-deterministic across two runs.
- Degenerate guards: zero queries, zero existing routes (`pFoundGivenExists = 0`, not NaN), `entityCount < 2` — all 0, no NaN, no throw.
- `falseFoundCount === 0` asserted in every seeded test — a non-zero count is a harness/terms bug; fail loudly.
