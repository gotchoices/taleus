## sim/consensus-runner.ts

A **separate** runner (do NOT widen `SimRunRecord` — that keeps the pinned byte-identical discovery sweep
untouched). It consumes the existing `SimSweepSpec` (its `base` is now a `SimScenario` that may carry a
`consensus` block + `consensusSeed`); no new sweep-spec type needed. Reuse `sweep-vary.ts`
(`cartesian`/`coordsOf`/`setByPath`/`requireNonEmptyValues`) exactly as `sim-runner.ts` does.

```ts
export interface ConsensusRunRecord {
  generator: string         // materialized ⇒ network.meta.generator, else scenario.network.generator (as SimRunRecord)
  capacity: string          // 'materialized' | the capacity.kind
  params: Record<string, number>
  seed: number
  metrics: ConsensusRunMetrics
}
export async function* runConsensusSweep(spec: SimSweepSpec): AsyncGenerator<ConsensusRunRecord>
export async function runConsensusSweepToArray(spec: SimSweepSpec): Promise<ConsensusRunRecord[]>
```

**No `concurrent` dep.** Consensus runs **sequentially**: a sequence of lifts mutates the one kept network
in order, so balances between lifts are defined only under a fixed lift order. State this invariant in the
module header; do not offer a concurrent mode.

### The per-run loop (load-bearing decisions — these were the hard part)

Per `(cell × seed)`:
1. `network = cloneNetwork(materializeNetwork(scenario.network, runSeed))` — a **clone**, because lifts
   mutate `tally.balance` in place on commit and the kept network is mutated across the run.
2. Streams, all run-seed-offset (mirror `sim-runner.ts`): network (`materializeNetwork` handles it),
   workload (`workload.seed + runSeed`), conditions (`(conditionsSeed ?? 0) + runSeed`), **refuser
   (`(consensusSeed ?? 0) + runSeed`)**, identity (`(consensus.identitySeed ?? DEFAULT) + runSeed`).
3. `refusers = compileConsensusConditions(network, scenario.consensus ?? {}, refuserSeed).refusers`;
   build `resourceFor` ONCE via `makeSimResources({ [id]: { shouldPromise: false }, ... })` (its handles
   accumulate observations across lifts but behaviour is stateless/deterministic — fine to reuse).
4. `queries = drawPaymentQueries(workload, network.entityCount, workloadRng)` (same draw order as the
   discovery runner).
5. **Rebuild the sim PER QUERY** from the current (mutated) `network`, each with a **fresh events array +
   fresh `TraceSink`**:
   ```
   for each query:
     const events: TraceEvent[] = []
     const sim = buildSimNetwork(network, conditions, conditionsSeed, e => events.push(e), budget,
                                 { identitySeed, resourceFor })
     const outcome = await runQuery(sim, query)
     const result  = await runLiftForOutcome(sim, network, outcome, query)  // mutates network.balance on commit
     if (result) liftMetrics.push(analyzeLift(events, result))
   ```
   **Why rebuild per query:** `InMemoryNetwork` freezes link terms at construction, so a committed lift's
   balance change is invisible to an already-built sim; the next query must see the changed capacity (the
   §invariant), AND discovery must stay consistent with the mutated network or a later `settleRoute` would
   assert over-limit. Fresh events arrays make the per-query **session/transaction-code reset harmless**
   (buildSimNetwork reseeds its session-code RNG from a fixed constant each build, so codes collide across
   rebuilds — but each lift's metrics read only its own query's array, filtered by its own `transactionCode`
   within that array, so collisions never mix lifts). **No oracle is needed** (the headline is commit÷found,
   not found÷oracle). Add a `NOTE:` tripwire at the loop: rebuild-per-query pays keygen per query; fine for
   the small grids (~50 queries), revisit if a grid grows.
6. `structural = { meanDegree(network), connectedComponents(network).largestFraction }`.
7. `metrics = summarizeConsensusMetrics(liftMetrics, structural, queries.length)`.

A sub-two-entity network: emit a zeroed `ConsensusRunMetrics` (mirror the discovery runner's degenerate
guard: `liftCount 0`, `pCommitGivenFound 0`, all-zero void reasons/distributions).

### cloneSimScenario for vary

Mirror `sim-runner.ts`'s private `cloneSimScenario`, **plus** clone `consensus` (`{ ...consensus }`) and
copy `consensusSeed`, so a vary over e.g. `consensus.refuserFraction` or `conditions.dropFraction` is
isolated. (Don't touch `sim-runner.ts`'s own clone — keep discovery byte-identical.) `validateSimSweep`
can be reused/duplicated as-is.

## cli/consensus.ts

Mirror `cli/simulate.ts` (Node-only; excluded from the neutral build + `no-node-globals` guard; compiled
by `tsconfig.cli.json`). Streams JSON-lines (`consensusRecordToJsonLine`) to stdout/`--jsonl`, builds the
CSV (`createConsensusCsvAccumulator`) on the same pass, writes it to `--csv`. No `--concurrent`. (`--trace`
support is **not** required here — the trace lives in sibling `tallysim-consensus-trace-v2`; add it only if
trivially reusable.) Add the new package script wiring if `cli/simulate` has one (`package.json` `scripts`
+ any `tsconfig.cli.json` include globs — check how `simulate` is registered and match it).

## Tests

- **Seeded scenarios, known outcomes** (`consensus-runner.test.ts`, real networks — use a `materialized`
  line/clustered network so outcomes are predictable, like `consensus-harness.test.ts` does):
  - all-cooperative → `pCommitGivenFound = 1`, every lift commits.
  - one refuser (count-based, `consensus.refuserFraction` sized to hit a known entity on the route) → the
    lifts through it void with `voidReasons['refused-promise'] >= 1`.
  - a dropped push on a cut edge (a sleeping/dropped **target**, per the failure-injection ticket's
    mechanism) → `pendingCount >= 1`, `voidReasons.stalled >= 1`.
  - **determinism**: `runConsensusSweepToArray(spec)` twice ⇒ deep-equal records (metrics identical).
- **CSV self-description** (`serialize-consensus-records.test.ts`, mirror `serialize-sim-records.test.ts`):
  a `ConsensusRunRecord` flattens to the documented columns; `.jsonl` and `.csv` agree; round-trips.
