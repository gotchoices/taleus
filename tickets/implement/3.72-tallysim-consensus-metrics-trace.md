prereq: tallysim-consensus-core

`tallysim-consensus-core` can drive one found route to `commit` / `void` / `pending` and move balances. This
ticket turns that into **measurement, failure injection, and a recordable trace**: metrics over many lifts, the
scenario knobs that make lifts fail, and a trace-header extension that carries each lift's route + member map so
the viewer (`tallysim-viewer-consensus`, next) can animate precisely.

## 1. Consensus metrics (`sim/consensus-metrics.ts`, a pure module)

Mirror `sim/protocol-metrics.ts`: **recorded run in, metrics out**, no network / clock / filesystem, testable
from hand-built `LiftResult`s + consensus `TraceEvent`s. From one lift's events (filtered by `transactionCode`)
and its `LiftResult` derive a `ConsensusLiftMetrics`, and aggregate to a `ConsensusRunMetrics`:

- **`pCommitGivenFound`** — the headline: `commitCount / liftCount` (lifts attempted = routes found and taken).
  **0, never NaN**, when no lift ran.
- **`timeToSettleMs`** — a `DistributionSummary` (reuse `summarizeDistribution`) over settled lifts: last
  consensus event's `time` − first `record-pushed`/`promise-signed` time. Omitted for `pending` lifts.
- **`messagesPerLift`** — distribution of `record-pushed` counts per lift (the push is the consensus message).
- **`voidReasons`** — a per-reason tally (zero-initialised over the full reason set, like `pruneReasons`):
  `refused-promise` (a counted `NP`), `voted-no-commit` (a counted `NC`), `stalled` (ended `pending`: a dropped
  push or an unbroken tie — no majority either way), and `expired` (a `signature-rejected`/refusal with reason
  `expired`). Derive the reason from the trace + outcome; document the precedence when more than one applies.
- Carry `commitCount` / `voidCount` / `pendingCount` / `liftCount` raw, so a CSV row is self-describing.

`voidReasons` must be a compile-checked source of truth (one `zeroVoidReasons()` the aggregator and any
`ALL_VOID_REASONS` derive from), the pattern `protocol-metrics.ts` uses for `pruneReasons`.

## 2. Failure injection (scenario knobs)

Add a `consensus` block to the sim scenario (`scenario.ts`) that selects, from **dedicated seeded streams**
(do not perturb the discovery streams), the failures the parent ticket names. Reuse `sim/conditions.ts`'s
count-based selection (`round(fraction · poolSize)` via a seeded partial shuffle) so a test asserts exact
counts:

- **A refuser** — a route participant that signs `NP`: a fraction of participants get `shouldPromise=false`
  (via the core ticket's resource port). Only bites when the drawn node lands on a taken route.
- **A node that sleeps mid-transaction** — reuse the conditions model: a sleeping node's incident links `drop`,
  so consensus pushes to/from it never deliver; the lift stalls (`pending`) unless the voter set is reachable
  another way. (Note the asymmetry with discovery: a sleeping relay that is **not** a voter still lets a lift
  commit if the voter set and all promisers are otherwise reachable — phase-2 "a refuser only hurts itself" is
  **not** in v1, so a dropped push on a needed edge stalls; document this honestly.)
- **A dropped push** — a `dropFraction` of links `drop` (same surface as discovery's dropped links), applied to
  consensus pushes via the harness's `pushCondition`.
- **A slow voter** — an `R` member reached over a link carrying `lateLatencyMs`; the record folds in late, so
  `timeToSettleMs` grows but the lift still settles (keep the latency well under the code TTL, as the exemplar
  does, or an expired code changes the outcome — document the ceiling).

Each injected failure must show up in the trace (it already does — the events are emitted) and in `voidReasons`
/ `timeToSettleMs`.

**Consensus runs sequentially** (unlike the discovery sweep's optional concurrent mode): a sequence of lifts
mutates the one kept network in order, so balances between lifts are defined only under a fixed lift order. State
this invariant; do not offer a concurrent consensus mode.

## 3. The consensus run loop + CSV

Add a run path that, per query, runs discovery → picks a plan → runs the lift → records a `LiftResult` +
metrics. Decided: a **separate `sim/consensus-runner.ts`** mirroring `sim-runner.ts`, emitting a
`ConsensusRunRecord` ({ generator, capacity, params, seed, metrics: ConsensusRunMetrics }), rather than
widening `SimRunRecord` — this keeps the pinned byte-identical discovery sweep untouched. Add a
`serialize-consensus-records.ts` counterpart (reuse the generic `metricsRecordToJsonLine` /
`createSweepCsvAccumulator(metricColumns)` machinery; only the column order is new) and a `cli/consensus.ts`
(or a `--consensus` mode on `cli/simulate.ts`) that streams JSON-lines + CSV. A small checked-in experiment
(`experiments/commit-vs-found/`, a modest grid — small `N`, few seeds, ~50 queries, `regenerate.sh` well under
~10 min, streamed with `tee`) is the stretch deliverable; the seeded scenario tests below are the primary one.

## 4. Trace header extension (`sim/trace-format.ts`)

The consensus `TraceEvent`s already pass through the writer/reader unchanged (the union spans both milestones),
so **event lines need no change**. But the viewer must place those events, and a consensus event's `nodeId` /
`to` / `from` are member **keys** (ed25519 pubkeys), not entity ids — and the chosen route is not recoverable
from the discovery event stream (the found-plan path gap). So extend the **header envelope** with the lift data
the sim holds:

```ts
interface TraceLiftEntry {
  sessionCode: string                  // joins to the TraceQueryEntry (discovery) this lift came from
  transactionCode: string              // joins consensus events (event.transactionCode)
  route: number[]                      // ordered entity ids [from, …, to] (originator first)
  tallyPath: number[]                  // ordered tally indices, one per hop — resolves edges exactly
  memberKeys: Record<string, number>   // member key (base64url) → entity id, to place consensus events
  amount: number
}
// TraceHeader gains:  lifts?: TraceLiftEntry[]
```

A header-envelope change **is** a version bump: set `TRACE_FORMAT_VERSION = 2`. **Keep reading older traces** —
`readHeader` must accept version ∈ {1, 2} and treat `lifts` as **optional** (absent on a v1 file and on a
discovery-only v2 run). A v1 reader rejecting a v2 file is correct (it cannot know `lifts`); the new reader
reads both. Update the `trace-format.ts` module header, which currently says consensus needs no bump — correct
it: *events* need no bump, this *header* field does.

Wire `cli/trace.ts` (and `cli/simulate.ts`'s `--trace`) to populate `lifts` when the recorded run runs
consensus: its two-pass determinism already reruns the batch, so pass 2 records each lift's entry. The
selected-query consistency the writer guarantees extends to lifts: every recorded lift's `sessionCode` is in
`queries[]`.

## Edge cases & interactions

- **A pending lift** contributes to `pCommitGivenFound`'s denominator, has **no** `timeToSettleMs` sample, and a
  `stalled` void-reason.
- **A lift that both has a refuser and crosses a dropped edge:** `voidReasons` counts it once under a documented
  precedence (refusal is observed before the stall deadline, so `refused-promise` wins).
- **`voidReasons` over zero lifts** is the all-zero tally, not an error; `pCommitGivenFound` is `0`.
- **v1 trace round-trips** unchanged through the v2 reader (no `lifts`); a v2 discovery-only trace has no
  `lifts`; a v2 consensus trace has one `lifts` entry per committed-or-attempted query.
- **Determinism:** the consensus sweep run twice is byte-identical (metrics, records, and the trace file),
  resting on the core ticket's identity-seed + the sequential lift order.
- **Late-folded voter answer** lands in the stream at its own time; `timeToSettleMs` reflects the later settle,
  not a duplicate.

## Tests to plan

- **Metrics from hand-built events** (pure, no network): a commit stream → `pCommitGivenFound=1`, a `timeToSettle`
  sample, `messagesPerLift` = the push count; an `NP`-then-void stream → `voidReasons.refused-promise=1`; a
  stalled (no `settled`) stream → `pendingCount=1`, `voidReasons.stalled=1`, no settle sample.
- **Seeded scenarios with known outcomes:** all-cooperative → every lift commits; one refuser (count-based) →
  the lifts through it void with reason `refused-promise`; a dropped push on a cut edge → `stalled`.
- **Determinism of the full discovery + consensus trace:** the recorded trace file is byte-identical across two
  runs of the same scenario + seeds.
- **Trace versioning:** a v1 file still parses (no `lifts`); a v2 file with `lifts` round-trips; a v3 (bogus)
  version is rejected naming found-vs-supported.
- **CSV self-description:** a `ConsensusRunRecord` flattens to the documented columns; `.jsonl` and `.csv` agree
  (the pattern `serialize-records.ts` tests pin).
