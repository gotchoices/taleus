## Summary (reproduced + root-caused in the fix stage)

Route discovery was *measured* to reach only about half as far as its depth ceiling says: a route of
**L** hops was found only at `maxDepth ≥ 2(L − 1)` (for L ≥ 2). The fix stage reproduced this exactly
and traced it to its root. **It is not a protocol defect — it is an artifact of the test/sim virtual
clock.** The real protocol finds an L-hop route at `maxDepth = L` (one round per level). The fix is a
one-line change to the virtual clock's microtask-drain constant, plus correcting the tests and docs
that had codified the wrong `2(L − 1)` relationship as if it were real.

### What was reproduced

A straight chain `N0-N1-…-N{L}` (target `N{L}`, resolved as a **peer-match** by its neighbour `N{L-1}`),
driven through `tallynet/testing`'s `InMemoryNetwork` on the `VirtualClock` with default options:

| route hops L | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| smallest `maxDepth` that finds it (current/buggy) | 1 | 2 | 4 | 6 | 8 | 10 |

This matches the ticket's table and `tallysim/docs/design.md` § *Rounds ↔ hops* exactly.

### Root cause (named mechanism)

The round-trip to even an **instantly-answering** child costs a full round, because
`budgetedStep` (`packages/tallynet/src/sequencing.ts`) never short-circuits on completion **under the
VirtualClock**. The mechanism:

- A discovery round issues sub-queries, then `await budgetedStep(clock, budget, requests)`.
  `budgetedStep` arms a budget timer at `now + budget` and registers `checkDone` on each request; when
  all requests complete it is supposed to `clearTimer` the budget and resolve **early**.
- Under the real clock (and in isolation on the virtual clock) this works. But in the real nested
  discovery path, a sub-query's *completion cascade* — `send` delivery resolves → `Pending.then` →
  `budgetedStep`'s `checkDone` → `clearTimer` → the child's `reenter` continues (`harvest`, `foldPlans`,
  `await saveContext`, `makeResponse`) → the child's `query` resolves → the parent's `Pending` resolves
  → the parent's `checkDone` — is a chain of **~17–23 microtask hops that schedule no timer**.
- `VirtualClock.drainMicrotasks` (`packages/tallynet/src/testing/clock.ts`) ends a drain after
  `DRAIN_QUIET = 16` *consecutive quiet hops* (no timer created/cleared/fired). The ~20-hop completion
  cascade **exceeds 16**, so the drain quiesces *mid-cascade*; the runUntilIdle loop then fires the
  budget timer (advancing virtual time to full budget) **before** `checkDone` clears it. So every round
  runs to its full budget, and an answer that lands exactly at budget-expiry is folded one round **late**
  (`candidate.depth < context.depth`), which is where the *extra* round per level comes from → `2(L − 1)`.

The `clock.ts` doc already warns about exactly this (§ *The microtask-drain problem*, the `DRAIN_QUIET`
NOTE): "discovery's callbacks return void, so they still rely on their whole query chain fitting inside
16 quiet hops. If discovery ever grows a longer void chain that under-drains, … raise DRAIN_QUIET." The
discovery chain is now longer than that estimate assumed.

### Proof it is the clock, not the protocol

Raising `DRAIN_QUIET` collapses the table to exactly `maxDepth = L` for every L, confirming the protocol
reaches its full ceiling. Measured in the fix stage (straight chains, L = 1..14):

- `DRAIN_QUIET = 16` → `2(L − 1)` at **every** depth (the per-level cost is a constant 2 rounds).
- `DRAIN_QUIET = 24` and above → `maxDepth = L` at **every** depth up to L = 14.

The threshold is **constant in depth** (the completion cascade is per-level, ~17–23 hops, *not*
cumulative — each level's harvest is its own fire/drain cycle), so a single modest bump fixes it at any
depth; it does not need to scale with `maxDepth`. With the bump, the full tallynet discovery suite
passes except the one boundary test that asserts the buggy `2(L − 1)` (expected — that test codifies the
artifact and is rewritten below). Latency / sleeping-peer / late-answer / 1,000-node-scale tests all
still pass: the fix only stops *instant* answers being spuriously treated as late; genuine
`latencyMs`-past-budget answers still fold into a later round as intended.

### Decision (to record in `tallynet/docs/design.md` § Protocol design)

**Defect, in the simulation harness (the `VirtualClock`), not the protocol.** The protocol's reach is
`maxDepth = L`: a route of L hops is found at `maxDepth = L`, with one round per level. (The last hop is
resolved by the target's neighbour as a peer-match, but that costs no extra round — an L-hop plan has
`path.length = L ≤ maxDepth = L`.) `maxDepth` counts hops, same as the oracle. The `⌊D/2⌋ + 1` "reach is
half the ceiling" claim is withdrawn.

### Why `return the promise` is NOT the fix (don't go there)

The other option the `clock.ts` NOTE lists — have discovery's delivery timer callback *return* its query
promise so `fire()` pending-tracks it (as consensus does) — **deadlocks** for discovery. A discovery
`query` awaits a nested `budgetedStep` whose budget/delivery timers only fire in the runUntilIdle loop,
not during a drain. If the drain waits (`pending > 0`) for that query promise, the nested timer can never
fire, so the promise never settles → the drain spins to `MAX_DRAIN`. (Consensus callbacks are pure
await-chains that arm no timer mid-flight, so they don't have this problem.) Raise `DRAIN_QUIET` instead.
