Third viewer ticket. The graph-view ticket draws a loaded trace's network at rest; the scaffold-core ticket
built the `timeline` reducer and the `deanonymise` decoder. This ticket wires a **timeline UI** that replays
a query spreading through the graph and shows the routes it finds.

## Architecture

### Timeline controls (`src/replay/controls.ts`)

- Play / pause / speed (e.g. 0.25×–8×) / scrub bar over the trace's event-time range (from `trace-index`).
  The controls own the **clock**: a `requestAnimationFrame` loop that advances `currentTime` by
  `speed · realDelta` and calls the pure `timeline` reducer's `seek`; the reducer stays the single source of
  truth for the "lit" state (so scrubbing and playing share one code path). Scrubbing backward must be correct
  (the reducer already handles it).
- A session picker: a trace may hold **multiple concurrent queries** (sessions). Default to showing one
  chosen session; offer "colour by session" to overlay several (distinct hues per `sessionCode`). The graph's
  hover/selection state (from graph-view) must compose with the lit state, not replace it.

### Lighting the graph (`src/replay/paint.ts`)

Translate the timeline reducer's active-set data into sigma node/edge styling (via the palette module):

- **Nodes light up as the search reaches them**, coloured by **round / depth** (a sequential, colour-blind-safe
  scale). A node becomes active on its first `query-received` / `round-started` / `query-sent` at or before
  `currentTime`.
- **Edges light up** using the deanonymiser: every nonce-bearing event (`query-sent`, `query-received`,
  `candidate-pruned`, `plan-returned`, `late-answer-folded`) maps to its exact tally edge, so edge lighting is
  **precise, not inferred**. Colour an edge by the round of the event that lit it.
- **Pruned branches fade**, with the **prune reason on hover** (`candidate-pruned`'s `PruneReason`:
  `cycle` / `failed` / `timed-out` / `max-depth` / `expired` / `no-reentrance`). Fade is distinct from
  "never reached".
- **Sleeping / late nodes are visibly distinct** (e.g. dimmed/dashed outline). Derive them from the trace
  header's `conditions` + `conditionsSeed` by calling tallysim's `compileConditions` — it returns the
  `sleeping: Set<number>`. **The `late` set is not currently returned**: either (a) derive late nodes from the
  compiled per-link `conditions` map (links carrying `lateLatencyMs`), or (b) — preferred, cleaner — extend
  `CompiledConditions` in `packages/tallysim/src/sim/conditions.ts` to also return `late: Set<number>`
  alongside `sleeping` (a small, in-scope change; update its test). Pick (b) unless it balloons; document the choice.

### Found routes (`src/replay/routes.ts`)

- Each plan the search found is a highlighted path. Reconstruct the node path from the plan's `path` (link
  nonces) via `deanonymise.nodePathOfPlanPath(sessionCode, from, linkNonces)`. A **circular lift**
  (`from === to`, a self-payment) is a **closed loop** — render it as a cycle, not an open path.
- A side list of the found plans with **length (hops) and terms** (the per-link negotiated terms on the
  plan's path). Selecting a plan **isolates it** in the graph (dim everything else, show just that path).
- **Empty result** (a session that found no route) is shown as such — explicitly "no route found", distinct
  from "still searching" (mid-scrub) and from "still loading".

## Edge cases & interactions

- **Late answer** (`late-answer-folded`): appears at its own clock time folded into a later round — the paint
  layer must show it lighting its edge at that later time, not dropped and not double-counted (the `timeline`
  reducer already models this; assert it end-to-end here).
- **Multiple concurrent sessions**: one-at-a-time by default; colour-by-session must keep each session's
  lit/pruned/found state separate (events are filtered by `sessionCode`, as `analyzeQuery` does).
- **Sleeping target vs. sleeping relay**: a sleeping *target* does not block a route (a neighbour resolves the
  peer-match from its own adjacency); only a sleeping non-target *relay* blocks. Rendering just marks nodes
  distinct — do not imply a sleeping target failed the query.
- **Scrub to t=0 / t=end**: clean empty state at the start, full final state at the end; backward scrub from
  end recomputes correctly.
- **Very large traces**: scrubbing must stay responsive — the reducer should seek without replaying every
  event from zero on each frame where avoidable (incremental cursor forward, reset only on backward seek);
  if a single trace's event count makes naive seek janky, index events by time for binary-search seek.
- **Plan path that does not resolve** (a nonce the viewer can't invert): surfaces the deanonymiser sentinel as
  a visible "route decode failed" rather than a silent empty path — this would indicate a bug worth seeing.
