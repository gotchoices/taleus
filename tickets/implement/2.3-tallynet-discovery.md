### Record the budget decision — `docs/design.md` § *Protocol design*
Add a short subsection (the ticket's "Time budget (decided: drop sparstogram)" rationale, condensed):
- Sparstogram is **dropped as a dependency** — not for compatibility (it is pure-ESM, RN-safe) but because adaptive histogram budgeting is an untested prototype optimisation, and dropping it removes the "trust a peer's reported stats" attack surface entirely.
- The budget is computed **solely from the originator's own options** (`initialBudgetMs + round * perHopBudgetMs`), never from peer-reported stats. Peer `QueryStats` stay in the protocol as **informational only**; nothing in control flow trusts them, so there is nothing to validate. The existing bullet in § Protocol design that says "validate peers' timing statistics before trusting them" should be corrected to reflect this (nothing is trusted).
- A deeper round gets a larger budget because its round-trip is longer. Constants are coarse (no adaptive tuning in v1).
- Reference backlog `feat-tallynet-adaptive-budget` for the parked adaptive version.

### File the backlog ticket — `tickets/backlog/feat-tallynet-adaptive-budget.md`
`feat-` prefix. Plain-language description: route searches currently give each deeper round a fixed, larger time budget from a simple formula; a future version could learn how long peers actually take and size each round's budget adaptively. Body: ChipNet grew the per-round budget from peers' reported timing histograms (`sparstogram` + Pareto quantile) with a `validatedStats` stub that trusted peers; TallyNet dropped it for a local linear budget. The adaptive version must size budgets from the **originator's own** clock measurements (never trust peer-reported stats — that was the dropped attack surface), e.g. track observed round-trip distributions locally and project a quantile. Note it depends on nothing but is a pure optimisation. Reference it from the design-doc note.

### End-to-end tests (the heart of this ticket)
Put discovery scenarios in `src/testing/discovery.test.ts` (or `src/discovery/engine.test.ts`), driving `InMemoryNetwork` + `VirtualClock`. Pattern: `const p = net.discover(from, target, intents); await clock.runUntilIdle(); const result = await p`.

- **Port ChipNet's 6-node happy path** (`../chipnet/test/uni-discovery.test.ts`): graph N1-L1-N2, N2-L2-N3, N2-L3-N4, N4-L4-N5, N3-L5-N6, each link `{ L: { balance: 500 } }`. Originator N1, target N6, intent `{ L: { balance: 100 } }`. **Use custom hooks replicating ChipNet's min-balance negotiation** (filter to `L`; same-sign + `abs(link) >= abs(want)` → `sign(want) * min(abs(link), abs(want))`; else drop) — the default pass-through hooks would carry 500, not 100. With inverted terms on back-links, the sign check matters. Assert: **exactly one plan**, **path length 3**, every link carries the single `L` intent at **balance 100**, **4 members ordered N1,N2,N3,N6**, and the originator's `getNonceToLinkMap(sessionCode)` maps `plan.path[0].nonce → 'L1'`. (ChipNet asserted nothing on its plans; we do better.)
  - **Worked trace** (so you can sanity-check the implementation): round 0 = N1.enter (candidates [L1], reentrance). round 1 = N1.reenter issues entrance to N2 → N2 enumerates [L2,L3] (L1 pruned cycle), reentrance; N1 folds nothing, advances. round 2 = N1.reenter → N2.reenter issues entrances to N3,N4 → N3.enter finds N6 as a **peerMatch** over L5, builds plan path [L1,L2,L5] members [N6], prepends N3 → returns plan+reentrance; N2 folds (members [N2,N3,N6]); N1 folds (members [N1,N2,N3,N6]), `planSatisfies` true → concludes satisfied. The originator sees a satisfying plan at round 2 and returns it. Path length 3, found at search round 2 — note **path length = reach-depth + 1** for a peer-match terminus.
- **Seeded random graph (hundreds of nodes):** every returned plan is a **valid path** (consecutive links share a node — resolve nonces via the harness's per-node maps, or assert structurally), has **no repeated nonce**, **ends at the target** (last member address = target key), and **respects maxDepth** (`path.length <= maxDepth + 1`; confirm the exact invariant empirically and assert what actually holds, documenting it). Reproducible under a fixed seed + `VirtualClock`.
- **Latency / drop / sleeping:** a slow link (latency > a round's budget) still folds into a later round (assert a plan via that path and/or a `late-answer-folded` trace); a dropped link never produces a plan; a sleeping node (finite large latency) is skipped by the budget and, when it wakes, its answer is folded in, **not double-counted** (dedup by path — the participant already dedups; assert exactly one copy).
- **Not-found / unreachable:** target not in the graph (or disconnected) → **empty plans, no throw**.
- **Self-is-target (circular):** originator = target → the entrance self-matches at round 0; result has a plan with empty path and `[self]` members. No throw.
- **1,000-node scale smoke test** on the `VirtualClock`: seeded random graph, asserts **completion** and **plan validity**, in a few seconds wall time. Give the test a generous jest timeout. Run `yarn workspace tallynet test 2>&1 | tee /tmp/t.log` so the long run streams (never silent-redirect — the runner's 10-min idle timer). **Scale invariant to defend:** nothing per query may be O(total nodes) — a node touches only its own links and per-session contexts. If the harness's `findAddress` or anything accidentally scans all nodes, fix it so cost is local to a node's degree.
- **Edge cases:** `maxDepth` reached with candidates open → stop, return what was found (no throw); target a direct peer (plan at depth 1); the same plan arriving by two different paths = two valid candidates (distinct path keys) while the same path twice must not surface two identical plans; no leaked timers after a full run (`runUntilIdle` leaves an empty queue); concurrent searches from different originators on the same graph don't interfere.

### Trace-overlap note (for the test author)
`UniOriginator.discover` emits `round-started` and `plan-found` from the originator loop. The **local participant's** `reenter` also emits `round-started`/`plan-found` for the same node — so an originator node shows both. This is intentional (two levels: the search round vs the participant's local sub-query round) and harmless (traces are informational). Assert **presence**, not counts, on these events.
