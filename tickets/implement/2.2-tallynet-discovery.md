The **originator** side of unidirectional discovery plus the end-to-end wiring, the time budget, and a shipped in-memory network harness that the simulator (`packages/tallysim`) builds on. This completes route discovery; the commit/consensus half is a separate ticket (`tallynet-consensus`). The participant, the data model, the state split and the hooks already exist from `tallynet-discovery-participant` — this ticket drives them from the payer's node and proves the whole thing on a simulated clock.

This ticket keeps the slug `tallynet-discovery` because four downstream plan tickets (`tallynet-consensus`, `tallynet-bind-taleus-core`, `tallynet-multi-denomination`, `tallysim-discovery`) name it as a prereq; it is the complete-discovery milestone they wait on.

## Originator (`src/discovery/originator.ts`)

Port `UniOriginator`. It mints a session code (from the injected `RandomSource` + `Clock` via the scaffold's `session-code.ts` `generate`), encrypts the target secret if any, builds the `UniQuery` (carrying `maxDepth`), then **drives its own local participant** in rounds: an `entrance` first, then the returned `reentrance` each round, up to `maxDepth`. After each round it checks `hooks.planSatisfies` on the returned plans and stops when satisfied, or when there is no reentrance (search exhausted), or at `maxDepth`. Emits `round-started` (with the round's budget), `plan-found` when a satisfying plan arrives.

A partial round is a normal, possibly-empty result — **never a throw for "not found."** The final result is `{ sessionCode, plans }` with `plans` possibly empty.

### Time budget (decided: drop sparstogram; simple, documented, local-only)

ChipNet grew the per-round budget from peers' reported timing histograms (`sparstogram` + a Pareto quantile, `originator.ts:66-112`), with `validatedStats` a TODO stub that trusted peers outright. **This ticket does not port that.** Decision and rationale, to record in `docs/design.md` § *Protocol design*:

- **Sparstogram is dropped as a dependency.** (It is pure-ESM and React-Native-safe — `npm view sparstogram` shows `type: module`, v1.1.0 — so compatibility is not the reason; the reason is that adaptive histogram budgeting is an untested prototype optimisation, and removing it removes an entire "trust a peer's reported stats" attack surface.)
- **The budget is computed solely from the originator's own `Clock` measurements**, never from peer-reported stats. Peer `QueryStats` stay in the protocol as **informational only** (useful for trace/diagnostics); nothing in control flow trusts them, so the "validate peer stats before use" concern dissolves — there is nothing to validate because nothing is trusted.
- **Growth rule:** per-round budget = `initialBudgetMs + round * perHopBudgetMs` (both options, documented defaults e.g. 2000 ms and 1500 ms). A deeper round gets a larger budget because its round-trip is longer. The participant honours `budgetMs - elapsed` locally (already implemented).
- Adaptive, histogram-based budgeting is parked as backlog `feat-tallynet-adaptive-budget` — see that ticket. Reference it in the design-doc note.

`UniOriginatorState` shrinks accordingly: it no longer learns a histogram growth rate. Keep a tiny `OriginatorOptions { maxDepth, initialBudgetMs, perHopBudgetMs }` and an in-memory originator state if any state is still needed; otherwise fold options into the originator constructor. Document the simplification.

## Engine API (`src/discovery/engine.ts`)

A per-node bundle `DiscoveryNode<TTerms, TPayload>` that a host constructs once per node and uses in both roles:

```ts
export interface DiscoveryResult<TTerms, TPayload> {
	sessionCode: string
	plans: Plan<TTerms, TPayload>[]
}

export class DiscoveryNode<TTerms, TPayload> {
	constructor(deps: DiscoveryNodeDeps<TTerms, TPayload>)  // nodeId, store, clock, random, trace, hasher,
	                                                        // session validators, findAddress, hooks, queryPeer, options

	/** Originator role: run one unidirectional search. Never throws for "not found". */
	discover(target: Target, intents: Record<string, TTerms>, options?: Partial<OriginatorOptions>): Promise<DiscoveryResult<TTerms, TPayload>>

	/** Participant role: what a peer's queryPeer calls to pass a request through this node. */
	query(request: QueryRequest<TTerms, TPayload>, inLinkId?: string): Promise<QueryResponse<TTerms, TPayload>>
}
```

`discover` wires the node's own `query` as the originator's local participant. `query` delegates to the participant from the previous ticket.

### Adapter note for `tallynet-bind-taleus-core` (do NOT change taleus-core here)

`taleus-core` already defines `DiscoveryEngine.discover(query: LiftQuery, callbacks: NegotiateCallbacks): Promise<CandidateRoute[]>` (`src/lift/agent.ts:131`, `src/lift/discovery.ts:316`). The binding ticket will wrap a `DiscoveryNode` so that:
- `LiftQuery { sessionCode, amount, payeeDenom, payeeDivisor, maxDepth, kind }` maps to a tallynet `Target` (payee address) + `intents` (one `'L'` code whose `TTerms` is Taleus's `LiftTerms`-shaped record) + `maxDepth`. A `circular` kind is the self-is-target case.
- `NegotiateCallbacks.negotiateIntent(intent, edge)` maps onto tallynet `DiscoveryHooks.negotiateIntent`; `negotiatePlan` onto `planSatisfies` + `annotateReturn` (the backward accumulation moves to `annotateReturn` under the multi-denomination ticket — until then taleus-core keeps its originator-side accumulation and `annotateReturn` stays identity).
- `DiscoveryResult.plans` maps to `CandidateRoute[]` (each `Plan.path` → `CandidateEdge[]`; the originator owns the first edge's `linkId`).
Write this mapping as a comment block in `engine.ts` so the binding ticket has it in hand. Do not edit any `packages/taleus-core` file in this ticket.

## In-memory network harness (`src/testing/`, shipped as `tallynet/testing`)

A **platform-neutral, shipped** module behind a subpath export — not a private test file — because `tallysim` builds on it and the viewer uses the same traces. Add the `./testing` export to `packages/tallynet/package.json` `exports` (and to `tsconfig.build.json` includes); build it alongside `src/`.

Contents:
- **`VirtualClock`** implementing the ports ticket's `Clock`: a `now()` that only advances when timers fire, a priority queue of scheduled timers, `advance(ms)` / `runUntilIdle()` drivers. This is where simulated time lives. Deterministic: ties broken by insertion order.
- **`SeededRandom`** implementing `RandomSource` (`crypto.ts`): a seeded PRNG (e.g. xorshift/pcg) producing `randomBytes(n)` reproducibly. No `Math.random`.
- **`InMemoryNetwork<TTerms, TPayload>`**: constructs a `DiscoveryNode` per graph node, wires each node's `queryPeer` directly to the target node's `query` (resolving a `linkId` to the neighbour via the node's own link table), and applies per-link **latency**, **drop**, and **sleeping-node** settings by scheduling the delivery on the `VirtualClock`. Takes the clock, a `SeededRandom`, and the link settings. Its own tests run on the `VirtualClock`.
- A `findAddress` builder mirroring the ChipNet test harness (`uni-scenario.ts`): self match iff the node is the target; peer matches for neighbours that are the target; candidates = all the node's links; terms inverted on traversal as the ChipNet `TestLink.invertedLink()` does (a credit balance flips sign across the edge).

Anything simulator-specific (graph generators beyond a basic random one, a scheduler, metrics collection, the Taleus trading model) stays in `tallysim`, not here. Ship only the minimum the harness needs plus a basic seeded random-graph generator for the scale test.

### Scale

Nothing per query may be O(total nodes): a node touches only its own links and its own per-session contexts. Add a smoke test: a seeded **1,000-node** random graph completes a search on the `VirtualClock` in a few seconds of wall time. If any structure is accidentally global-per-node (e.g. scanning all nodes inside `findAddress`), fix it so the cost is local to a node's degree.

## Tests to write

- **Port ChipNet's 6-node happy path** (`../chipnet/test/uni-discovery.test.ts`): N1→N6 via the described graph, asserting exactly one plan, path length 3, every link carries the single `L` intent at the negotiated balance, 4 members ordered N1…N6, and the originator's nonce→linkId map resolves the first hop. Assert on the found plans (ChipNet's large test asserted nothing — we do better).
- **Seeded random graph** (hundreds of nodes): every returned plan is a **valid path** (consecutive links share a node via the harness), has **no repeated nonce**, **ends at the target**, and **respects maxDepth**. Reproducible under a fixed seed + `VirtualClock`.
- **Latency / drop / sleeping**: a slow link's answer still folds into a later round; a dropped link never produces a plan; a sleeping node is skipped by the budget and, if it wakes late, its answer is folded in, not double-counted.
- **Not-found / unreachable**: empty plans, no throw.
- **Self-is-target (circular)**: the originator finds itself as payee.
- **1,000-node scale smoke test** on the `VirtualClock`, asserting completion and plan validity, in a few seconds wall time.
- **`VirtualClock` / `SeededRandom` unit tests**: timers fire in time order; a cleared timer never fires; the same seed yields the same byte stream; `advance`/`runUntilIdle` drive a `budgetedStep` to completion.

## Edge cases & interactions

- Originator `maxDepth` reached with candidates still open → stop, return what was found (no throw).
- A round whose budget expires with everything outstanding → `round-budget-expired`, proceed to the next round folding late answers (not lost).
- Target is a direct peer (plan at depth 1) vs target unreachable (empty).
- The same plan arriving by two different paths is two valid candidates (distinct path keys at the intermediary); the same path twice is rejected at the participant (already covered there) and must not surface two identical plans at the originator.
- Harness: a `linkId` that resolves to no neighbour is a delivery error surfaced as a failed sub-query (pruned `failed`), never a crash; a drop manifests as a never-resolving (sleeping) delivery or an error, per the link setting — pick one and document it.
- No leaked timers after a full run (`VirtualClock.runUntilIdle()` leaves an empty queue); concurrent searches from different originators on the same graph don't interfere.
