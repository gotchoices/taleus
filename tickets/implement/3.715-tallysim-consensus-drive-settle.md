After discovery finds routes, the simulator today stops at `QueryOutcome.plans`. This ticket adds the
**consensus phase**: the originator picks one found plan, the sim drives the real `tallynet` sign-and-settle
protocol over that exact route on the virtual clock, reads whether it **committed** / **voided** / **stalled
(`pending`)**, and — on commit — moves each tally's balance along the route in the network model so the next
query sees the changed capacity. Metrics, failure-injection scenarios and the trace-header extension are the
**next** ticket (`tallysim-consensus-metrics-trace`); the viewer animation is `tallysim-viewer-consensus`.

## What to build

### 1. Pick a plan — `sim/plan-select.ts`
A documented originator policy over `QueryOutcome.plans` (each `Plan` has `path: Link[]`, `members`). Default
**shortest path** (fewest `path.length`), ties → **first found** (stable array order; replace `best` only on
strict `<`, so the earliest min-length wins). Expose as a small enum/function (`PlanPolicy = 'shortest'`) so
the next ticket can sweep it; ship `shortest` only. Empty plans ⇒ return `undefined` (caller skips the
consensus phase).

### 2. Reconstruct the exact route — `sim/route.ts`
The chosen plan's `path` is per-session link **nonces** (`plan.path.map(l => l.nonce)`). Invert the hash
exactly as `packages/tallysim-viewer/src/core/deanonymise.ts` does, but **throw instead of returning a
sentinel** (the sim built the network it is decoding, so an unresolvable nonce / non-contiguous walk is a
bug): for `outcome.sessionCode`, build `nonce → tally index` by recomputing `makeNonce(sessionCode,
linkIdForTally(i))` (`makeNonce` from the `tallynet` barrel; `linkIdForTally` from `sim/naming.ts`) for every
tally `i`; walk from `query.from` across each tally's `{ stock, foil }` endpoints. Return:
```ts
interface LiftRoute { tallyPath: number[]; route: number[] } // tally indices per hop; entity ids [from,…,to]
```
`next = stock === current ? foil : foil === current ? stock : throw`. Push the crossed tally to `tallyPath`,
the far endpoint to `route`.

### 3. Build + drive the lift — `sim/consensus-harness.ts`
From `tallyPath` + `route` + `q.amount`, assemble a `LiftSpec` and drive it:
- **Members:** every entity on `route` is a participant (`['P']`); the voter set (default `[route[0]]`, the
  originator) additionally gets `['R']`. A circular lift (`route[0] === route[last]`) lists the originator
  **once** in `members` but it appears on two links — `buildLift` handles that via the route pairs.
- **Exact links:** `routeLinkIds: tallyPath.map(linkIdForTally)` (the prereq ticket's harness extension) so
  parallel tallies pick the tally discovery used, not the first.
- **Codes:** pass `sessionCode: outcome.sessionCode` (reuse the discovery session); let `buildLift` mint the
  transaction code from the shared seeded random (deterministic given the same query sequence).
- **Payload:** `{ amount: String(q.amount) }` — a **string** (DAG-CBOR number/bigint caveat; matches the
  exemplar's `PAYLOAD`).
- **⚠ Sanitise link intents before signing (the critical finding).** `recordDigest` encodes
  `topology.links[*].intents`, and DAG-CBOR **throws on `Infinity`**; an `unlimited`-capacity tally carries
  `Infinity` in `capFwd`/`capBack`. After `net.buildLift(...)` and **before** `start(record)`, rewrite each
  `record.topology.links[nonce].intents` to a CBOR-safe finite copy (TallyNet never interprets terms, so any
  encodable value is fine — recommend mapping each `LiftTerms` field, replacing non-finite with
  `Number.MAX_SAFE_INTEGER`). Nonces are keyed by `sessionCode`+`linkId`, independent of intents, so
  rewriting values is safe and keeps the `nonceToLinkId` maps valid. Every node signs/verifies the same
  sanitised record, so settlement is unaffected. **The `unlimited` distribution is the default in the
  committed `found-vs-oracle` experiment — this is not an obscure edge.** Do **not** sanitise the shared
  discovery adjacency terms (would break the pinned byte-identical discovery sweep); sanitise only this lift
  record.
- **Drive:** `net.consensusNode(entityName(route[0])).start(record)` then `await net.clock.runUntilIdle()`.
- **Outcome:** read `consensusNode(entityName(route[0])).outcome(txCode)` → `'commit' | 'void' | 'pending'`.
  `pending` (a stalled lift — dropped push or an even voter tie; v1 has no timeout) is a **real third
  outcome**, surfaced not thrown. (A clean run has every node agreeing and `deliveryErrors === []`; a
  `promise`-throw refuser still leaves `deliveryErrors === []` — the engine catches it, signs `NP`.)

Return:
```ts
interface LiftResult { transactionCode: string; sessionCode: string; route: number[]; tallyPath: number[]; amount: number; outcome: 'commit' | 'void' | 'pending' }
```
Signature sketch: `runLiftForOutcome(sim, network, outcome, q, options?: { policy?: PlanPolicy; voters?: number[] }): Promise<LiftResult | undefined>` — `undefined` when no plan (phase skipped).

### 4. Move money on commit — `capacity.ts` + `model.ts` + consensus-harness
Only on `outcome === 'commit'`. Payment flows originator→target; for each hop `u → v` (route pair) resolved
to tally `t` (`tallyPath[i]`), value flows `u → v`. **Single directed helper in `capacity.ts`:**
```ts
export function applyLiftToBalance(tally: Tally, fromIsStock: boolean, amount: number): void {
  tally.balance += fromIsStock ? -amount : amount
}
```
Derivation (verified against the capacity model): `u = foil, v = stock` ⇒ `b += amount` (cap(F→S) consumed,
`b` rises toward `+stockCreditLimit`); `u = stock, v = foil` ⇒ `b -= amount` (cap(S→F) consumed, `b` falls
toward `-foilCreditLimit`). `fromIsStock = tally.stock === u` (assert `u` is `stock` or `foil`). A single
lift over the found route stays in bounds (discovery already ensured `capFwd ≥ amount` each hop) — **assert**
`-foilCreditLimit ≤ balance ≤ stockCreditLimit` after each hop (a violation is a route-reconstruction or
direction bug). `Infinity` limits make the bound check trivially pass; `b` stays finite, moving by `amount`.
- **`Infinity` carries through fine in the model** — the balance walk uses plain arithmetic, never CBOR, so
  unlimited edges just keep their `Infinity` limit and a finite balance.
- **`model.ts`: add `cloneNetwork(network): Network`** (shallow-clone `tallies` via `{ ...t }`, clone `meta`
  + `meta.params`; `Infinity` copies fine). The consensus driver mutates the `network` it is given; a caller
  that holds a `materialized`-by-reference network must clone per run (mirror the `NOTE` in `runner.ts` /
  `workload.ts` `materializeNetwork`). Within one run a **sequence** of lifts mutates the one kept network in
  order. On `void`/`pending`, balances are unchanged.

> **Non-obvious: capacity change needs a sim rebuild.** `InMemoryNetwork` freezes each link's terms from
> `network.tallies` at **construction**; mutating `network.tallies[t].balance` afterward does **not** change
> an already-built sim. For "the next query sees the changed capacity," rebuild `buildSimNetwork(network,
> …)` from the mutated model before the next query. The two-lift-sequence test must rebuild between lifts.

## Edge cases (from investigation)
- **Circular lift** (`route[0] === route[last]`): one closed loop; originator once in `members`, twice on
  links; `tallyPath` first and last tallies both touch the originator; settles once; balance walk visits each
  tally once; conservation holds around the loop.
- **No plan / `from === to` / `< 2` entities:** discovery returns no usable plan ⇒ phase skipped, no mutation.
- **Parallel tallies:** `routeLinkIds` selects the discovery-chosen tally; verify with a two-tally pair where
  only one direction has capacity.
- **Refuser** (`shouldPromise: false` or `promiseThrows`): lift voids everywhere, every promising node
  releases `success:false` once, balances unchanged, `deliveryErrors === []`.
- **Voter votes no-commit** (`shouldCommit: false` on an `R` member): voids everywhere; balances unchanged.
- **Credit-bound after a lift:** a now-zero-capacity direction is pruned by a later query — cover with a
  two-lift sequence (rebuild between).
- **Determinism:** same `(network seed, identity seed, workload seed, conditions seed)` ⇒ identical member
  keys, outcome, resulting balances. The dedicated identity-seed stream is the guard.

## Tests to plan
- **All-cooperative commits.** Seeded small graph, known route: originator picks shortest plan, lift commits
  at every member, targeted tally balances moved by `amount` in the right direction.
- **One refuser voids.** Same route, one participant `shouldPromise:false`: every outcome `void`, every
  promising node released `success:false`, balances unchanged.
- **Conservation.** Over a committed lift each **intermediary**'s net position is unchanged — the signed
  change on its in-tally equals the signed change on its out-tally (derive from `capacity.ts`); only payer +
  payee see net change.
- **Capacity changes between lifts.** Two lifts over overlapping edges (rebuild the sim from the mutated
  network between them): the second sees the first's balance change (a route available before is pruned
  after, or an amount that fit no longer fits), deterministic under one seed.
- **Determinism of the full discovery + consensus pass.** Run the same scenario twice ⇒ identical
  `LiftResult`s and byte-identical `serialize(network)` after.
- **Parallel-tally disambiguation.** `routeLinkIds` drives the lift over the exact tally discovery chose.
- **`Infinity`-capacity route commits.** A lift over an `unlimited`-credit edge signs and commits (proves the
  intents sanitisation); balance moves by `amount`, limit stays `Infinity`. (This is the test the parent
  ticket's wrong "no CBOR Infinity path" claim would have missed.)
