First of three tickets that join the two tallysim tiers: the all-seeing **oracle** (ground truth: *does a route exist*) and the real decentralised **discovery protocol** (`tallynet`), to measure whether the protocol finds the routes the oracle proves exist. This ticket builds the **wiring**: turn a tallysim `Network` into a running `tallynet` discovery network on simulated time, give each node a realistic local-only view of its tallies' capacity, impose network conditions, and run a single payment query to completion. The next two tickets add the trace file format (`tallysim-discovery-trace`) and the protocol metrics + sweep + experiments (`tallysim-discovery-metrics`).

**The discrete-event scheduler already exists** and is *not* to be rebuilt: `tallynet/testing` ships `VirtualClock` (a min-heap of timers; `now()` advances only when a timer fires; `runUntilIdle()` drains everything deterministically) and `InMemoryNetwork` (one `DiscoveryNode` per graph node, wired over that clock, with per-link `latencyMs`/`drop` conditions, a shared `SeededRandom`, and an optional shared `TraceSink`). See `packages/tallynet/src/testing/network.ts` and `clock.ts`. This ticket **consumes** that harness; everything simulator-specific lives in `tallysim`, never in `tallynet/testing`.

## What this tier joins, concretely

- tallysim `Network`: entities are integer ids `0..entityCount-1`; tallies are edges with `stock`/`foil`/`balance`/`stockCreditLimit`/`foilCreditLimit` (`src/model.ts`).
- The oracle's directed-capacity view: each tally is two directed edges, `stock→foil` carrying `cap(S→F)=b+foilCreditLimit` and `foil→stock` carrying `cap(F→S)=stockCreditLimit−b` (`src/capacity.ts`, `src/graph-view.ts`). The oracle's `routeExistence(from,to,amount,maxDepth)` BFSes over directed edges with `capacity ≥ amount`.
- `tallynet` discovery: `InMemoryNetwork<TTerms,TPayload>` built from a `NetworkGraph<TTerms>` of named nodes and undirected links. Each link carries `intents` (terms seen `node1→node2`); the reverse view is produced by an injected `invertTerms`. A search runs via `net.discover(from, target, intents, options)` then `await net.clock.runUntilIdle()`.

New code lives under `packages/tallysim/src/sim/`.

### Node ↔ entity bijection

The harness keys nodes by string name; entities are integers. Use a single documented bijection — `entityName(id) = String(id)` and its inverse — in one place (`sim/harness.ts`), so trace events (which carry `nodeId`) and metrics can map back to entity ids. Deterministic and total over `0..entityCount-1`.

### Link terms and the capacity-aware node policy (the correctness anchor)

Define the discovery term type so that the capacity a node sees on a candidate link is **exactly** the oracle's directed-edge capacity for the direction the search would traverse. This equality is what guarantees *found ⊆ oracle-reachable*; it must be computed by the **same `src/capacity.ts` helpers** the oracle's graph view uses, not re-derived.

```ts
// sim/terms.ts
export interface LiftTerms {
	/** Directed capacity available in THIS view's forward direction (on a link); on a query: the required amount. */
	capFwd: number
	/** Opposite-direction directed capacity (on a link); on a query: 0 (unused). */
	capBack: number
	/** Required payment amount (on a query); on a link: 0 (unused). */
	amount: number
}

// Build the link node1=stock, node2=foil (orientation fixed deterministically, e.g. by the tally's
// stored stock/foil). node1→node2 view: capFwd = cap(S→F), capBack = cap(F→S), amount = 0.
export const invertLiftTerms = (t: LiftTerms): LiftTerms => ({ capFwd: t.capBack, capBack: t.capFwd, amount: t.amount })
```

So when node `u` reaches neighbour `v` over a link, the view `u` holds has `capFwd === cap(u→v)` — identical to the oracle's directed edge `u→v`. Unlimited credit yields `capFwd = Infinity`; `Infinity >= amount` is true, matching the oracle (`LiftTerms` never enters a digest, so `tallynet`'s CBOR `Infinity` rejection does not apply here).

The node policy is `tallynet`'s `DiscoveryHooks` (`packages/tallynet/src/discovery/hooks.ts`), overriding only the capacity checks (single-denomination otherwise — the default hooks' behaviour):

- `negotiateIntent({ code, linkTerms, query })` → return `linkTerms` iff `linkTerms.capFwd >= query.intents[code].amount`, else `undefined`. This prunes an insufficient-capacity candidate **early**, so a node only forwards over its own tallies that can actually carry the amount — exactly a real node acting on its local view, and it keeps the message count honest.
- `planSatisfies(query, plan)` → the code is present on every path link AND every `link.capFwd >= query.intents[code].amount` AND the path is non-empty (payment: originator ≠ payee). (Capacity is re-checked here, not only in `negotiateIntent`, so a plan that slipped through is still rejected.)
- `annotateReturn` / `negotiatePlan`: identity (single-denomination; multi-denomination is ticket 5).

The required amount **must ride on the query**, not be baked into a closure: a `uniform` amount workload draws a different amount per query against one reused network, and the hooks object is fixed at harness-construction time. So the query is `net.discover(entityName(from), { address: { key: entityName(to) } }, { L: { capFwd: 0, capBack: 0, amount } })`.

### Rounds ↔ hops alignment (name and verify the off-by-one)

The oracle's `maxDepth` **counts hops** (a 1-hop path is length 1; a target reachable only at `maxDepth+1` reports `exists:false`). The originator drives `round = 0..maxDepth` where round 0 is the local entrance and each later round steps one hop deeper (`packages/tallynet/src/discovery/originator.ts`). Determine the exact relationship empirically and set the discovery `maxDepth` so the protocol's reachable hop count equals the oracle's `depth` for the same query. Verify with a test: every found plan's `path.length ≤ depth`, and at matched depth *found ⊆ oracle*. Document the mapping in `design.md`; if an off-by-one exists, reconcile it in the wiring (adjust the `maxDepth` passed to `discover`), never by loosening the oracle.

### Network conditions compiler

The scenario's conditions degrade the protocol below the oracle's ground truth — that gap is the whole experiment, so the **oracle always runs on the full, undegraded network**. Compile a scenario conditions block into the harness's static per-link `conditions` map + a sleeping-node set, **precomputed from a dedicated `SeededRandom` stream** (a new *conditions* seed, independent of network/workload/economy — see the runner's existing three-stream scheme in `src/runner.ts`). Precompute, because the harness's shared `random` mints session codes; drawing conditions from it would make session codes change whenever a condition changes and break determinism.

```ts
// sim/conditions.ts
export interface ConditionsSpec {
	/** Base per-link request latency (ms). A numeric distribution reusing the distributions.ts shapes. */
	latency?: LatencyDistribution            // 'constant' | 'uniform' | 'lognormal' over ms, >= 0 integers
	/** Fraction of links that drop every delivery (eternally). 0..1. */
	dropFraction?: number
	/** Fraction of entities that never answer (asleep). 0..1. */
	sleepingFraction?: number
	/** Fraction of entities that answer, but only after a large latency (late). 0..1. */
	lateFraction?: number
	/** The latency a late node's links carry (ms), chosen to exceed a round budget so answers fold into a later round. */
	lateLatencyMs?: number
}
```

Mapping to the harness (all per-link, because `LinkCondition` is per-link and resolved per delivery as a function of `linkId`):
- **Sleeping node (never answers):** mark a `sleepingFraction` of entities asleep; every incident link gets `drop: true`. The harness models a sleeping node as an eternally-sleeping delivery (no timer armed), so the sender's budget skips it each round and it is pruned at the depth ceiling. Document that this is an *undirected* approximation (both incident links drop), which is exactly "this node contributes nothing" — acceptable, and the only model the per-link `conditions` surface allows without a second transport.
- **Late node:** incident links get `latencyMs = lateLatencyMs` exceeding a round budget; the participant folds the late answer into a later round (trace `late-answer-folded`). (The harness module doc states this explicitly.)
- **Dropped links:** a `dropFraction` of links (not incident to an already-sleeping node) get `drop: true`.
- **Base latency:** every other link draws `latencyMs` from `latency`.
- **Precedence:** sleeping (drop) > late (large latency) > dropFraction (drop) > base latency. Document it.

## Edge cases & interactions

- **found ⊆ oracle (the anchor):** on seeded random graphs with *no* degrading conditions (no drop/sleep/latency) and matched depth, every plan the protocol returns must be a route the oracle confirms exists (`routeExistence` true, `path.length ≤ depth`, every hop's directed capacity ≥ amount). A protocol "found" that the oracle denies is a bug in the terms/capacity mapping or the rounds↔hops alignment.
- **Unreachable target:** empty `plans`, no throw (the originator never throws for "not found"). `found:false`.
- **`entityCount < 2`:** no distinct `(from,to)`; the caller (metrics ticket) handles it — `runQuery` should still not throw.
- **Infinity capacity (unlimited credit):** `capFwd = Infinity`; comparisons and `invertLiftTerms` round-trip it; never serialised here.
- **Sleeping/late approximation is undirected:** both links incident to a sleeping/late node carry the condition. Name this limitation in the doc; it is the correct "node contributes nothing / answers late" model for the per-link surface.
- **Zero-capacity direction:** a tally at a credit bound has `capFwd = 0` in one direction; `0 >= amount` is false for `amount > 0`, so that direction is pruned — consistent with the oracle's `capacity ≥ amount` filter.
- **Reused network across queries:** one `InMemoryNetwork` serves all queries in a run (no balances move in this tier); per-session state lives in per-node stores, so concurrent originators do not interfere (harness guarantee). Verify a second query on the same `SimNetwork` is unaffected by the first.
- **Shared-random determinism:** conditions are precomputed from their own stream so session-code minting (which uses the harness's shared `random`) stays stable when conditions change.

## Tests to plan

- Small hand-built graphs where the expected plan(s) and reachability are known exactly (a line, a diamond, a dead-end, a zero-capacity gate); assert plans and `found`.
- Seeded random graphs (reuse the generators): for every found plan, the oracle confirms it (exists, within depth, capacity respected); `found ⊆ oracle-reachable` at matched depth.
- Rounds↔hops: found `path.length ≤ depth`; a target reachable only beyond `depth` is not found.
- Conditions: a graph whose only route passes through a node made sleeping ⇒ `found:false` while the oracle still says the route exists (the degradation gap). A late node's answer still folds in and the route is found if the budget allows enough rounds.
- A `uniform`-amount query batch exercises per-query amounts against one reused network (hooks read the amount from the query, not a closure).
