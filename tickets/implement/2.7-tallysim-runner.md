# tallysim — experiment runner, CLI, first experiment

Third and **final** ticket of the network-model tier (after `tallysim-model-generators` and
`tallysim-oracle`). It turns the generators + oracle into a usable experiment harness and produces the
tier's first checked-in result. This ticket is the **tail of the tier**: the downstream plan ticket
`tallysim-discovery` and the backlog item `feat-tallysim-trading-model` depend on it (it owns the sweep
runner they build on, and the "step the economy" seam the trading model plugs into).

Keep the **core runner platform-neutral** (the viewer runs sweeps live in a page). The **CLI** is the one
Node-specific file — it does file I/O — and lives outside the neutral core.

## Scenario and sweep model

```ts
/** What to generate and how to query it. The network is given EITHER as (generator, params, seed) OR as
 *  a materialised Network — both are valid inputs; the runner materialises the former. (Parent plan's
 *  second design point, decided: store either; runner materialises.) */
interface ScenarioSpec {
	network:
		| { generator: string; params: Record<string, number>; seed: number }
		| { materialized: Network }
	workload: {
		kind: 'payment' | 'clearing'
		queries: number                 // how many random queries
		amount: { dist: string; params: Record<string, number> }  // query amount distribution
		depth: number                   // max depth D
		seed: number                    // workload PRNG seed (separate from the network seed)
		metrics?: string[]              // which metrics to compute (max-flow opt-in; see below)
	}
}

/** A sweep varies ONE OR TWO parameters over ranges and repeats over seeds. */
interface SweepSpec {
	base: ScenarioSpec
	vary: { path: string; values: number[] }[]   // 1 or 2 entries (e.g. network.params.k)
	seeds: number[]                               // repeat each cell over these seeds
}
```

**Runner behaviour.** For each sweep cell (one combination of varied values) and each seed: materialise
the network, draw the workload (random `(X, Y)` pairs and amounts from the workload PRNG — reuse
`tallynet`'s `SeededRandom`), run the oracle per query, aggregate the metrics. Emit **one record per
run** (the resolved parameters + seed + metrics). The core runner **yields records as plain objects**
(an array or generator) — it does not touch the filesystem, so the browser viewer can drive it too.

**Max-flow is opt-in per run** (`workload.metrics` must include it), because Edmonds–Karp is costly on
large graphs — honour the sampling guidance from `tallysim-oracle` (sample a subset of query pairs for
max-flow, never all 1,000 on a 10k graph). Document the default (max-flow off unless requested).

## Metrics (oracle level)

Aggregated per run, over its workload:
- **P(route exists)** — fraction of payment queries with a route (the headline metric).
- **path-length distribution** — histogram / mean+quantiles of `shortestLength` over successful queries.
- **max-flow distribution** — when enabled, over the sampled pairs.
- **largest-connected-component fraction** — one per network (reuse `src/structure.ts`).
- **clearing-cycle availability** — for `kind: 'clearing'`, fraction of sampled nodes with ≥ 1 usable
  cycle, and the cycle-length distribution.

Keep metric aggregation a pure module (`src/metrics.ts`): records in, summary out.

## Output serialisation + CLI

- **Serialisers (platform-neutral, `src/serialize-records.ts` or similar):** a record → one **JSON-lines**
  string; a set of records → a **CSV summary** string (one row per run, columns = varied params + seed +
  scalar metrics; distributions summarised to mean/quantile columns). Pure string functions, testable
  without a filesystem.
- **CLI (`src/cli/sweep.ts`, Node-only):** `yarn workspace tallysim sweep <spec.json>` reads a `SweepSpec`
  JSON file, runs the sweep, and **streams** the JSON-lines records to stdout / an output file as they are
  produced (never buffer a whole large sweep in memory), then writes the CSV summary. Wire it as a package
  `bin`/script so `yarn workspace tallysim sweep …` works. This file is the sole place `node:fs`/process
  args appear; exclude `src/cli/**` from the `no-node-globals` guard and the `types: []` build (give the
  CLI its own tsconfig that includes `node` types, mirroring how the core build excludes it).
- **Determinism:** a sweep run twice with the same spec produces byte-identical JSON-lines (test on a tiny
  sweep).

## "Step the economy" seam (leave the seam; do not build it)

The trading-model backlog item (`feat-tallysim-trading-model`) will evolve balances between query batches
so capacity gets used up and restored like a real economy. Leave a **hook** the runner calls between
batches and a default **no-op** implementation — do not build any trading behaviour:

```ts
/** Advances the economy (mutates balances) between query batches. Default: no-op.
 *  feat-tallysim-trading-model supplies a real implementation. */
interface EconomyStep { step(network: Network, rng: RandomSource): void }
```

Document the seam in design.md and point to `feat-tallysim-trading-model`. The runner's per-cell loop
should have an obvious place to call `economyStep.step(...)` even though the default does nothing.

## First experiment (checked in)

Add `packages/tallysim/experiments/` with the tier's first experiment and its checked-in output:

- **Question:** P(route exists) vs. **mean tallies per entity**, for `N ∈ {100, 1000, 10000}`,
  `D ∈ {4, 6, 8}`, generators `uniform` and `scale-free`, run with **unlimited capacity** and then with a
  **realistic capacity** distribution.
- **Form:** a committed sweep spec (JSON) + the generated JSON-lines/CSV output, plus a short script or
  documented command to regenerate it. Route-existence uses BFS (cheap), so this experiment is fast even
  at `N = 10000` — but stream output and keep seeds modest so a single agent run finishes well inside the
  idle-timeout window. If the full `N = 10000 × all depths × both capacity modes × many seeds` grid is too
  slow for one run, **reduce the seed count** (document the reduction) rather than dropping cells.
- **Record the finding briefly in `docs/design.md`** (not a new summary doc): where the P(route exists)
  curve turns up against mean degree, and how the realistic-capacity mode shifts it versus unlimited.
  Rough expectation to check against (from the parent plan): route existence takes off once mean degree
  passes ~1 (the giant-component threshold); with a depth limit `D` you need roughly `degree^D ≳ N`;
  capacity limits push both thresholds up. State what the data actually shows.

## Edge cases & interactions

- **A tiny sweep** (parent plan's test) produces the expected record shape and is **identical across two
  runs with the same seed** (byte-identical JSON-lines).
- **Empty / degenerate cells:** mean degree 0 (no routes → P = 0), one entity, all-isolated graph — metrics
  computed without throwing (P(exists) = 0, not NaN; divide-by-zero guarded when no successful queries).
- **Two-parameter sweeps** produce one record per `(valueA, valueB, seed)` cell; CSV columns cover both.
- **Large sweeps stream** — the CLI never holds the full record set in memory; CSV summary may require a
  second pass or an online aggregation (document which).
- **`materialized` network input** path works as well as the `(generator, params, seed)` path.
- **Max-flow enabled** on a large grid samples pairs (does not run per query) and stays within the runtime
  budget.
- **Determinism:** network seed and workload seed are independent and both honoured; no `Math.random`.

## Tests to plan

- **Runner record shape:** a tiny sweep yields records with the documented fields and resolved params.
- **Determinism:** same `SweepSpec` ⇒ byte-identical JSON-lines, run twice.
- **Metrics correctness** on hand-built networks with known answers (P(exists), largest-CC fraction,
  path-length mean), cross-checked against the oracle directly.
- **Serialisers:** JSON-lines round-trips; CSV has the expected header and one row per run; distributions
  summarised to the documented columns.
- **CLI smoke** (Node test): run `sweep` on a tiny spec file, assert the output file contents; confirm the
  CLI is the only module importing `node:*` (the `no-node-globals` guard still passes over the core).
- **Experiment regenerates** deterministically (a fast subset in CI; the full grid is the checked-in
  artifact, regenerable by the documented command).
