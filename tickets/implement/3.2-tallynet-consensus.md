It assembles the per-node bundle, extends the in-memory network harness to **push records between members**, puts the consensus engine on the public surface, and proves end to end that a found route commits or voids atomically — including the adversarial propagation cases. The record/digest/signature/store (core ticket) and the state machine (participant ticket) already exist and are unit-tested; this ticket is wiring + end-to-end proof.

## The per-node bundle (`src/consensus/engine.ts`)

Mirror discovery's `DiscoveryNode` (`src/discovery/engine.ts`). A `ConsensusNode` wraps a `TrxParticipant` and exposes the two roles a host uses:

```ts
export interface ConsensusNodeDeps<TTerms,TPayload> { /* self, signer, verifier, store, resource,
	updatePeer, nonceToLinkId, clock, hasher?, trace?, log?, sessionCodes? — passed through */ }

export class ConsensusNode<TTerms,TPayload> {
	readonly nodeId: string
	/** Originator role: seed the transaction with the built record (our own first update). */
	start(record: TrxRecord<TTerms,TPayload>): Promise<TrxRecord<TTerms,TPayload>>
	/** Participant role: what a peer's updatePeer delivers into us. */
	update(record: TrxRecord<TTerms,TPayload>, from?: Address): Promise<TrxRecord<TTerms,TPayload>>
	/** Read the settled outcome of a transaction (commit / void / unsettled) from the store. */
	outcome(transactionCode: string): Promise<'commit' | 'void' | 'pending'>
}
```

Consensus has **no originator round-loop** like discovery — it is push-driven. `start` is just `update` on the originator's own freshly-built record (all topology, no signatures yet); propagation does the rest. `outcome` derives from the stored record's classification (the participant ticket's `getRecordState`), so the simulator can read "did this node settle, and which way".

Export `src/consensus/index.ts` from `src/index.ts` (the public barrel — this is where the consensus surface lands atomically, now that a working state machine backs it). Update the `src/index.ts` module doc, which still says "The consensus engine remains a later ticket".

## Harness extension (`src/testing/network.ts`) — extend, do not duplicate

The design contract (`docs/design.md` § Simulation hooks, and the discovery milestone's § Simulation readiness) requires the consensus engine serve the simulator unchanged: all time through the injected `Clock`, typed events through the same exported `TraceSink`, deterministic under a seeded `RandomSource` + `VirtualClock`, and the harness **extended** in `tallynet/testing`, not forked. Extend `InMemoryNetwork` (which already wires `queryPeer` for discovery over the shared `VirtualClock`) to also build consensus nodes and wire `updatePeer`:

- **Addressing.** Discovery addresses nodes by name; consensus `updatePeer(record, to)` addresses by **member key**. The harness maps `Address.key → node`. **(See design note below: consensus member keys are the base64url public keys, not the node names — the two addressing spaces differ, and the harness keeps a name↔key bijection.)** A push to a member with a `physical` dial address or a direct link neighbour routes to that node; honour the same per-link `LinkCondition` (`latencyMs`, `drop`) so "a dropped push" and "a sleeping node" are the same knobs discovery uses.
- **Crypto injection.** tallynet ships no curve, so the harness takes an injected signer factory + verifier (e.g. `signerFor(nodeId) → Signer`, one `Verifier`). Tests back them with `@noble/curves` ed25519 (the devDependency the core ticket added); the simulator (`tallysim-consensus`) supplies its own from `taleus-core`'s `CryptoProvider`. **No runtime curve dependency enters tallynet.**
- **Resource doubles.** Accept a per-node `TrxParticipantResource` (a cooperative holder by default; a refuser / sleeper / dropper for failure injection), so a scenario can make one node refuse to promise or sleep mid-transaction.
- **Driving.** As with discovery, `start(...)` settles only once the `VirtualClock` is driven (`runUntilIdle`); assert `clock.pendingTimers === 0` at quiescence. Record pushes ride `clock.setTimer`, exactly like discovery deliveries.

Keep anything richer (balance-moving network model, metrics, scenario generators) out — that is `tallysim`/`tallysim-consensus` (ticket `3.7`). This harness provides only the record-push primitive + enough to assert atomic settlement.

### 1. `TrxParticipant.outcome()` — a small, DRY addition to `src/consensus/participant.ts`

`ConsensusNode.outcome` must reuse the existing classifier, not re-derive strict-majority logic (AGENTS.md: stay DRY). `getRecordState` is private and returns role-dependent intermediate states, but its **terminal** states (`consensus`, `rejected`) are role-independent (they are global properties of the record: any `NP`, or a strict commit/void majority — see `participant.ts:269-309`). So add one public method:

```ts
/**
 * The settled outcome of `transactionCode` from our stored record: 'commit' on a strict commit
 * majority, 'void' on any refusal or strict void majority, 'pending' otherwise (and when the
 * record has never been seen). Role-independent for the terminal states, so any observer — a relay,
 * the simulator polling every node — reads the same commit/void a member does.
 */
async outcome(transactionCode: string): Promise<'commit' | 'void' | 'pending'> {
	const record = await this.store.getRecord(transactionCode)
	if (!record) { return 'pending' }
	const state = await this.getRecordState(record)
	return state === 'consensus' ? 'commit' : state === 'rejected' ? 'void' : 'pending'
}
```

### 4. Harness extension (`src/testing/network.ts`) — detailed design

**CRITICAL — addressing reality.** `TrxParticipant`'s constructor throws unless `bytesToBase64url(signer.publicKey) === self.key` (`participant.ts:133-135`). ed25519 public keys are 32 bytes; node names ("N1", "A") are not valid 32-byte keys. **So consensus member keys MUST be the base64url ed25519 public keys, not the node names.** The ticket's "reuse the node names as keys" cannot hold for consensus. Keep two maps:
- `memberKeyByName: Map<string,string>` — node name → base64url pubkey (from `signerFor(name).publicKey`).
- `nameByMemberKey: Map<string,string>` — inverse, for routing `updatePeer(record, to)` → node.

Discovery is unchanged (still keys == names). The discovery↔consensus bridge (below) translates.

**Gate consensus on crypto.** Only build consensus nodes when both `signerFor` and `verifier` are given in config. Otherwise skip entirely — keeps the 300/1000-node discovery scale tests from paying ed25519 keygen and avoids any behavioural regression to the discovery suite. Add `consensusNode(name): ConsensusNode` accessor that throws a clear error if consensus was not configured.

New config fields on `InMemoryNetworkConfig`:
```ts
signerFor?: (nodeId: string) => Signer      // one ed25519 keypair per node (test supplies via @noble/curves)
verifier?: Verifier                          // shared verifier
resourceFor?: (nodeId: string) => TrxParticipantResource<TTerms,TPayload>  // default: cooperative holder
consensusLog?: (nodeId: string) => Logger    // optional; else no-op
```
`network.ts` must **not** import `@noble/curves` (it is a shipped module behind `tallynet/testing`, scanned by `no-node-globals.test.ts` and built under `types: []`). Signer factory + verifier are injected only. A trivial default cooperative resource can live in `network.ts` (just `promise(){}` / `release(){}`), since it needs no curve.

**`updatePeer` MUST be fire-and-forget — this is the crux.** The participant's `push` does `await this.updatePeer(snapshot, peer)` *then* `savePeerRecord` (`participant.ts:470-488`). If the harness `updatePeer` awaited the neighbour's full `update` (as discovery's `send` awaits `query`), then over **cyclic** reachability (a tally link is bidirectional: A↔B both push to each other) the echo re-enters a node *before* its `savePeerRecord` runs, so the per-peer suppression never fires and you get unbounded recursion / deadlock. Discovery avoids this because its search is a nonce-pruned DAG; consensus reachability has 2-cycles on every link. Therefore:

```ts
makeUpdatePeer(fromName) = (record, to) => {
	const toName = this.nameByMemberKey.get(to.key)
	if (!toName) { return Promise.reject(new Error(`no consensus node for member ${to.key}`)) } // → push logs ok:false
	const condition = this.pushCondition(fromName, toName)   // link between them, else undefined (physical dial)
	if (condition?.drop) { return Promise.resolve() }        // sender "sent" into the void; schedule NO delivery
	const fromKey = this.memberKeyByName.get(fromName)!
	this.clock.setTimer(() => {
		void this.consensusByName.get(toName)!.update(record, { key: fromKey })
			.catch((err) => { this.deliveryErrors.push(err) })  // receiver-side throw is caught here, not at the sender
	}, condition?.latencyMs ?? 0)
	return Promise.resolve()                                  // resolve immediately: the push is "handed to transport"
}
```
Expose `deliveryErrors: Error[]` so a test can assert a clean run (`[]`) or an expected receiver error. In the designed scenarios deliveries never throw (forgeries are *dropped*, not thrown; core-mismatch is not injected), so `deliveryErrors` should stay empty.

Rationale for `drop` = resolve-immediately + schedule-nothing: with fire-and-forget semantics a never-resolving promise would hang the push; `drop` here means "the neighbour never receives this copy" (sender unaware), so the record must arrive via another reachable path or the run stalls — exactly the ticket's dropped-push requirement. `savePeerRecord` still records it as last-sent (correct: we did send; it was lost), so an unchanged record is not re-pushed but a *changed* one is.

**`pushCondition(from, to)`**: look in `from`'s adjacency for an entry whose `neighbour === to`; if found, use that link's `LinkCondition` (reuse `resolveCondition(linkId)`). If none (a referee-only member reached by `physical` dial, not a direct neighbour), return `undefined` → instant, reliable delivery. The adjacency + `resolveCondition` already exist (`network.ts:127, 299-304`).

**Convergence/termination (verified by hand-trace).** With fire-and-forget, each `push` saves the peer snapshot synchronously right after scheduling. Signature sets grow monotonically by union, so each node pushes to each peer at most once per distinct growth step (finite). The echo terminates: on a linear A–B commit the deliveries are A→B (save [P(A)]), B→A (save full), A→B again ([P(A)]≠full → push, save full), B→A suppressed (full==full). `runUntilIdle`'s MAX_STEPS is the safety valve. `clock.pendingTimers` drains to 0.

**Building consensus nodes** (in `buildNode` alongside the discovery node, gated on crypto): give each a fresh `MemoryTrxStore`, its `signerFor(name)` signer, the shared `verifier`, its `resourceFor(name)` resource (default cooperative), `makeUpdatePeer(name)`, a **live** per-node `nonceToLinkId: Record<string,string>` object the harness owns (initially `{}`, populated by `buildLift`), `this.clock`, `this.hasher`, `config.trace`, the log. Keep the stores in a `consensusStoreByName` map if a test needs direct access.

### 5. Record/topology builder + discovery→consensus bridge (the required helper)

**Consensus nonces are derived locally, not from discovery.** Key each topology link by `makeNonce(record.sessionCode, linkId)` for the graph edge it mirrors (same function both ends of a tally already agree on, `nonce.ts`). This decouples the consensus record from whether discovery ran and keeps the harness self-contained.

`buildLift(spec)` on the harness, where:
```ts
interface LiftMemberSpec { name: string; roles: MemberType[]; physical?: boolean }  // roles: [P] | [R] | [P,R]
interface LiftSpec<TPayload> {
	members: LiftMemberSpec[]        // ordered; fixes the immutable member-array order
	route: string[]                  // ordered node names; each consecutive pair is a graph link (the lift chain)
	payload: TPayload
	sessionCode?: string; transactionCode?: string   // else minted
	ttlMs?: number; now?: number; random?: RandomSource  // for deterministic minting (pass net.random + a fixed now)
}
```
Builder steps:
- Mint `sessionCode`/`transactionCode` via `generate(ttlMs ?? 600_000, { now: now ?? clock.now(), random })` when not supplied. For determinism tests pass a fresh `SeededRandom(seed)` so two runs mint identical codes.
- `members`: for each spec, `{ types: roles, address: { key: memberKeyByName.get(name) }, ...(physical ? { physical: 'dial:'+name } : {}) }`.
- `links`: for each consecutive `(a,b)` in `route`, find the graph `NetworkLink` between them (scan adjacency of `a` for `neighbour===b` → its `id`), `nonce = makeNonce(sessionCode, id, hasher)`, `link = { source: key(a), target: key(b), intents: <that link's intents from a's view> }`. Populate `nonceToLinkId[name]` live-maps for both endpoints (`map[a][nonce]=id`, `map[b][nonce]=id`) so each node's resource context resolves its real `linkId`.
- Return `{ record, sessionCode, transactionCode }` with `promises: [], commits: []`.

**Discovery→settle bridge** (one test): run `net.discover(...)`, drive clock, get `plan`. In the harness, discovery member keys == node names, so `plan.members.map(m => m.address.key)` IS the route node sequence (origin-first, target-last) and `plan.path[i]` connects `members[i]→members[i+1]`. Build a `LiftSpec` from it: members = plan members as `[P]`, with one chosen member (e.g. the target, or an appended referee-only physical member) given `R`; route = that node sequence. Then `buildLift` → `start` → `runUntilIdle` → assert every node's `outcome === 'commit'`. This proves the discovered route is liftable end to end.

### 7. Topology recipes for the scenarios

- **3/5/8 linear commit:** route `[A,B,...]`, all `[P]`, last (or mid) node also `[R]` as sole referee, no `physical` (link reachability only). All promise; referee votes C; 1-of-1 majority → commit diffuses to all. **Void:** make one participant a refuser (`shouldPromise:false` → `NP`) → `void` everywhere; or the sole referee `shouldCommit:false` → `NC` → void.
- **Circular:** route `[A,B,C,A]` (ring; A rides two links), members `[A(P,R),B(P),C(P)]`. Hand-built (the discovery self-is-target case returns an empty path, so this one does not come from a plan). Releases once; `outcome` consistent at every node.
- **Refuser → void:** one participant `shouldPromise:false`; assert every node `outcome==='void'`, every `releaseSuccesses===[false]`, trace shows the `NP` (`promise-signed` `signatureType:'NP'`) and `resources-released` `success:false` at each.
- **Dropped push:** diamond `A-B-D`, `A-C-D`, drop link `A-B`; D the referee. Record reaches D via C; commits everywhere; no double-release. (Optionally a second case: sole-path drop → stall, all `pending`, none committed.)
- **Sleeping node:** linear chain, one inbound link `latencyMs: 1e9`. `clock.advance(partial)` → that node still `pending` → `runUntilIdle` → all `commit`; `pendingTimers===0`. Proves settlement waits for the sleeper, determinism holds.
- **Referee sets (separate `[R]`-only members, all members `physical` for complete reachability):** set of 1 → commits; set of 2 both C → commits; set of 2 split (one `shouldCommit:false`) → **stall** (`pending`, no release); set of 3 with 2 C and the third on a huge-latency link → commits on the 2 votes (`clock.advance(partial)` to show it settles before the third).
- **Out-of-order / duplicate (network level):** a slow link so a commit overtakes a promise at some node (retained, counted once the promise lands); re-deliver a settled record (`net.consensusNode(x).update(settledRecord)`) → no second release (peer-copy / release-once).
- **Adversarial (1–2 proofs only):** (a) deliver a record carrying a **corrupted** referee commit (flip a byte of `value`) during the promise phase → dropped as `forged`, route still commits. (b) **Equivocation**: after the route commits, deliver a record with the referee's opposite face → dropped (`equivocation`/`changed`), outcome unchanged, single release. The unit-level signature rows (replay, type-substitution, expiry, core-mismatch) are already proven in `participant.test.ts` and need no network re-proof.
- **Determinism:** capture the full `TraceEvent[]` of a commit run, repeat with a fresh network built from the same seed (same seeded keys + seeded code minting), assert the two arrays are deeply equal.

### 8. Tripwire to record (NOT a ticket)

While tracing the merge: a **forged commit carrying a referee's `address` but a garbage `value`, arriving BEFORE `promisePhaseComplete`**, is retained unverified (`participant.ts:245-252`) and occupies that referee's commit slot; the genuine vote then arrives and is refused as `equivocation`/`changed` (`:232-238`), so it is never counted → the lift **stalls** (liveness denial). This is **safety-preserving** (no wrong settlement — the forged value never verifies, so `countVerifiedCommits` never counts it, `:324-343`) which is all this ticket must prove, but it is a real liveness edge. Park it as a `NOTE:` comment at `participant.ts` mergeSignature (the commit-retain branch) and add one line to the review's `## Review findings`. Keep the network forgery tests to the clean safety cases above so they do not trip this edge. **Do not file a ticket** unless implementation shows it is reachable as a *flip* (it is not: the value cannot verify).

## Edge cases & interactions (end-to-end, on the network)

- **3-, 5- and 8-member routes, each to commit and to void.** Commit: all participants promise, the referee votes C, every node settles `commit` and releases `success`. Void: a participant signs NP (or the referee votes NC), every node settles `void` and releases `!success`. Assert **atomicity**: no node ends in a mixed state (some committed, some voided).
- **Circular lift** (originator on two links): animates/settles as one closed loop, releases once, `outcome` consistent at every node.
- **A participant refuses to promise** → the whole route voids; every held resource is released; the trace shows the NP and the releases.
- **A dropped push** (`drop` link): the record reaches the node by another reachable path or the run stalls without a false settlement (no node commits while another never saw the commit). No node double-releases.
- **A sleeping node** (large `latencyMs` spanning the run): its promise/vote folds in when it wakes; settlement waits for it; determinism holds.
- **Out-of-order / duplicate delivery across the real harness** (not just unit-level): a commit that overtakes a promise is retained and counted once the promise arrives; a re-delivered record is a no-op (peer-copy skip).
- **Referee set > 1** on the network: a set of 3 commits on 2 C votes even if the third referee is slow; a set of 2 that splits (1 C, 1 NC) does **not** settle in-band (stalls — the timeout that would void it is out of scope).
