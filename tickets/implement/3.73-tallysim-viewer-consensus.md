The replay tier today animates **discovery** — the frontier spreading, prunes fading, found-plan markers. This
ticket adds the **consensus phase**: once a loaded trace records a lift (the v2 header's `lifts[]` from
`tallysim-consensus-metrics-trace`), the chosen route animates through its settlement — promises arriving per
edge, the voter's vote, then **commit** (the route turns solid) or **void** (the route flashes and clears,
releasing every held edge).

Scope is **recorded-trace replay** — it is now precise even from a file, because the v2 header carries the
chosen route (`tallyPath`) and the member-key↔entity map the event stream lacks. Animating a **live** consensus
run (the worker driving consensus) is deliberately out of scope and filed as a backlog `feat-` (see below).

## Why this is now precise (read first)

Consensus `TraceEvent`s (`record-pushed`, `record-received`, `promise-signed`, `referee-vote`, `settled`,
`resources-released`, `signature-rejected`) carry the member **key** as `nodeId`/`to`/`from`, **not** an entity
id, and **no link nonce**. On their own they cannot be placed on the graph. The v2 trace header closes both
gaps per lift:

- `memberKeys: Record<string,number>` maps each member key → entity id, so every consensus event places on a
  node; and
- `tallyPath: number[]` + `route: number[]` give the exact edge sequence of the lift (resolving the found-plan
  path gap the discovery replay documented), so per-edge promise/settle animation is **precise, not inferred** —
  honouring the tier's "edge lighting is precise" rule.

A `record-pushed` with `from`/`to` member keys maps to the ordered pair of entities, which maps to the one
`tallyPath` edge between them — that edge is the one the push promises.

## What to build

### Core: read the lifts (`core/trace-index.ts`, `core/timeline.ts`)

- `trace-index.ts`: surface `header.lifts` (keyed by `transactionCode`, and by `sessionCode` to join a lift to
  its discovery session). Build a per-lift `memberKey → entityId` resolver and a `(fromEntity, toEntity) →
  tallyIndex` resolver from `tallyPath` + `route`. A v1/no-`lifts` trace yields no consensus phase — the
  existing discovery replay is unchanged.
- `timeline.ts`: extend the pure reducer so the active set, recomputed from every event with `time ≤ t`, also
  tracks per-lift consensus state: each route edge's phase (`promised` / `committed` / `released`) and each
  member node's phase (`promised` / `voted` / `settled`), plus the lift's settled decision. Recompute-from-
  scratch keeps backward scrubbing correct — no incremental cursor. A `void` `settled` marks the whole lift
  released; a `commit` marks it solid. Emit only plain data (entity ids, tally indices, phase enums, decision) —
  colour stays in the graph tier.

### Paint: the consensus overlay (`replay/paint.ts`, `app/theme.ts`, `graph/render.ts`)

Extend `paint.ts`'s `ReplayOverlay` to colour the consensus phase, composed **after** the discovery overlay and
before sigma's hover/selection accent (the existing three-layer order):

- **Promise arriving on an edge** → the edge lights in a distinct "promised" colour (separate from the discovery
  round scale).
- **Voter vote** → the voting node marks (commit-pending vs no-commit visible).
- **Commit** → every route edge switches to a solid "committed" style (full-strength, the route reads as a
  closed settled path); the route stays lit.
- **Void** → the route flashes the "void" colour then **clears** (edges return to resting style, holds
  released). "Flash then clear" is a time-bounded style the reducer expresses as the `released` phase after a
  `void` `settled`; `controls.ts` drives the brief flash window off the transport clock (document the fixed
  flash duration in virtual-time).

Add the consensus colours to the one shared palette in `theme.ts` (light + dark, colour-blind-safe, distinct
from the capacity edges and the discovery round scale): `promised`, `committed`, `voidFlash`. `render.ts` needs
no new channel — reuse `setReplayOverlay`.

### Controls: the phase display (`replay/controls.ts`, `replay/routes.ts`)

- The found-routes side list, which for a loaded trace currently shows **markers only** (the path gap), now
  shows the **chosen lift's full route** (from `tallyPath`) with its settlement outcome badge
  (committed / voided / stalled), and selecting it isolates the route (`dim` everything else) as the discovery
  isolate already does. `routes.ts` reconstructs the node path from `tallyPath` directly (no inference).
- The transport plays discovery then consensus as one continuous timeline (events are already in global time
  order). No new clock — the existing rAF transport + seek path drive it; scrubbing into the consensus window
  shows the partial settlement at that instant.

## Edge cases & interactions

- **v1 / discovery-only v2 trace** (no `lifts`): no consensus phase, no new UI; the discovery replay is
  byte-for-byte as before. Guard this explicitly.
- **Void after some promises:** the edges that were promised flash and clear; the side list shows `voided` with
  the reason if the trace carries it; no edge stays solid.
- **Circular lift** (`route[0] === route[last]`): animates as a **closed loop**; the shared originator node
  carries both its promise and its vote marks; it settles once (one `settled` per node). The `(from,to) →
  tally` resolver must handle the originator appearing on two route edges.
- **Stalled (pending) lift:** no `settled` event — the route shows promises arriving and then **stays**
  partially-promised (nothing turns solid, nothing clears); the badge reads `stalled`. Do not fabricate a
  settle.
- **Backward scrub across a commit/void boundary:** recompute-from-scratch yields the correct partial state at
  any `t` (a scrub back before `settled` un-solidifies the route).
- **A node both relays discovery and participates in consensus:** the discovery overlay (round colour) and the
  consensus overlay compose; consensus (later in time) wins at times past settlement, discovery colour shows
  before the lift starts — document the compose order.
- **Member key not in `memberKeys`** (malformed trace): surface as the tier's explicit sentinel/bug, never a
  silent drop — a well-formed self-recorded trace always resolves.
- **Multiple lifts in one trace** (several queries each settling): each `transactionCode` animates
  independently on its own route; selecting one in the side list isolates that route.

## Tests to plan

- **Headless `timeline.ts`:** hand-built consensus events + a `lifts` entry → the reducer's per-edge/per-node
  phases and settled decision at a sequence of `currentTime`s; backward seek recomputes correctly; a `void`
  clears, a `commit` solidifies.
- **Headless `paint.ts`:** a committed lift overlay has every route edge in `committed` style; a voided one has
  the route in `voidFlash` during the window then resting after; a stalled one leaves promised edges promised.
- **Headless `routes.ts`:** `tallyPath` → the exact node path (no inference), including a circular route.
- **Headless `trace-index.ts`:** `memberKeys` / `tallyPath` resolvers; a v1/no-`lifts` trace yields no lifts.
- **Build gate + manual check** (the browser-only `controls.ts`/`render.ts` are build-plus-manual, per the
  tier's testing policy): `yarn build`, then load a consensus trace → play → watch promises light the route →
  commit turns it solid (or void flashes + clears); scrub back across settlement; select a lift to isolate it.
  A consensus trace fixture to drive this comes from `tallysim`'s `cli/trace.ts --consensus` (or the committed
  experiment) — name it in the manual steps.

## Backlog spin-off (do not build here)

File `tickets/backlog/feat-viewer-live-consensus.md` (`feat-`): animate a **live** consensus run — the live-run
worker (`src/live/`) drives discovery **and** consensus in-browser, streams consensus events + the lift header,
and animates settlement without a recorded file. It reuses this ticket's overlay/reducer; the new work is the
worker running `tallysim`'s consensus harness and streaming a v2 header. Rationale: recorded-trace replay fully
satisfies "the viewer animates the route settling"; the live path is a sizeable worker change best taken on its
own. Reference `tallysim-consensus-core`/`-metrics-trace` as the engine it would drive.
