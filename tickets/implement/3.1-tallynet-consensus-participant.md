### Implementation decisions the tests must match (read before writing tests)

1. **Merge check order is membership → role → already-have-one-from-this-signer → crypto-verify → store**
   (NOT verify-first, despite the ticket prose). Rationale is in the `mergeSignature` doc comment. The
   test consequences:
   - **Type-substitution → `forged`** only when the relabelled signature arrives with **no prior genuine
     signature from that member** (fresh arrival → verify runs → fails → `forged`). Construct the
     type-substitution test that way.
   - **Genuine equivocation → `equivocation`**: a referee that *really* signs both `C` and `NC` (two valid
     signatures, different preimages). The second is refused as `equivocation` without re-verifying. The
     first stands.
   - **`changed`**: a second signature, same `address` + same phase `type`, **different `value`** — refused
     as `changed`, first kept. (No verifier call on the second, so a hand-built different value works.)
   - **`non-member` / `wrong-role`** are caught before verify.
2. **First-sight validation rejects (throws) an expired/malformed record** via the new-record `RuleSet`.
   **Expiry-at-promise/commit-time** (sign `NP`/`NC`) is therefore tested on a **second delivery**: seed a
   valid record (first sight), advance the injected clock past expiry, then `update` again — not first
   sight, so the RuleSet does not re-run, and `advanceState` signs `NP`/`NC`.
3. **Commits are verified lazily** — `mergeSignature` only crypto-verifies a `C`/`NC` once the promise
   phase is complete; otherwise it is retained unverified. `getRecordState`/`countVerifiedCommits`
   re-verifies and counts. This is how out-of-order commit delivery works (retained, not rejected, counted
   once the last promise lands).
4. **`release` throw is logged AND re-thrown** (`releaseOnce`) — the flag is set only after `release`
   resolves. So the "release throws, retried next update, never double-released" test should expect the
   first `update` to reject, then a second `update` (with a now-cooperative release, or a
   throw-once-then-succeed double) to release exactly once. Count only *successful* release calls.
5. **`self.key` must equal `base64url(signer.publicKey)`** — the constructor throws otherwise. Build test
   signers so their member key matches (see `signature.test.ts` `makeSigner` for the ed25519 pattern).
6. **`nodeId` on trace events is `self.key`** (no separate `nodeId` config field).
7. **Push snapshots per peer** and the skip test compares signature sets by `type|address|value`
   (attachment excluded). A re-push with an unchanged signature set is suppressed.
8. The new-record `RuleSet` also enforces: ≥1 participant member, ≥1 referee member, no duplicate member
   key, every link endpoint is a member key, our member/links consistent (participant ⇒ on a link; on a
   link ⇒ member; referee-only members exempt from needing a link), and the core is canonically encodable.

## Edge cases & interactions (write a test for each)

- **Forged signature**, **signature from a non-member**, **a promise from a referee-only member**, **a commit from a non-referee** — each dropped with the matching `signature-rejected` reason; the record is otherwise unharmed.
- **Signature-type substitution** (P→NP, C→NC relabel), arriving fresh — fails verification (`forged`). (See decision #1.)
- **Replay** of a valid signature from another transaction with the same topology — fails (`forged`, tx/sc differ).
- **A member changes its signature between deliveries** — `changed`, first kept.
- **Payload or topology differs from the prior copy** — `core-mismatch`, whole update refused (throws).
- **Expired transaction code or session code at promise time → sign NP; at commit time → sign NC** (never approve). (See decision #2 for how to construct.)
- **Out-of-order delivery**: a commit arriving before all promises is retained by union, not counted, not rejected; once the last promise arrives the commit verifies and consensus is reached.
- **Duplicate delivery**: identical signatures dedupe; no state change, re-push suppressed by the peer-copy skip.
- **Delivery after settlement**: a record arriving once `isReleased` is set re-verifies but does not re-release.
- **Node restart between promise and release**: a fresh participant over the same store sees the stored record, reclassifies, and releases once (flag persisted).
- **`release` throws**: logged, flag left unset, retried next `update`, never double-released. (See decision #4.)
- **Single referee signs both commit and void (equivocation)**: the second face is refused on merge (`equivocation`); the first stands; logged. For a set of 1, whichever face arrived first is the outcome.
- **Circular topology** (originator source of one link, target of another): our-links returns both; promise/release act over both; a duplicate *member entry* (not a duplicate link) is the only invalid case.
- **Referee sets of 1, 2 (tie), 3**: size 1 settles on its one vote; size 2 needs both to agree (1+1 or 1+0 = no consensus yet); size 3 settles on 2. Assert never-both.
- **Empty referee set**: invalid record, rejected at validation.
- **Pure relay** (self not a member): merges and pushes, never promises/votes/releases.
