Second of three `tallynet-consensus` tickets (chain: `tallynet-consensus-core` → **this** → `tallynet-consensus`). It builds the state machine: the per-node logic that ingests a record, merges it, decides whether to promise / vote / release, and pushes it onward. It depends on the core ticket's record, digest, sign/verify, store, and trace events. It does **not** build the network harness or the end-to-end scenarios — that is the final ticket. Everything here is unit-testable against the in-memory store, injected signer/verifier, and resource doubles.

Read `chipnet-review.md` § Transaction and § Transaction module defects (**every row there must be closed by the end of this chain — most of them close here**), and `docs/design.md` § Protocol design (Consensus). Mirror the discovery participant's shape (`src/discovery/participant.ts`): a class built from injected ports, a `RuleSet` for explainable validation, all time through the injected `Clock`, all events through the wrapped `TraceSink`.

## The resource port (`src/consensus/resource.ts`)

Where the host holds and releases value and casts a referee vote. Ported from ChipNet's `TrxParticipantResource` with the **ordering bug fixed** (ChipNet held resources in `promise` *before* `shouldPromise` decided — review `:75-77`).

```ts
/** Our member plus our in/out links (with real link ids resolved from the discovery nonce map). */
export interface ResourceContext<TTerms, TPayload> {
	member: DependentMember
	inLinks: OurLink<TTerms>[]    // links whose target is us (incoming)
	outLinks: OurLink<TTerms>[]   // links whose source is us (outgoing)
	record: TrxRecord<TTerms, TPayload>
}
export interface OurLink<TTerms> { nonce: string; linkId?: string; source: string; target: string; intents: Record<string, TTerms> }

export interface TrxParticipantResource<TTerms, TPayload> {
	/** Policy gate — runs FIRST, before any hold. false → we sign NP, nothing is held. Default: true. */
	shouldPromise?(ctx: ResourceContext<TTerms,TPayload>): boolean | Promise<boolean>
	/** Hold our edges' value. Throw to refuse (→ we sign NP, log the reason). Only ever called after shouldPromise:true. */
	promise(ctx: ResourceContext<TTerms,TPayload>): void | Promise<void>
	/** Release held value exactly once per transaction. `success` = committed vs voided. Idempotent across restarts. */
	release(ctx: ResourceContext<TTerms,TPayload> & { success: boolean }): void | Promise<void>
	/** Referee vote gate (R members only). false → sign NC. Default: true. */
	shouldCommit?(ctx: ResourceContext<TTerms,TPayload>): boolean | Promise<boolean>
	/** Referee only: opaque per-edge settlement signatures to attach to our C/NC signature. Default: none. */
	resolveAttachment?(decision: 'C'|'NC', ctx: ResourceContext<TTerms,TPayload>): unknown | Promise<unknown>
}
```

`resolveAttachment` is how the Taleus referee rides its per-edge signatures on the vote (the core ticket's attachment seam). TallyNet never inspects what it returns.

## The participant (`src/consensus/participant.ts`)

export class TrxParticipant<TTerms,TPayload> {
	/** Ingest a record (from ourselves to start, or pushed by `fromAddress`). Merge, advance, push. */

### `update` flow

1. **Validate + merge** (`validateAndMerge`):
   - **No prior copy** (first sight): run the new-record `RuleSet` (below). Store it.
   - **Prior copy exists**: the **immutable core** (`transactionCode`, `sessionCode`, `payload`, `topology`, including member array order) must be deep-equal to the stored copy — else reject the whole update `core-mismatch` (trace + throw; the push model tolerates a throw, the caller logs). Then **union the signatures** with per-signer phase rules (below).
   - Emit `record-received` with the merged counts.
2. If `self` is **not** a member of `topology.members`, we are a pure relay: skip to push.
3. If `self` **is** a member, loop `advanceState(record)` until it stops changing the record.
4. **Push** to reachable peers (below). Emit `record-pushed` per peer.
5. Return the merged/advanced record.

### Signature union + per-signer phase rules (closes several defect rows)

When merging an incoming signature into our set, for each signature:
- **Verify it** (`verifySignature`). Fail → `signature-rejected` `forged`, drop the signature (do not store it); the rest of the merge continues. A commit/no-commit that cannot *yet* verify because the full promise set is absent is **not** `forged` — see § The two phases.
- **Membership**: `signature.address` must be a member key → else `non-member`, drop.
- **Role**: `P`/`NP` only from a member whose `types` include `P`; `C`/`NC` only from a member whose `types` include `R` → else `wrong-role`, drop. (Closes "a promise from a referee-only member", "a commit from a non-referee".)
- **Changed / equivocation**: a signer contributes at most one promise-phase signature and at most one commit-phase signature. A second signature of the same phase that differs in `value` → `changed`; one that differs in `type` (P vs NP, or C vs NC) → `equivocation`. Either drops the new signature, keeps the first, and logs once. (Closes "a member changes its signature between deliveries" and defines the single-referee-signs-both-commit-and-void outcome: the second face is refused on merge, atomicity preserved, logged.)
- Identical (same type + value) → dedupe silently (idempotent re-delivery).

### The two phases — `getRecordState` (closes the majority / tie / empty-set rows)

Classify the record for **our** member role:

- **Promise phase.** Let `P-members` = members whose `types` include `P`.
  - Any **NP** signature present → the lift cannot form → **void** outcome (`rejected`).
  - Every `P-member` has a verified **P** signature → promise phase complete, open the commit phase.
  - Else, if we are a `P-member` without our own P/NP yet → **ourPromiseNeeded**.
  - Else → **promising** (waiting on other participants).
- **Commit phase** (only once every participant promised — so the full promise set is present and commit signatures verify deterministically). Let `R-members` = members whose `types` include `R`.
  - **Empty `R-members` → invalid record** (reject at validation, see rules). This closes ChipNet's `isConsensus(0,0)=true` bug (review `:285-287`): there is no "majority of zero".
  - `commitCount` = verified C signatures from distinct referees; `noCommitCount` = verified NC.
  - **Commit consensus** iff `commitCount > R/2` (strict majority).
  - **Void consensus** iff `noCommitCount > R/2` (strict majority).
  - These are mutually exclusive (both cannot be strict majorities) — **never both**, fixing ChipNet's even-split-satisfies-both-and-reject-wins bug.
  - Else if we are an `R-member` without our own C/NC yet → **ourCommitNeeded**.
  - Else → **propagating** (waiting on other referees).

**Tie handling (decision — reconcile the docs).** A tie (e.g. set of 2 with 1 C + 1 NC, or set of 2 with only 1 vote) is **neither** a commit nor a void consensus under the strict-majority rule — classify it **no-consensus-yet** (`propagating`). It does **not** settle either way and never satisfies both. The main plan ticket's "tie → no consensus yet; never both" and `docs/design.md`'s "ties have a defined outcome (void)" are reconciled thus: vote-counting here yields no commit majority; the *eventual* resolution of a stuck tie to void is a **timeout**, which is out of scope (`feat-tallynet-propagation-timeouts`) and reached through the extension point below. **Update `docs/design.md` § Protocol design (Consensus)** to state this precisely (strict majority for both; a tie stalls until timeout-void; v1 has no timeout so a tie simply does not settle in-band).

### Acting on the state

- **ourPromiseNeeded**: if `transactionCode` **or** `sessionCode` is expired at `clock.now()` → sign **NP** (refuse; never approve — closes the precedence bug review `:151-153,169-171`). Else `await shouldPromise(ctx)` (default true); false → sign **NP**. True → `await resource.promise(ctx)` (the hold) — if it throws, sign **NP** and log the reason (a declined promise must **not** have held anything, because `promise` only runs on `shouldPromise:true`, and a throw means nothing was held). Success → sign **P**. Emit `promise-signed`.
- **ourCommitNeeded**: if either code is expired → sign **NC**. Else `await shouldCommit(ctx)` (default true); true → sign **C**, false → sign **NC**. Attach `await resolveAttachment?(decision, ctx)` to the signature. Emit `referee-vote`.
- **consensus (commit) / rejected (void)**: `release` **exactly once**. Gate on `store.isReleased(tx)`; if not released, `await resource.release({…, success})`, then `store.setReleased(tx)` — **set the flag only after `release` resolves**, so a throwing `release` leaves the flag unset and is retried on the next `update` (never double-released). Log a `release` throw; do not swallow it. Emit `settled` then `resources-released`.

Signing appends our signature to `promises` (P/NP) or `commits` (C/NC) and re-saves the record. Each produced signature is self-verified before storing (cheap guard that our own preimage matches what a peer will check).

### Membership resolution (closes the circular-lift row)

- **Our member** = the single `topology.members` entry whose `address.key === self.key`. A member key appearing **twice** in `members` → invalid record (duplicate member entry; reject at validation). (Review `:105` threw when our address appeared more than once — that was wrong for a circular lift; the fix is: one *member entry* per address, but that address may appear on *many links*.)
- **Our links** = every `topology.links` entry whose `source` or `target` equals `self.key`, split into `outLinks` (source = us) and `inLinks` (target = us). A circular lift puts the originator on two links; both appear. Resolve each link's real `linkId` from `nonceToLinkId` where present (ours will be; others won't and stay `undefined`).

### Reachability + push (closes the double-log row)

Push the current record to **reachable** members (as ChipNet `reachablePeers`): members with a dialable `physical` address, **plus** our direct link neighbours (the member at the other end of each of our links). **Skip** a peer whose last-acked copy (`store.getPeerRecord`) equals the record we would push (compare the merged signature sets — the core is immutable). On a successful `updatePeer`, `savePeerRecord`. On a failure, **log once** (ChipNet called `logUpdateError` twice — review `:133-134`) and emit `record-pushed` with `ok:false`; do not retry in-band (retry is the push-wake transport's concern).

### New-record validation `RuleSet` (closes the `participant.ts:210-212` TODO row)

Explainable rules (reuse `rule.ts`), run on first sight of a record:
- **Codes**: `transactionCode` and `sessionCode` both well-formed and not expired at `clock.now()` (reuse `session-code.ts` for both — the transaction code is the same self-expiring format).
- **Topology well-formed**: no duplicate member key; every `links` entry's `source`/`target` is a member key; the referee set (`R-members`) is **non-empty**; at least our own member/links are consistent (our member exists iff we hold any of its links).
- **Our terms**: hand our in/out links' terms to the host via `shouldPromise`'s `ResourceContext` — TallyNet does not itself know "what we agreed in discovery"; the host (Taleus) checks the record's edge terms against its own policy/quote there. The `nonceToLinkId` map is what lets us *identify* our links; the terms check is the host's.

## Out of scope — leave the extension point (`feat-tallynet-propagation-timeouts`)

Pre-promise void, void-on-timeout, stalled-transaction recovery, and ring/star convergence are **not** built here. Leave a clearly-commented seam:
- `expiresAt(record.transactionCode)` is the record's deadline (the self-expiring code already carries it) — the "expires at" hook the timeout feature needs, no new field required.
- Mark the `propagating`/tie branch of `advanceState` with a `NOTE:` naming where a timeout-triggered referee NC (void-on-timeout) would be injected, and that stalled-transaction recovery hangs off the same point. This is the hook; do not implement the timer.

## Edge cases & interactions (write a test for each)

- **Forged signature**, **signature from a non-member**, **a promise from a referee-only member**, **a commit from a non-referee** — each dropped with the matching `signature-rejected` reason; the record is otherwise unharmed.
- **Signature-type substitution** (P→NP, C→NC relabel) — fails verification (`forged`).
- **Replay** of a valid signature from another transaction with the same topology — fails (`forged`, tx/sc differ).
- **A member changes its signature between deliveries** — `changed`, first kept.
- **Payload or topology differs from the prior copy** — `core-mismatch`, whole update refused.
- **Expired transaction code or session code at promise time → sign NP; at commit time → sign NC** (never approve).
- **Out-of-order delivery**: a commit arriving before all promises is retained by union, not counted, not rejected; once the last promise arrives the commit verifies and consensus is reached.
- **Duplicate delivery**: identical signatures dedupe; no state change, re-push suppressed by the peer-copy skip.
- **Delivery after settlement**: a record arriving once `isReleased` is set re-verifies but does not re-release.
- **Node restart between promise and release**: a fresh participant over the same store sees the stored record, reclassifies, and releases once (flag persisted).
- **`release` throws**: logged, flag left unset, retried next `update`, never double-released.
- **Single referee signs both commit and void (equivocation)**: the second face is refused on merge (`equivocation`); the first stands; logged. For a set of 1, whichever face arrived first is the outcome.
- **Circular topology** (originator source of one link, target of another): our-links returns both; promise/release act over both; a duplicate *member entry* (not a duplicate link) is the only invalid case.
- **Referee sets of 1, 2 (tie), 3**: size 1 settles on its one vote; size 2 needs both to agree (1+1 or 1+0 = no consensus yet); size 3 settles on 2. Assert never-both.
- **Empty referee set**: invalid record, rejected at validation.
