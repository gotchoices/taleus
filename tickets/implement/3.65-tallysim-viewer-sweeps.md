Fifth and last viewer ticket. The scaffold-core ticket built `sweep-data.ts` (the headless JSONL/CSV parser →
tidy series). This ticket adds the **charts view** that renders those series. It is independent of the graph
and the replay animation — it only needs the app shell (from graph-view) and `sweep-data` (from
scaffold-core), so it can land any time after graph-view.

## Architecture

### Sweep source + view (`src/sweeps/`)

- A third source tab (alongside file-load and live-run): load a sweep's output — the `tallysim` CLI's
  **JSON-lines** (`--jsonl`, one `SimRunRecord`/`RunRecord` per line) or **CSV** (`--csv`) summary
  (`cli/sweep.ts` / `cli/simulate.ts`; committed examples under `packages/tallysim/experiments/`). Parse via
  the headless `sweep-data` module.
- **Axis/series pickers**: choose the **x** axis (a varied parameter path, e.g.
  `network.params.meanDegree`) and one or more **metrics** (e.g. `pFoundGivenExists`, `routeExistsCount`,
  `pRouteExists` for oracle sweeps), with one **line per series** — a series being each distinct combination of
  the *other* varied dimensions plus `generator` / `capacity` (e.g. `P(found)` and `P(exists)` vs. mean
  tallies per entity, one line per generator). Default sensible picks from the loaded file's columns.
- **Charts: `uPlot`** (the settled chart lib) — fast canvas line charts, colour-blind-safe series colours and
  light/dark theme from the shared palette module. Legend, axis labels (the metric + param names), hover
  readout of a point's `(x, y)` and its series key.

## Edge cases & interactions

- **Both record kinds**: oracle sweeps (`RunRecord`: `pRouteExists`, `pathLength`, structural metrics,
  optional `maxFlow`) and discovery sweeps (`SimRunRecord`: `pFoundGivenExists`, cost distributions, prune
  reasons). The view must read the columns present in the loaded file and offer only those metrics — do not
  assume one shape.
- **Non-finite values**: an unbounded max-flow serialises as `null` / empty CSV cell (the model's
  `Infinity ↔ null` rule). `sweep-data` already reads these as non-finite/absent; the chart must **skip** such
  points (gap in the line), not plot them as `0`.
- **Distribution-summary columns**: a metric like `pathLength` / `messages` is a `DistributionSummary`
  expanded to `count/mean/min/max/p50/p90/p99` columns — let the user pick which sub-field (default `mean`),
  and treat `count: 0` ("no data") as a gap, never `0`.
- **Multiple seeds per cell**: the sweep repeats each cell over several `seeds`. Decide and document: either
  plot each seed as its own faint point and a mean line, or aggregate to a mean per cell. Pick mean-per-cell
  with the raw points shown lightly, unless that clutters — document the choice.
- **Single-value / empty sweep**: a one-cell file (nothing to sweep) shows a single point / a clear "nothing
  to plot" rather than an empty axis; a malformed file shows a parse error in-UI.
- **CSV vs JSONL agreement**: the same sweep loaded from either format must yield the same series (the
  `sweep-data` tests already pin this; the view must not diverge).
