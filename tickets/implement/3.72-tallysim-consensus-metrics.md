Build the **pure** consensus-metrics module: recorded lift in, metrics out — no network, clock, or
filesystem, testable from hand-built `LiftResult`s + consensus `TraceEvent`s, exactly like
`sim/protocol-metrics.ts` is for discovery. Mirror that file closely (it is the template for every

## Inputs you can rely on (already discovered)

- `LiftResult` (from `sim/consensus-harness.ts`): `{ transactionCode, sessionCode, route: number[],
  tallyPath: number[], amount, outcome: 'commit' | 'void' | 'pending' }`.
- The consensus `TraceEvent` variants (tallynet `src/trace.ts`) — **every consensus event carries
  `transactionCode`; discovery events do not**, so filtering events by `event.transactionCode ===
  result.transactionCode` cleanly isolates one lift's consensus events and drops all discovery noise.
  The relevant variants and their fields:
  - `record-pushed { transactionCode, to, promiseCount, commitCount, ok }` — **the consensus message**
    (count these for `messagesPerLift`).
  - `record-received { transactionCode, from?, promiseCount, commitCount }`
  - `promise-signed { transactionCode, signatureType: 'P' | 'NP' }` — an `NP` is a refusal.
  - `signature-rejected { transactionCode, reason: SignatureRejectReason }` — `reason === 'expired'` is
    the expiry signal.
  - `referee-vote { transactionCode, decision: 'C' | 'NC' }` — an `NC` is a no-commit vote.
  - `settled { transactionCode, decision: 'commit' | 'void' }`
  - `resources-released { transactionCode, success }`
  - every event also has `TraceBase { time, nodeId, sessionCode }`.
- `summarizeDistribution(values): DistributionSummary` and `StructuralMetrics { meanDegree,
  largestComponentFraction }` from `metrics.ts`.

## Interfaces

```ts
/** The non-commit reasons, one tally per reason. The literal in zeroVoidReasons() is the SOURCE OF TRUTH
 *  (missing key ⇒ compile error), exactly as protocol-metrics.ts's zeroPruneReasons does for PruneReason. */
export type VoidReason = 'refused-promise' | 'voted-no-commit' | 'stalled' | 'expired'
export function zeroVoidReasons(): Record<VoidReason, number> {
  return { 'refused-promise': 0, 'voted-no-commit': 0, stalled: 0, expired: 0 }
}
export const ALL_VOID_REASONS: readonly VoidReason[] = Object.keys(zeroVoidReasons()) as VoidReason[]

export interface ConsensusLiftMetrics {
  outcome: 'commit' | 'void' | 'pending'
  /** ms from the first record-pushed/promise-signed to the last consensus event; undefined for pending. */
  timeToSettleMs?: number
  /** count of record-pushed events for this lift (the push is the consensus message). */
  messages: number
  /** the void reason for a non-commit lift (void OR pending); undefined for a commit. */
  voidReason?: VoidReason
}

export interface ConsensusRunMetrics {
  queryCount: number           // carried through from the runner (queries attempted; found ⇒ a lift)
  meanDegree: number           // structural (one per network) — for the CSV x-axis
  largestComponentFraction: number
  liftCount: number            // routes found AND taken = lifts attempted = commit+void+pending
  commitCount: number
  voidCount: number
  pendingCount: number
  pCommitGivenFound: number    // commitCount / liftCount; 0 (never NaN) when liftCount === 0
  timeToSettleMs: DistributionSummary    // over SETTLED lifts (commit|void); pending contributes no sample
  messagesPerLift: DistributionSummary   // over ALL lifts
  voidReasons: Record<VoidReason, number> // zero-initialised via zeroVoidReasons()
}
```

## Functions

- `analyzeLift(events: readonly TraceEvent[], result: LiftResult): ConsensusLiftMetrics`
  - Filter `events` by `event.transactionCode === result.transactionCode` (discovery events lack the
    field and drop out).
  - `messages` = count of `record-pushed`.
  - `timeToSettleMs` (commit|void only; **omit for pending**) = `max(time over all this lift's consensus
    events)` − `min(time over record-pushed | promise-signed events)`.
  - `voidReason` via this **outcome-driven precedence** (document it in the module header):
    - `commit` → `undefined`.
    - `pending` → `'stalled'` (always — pending means no decision was reached: a dropped push on a needed
      edge, or an even voter-set tie; v1 has no timeout). Do **not** infer a different reason from stray
      `NP`/`NC` events that never reached a decision.
    - `void` → first match of: a `signature-rejected` with `reason==='expired'` ⇒ `'expired'`; else any
      `promise-signed` `NP` ⇒ `'refused-promise'`; else any `referee-vote` `NC` ⇒ `'voted-no-commit'`;
      else defensively `'voted-no-commit'` (a void always has one of these causes — note it's unreachable).
    - This satisfies the precedence note "a refuser **and** a dropped edge counts once as `refused-promise`
      (refusal is observed before any stall)": when the refusal reaches a decision the outcome is `void`
      and `NP` wins; when the drop prevents any decision the outcome is `pending` ⇒ `stalled`.
- `summarizeConsensusMetrics(lifts: readonly ConsensusLiftMetrics[], structural: StructuralMetrics,
  queryCount: number): ConsensusRunMetrics` — aggregate. `lifts.length === liftCount`. Sum `voidReasons`
  per lift's `voidReason` (a commit adds nothing). `timeToSettleMs` distribution over the lifts whose
  `timeToSettleMs` is defined; `messagesPerLift` over all lifts.

## Edge cases

- Zero lifts: `pCommitGivenFound = 0`, `voidReasons` all-zero (not an error), both distributions `count: 0`.
- A pending lift: counts in `liftCount` (denominator), no `timeToSettleMs` sample, `voidReason: 'stalled'`.

## Tests (hand-built events, no network)

- `zeroVoidReasons`/`ALL_VOID_REASONS` cover exactly the four reasons, all zeroed.
- A commit stream (record-pushed + promise-signed P + settled commit) → `pCommitGivenFound = 1`, one
  `timeToSettleMs` sample equal to last−first, `messages` = the record-pushed count.
- An `NP`-then-void stream → `voidReasons['refused-promise'] = 1`, `voidCount = 1`.
- A stalled stream (pushes but no `settled`, outcome pending) → `pendingCount = 1`,
  `voidReasons.stalled = 1`, **no** `timeToSettleMs` sample.
- An `expired` stream (`signature-rejected` reason=expired on a void) → `voidReasons.expired = 1`, and
  proves `expired` beats a co-present `NP`.
- A refuser-AND-drop void (both an `NP` and the outcome void) → counts once as `refused-promise`.
- Zero lifts → all-zero tally, `pCommitGivenFound = 0`, distributions `count: 0`.
