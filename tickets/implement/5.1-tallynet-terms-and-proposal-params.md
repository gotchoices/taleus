The foundation for the voter model (design.md § Lift proposal and settlement). Two changes, both wide but mechanical-plus-a-little: (1) rename the "referee" concept to "voter"; (2) carry the **consensus method** and an optional **lift-contract CID** as explicit proposal parameters, and make settlement read the threshold from the record instead of hard-coding a strict majority. No behavioural change at the defaults — a default-threshold lift settles exactly as today.

## Terms rename

Today every voter is called a "referee" and the member-type code is `R` (`discovery/types.ts` `MemberType`, `MemberTypes.referee`). Rename to match the settled terms (design.md § Lift proposal and settlement): a **voter** is any member proposed to vote; a **referee** is a voter that is not a participant (we no longer need a distinct code for it — a referee is simply a `V` member that is not also `P`).

- `MemberType` `'R'` → `'V'`; `MemberTypes.referee` → `MemberTypes.voter` (`'V'`). `'P'` / `MemberTypes.participant` unchanged. This changes the member-type **wire code**, which changes the record digest bytes — fine, all nodes use the same code and there is no backwards compat (AGENTS.md). Signature faces `C`/`NC` (commit/void) are vote outcomes, not roles — **leave them**.
- Rename identifiers throughout `consensus/participant.ts`: the `referees` locals → `voters`, `membersWithRole(MemberTypes.referee)` call sites, `countVerifiedCommits`'s `referees` param, `MAX_PENDING_COMMITS_PER_REFEREE` → `MAX_PENDING_COMMITS_PER_VOTER`, the `empty referee set` log/rule messages, the "wrong-role" comment. The `SignatureRejectReason` string values stay as-is except any that say "referee" in their comment.
- Sweep comments and doc prose in `src/` and `docs/design.md` (`chipnet-review.md` is a historical record — leave its ChipNet-vs-TallyNet table wording, which quotes ChipNet's own "referee").
- Sweep the consumers so the whole monorepo still builds: `tallysim` (`sim/consensus-resource.ts`, `sim/consensus-harness.ts`, `sim/naming.ts`, `plan-select.ts`, metrics, tests) and `tallysim-viewer` (any `R`/referee references in the consensus animation). Keep behaviour identical — this ticket is a rename, not a policy change. The *new* voter policies land in `tallysim-voter-model`.

## Proposal parameters

Add, as part of the **immutable, promise-signed record core** (so every signature binds them and a peer cannot alter them), a consensus method and an optional lift-contract CID. Mirror them onto the discovery `UniQuery` so a node can refuse a method or contract it dislikes during the search, before it ever promises.

```ts
// consensus/types.ts and discovery/types.ts (shared shape; define once, import)
export interface ConsensusMethod {
	/** v1 implements only 'distinct-voter' (one vote per distinct voter; total weight = voter count).
	 *  Reserved, validation-rejected until built: 'nominator-split' and future weightings. */
	weighting: 'distinct-voter'
	/** Rational fraction of total vote weight the winning side must STRICTLY EXCEED. Default 1/2. */
	thresholdNum: number
	thresholdDen: number
}

// TrxRecord gains (core — part of the digest preimage):
//   method: ConsensusMethod
//   liftContract?: string   // Stroc CID; omit when absent (never set undefined — see types.ts discipline)
// UniQuery gains the same two fields, so a discovery-time hook/policy can see them.
```

**Settlement reads the threshold.** In `getRecordState` (`consensus/participant.ts:414`), replace the two `> referees.length / 2` tests with a comparison against the record's method:

- total weight `W` = voter count (the only `weighting` in v1);
- commit settles when `commitWeight * thresholdDen > thresholdNum * W`;
- void settles when `voidWeight * thresholdDen > thresholdNum * W`;
- with the default `1/2` these reduce to `commitCount * 2 > W` i.e. `> W/2` — **byte-identical outcome to today**. Use integer arithmetic (no floats) so the comparison is exact and deterministic.

**Validation.** Add new-record rules (and the same checks when minting/accepting a query):

- `ConsensusMethod` present, `weighting === 'distinct-voter'` (reject reserved weightings with a clear message), `thresholdNum`/`thresholdDen` positive integers;
- the protocol invariant **`thresholdNum/thresholdDen ≥ 1/2`** (so commit and void can never both be reached) — `2 * thresholdNum >= thresholdDen`;
- `thresholdNum/thresholdDen ≤ 1` — `thresholdNum <= thresholdDen`;
- `method` (and `liftContract`, when present) must canonically encode (already covered by `coreEncodable`, but add explicit rules so the failure message points at the field).

Keep the existing `NonEmptyVoterSet` (renamed) rule: an empty voter set is still invalid (no "majority of zero").

The `digest.ts` preimage already covers the whole core; adding fields to `TrxRecord` automatically binds them — confirm `coreEqual`/`recordDigest` pick them up and add a digest vector test for a record that differs only in `method` or `liftContract`.

## Edge cases & interactions

- Default method (`1/2`) reproduces every existing consensus test — they must pass unchanged after the rename (expect only `R`→`V` substitutions in fixtures).
- Threshold `2/3` on a 3-voter set: 2 commits is `2*3 = 6 > 2*3 = 6`? No → not settled; 3 commits settles. A 2/1 split neither commits nor voids (the no-settle band) → stays `propagating` (v1 has no timer; `tallynet-propagation-timeouts` resolves it). Add a test asserting the band does not settle.
- Reject at validation: `thresholdNum/thresholdDen < 1/2` (e.g. `1/3`), a non-integer or zero denominator, a reserved `weighting`.
- A voter set of 1 with default threshold: 1 commit is `1*2 = 2 > 1`? → settles commit (a lone voter is a valid, if trust-foolish, proposal — the protocol permits it; policy refuses it, `tallynet-lift-policy-hooks`).
- A query carrying a `method`/`liftContract` the originator did not set: minting must stamp the record's core from the query's values so the two agree; a mismatch at a downstream node reads as `core-mismatch`.
- The `attachment` field and the per-edge seam are untouched here (retired later by `feat-tallynet-bind-taleus-core`).
- Interplay with the side pool and equivocation is unchanged — this ticket does not alter merge logic, only the win condition and the names.
