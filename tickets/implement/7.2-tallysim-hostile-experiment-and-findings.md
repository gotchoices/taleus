## Why

The mechanisms now exist (refusers, non-relayers, stacked-voter padding, multi-voter sets, no-commit voters, the `consensusMethod` override, and the inconsistent-settlement / equivocator metrics). This ticket turns them into a **checked-in experiment** that answers the parent plan's two headline measurement questions and records the answers:

1. *How much does each hostile type hurt lift success, and does the majority-voting defence hold?*
2. *Which consensus method should be the default?* — run the same attacks under strict-majority `1/2` and a raised `2/3` (and a weight-split method if one ships), and recommend.

Model it on the existing checked-in experiments (`packages/tallysim/experiments/commit-vs-found/` and `found-vs-oracle/`): committed `specs/*.json`, a `regenerate.sh` that rebuilds `out/*.{jsonl,csv}` and the combined file **byte-identically** and runs agent-runnably (well under ~10 min — keep `N` small, ~50 queries, seeds `[1,2]`, one fixed mid-degree topology such as `scale-free, edgesPerNode=3`, unlimited capacity so a non-commit is always an attack effect, never a depleted tally). Drive it with the existing `yarn workspace tallysim consensus <spec>` CLI.

## The sweeps (one file each, one or two dimensions)

- **No-commit voters × method.** Multi-voter set (`k = 3` or `5`, off-route well-known hubs), sweep `voteNoFraction ∈ {0 … }` under `consensusMethod = 1/2` and `2/3`. Expected: under `1/2`, a *minority* of NC voters cannot break the lift (success holds) and the break point is at the majority; raising to `2/3` moves the break point **earlier** (a split clears neither threshold → more `pending`). `inconsistentSettlementCount` is **0 everywhere** (the correctness floor).
- **Stacked voters × method.** Sweep `stackedVoters` (obscure-referee padding count) under each method; the payer's discovery-time refusal (`planRefusalCount`) should rise with padding and be method-independent (refusal is a discovery-scorer decision, not a vote-threshold one) — confirm and report.
- **Refusers × method** (reuse the existing refuser dial) as the baseline "how much does a promise-refuser cost" curve, to sit beside `commit-vs-found`'s refuser result and show method-independence of a clean void.

## Edge cases & interactions

- **Agent-runnable wall-clock.** The consensus sweep is the costliest (keygen + sign/settle per query). Keep the grid small and **stream** output with `tee`; if a spec risks >~10 min, shrink `N`/seeds rather than letting the idle timer kill the run.
- **Byte-identical regeneration.** Pin seeds and spec order; the combined file must reproduce exactly, like the sibling experiments — this is asserted by re-running `regenerate.sh` and diffing.
- **Method comparison must share the attack draw.** `consensusMethod` is drawn on no RNG (it is a static spec field), so the `1/2` and `2/3` runs of a cell see the **same** injected hostile set and the **same** network/queries — the comparison is apples-to-apples. Verify the two method specs differ *only* in `consensusMethod`.
- **`inconsistentSettlementCount === 0` across the whole experiment** — assert it in the write-up as the headline safety result; a non-zero cell is a regression to chase, not a finding to report.
- **Do not add new mechanism here.** If a sweep needs a knob that does not exist, that is a gap in the prereq ticket — note it and route back, don't grow this experiment ticket into a mechanism change.
