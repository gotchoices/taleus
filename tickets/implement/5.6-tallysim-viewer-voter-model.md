Make the voter-model runs from `tallysim-voter-model` legible in the viewer, building on the existing consensus animation (STATUS: "consensus animation (in progress)"). The headless core stays unit-tested; rendering stays Vite + graphology/sigma + uPlot.

## What to show

- **The route and the voter set.** Highlight the chosen plan's path, and mark the voters distinctly — participants that self-vote vs. referee-only (`V`-only) voters, and which member nominated each. A voter set stacked with obscure voters should *look* stacked.
- **The record's flow.** Animate the record spreading: promises in phase 1, votes in phase 2, settlement, and release — reusing the trace events the engines already emit (`record-pushed`, `promise-signed`, `referee-vote`, `settled`, `resources-released`). Add the new events from `tallynet-record-availability`: a **pull** (fetch-from-voter) and an **equivocation / contradiction** marker, so the viewer shows a silent node being routed around by a pull.
- **Contact points.** Indicate which members published a contact point, so the difference between "settles" and "stalls" on a linear lift with a refuser is visible on screen.

## Edge cases & interactions

- A linear lift with an interior non-relayer: with contact points, show the pull that recovers the far members; without, show them stuck pending (greyed, not errored).
- A circular lift routing around a refuser via the ring (no pull needed).
- An equivocating voter: show both faces it emitted and which one settled.
- A tie (no settlement): the viewer must render "unsettled", not spin.
- Keep rendering out of the headless core; the new trace events must round-trip through the existing trace serializer (`tallysim`'s `serialize-consensus-records`) — coordinate the event shape with `tallynet-record-availability` so no viewer-only fields are needed.
- Headless/WebGL smoke coverage stays per `debt-tallysim-viewer-headless-webgl-smoke` — don't regress it.
