## The mechanism, confirmed from the tallynet source (ALL READ AND VERIFIED)

Everything needed already exists in `packages/tallynet/src/testing/network.ts` (the `InMemoryNetwork`) and `packages/tallynet/src/consensus/participant.ts`. The simulator's job is to *pass config fields through* — no protocol change. Confirmed facts (file:line references are current):

- **`hooks?: DiscoveryHooks | ((nodeId)=>DiscoveryHooks)`** — per-node factory IS supported (`network.ts:106-107`, resolved by `resolveHooks` at `network.ts:789-797`). `DiscoveryHooks.negotiatePlan(plan)=>plan|undefined` drops a plan whose voter-set-so-far a node rejects (`hooks.ts:70-82`). The sim passes `hooks: makeCapacityHooks()` today (`harness.ts:137`); extend to a factory that composes capacity hooks + `negotiatePlan` for nodes that vet the set.
- **`scorePlan?: ScorePlan`** (`network.ts:114`) — originator-only, **shared** (not per-node — a `ScorePlan` is itself a function so a factory can't be disambiguated; see the network.ts comment). Pass `voterAwareScorePlan(wellKnown)` from `plan-select.ts`.
- **`resourceFor?: (nodeId)=>TrxParticipantResource`** (`network.ts:144`) — already wired (entity-id→node-name adapt at `harness.ts:162`). The `acceptsProposal` specs from `consensus-resource.ts` flow through unchanged.
- **`refuseRelay?: (nodeId)=>boolean`** (`network.ts:148-153`) — the **non-relayer**: promises normally (promise-phase pushes always deliver) but **drops every commit-phase record it would send/forward, and serves no pulls**. Confirmed in `makeUpdatePeer` (`network.ts:604-607`: `commitPhase = record.commits.length>0`; suppressed when `refuseRelay(from) || silentAfterPromise(from) || silentAfterPromise(to)`) and `makeFetchRecord` (`network.ts:644-656`: returns `undefined` when the **target** refuses/silent, or the direct edge drops).
- **`silentAfterPromise?: (nodeId)=>boolean`** (`network.ts:154-159`) — offline after promising (no commit-phase either way, serves no pulls).
- **`nomineesFor?: (nodeId)=>RefereeNomination[]`** (`network.ts:160-167`, folded by `makeFindAddress` at `network.ts:734-755`) — per-node referee nomination, folds voter-only `[V]` members into plans, `physical` by default. Keyed by node **name**.
- **`LiftMemberSpec.physical?: boolean`** (`network.ts:179-184`) — `buildLift` stamps `physical: 'dial:<name>'` (`network.ts:449-453`) → a **contact point** reachable by any record-holder.

### The pull — load-bearing detail (CONFIRMED)

- **`reachablePeers(record)`** (`participant.ts:886-906`) = **every `physical` member (except self) ∪ the far end of each of our links**. **VERIFY requirement in the original ticket is SATISFIED:** a `physical` member IS addressed with no shared tally link (it's added purely from `member.physical`), and a non-`physical` member's reachable set is link-neighbours only. The principle-3 test hinges on exactly this — no adjustment needed.
- **`ConsensusNode.fetchOutcome(tx)`** (`engine.ts:130-131` → `participant.ts:241-253`): reads own stored record, pulls from every reachable peer, merges each reply, returns the resulting outcome. A member cut off by an interior non-relayer still HAS the record (promised in phase 1) — missing only the *commit* evidence — so `fetchOutcome` recovers it by pulling the committed signatures from a physical voter/originator. The pull resolves on a **microtask** (so `await fetchOutcome` returns the recovered outcome), but the pushes settlement then schedules need a following `runUntilIdle`.
- **Pulls are NOT auto-triggered** (timer loop deferred to `tallynet-propagation-timeouts`). So the simulator must call `fetchOutcome` itself on each still-pending cooperating member after `runUntilIdle`, then `runUntilIdle` again.
- **Directly analogous tallynet tests to mirror** (read these — they prove the exact behaviour at the tallynet level; this ticket reproduces them at the tallysim harness level with `line()`/ring `Network`s): `tallynet/src/testing/consensus.test.ts:1074-1210` — "linear chain with contact points: interior refuser cuts the far member off, a pull settles it" (1075), "same chain without contact points: stays pending even after a pull" (1116), "circular lift routes around one refuser with no contact points" (1143), "originator goes silent after promising" (1170), "payee goes silent" (1200). And `tallynet/src/testing/discovery.test.ts:476-590` — "default scorePlan ranks the lean voter set ahead of a stacked one" (507), "negotiatePlan returning undefined drops just the rejected plan" (550).

In `buildSimNetwork`, replace `hooks: makeCapacityHooks()` with `hooks: consensusHooks(consensus)` and add scorePlan + the three new ports into `consensusPorts`:
```ts
function consensusHooks(consensus): DiscoveryHooks | ((nodeId)=>DiscoveryHooks) {
  const base = makeCapacityHooks()
  const negotiatePlanFor = consensus?.negotiatePlanFor
  if (!negotiatePlanFor) return base            // DISCOVERY-ONLY PATH BYTE-IDENTICAL: same shared object as today
  return (name) => { const np = negotiatePlanFor(entityId(name)); return np ? { ...base, negotiatePlan: np } : base }
}
```
Extend `consensusPorts(consensus)` (still returns `{}` when `!consensus`) to also spread, each only when defined:
`...(scorePlan ? { scorePlan } : {})`, `...(nomineesFor ? { nomineesFor: (name)=>nomineesFor(entityId(name)) } : {})`, `...(refuseRelayFor ? { refuseRelay: (name)=>refuseRelayFor(entityId(name)) } : {})`, `...(silentAfterPromiseFor ? { silentAfterPromise: (name)=>silentAfterPromiseFor(entityId(name)) } : {})`. The pinned discovery sweep must not move — do NOT turn hooks into a factory unconditionally.

### Step 2 — `sim/consensus-harness.ts`: contact points + pull-recovery pass
- `RunLiftOptions` grows: `contactPoints?: boolean`, `nonCooperating?: number[]` (entity ids that are non-relayers/silent — excluded from the pull pass; MUST match the network's `refuseRelayFor`/`silentAfterPromiseFor`), `wellKnown?: Set<number>` (passed to `selectPlan` for the `voter-aware` policy).
- `liftMembers(route, voters, contactPoints)` stamps `physical: true` on **`route[0]` ∪ every voter** when `contactPoints` (mirrors `mintFromPlan`, which already stamps the originator). When false/omitted, no member physical (today's behaviour).
- `LiftResult` grows: `pullCalls: number`, `recovered: number`.
- After the initial `start` + `runUntilIdle`, run the pull pass, THEN read the originator outcome and settle:
```ts
const members = [...new Set(route)]                 // distinct route participants
const canPull = members.filter((e) => !(options?.nonCooperating ?? []).includes(e))
const pending = async () => { const out:number[]=[]; for (const e of canPull) if (await net.consensusNode(entityName(e)).outcome(transactionCode)==='pending') out.push(e); return out }
const pendingBefore = await pending()
let pullCalls = 0
for (let round = 0; round <= members.length; round++) {
  const stuck = await pending(); if (stuck.length === 0) break
  for (const e of stuck) {
    const node = net.consensusNode(entityName(e))
    if (await node.outcome(transactionCode) !== 'pending') continue   // recovered mid-round via a push
    pullCalls++; await node.fetchOutcome(transactionCode); await net.clock.runUntilIdle()
  }
  if ((await pending()).length === stuck.length) break                // no advance this round → stop (finite, deterministic)
}
const recovered = pendingBefore.length - (await pending()).length
const settled = await net.consensusNode(entityName(route[0])).outcome(transactionCode)   // originator, AFTER the pull pass
if (settled === 'commit') settleRoute(...)
return { ..., outcome: settled, pullCalls, recovered }
```
This is finite (each round reduces pending or breaks), deterministic, and **leaves every existing `consensus-harness.test.ts` test passing** (verified by tracing: all-commit → 0 pending → no-op; all-void → 0 pending; split-voter tie → pending stays, `recovered:0`, `pullCalls>0`, outcome still `pending`, balances unchanged, `pendingTimers:0`). The determinism test's `toEqual` still holds (new fields are deterministic).

### Step 3 — `sim/route.ts`: circular-route constructor
`oracle.ts` cycle code (`selfPayment`/`clearingCycles`) returns only **counts/lengths, not the node path**, so a dedicated path-returning finder is needed. Add a deterministic DFS over the undirected tally multigraph (neighbours iterated in tally-index order; `visitedEntities` keeps it simple & bounded by `entityCount`):
```ts
// findCycleThrough(network, origin): number[] | undefined  → ordered tally indices forming the shortest simple cycle through origin (first-found on a length tie). Handles parallel-tally 2-cycles. NOTE: DFS, for small hand-built rings — tripwire comment: exponential on dense graphs; this is the clearing-discovery stand-in, not for large sweeps.
export function buildCircularOutcome(network, sessionCode, origin): QueryOutcome | undefined {
  const cycle = findCycleThrough(network, origin); if (!cycle) return undefined
  const path = cycle.map((i) => ({ nonce: makeNonce(sessionCode, linkIdForTally(i)), intents: {} }))
  return { sessionCode, plans: [{ path, members: [] }], found: true }
}
```
`QueryOutcome` is a type-only import from `./harness.js` (no cycle: harness.ts does not import route.ts). Verified against the existing hand-built circular test (`consensus-harness.test.ts:258-286`): ring `0-1-2-0` → `findCycleThrough(net,0)` must yield `[0,1,2]`.
**Design note (document in the final ticket's doc update):** real *clearing discovery* is deferred to `feat-tallysim-clearing-discovery`; constructing the ring directly from the known graph is the chosen stand-in so the circular *consensus* path (and "ring routes around a non-relayer") is exercisable now.

## Tests — `sim/voter-harness.test.ts` (new file; keep existing `consensus-harness.test.ts` unchanged except maybe extend the determinism test for the new fields)

Build on hand-made line/ring `Network`s (reuse the `line(n, limit)` helper shape from `consensus-harness.test.ts`). Key design decisions baked in:
- **Principle-3 curve (headline):** `line(5)`, non-relayer at interior node 2 (`refuseRelayFor: (id)=>id===2`, and `nonCooperating:[2]` in RunLiftOptions). **Voter = originator (the default `voters:[route[0]]`)** so the commit evidence originates at node 0 and node 0 (being the voter) always commits + money always moves. With `contactPoints:true` the terminus-side members (3,4) recover via pull from the physical originator/voter → **every cooperating member commits** (`recovered===2`, `pullCalls>0`). With `contactPoints:false` nodes 3,4 **stay `pending`** (assert this gap as EXPECTED: `recovered===0`) while 0,1,2 commit and `result.outcome==='commit'`. Trace of commit propagation confirmed: initial pass → `[commit,commit,commit,pending,pending]`.
- **Nomination + score:** a network with an off-route well-known hub; `nomineesFor` = `makeNomineesFor(network, wellKnown, 'well-known')` adapted; assert the discovered plan's `members` include the hub as `[V]`; `selectPlan(..., 'voter-aware', wellKnown)` / `scorePlan: voterAwareScorePlan(wellKnown)` picks the lean/well-known plan. (Heed the `well-known.ts` NOTE: the nominated voter MUST be OFF the route, else NoDuplicateMembers rejects or the vote is dropped.)
- **Stacked refusal:** a plan padded with obscure `V`-only voters is refused — at discovery (`negotiatePlanFor` via `refuseStackedPlanHook`) AND/OR promise time (`resourceFor` with `refuseStackedVoters` → `acceptsProposal`→`NP`→void); assert the lift does not commit and the attributable reason is the voter set (`handles.get(x)!.voterSetRefusals>0`).
- **Circular routes around:** ring `0-1-2-0` + one non-relayer, `contactPoints:false`; use `buildCircularOutcome`; the lift still settles for cooperating members (ring routes around — see tallynet test :1143). (Voter = originator; the ring delivers the originator's own commit to both neighbours directly.)
- **Edge cases:** non-relayer that is also a voter; non-relayer next to the payee; payee `silentAfterPromise` after mint (originator holds the plan ⇒ still settles — mirror tallynet :1200); voter set of 2 that splits ⇒ `pending` (unsettled, does NOT hang — `runUntilIdle` terminates, pull pass terminates).
- **Determinism:** same `(network, seeds)` ⇒ identical `LiftResult`s (incl. `pullCalls`/`recovered`) and byte-identical serialized networks.
- `net.deliveryErrors===[]` and `net.clock.pendingTimers===0` on clean runs.
