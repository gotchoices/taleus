## Context (background — Phase 1 code already embodies all of this)
A lift whose promise phase never completes (a needed participant dies before promising) stayed permanently `pending`, every promiser holding credit forever. After this ticket, if a **voter** is reachable it votes `NC` at its deadline on the incomplete set and a void majority settles, releasing everyone. Only the **dead-voter** case (a voter majority that never hears the record) remains stuck `pending`. Design decisions (implemented): (1) a void's preimage binds the immutable core only → `NC` verifies on arrival, no side pool, a forged `NC` drops `forged`; (2) a void majority settles (`rejected`) from the voter set regardless of promise-set completeness; a commit majority still needs the complete set; (3) the record reaches reachable voters through existing push/pull/recovery; (4) each voter acts at its own deadline (recovery timer at `expiry + skewGraceMs`; classification gate uses raw `anyCodeExpired`).
