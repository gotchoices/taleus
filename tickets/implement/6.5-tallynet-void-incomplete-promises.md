## Context (background — the Phase 1 code already embodies all of this)

**What's wrong:** a lift whose promise phase never completes (a needed participant dies before promising) stayed permanently `pending`, every promiser holding credit forever. After this ticket, if a **voter** is reachable it votes `NC` at its deadline on the incomplete set and a void majority settles, releasing everyone. Only the **dead-voter** case (a voter majority that never hears the record) remains stuck `pending`.

**Design decisions (all implemented):** (1) a void's preimage binds the immutable core only, always — so `NC` verifies on arrival, needs no side pool, and a forged `NC` drops `forged`. (2) a void majority settles (`rejected`) from the voter set regardless of promise-set completeness; a commit majority still needs the complete set; same `settles(count)` formula both sides. (3) the record reaches reachable voters through existing push/pull/recovery — no new transport. (4) each voter acts at its own deadline; recovery timer armed at `expiry + skewGraceMs`; classification gate uses raw `anyCodeExpired`.
