## MAJOR FINDING — found-route paths are not in a trace file (design constraint, must honour)

A recorded NDJSON **trace does not carry found-plan paths**: the `tallynet` `plan-found` event is **path-less**
and `plan-returned` carries only a single per-node inbound `nonce` (see `packages/tallynet/src/trace.ts` and
`discovery/participant.ts` / `originator.ts`). So the winning route's ordered link-nonce path **cannot be
recovered from the event stream** without *inferring* it (walking the union of `plan-returned` tallies), which
the design explicitly forbids — edge lighting is "precise, not inferred", and inference misorders branching /
multiple plans.

Consequence for this ticket: `routes.ts` reconstruction works whenever the **link-nonce path is supplied** —
the live-run source (a later ticket that drives the sim and holds `QueryOutcome.plans[i].path`) or a test. For
a **loaded trace file**, you CAN still show the `plan-found` **markers** (finder node + time + count — already
derived by the `timeline` reducer as `ActiveSet.foundPlans`) and the `sessionFoundState`, but you **cannot draw
the exact winning path**. Do not fake it. Surface the found markers + an explicit honest note
("exact route path is not recorded in trace format v1 — showing finder & time"); wire full path
highlighting/isolation through `routes.ts` so it lights up for the live-run source and tests.

**Clean fix (file as a follow-up `feat-`/`debt-` backlog ticket, do not build here):** have the originator's
`plan-found` event carry its own plan's path nonces. The originator owns the search result, so this discloses
nothing new (unlike relay events). It touches `tallynet` `TraceEvent` (additive field on `plan-found`), the
originator emission, and bumps `TRACE_FORMAT_VERSION` in tallysim — a cross-package change deliberately out of
this ticket's viewer scope.

## Remaining architecture (browser-only unless noted)

### `src/app/theme.ts` — replay palette additions
Extend `Palette` (the single shared palette module) with a **round/depth sequential, colour-blind-safe scale**
(`roundScale: readonly string[]`, ~5–6 steps — a node/edge is coloured by its round), plus `pruned` (the fade
colour, distinct from "never reached"), `sleeping`, `late` (dimmed/dashed distinct styles), and a `dimmed`
role for isolate-on-select. `found` already exists. Add to both light and dark palettes.

### `src/graph/render.ts` — replay overlay hook
`render.ts` keeps all sigma mechanics; the paint layer owns colour. Add to `GraphView`:
`setReplayOverlay(overlay: ReplayOverlay | undefined): void`, where `ReplayOverlay` is plain data
`{ nodes: Map<nodeKey, {color?,size?}>, edges: Map<edgeKey, {color?,size?,zIndex?,hidden?}>, dim?: {node,edge} }`.
The node/edge reducers apply overlay styling for keyed items, the `dim` style for the rest (when an isolate is
active), and let the existing built-in hover/selection (`isHovered`/`isHighlighted`) **compose on top** (lit
hover wins) — the design's `customNodeState`/`customEdgeState` seam. `edgeKeyForTally(i)` maps a tally index to
the sigma edge key; `entityName(id)` maps a node id to the node key.

### `src/replay/paint.ts` — active set → overlay (browser-only)
Translate a `timeline` `ActiveSet` + the compiled `{sleeping, late}` sets + an optional isolated route into a
`ReplayOverlay` (pure-ish; it only builds the plain overlay object — keep it free of sigma imports so it *could*
be tested later):
- **Nodes** light by round via `palette.roundScale` (a node becomes active on its first reaching event ≤ t).
- **Edges** light precisely via the deanonymiser (the reducer already resolved tally indices in `ActiveEdge`),
  coloured by the edge's round. A `late-answer-folded` edge lights at its later round (the reducer already
  models this — assert it end-to-end in the manual/dev check).
- **Pruned** edges fade (`palette.pruned`); prune reason on hover (extend the edge tooltip with
  `PrunedCandidate.reason`). Fade must read distinct from "never reached".
- **Sleeping/late** nodes styled distinct (dimmed/dashed); a sleeping **target** must not imply the query
  failed (a neighbour resolves the peer-match) — only a sleeping non-target relay blocks. Rendering only marks
  nodes distinct; do not add failure semantics.
- **Isolate**: when a found route is selected, set `overlay.dim` and key only that route's nodes/edges
  (`routeEdgeTallies`).

### `src/replay/controls.ts` — transport + panel (browser-only)
The rAF loop driving `clock.advanceClock` → `timeline.seek` → `paint` each frame (scrub and play share the one
seek path; backward scrub is already correct in the reducer). Build the panel UI:
- play / pause / speed (0.25×–8×) / scrub bar over `TraceIndex.timeBounds`, using `clock.progressFraction` /
  `timeAtFraction`.
- **session picker** (a trace may hold multiple concurrent queries): default one session; a **colour-by-session**
  toggle overlays several with distinct hues per `sessionCode`. Build one `Timeline` per session (events from
  `index.eventsForSession(code)`, `resolveTally` bound to `deanon.tallyOfNonce(code, …)`); overlay their active
  sets keeping each session's lit/pruned/found state separate (filter by `sessionCode`, as `analyzeQuery` does).
  The graph's hover/selection (graph-view) must **compose** with the lit state, not replace it.
- **found-routes side list** from `routes.ts`: each item shows length (hops) + per-link terms; selecting one
  **isolates** it (dim everything else). Show `sessionFoundState` explicitly: loading / still searching
  (mid-scrub) / no route found / found — never conflate them. Scrub to t=0 → clean empty; t=end → full final.
