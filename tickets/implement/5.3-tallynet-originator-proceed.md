The missing library step the regression check flagged (design.md § Lift proposal and settlement, and chipnet-review.md § Regression check): turning a discovered `Plan` into a `TrxRecord.topology` exists **nowhere** as protocol code — only the test harness `buildLift` hand-builds `topology.members` from a spec and never populates `dependsOn`. This ticket builds the real minting, the proceed/abort actions, contact-point stamping, and — critically — an end-to-end test that a `dependsOn`-nominated voter travels discovery → topology → vote count through a **real plan**, not a spec shortcut.

## Plan → topology minting

Add to the consensus side (likely `ConsensusNode`/`engine.ts`, or a new `mint.ts` it calls) the originator's record-minting:

```ts
mintRecord(args: {
	plan: Plan<TTerms, TPayload>,     // the chosen plan (one plan per record — see design.md)
	query: UniQuery<TTerms>,          // carries target, intents, method, liftContract, maxDepth
	payload: TPayload,                // the opaque Taleus value the originator sets once
	ttlMs?: number,                   // for the self-expiring codes; default from options
}): TrxRecord<TTerms, TPayload>
```

It must:

- **Assemble the voter (`V`) member set** = the union of each participant's self-vote and its `dependsOn` nominees, exactly the fold `prependMatch` already performs on the return trip. The originator's own member is included; a circular lift's originator appears once in `members` even though it rides two links. De-duplicate members by key (a voter nominated by several members appears once). This is the step whose absence the regression check named — it is the inverse-free continuation of the `dependsOn`→`plan.members` fold already present in discovery.
- **Key the path links by nonce** into `topology.links` (source/target member keys, negotiated per-intent terms) — the same shape `buildLift` produces, but from the plan's `path`, not a spec.
- **Stamp the proposal parameters** from the query: `method`, `liftContract` (omit when absent), and mint the self-expiring `transactionCode`/`sessionCode` (reuse the session code the plan's nonces were salted with, so `nonceToLinkId` maps still resolve).
- **Stamp contact points**: set `Member.physical` on the originator's own member and on voters that published one (carried on the plan's members). Contact points are how a promised lift stays resolvable (design.md § Lift proposal and settlement); the originator and voters publishing one is what makes principle 3 hold for a linear lift.
- Produce a record with **empty** signature sets, ready to feed to the originator's own `TrxParticipant.update` (which then classifies `ourPromiseNeeded` and signs the originator's promise, exactly as today).

The harness `buildLift` stays as a test convenience, but add a path so tests can mint from a real discovered plan (below). The `taleus-core` binding (`feat-tallynet-bind-taleus-core`) calls `mintRecord` from its `DiscoveryResult.plans` → `ConsensusEngine` hand-off.

## Proceed / abort

- **Proceed** = choose a plan (via the caller's `scorePlan`-ranked selection from `tallynet-lift-policy-hooks`), `mintRecord`, and `update` the record into the originator's own participant. Phase 1 is then under way; the originator waits like any member.
- **Abort** = only valid **before every participant has promised**. The originator signs a **pre-promise void** — an `NP` on its own participant member — which voids the lift by the existing "any `NP` voids" rule, and pushes it. After every participant has promised the originator has no special power; `abort` must refuse (no-op + logged) once `promisePhaseComplete` holds. Add an `abort(transactionCode)` to the originator/ConsensusNode that checks this and signs `NP` only when still allowed.
- A **linear** lift needs no separate "word back from the payee": plans return to the originator along the path the query took (discovery already does this), so by the time the originator mints, it holds the full plan. Document this (principle 4) — do not build a payee callback.

## End-to-end test (the flagged gap)

Add a test in `testing/` that runs **discovery then consensus on one harness network**, with no `buildLift` spec shortcut for the voter set:

- Build a small graph where an interior participant **nominates a referee** (a `V`-only member) via its `findAddress` `dependsOn`.
- Run a real `discover`, take a returned `Plan`, `mintRecord` from it.
- Assert the nominated referee appears in `topology.members` as a `V` member, rides no tally link (referee-only), and — after the promise phase completes — its `C` vote is **counted** toward the majority (and a missing/`NC` vote from it changes the outcome per the threshold).
- Cover: a voter nominated by **two** participants appears once and counts once; a circular lift where originator = payee mints a valid single-member-entry/two-link topology.

This closes "untested end-to-end in TallyNet" from the regression check.

## Edge cases & interactions

- Voter sets of 1, 2 (tie under default threshold → no settlement), 3, many — assert each mints a valid topology and settles (or doesn't) per `tallynet-terms-and-proposal-params`.
- A participant that is also a voter (self-vote): appears once in `members` with both `P` and `V` roles.
- The same voter nominated by several members: one member entry, counted once (de-dupe by key at mint).
- Abort after one participant has promised but not all: still allowed (phase incomplete) → signs `NP` → voids. Abort after **all** promised: refused (the lift is now resolvable only by voters).
- A plan whose members include a `dependsOn` nominee that is itself a participant → `prependMatch` already rejects this; `mintRecord` must surface the same invariant (a voter-only nominee).
- Circular lift: originator rides two links; `mintRecord` must not create a duplicate member entry (the `hasDuplicateMemberKey` rule would reject it).
- Minting must set the session code so `nonceToLinkId` resolution still works at every node that took part in discovery (reuse the discovery session code; don't mint a fresh one).
- Deadline/timeout seams stay untouched (`tallynet-propagation-timeouts`); `mintRecord` sets the transaction-code TTL only.
- No unverified input path is introduced — minting produces a record with empty signatures; all signing goes through the existing verified `update`.
