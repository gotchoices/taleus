The tallysim network-model tier (`tallysim-model-generators` → `tallysim-oracle` → `tallysim-runner`) builds networks, an oracle that says whether a route exists, and a sweep runner. `tallynet-discovery` ships the discovery engine with an injected `Clock`, a `TraceSink` emitting typed `TraceEvent`s, deterministic seeded behaviour, and an in-memory network harness under `tallynet/testing` (see that ticket's § Simulation readiness and `packages/tallynet/docs/design.md`). This ticket joins them.

## Scope

- **Simulated time.** A discrete-event scheduler implementing tallynet's `Clock`: timers and message deliveries are events on one queue; time jumps to the next event. A 10,000-node search takes seconds of wall time however long its simulated budget.
- **Network conditions** from the scenario: per-link latency distribution, drop probability, fraction of sleeping nodes (never answer), nodes that answer late (after the round's budget). Built on the `tallynet/testing` harness, not a second transport.
- **Node policy** for the simulation: the default single-denomination hooks, plus each node's local view of its own tallies' capacity from the network model (a node only knows its own tallies, as in reality).
- **Trace.** Collect every node's `TraceEvent`s into one time-ordered trace. Define and document the **trace file format** in `packages/tallysim/docs/design.md`: a header (scenario, seed, versions), the network snapshot, then events (JSON lines). Version it. The viewer (`tallysim-viewer`) reads exactly this; it must be possible to replay any recorded run.
- **Metrics (protocol level)**, per query and aggregated by the sweep runner: found vs. oracle (P(found | route exists)), time to first plan and to completion (simulated), messages per query, nodes touched, rounds used, plans found per query, and the prune reasons breakdown.
- **Experiments**, checked in alongside the oracle one: success vs. depth limit and time budget at fixed topology; effect of sleeping-node fraction and latency. Record findings briefly in the design doc.

## Edge cases & interactions

- Same seed + same scenario ⇒ byte-identical trace (test it).
- Late answers after the budget are folded into the next round, and the trace shows them as such (not lost, not double-counted in metrics).
- Concurrent queries in one simulation (several originators at once) don't share session state; traces keep them apart by session code.
- A query whose target is unreachable: empty result, metrics record "no route" vs. "route exists but not found" correctly.
- Large traces: streaming write, not one giant in-memory array; a 10,000-node run's trace size is reported and kept reasonable (consider an option to record only selected queries).

## Tests to plan

- Small hand-built graphs where the expected plans and event sequence are known exactly.
- Seeded random graphs: every found plan is valid per the oracle (exists, within depth, capacity respected); found ⊆ oracle-reachable.
- Determinism test above; scheduler unit tests (ordering of simultaneous events is defined and stable).
