The developer's requirement (2026-11-27): the simulator spins up independent nodes that act on their own. Only the simulator manager may see everything, and only to set up and monitor. Transitions depend only on the individual nodes. This is also the only way the simulator tests the per-node code Taleus will actually run.

**The boundary.** *World setup* may come from outside the nodes: the scenario gives each node its tallies, its list of voters it trusts, its settings and policy (as if handed out at birth), and it may derive these from the generated graph. *Runtime* decisions use only what the node holds. The manager:
- sets up the world;
- injects faults through the transport and resource layers;
- starts payments by telling an originator node "pay X to Y";
- observes via traces and metrics.

## Audit findings to fix (2026-11-27; read the code to confirm)

Discovery is already node-local (`makeFindAddress` in `tallynet/src/testing/network.ts`). Settlement is not:
- **The harness acts for the originator** (`tallysim/src/sim/consensus-harness.ts` `runLiftForOutcome`):
  - it picks the plan (`selectPlan`);
  - it mints the record with `net.buildLift`, not the originator's own `proceed()` / `mintFromPlan` (neither is called in tallysim);
  - it rewrites link intents before signing (`sanitiseRecordIntents`; fix this at the source, see memory note: lift terms must not hold Infinity).
- **Route reconstruction uses global knowledge.** `route.ts` `reconstructRoute` recomputes nonces for every tally in the network. `buildLift` / `addLiftLink` / `populateNonceMaps` take terms from the global adjacency and write nonce→link entries straight into nodes. The originator must build the record from its plan and its own nonce knowledge; each node maps nonces to its own links from what it recorded during discovery.
- **Voters and contact points are assigned by the harness** (`options.voters`, default `[route[0]]`; `liftMembers`), discarding the nominations discovery folded into the plan. Voters must come from nominations in discovery. This absorbs `debt-voter-nomination-on-path-composition`: self-vote must yield a `[P,V]` member, and a nominated hub must survive the fold.
- **"Well-known" is global degree used at runtime.** `well-known.ts` `wellKnownEntities` feeds `makeNomineesFor`, `voterAwareScorePlan`, `selectPlan`, `StackedVoterPolicy` and `countingRefusalScorer`. Turn this into world setup: each node receives a trusted-voter list at creation, which the scenario may generate from degree. Nodes then read only their own list.
- **Shared state across nodes:**
  - one `SeededRandom` shared by every node (it mints session and transaction codes, so one node's draws change others');
  - one `scorePlan` for every originator;
  - timing and discovery options applied to all nodes at once (`InMemoryNetwork`; `minPromiseMarginMs` / `skewGraceMs` not passed through);
  - a `planRefusals` counter shared by every node's scorer.

  Give each node its own random stream (derived deterministically from the run seed and node id), its own policy and its own settings. Metrics are collected by the manager from traces or per-node counters.
- **Nodes don't persist.** The runner rebuilds every node from the global network per query, and the manager moves balances on every tally from the originator's outcome alone. Nodes must persist across payments in a run, and each node books its own tallies from the outcome *it* reaches. The manager reads balances for metrics.
- **Library limits that are global, in `tallynet`:**
  - `MAX_PENDING_COMMITS_PER_VOTER` (participant.ts);
  - `MAX_PROOF_FACES_PER_SIGNER` (store.ts);
  - the `DEFAULT_MAX_TTL_MS` clamp in `proceed` (session-code.ts).

  Make each a per-node option with that default.

Legitimate and to keep: the oracle; metrics; fault injection in the transport and resource layers; adversary tests that inject forged records (`hostile-scenarios.test.ts`).

The circular lift is a stand-in for clearing discovery (DFS over the global graph, wrapped as a fake plan). Keep it only as a clearly labelled manager-supplied plan handed to the originator node, until `feat-tallysim-clearing-discovery` replaces it.
